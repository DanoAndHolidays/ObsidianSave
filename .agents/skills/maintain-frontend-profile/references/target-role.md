# 目标岗位：React + TypeScript 中大厂前端校招

## 目标定义

- 主投岗位：React + TypeScript 前端开发。
- 公司档位：互联网中大厂校招。
- 评价重点：扎实基础、真实项目交付、React 数据与状态流、TypeScript 建模、工程质量、现场编码和项目表达。

## 能力优先级

### P0：必须形成独立证据

- JavaScript 核心机制与异步并发。
- TypeScript 类型收窄、泛型、领域对象与接口边界。
- React Hooks、渲染行为、状态设计和常见闭包问题。
- 请求缓存、mutation、路由、表单、Schema 和错误反馈的完整链路。
- 浏览器事件、任务队列、渲染、缓存和常见网络问题。
- 项目探索、调试、最小改动、测试验证与风险说明。
- 高频代码题和边界条件处理。

### P1：应达到可应用或可解释

- CSS 布局、响应式、层叠和常见 UI 实现。
- 构建工具、包管理、模块机制、Lint、Git 和基本 CI。
- 性能指标、加载优化和基础可访问性。
- 项目难点、技术取舍、失败案例和个人贡献表达。

### P2：加分项

- React 原理与 Fiber 调度的准确心智模型。
- 前端架构、组件 API 设计、设计系统或复杂性能诊断。
- 对 Vue 或跨栈经验的清晰迁移说明。

## 学习计划约束

- 每周期最多三个重点，至少一个产生真实代码或测试证据。
- 新知识最多占一半；另一半用于复测旧弱点和形成独立证据。
- 优先修复会导致真实功能错误、测试缺口或项目讲解断裂的问题。
- 不把生僻 API、纯记忆冷知识或过度类型体操作为主要投入。

## 优先级公式

```text
priority = 0.40 × target_gap
         + 0.25 × recruitment_relevance
         + 0.20 × review_urgency
         + 0.15 × evidence_uncertainty
```

四项均归一化到 0–100。输出排序理由，不只输出结果数字。

## 默认周期分配

- 60%：P0 高频薄弱点和重复错误。
- 25%：真实 Issue、代码题、测试或 `create-exam` 验证。
- 15%：项目表达、面经复盘、简历证据和追问训练。
