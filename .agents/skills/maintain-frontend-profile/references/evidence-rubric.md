# 证据与评分规范

## 掌握等级

| 等级 | 定义 | 最低证据要求 |
|---|---|---|
| L0 | 没有有效证据 | 未发现或来源失效 |
| L1 | 接触过，能识别术语和用途 | 普通学习笔记、阅读记录 |
| L2 | 能准确解释并完成受控示例 | 本人推导、可运行示例、有效追问回答 |
| L3 | 能在有限提示下应用和排错 | 独立练习、代码题、局部真实修改及验证 |
| L4 | 能独立完成真实任务并处理边界 | 真实交付、测试或可观察验证、答辩通过 |
| L5 | 能跨场景设计、诊断、取舍和接管变化 | 至少两次跨时间独立验证，含变化题或复杂故障 |

## 证据强度

| 强度 | 典型来源 | 能力上限 |
|---|---|---|
| `trace` | 文件名、目录、摘录、参考答案 | 只用于覆盖统计 |
| `low` | 普通知识笔记、AI 辅助总结 | 通常 L1 |
| `medium` | 本人推导、可运行示例、独立代码题、面试原回答 | 通常 L2–L3 |
| `high` | 真实项目差异、测试结果、阅卷报告、答辩、现场接管 | 通常 L3–L5 |

证据强度只是上限，不是自动等级。项目笔记没有实现和验证结果时仍可能只有 `low`。

## 四个分项

- `knowledge`：解释概念、机制、边界和因果。
- `application`：在示例、练习或局部场景中正确使用。
- `delivery`：探索真实代码、完成行为、控制范围并验证。
- `explanation`：答辩、预测改动后果、指出证据和接管变化。

每项使用 0–100 整数。没有相应证据时使用 `null`，不要写 0 来伪装成已测失败。

当四项均有可比较证据时，派生准备度：

```text
readiness = 0.20 × knowledge
          + 0.30 × application
          + 0.30 × delivery
          + 0.20 × explanation
```

缺失分项时可以计算 `observed_readiness`，但必须显示覆盖率，并禁止与完整准备度直接排名。

## 置信度

- `low`：只有单一笔记、来源含混、独立性未知或证据陈旧。
- `medium`：至少一个可验证实践，或多个相互印证的中等证据。
- `high`：至少两个独立证据，且包含真实交付、答辩、测试或现场验证。

## 状态与复习

- 没有独立实践证据：`未定级`。
- 最近验证得分低于 70%：`薄弱`，3 天内复习。
- 70%–84.9%：`发展中`，7 天内复习。
- 最近两次独立验证均不低于 85%：`稳定`，首次 14 天、连续三次 30 天复习。
- 重复交付或掌握错误：无论总分，3 天内复测。
- 时间流逝只影响 `freshness` 和复习日期，不自动抹掉历史等级。

## 独立性

使用 `independent`、`assisted` 或 `unknown`：

- Agent 可以参与实现；保留交付证据，但只有本人能解释、预测、举证和接管时才提升独立掌握。
- 明确抄写、恢复标准答案或只粘贴参考实现时，不将其作为独立能力。
- 无法确认时使用 `unknown`，不追溯猜测。

## 反失真规则

- 不以笔记数量、篇幅、代码块数量或目录覆盖替代能力证据。
- 不把面经里的参考答案当成当时回答。
- 不把一次高分直接升级为稳定。
- 不把同一份材料的重复整理算成多次验证。
- 不因整体项目成功掩盖具体知识点错误。
- 每个分数、等级变化和学习优先级都必须能回链到证据 ID。
