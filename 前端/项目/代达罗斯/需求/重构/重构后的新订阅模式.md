# 重构后的新订阅模式
> Last Format Time：8/13/2026 15:14:04

提问：
```ts
const WorkspaceSwitcherContent = () => {
  const { t } = useTranslation();
  const store = useWorkspaceStore();
  const switcherStore = useWorkspaceSwitcherStore();

  ...

  const creating = useStore(switcherStore, (state) => state.creating);
  const closeMenu = useStore(switcherStore, (state) => state.closeMenu);
  const handleToggleClick = useStore(
    switcherStore,
    (state) => state.handleToggleClick,
  );
```

我有个问题，这里这些从store中去出来的值并不像我们平时开发使用的state，那么他们是怎么去触发更新的呢

它们虽然不是 React `useState` 返回的 state，但依然是“响应式快照”。关键在这一行：
```ts
const personal = useStore(store, (s) => s.personal);
```

这里的 `useStore` 是 Zustand 的 React Hook，它做了两件事：
1. 读取当前 Store 中 `personal` 的值。
2. 订阅 Store 的变化。

当 Store 内部调用 `set` / `setState`：
```ts
set({ personal: newPersonal });
```

大致会经过下面的流程：
```text
set 更新 Zustand Store
  → Store 通知所有订阅者
  → selector 重新执行：(s) => s.personal
  → 新旧 personal 通过 Object.is 比较
  → 值发生变化
  → WorkspaceSwitcherContent 重新渲染
```

因此，这个变量：
```ts
const personal = useStore(store, (s) => s.personal);
```

可以理解成当前这次 React 渲染所拿到的 Store 快照。组件重新渲染后，`useStore` 会再次返回最新快照。

它与 `useState` 的区别主要在状态放在哪里：
```ts
const [personal, setPersonal] = useState(...);
```

`useState` 的状态由 React 管理；而：
```ts
const personal = useStore(store, (s) => s.personal);
```

状态由 Zustand Store 管理，React 只是通过 `useStore` 订阅它。Zustand 底层会借助 React 的 `useSyncExternalStore` 把外部 Store 接入 React 的渲染机制。

你这里每一行都是一条独立订阅：
```ts
const personal = useStore(store, (s) => s.personal);
const teams = useStore(store, (s) => s.teams);
const isLoading = useStore(store, (s) => s.isLoading);
```

例如只更新：
```ts
set({ isLoading: true });
```

Zustand 会重新执行这些 selector，但只有 `isLoading` 的选择结果发生了变化。其余结果仍然相同，不会因为自己的 selector 结果变化而要求重渲染。不过由于它们属于同一个组件，只要其中任意订阅触发组件更新，整个组件函数都会重新执行一次。

需要注意引用比较。例如：
```ts
set((state) => {
  state.teams.push(newTeam);
  return state;
});
```

如果直接修改原数组，`teams` 的引用可能没有改变：
```ts
Object.is(oldTeams, newTeams); // true
```

订阅可能无法检测到更新。应该创建新引用：
```ts
set((state) => ({
  teams: [...state.teams, newTeam],
}));
```

还有一个重要区别：

```ts
const teams = store.getState().teams;
```

这种写法只读取一次，不会订阅，因此不会自动触发 React 更新。而：

```ts
const teams = useStore(store, (s) => s.teams);
```

才是 React 中响应式的用法。

至于这些 action：

```ts
const closeMenu = useStore(switcherStore, (state) => state.closeMenu);
```

它们同样经过订阅，不过 Zustand 中 action 函数一般在 Store 创建时生成，并且引用长期保持不变，所以其他状态更新时通常不会因为这些函数而触发更新。
