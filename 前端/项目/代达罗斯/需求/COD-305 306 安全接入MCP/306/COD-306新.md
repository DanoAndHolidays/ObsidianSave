**目标：** 让已经通过 COD-305 连接 Daedalus 的 Coding Agent，可以在连接绑定的 Workspace 内读取项目和治理信息、发起扫描、查看 Run/Trace/Finding，并在用户确认后处理 Finding。

**架构：** MCP 请求先经过 COD-305 的 OAuth 和 Workspace 授权，得到服务端生成的 `McpAuthorizationContext`。Tool 只能把这个上下文交给 MCP Service；Service 再调用 Workspace-scoped DAO 查询数据，不能相信客户端传入的 Workspace。Repository 只保留给跨表事务写入，不承担读取。每次 Tool 调用都写一条脱敏调用记录，Settings 页面只读取这些记录。

**技术栈：** TypeScript、Zod v4、neverthrow、Drizzle ORM、PostgreSQL、mcp-handler 2.1、MCP SDK v2、tRPC、Refine、React 19、Vitest、Storybook。

## 先用 5 分钟看懂这次要做什么
### 你最终要打通的请求链
```text
Coding Agent
    ↓ HTTP POST /api/mcp
OAuth 校验（COD-305）
    ↓
McpAuthorizationContext
    ├── connectionId
    ├── ownerUserId
    └── workspaceId（永远由服务端提供）
    ↓
MCP Tool Registry
    ↓
MCP 专用 Service
    ↓
Workspace-scoped DAO
    ↓
DAO / GitHub API / Scan Orchestrator
    ↓
统一 Tool 返回 + 调用记录
```

### 这几个词分别是什么
| 名词 | 你可以把它理解为 |
|---|---|
| MCP Handler | 接收 Coding Agent 请求的 HTTP 控制器 |
| MCP Tool | Coding Agent 可以调用的一个后端函数，例如 `project_list` |
| Tool Registry | 把 Tool 名称、输入 Schema 和真正执行的函数注册到 MCP Server |
| Zod Schema | 运行时输入校验，阻止错误参数进入业务逻辑 |
| Authorization Context | 服务端确认过的连接身份和固定 Workspace，不允许客户端修改 |
| DAO | 只做数据库读写；本需求的 `mcpReviewContextDao` 用联表查询保证对象属于当前 Workspace |
| Repository | 只处理跨表事务写入；本需求的 Workspace 读取防线不放在 Repository |
| Service | 做权限、确认、状态变化、错误转换等业务逻辑 |
| tRPC | Settings 页面读取调用历史的内部 API；MCP Tool 不经过 tRPC |
| Refine | React 页面调用 tRPC 的数据获取层 |

```typescript
import { desc, eq, sql } from "drizzle-orm";
import type { Database } from "@repo/db";
import {
  mcpToolInvocationsTable,
  type McpToolInvocationInsert,
} from "@repo/db-schema";

export const createMcpToolInvocationsDao = function(db: Database) {
  return {
    async create(input: McpToolInvocationInsert) {
      const rows = await db
        .insert(mcpToolInvocationsTable)
        .values(input)
        .returning();

      return rows[0]!;
    },

    async listByConnection(
      connectionId: string,
      input: { limit: number; offset: number },
    ) {
      const where = eq(mcpToolInvocationsTable.connectionId, connectionId);
      const [rows, totals] = await Promise.all([
        db
          .select()
          .from(mcpToolInvocationsTable)
          .where(where)
          .orderBy(desc(mcpToolInvocationsTable.createdAt))
          .limit(input.limit)
          .offset(input.offset),
        db
          .select({ count: sql<number>`count(*)` })
          .from(mcpToolInvocationsTable)
          .where(where),
      ]);

      return { rows, total: Number(totals[0]?.count ?? 0) };
    },
  };
};

export type McpToolInvocationsDao = ReturnType<
  typeof createMcpToolInvocationsDao
>;
```

```typescript
import { and, count, desc, eq } from "drizzle-orm";
import type { Database } from "@repo/db";
import {
  findingsTable,
  githubProjectsTable,
  reviewRunsTable,
  traceEventsTable,
  type FindingRecord,
  type GithubProjectRecord,
  type ReviewRunRecord,
  type TraceEventRecord,
} from "@repo/db-schema";

export type McpReviewContextPageInput = {
  limit: number;
  offset: number;
};

export type McpReviewContextPage<T> = {
  rows: T[];
  total: number;
};

export const createMcpReviewContextDao = function(db: Database) {
  return {
    async findManyProjectsByWorkspace(
      workspaceId: string,
      page: McpReviewContextPageInput,
    ): Promise<McpReviewContextPage<GithubProjectRecord>> {
      const workspaceScope = eq(githubProjectsTable.workspaceId, workspaceId);
      const [rows, totalRows] = await Promise.all([
        db
          .select()
          .from(githubProjectsTable)
          .where(workspaceScope)
          .orderBy(desc(githubProjectsTable.createdAt))
          .limit(page.limit)
          .offset(page.offset),
        db
          .select({ value: count() })
          .from(githubProjectsTable)
          .where(workspaceScope),
      ]);

      return { rows, total: totalRows[0]?.value ?? 0 };
    },

    async findProjectByWorkspaceAndId(
      workspaceId: string,
      projectId: string,
    ): Promise<GithubProjectRecord | null> {
      const rows = await db
        .select()
        .from(githubProjectsTable)
        .where(
          and(
            eq(githubProjectsTable.id, projectId),
            eq(githubProjectsTable.workspaceId, workspaceId),
          ),
        )
        .limit(1);

      return rows[0] ?? null;
    },

    async findRunByWorkspaceAndId(
      workspaceId: string,
      runId: string,
    ): Promise<ReviewRunRecord | null> {
      const rows = await db
        .select({ run: reviewRunsTable })
        .from(reviewRunsTable)
        .innerJoin(
          githubProjectsTable,
          eq(reviewRunsTable.projectId, githubProjectsTable.id),
        )
        .where(
          and(
            eq(reviewRunsTable.id, runId),
            eq(githubProjectsTable.workspaceId, workspaceId),
          ),
        )
        .limit(1);

      return rows[0]?.run ?? null;
    },

    async findFindingByWorkspaceAndId(
      workspaceId: string,
      findingId: string,
    ): Promise<FindingRecord | null> {
      const rows = await db
        .select({ finding: findingsTable })
        .from(findingsTable)
        .innerJoin(
          reviewRunsTable,
          eq(findingsTable.runId, reviewRunsTable.id),
        )
        .innerJoin(
          githubProjectsTable,
          eq(reviewRunsTable.projectId, githubProjectsTable.id),
        )
        .where(
          and(
            eq(findingsTable.id, findingId),
            eq(githubProjectsTable.workspaceId, workspaceId),
          ),
        )
        .limit(1);

      return rows[0]?.finding ?? null;
    },

    async findManyFindingsByWorkspace(
      workspaceId: string,
      page: McpReviewContextPageInput,
    ): Promise<McpReviewContextPage<FindingRecord>> {
      const workspaceScope = eq(githubProjectsTable.workspaceId, workspaceId);
      const [findingRows, totalRows] = await Promise.all([
        db
          .select({ finding: findingsTable })
          .from(findingsTable)
          .innerJoin(
            reviewRunsTable,
            eq(findingsTable.runId, reviewRunsTable.id),
          )
          .innerJoin(
            githubProjectsTable,
            eq(reviewRunsTable.projectId, githubProjectsTable.id),
          )
          .where(workspaceScope)
          .orderBy(desc(findingsTable.createdAt))
          .limit(page.limit)
          .offset(page.offset),
        db
          .select({ value: count() })
          .from(findingsTable)
          .innerJoin(
            reviewRunsTable,
            eq(findingsTable.runId, reviewRunsTable.id),
          )
          .innerJoin(
            githubProjectsTable,
            eq(reviewRunsTable.projectId, githubProjectsTable.id),
          )
          .where(workspaceScope),
      ]);

      return {
        rows: findingRows.map(({ finding }) => finding),
        total: totalRows[0]?.value ?? 0,
      };
    },

    async findManyTraceEventsByWorkspaceAndRun(
      workspaceId: string,
      runId: string,
      limit: number,
    ): Promise<TraceEventRecord[]> {
      const rows = await db
        .select({ traceEvent: traceEventsTable })
        .from(traceEventsTable)
        .innerJoin(
          reviewRunsTable,
          eq(traceEventsTable.runId, reviewRunsTable.id),
        )
        .innerJoin(
          githubProjectsTable,
          eq(reviewRunsTable.projectId, githubProjectsTable.id),
        )
        .where(
          and(
            eq(traceEventsTable.runId, runId),
            eq(githubProjectsTable.workspaceId, workspaceId),
          ),
        )
        .orderBy(desc(traceEventsTable.createdAt))
        .limit(limit);

      return rows.map(({ traceEvent }) => traceEvent);
    },
  };
};

export type McpReviewContextDao = ReturnType<
  typeof createMcpReviewContextDao
>;
```

这里有 4 条不能改的安全规则：

1. Project 直接同时按 `projectId + workspaceId` 查询。

3. Finding 和 Trace 必须连接 Run，再连接 Project，最后在 SQL 中按 `workspaceId` 过滤。
4. 不允许调用现有 `getById()` 后再写 `if (record.workspaceId !== ...)`；这种写法会让越权数据先进入内存。

```typescript
import type { Result } from "neverthrow";

export type McpToolFailure = {
  code:
    | "invalid_input"
    | "confirmation_required"
    | "workspace_scope_denied"
    | "not_found"
    | "operation_unavailable"
    | "connection_unavailable"
    | "internal";
  message: string;
  recovery: string | null;
};

export type McpToolSuccess<T> = {
  workspace: { id: string; name: string };
  result: T;
  nextActions: string[];
};

export type McpToolResult<T> = Result<McpToolSuccess<T>, McpToolFailure>;

export const toMcpContent = function<T>(
  result: McpToolResult<T>,
  meta: { tool: string; workspaceId: string },
) {
  const envelope = result.match(
    (success) => ({
      success: true as const,
      workspace: success.workspace,
      tool: meta.tool,
      result: success.result,
      nextActions: success.nextActions,
      error: null,
    }),
    (error) => ({
      success: false as const,
      workspace: { id: meta.workspaceId, name: null },
      tool: meta.tool,
      result: null,
      nextActions: error.recovery ? [error.recovery] : [],
      error,
    }),
  );

  return {
    content: [
      {
        type: "text" as const,
        text: JSON.stringify(envelope),
      },
    ],
    structuredContent: envelope,
    isError: !envelope.success,
  };
};
```

```typescript
import { err, ok, type Result } from "neverthrow";
import type { McpToolFailure } from "./mcp-tool-result";

export const validateMcpRepositoryPath = function(
  path: string,
): Result<string, McpToolFailure> {
  const normalized = path.trim();
  if (
    normalized.length === 0 ||
    normalized.startsWith("/") ||
    normalized.includes("\\") ||
    normalized.split("/").includes("..")
  ) {
    return err({
```

## 新手最容易踩的坑
1. **在当前 COD-305 分支直接继续写 COD-306。** 正确做法是等 COD-305、COD-257 合入 `develop` 后重新切分支。
2. **让 Tool 输入包含 workspaceId。** 不要这样做；Workspace 只能来自 `McpAuthorizationContext`。
3. **直接调用 public tRPC procedure。** MCP Tool 应调用 MCP Service；Service 再调用 Workspace-scoped DAO，tRPC 只是 Settings UI 的 adapter。
4. **先按 ID 查对象，再判断 Workspace。** 必须在 SQL query 中 join Project 并同时过滤 workspaceId。
5. **用 `confirmed: true` 但没有确认摘要。** Execute/Write 必须同时有 `confirmationSummary`，便于审计用户确认了什么。
6. **在调用记录保存完整输入或文件内容。** 只保存安全键和 500 字符以内摘要。
7. **同步等待扫描完成。** `scan_start` 只 enqueue；Agent 用 Run/Trace Tool 轮询。
8. **把所有 Tool 写进一个巨型文件。** 按 Project、Repository、Metadata、Scan、Finding 拆 Service；Registry 只负责注册。
9. **为了复用把页面组件放进全局 components。** 这两个 Tab 只服务 Settings，必须留在 `AiReviewsSettingsPage`。
10. **强制提交 docs。** `docs/COD-306/` 是你的本地说明书，不进入 Git。
