## 选题依据
这次以真实的 `WorkspaceSwitcher` 前端链路为题。它复测能力画像中仍偏弱的异步 UI、最终 JSX 消费和副作用清理，同时加入 Zustand 页面 Store 的新结构。业务场景与最近的 Finding、Anatomy、代码片段考试不同，避免只记住上一题答案。

建议用时：60–90 分钟。前两题用于快速进入状态，之后按题号从 Store 上游一路接到 JSX。

---
## Issue 背景
用户需要在侧栏切换工作区，也可以直接创建一个新团队。创建不是单次请求：前端必须先创建团队，再刷新工作区列表，最后才能选中新团队并收起菜单。任何一步失败都要保留可恢复的 UI；菜单打开后还要正确处理外部点击，且不能泄漏全局事件监听器。

---
## 行为验收
1. 团队名称输入框保持受控；继续输入会清除旧错误，创建期间不可编辑。
2. `Enter` 发起创建，`Escape` 清除错误并退出创建面板，普通按键不产生额外副作用。
3. 空字符串和纯空格在本地被拦截，不调用创建或刷新；超过 50 个字符仍沿用现有校验。
4. 正常流程严格按“创建 → 刷新 → 选中”执行；刷新失败时不能选中新团队。
5. 成功后关闭创建面板和菜单；失败后保留面板并显示可理解的错误；无论结果如何都结束 `creating` 状态。
6. 菜单只在打开时监听外部 `mousedown`；内部点击不关闭，外部点击关闭，重订阅和卸载时无监听器泄漏。

```text
        ↓ 成功                         ↓ 失败

menuOpen / showCreate / creating 状态回到 JSX

Provider: dependencies → 创建一次 Store → Context → Content / MenuRow
外部 mousedown → ref.contains 判断 → closeMenu → cleanup
```

## 逐题说明（代码 70 分）
### 第1题（5分）：把键盘意图映射到已有动作
- 文件：`workspaceSwitcherSlice.ts`
- 目标：分别处理 Enter 和 Escape。
- 边界：不要把异步 Promise 作为 React 事件回调的返回值；其他按键无副作用。
- 自检：Enter 调用已有创建动作；Escape 清错并退出创建面板。

### 第2题（5分）：同步受控输入并清除旧错误
- 文件：`workspaceSwitcherSlice.ts`
- 目标：在一次不可变状态更新中同步新值并清空错误。
- 边界：不要直接修改 Store 状态对象。
- 自检：输入后 `createName` 改变，旧 `createErrMsg` 变为 `null`。

### 第3题（10分）：为空名称建立早返回边界
- 文件：`workspaceSwitcherSlice.ts`
- 目标：利用已计算的 `trimmed` 拦截空白名称并展示本地化错误。
- 边界：不得进入请求，也不得把 `creating` 设为 `true`。
- 自检：空值和纯空格都不调用 `createTeam`/`refreshWorkspaces`。

### 第4题（10分）：串联刷新并保留创建结果
- 文件：`workspaceSwitcherSlice.ts`
- 目标：把刷新 Promise 接入当前 `ResultAsync`，成功后继续向下传递原 `team`。
- 边界：刷新失败必须进入后面的统一失败分支，不能提前选中工作区。
- 自检：顺序是 create → refresh；下游仍能取得 `team.id`。

### 第5题（15分）：收束异步成功与失败状态
- 文件：`workspaceSwitcherSlice.ts`
- 目标：补全 `match` 的成功、失败回调。
- 边界：非 `Error` 原因使用现有英文兜底；不要在分支里重复处理统一的 `creating` 复位。
- 自检：成功选中并关闭界面；失败不选中、保留面板并显示错误。

### 第6题（5分）：为 Provider 创建稳定 Store 实例
- 文件：`provider.tsx`
- 目标：使用已有的一次性初始化 Hook 创建 Store，并传入依赖。
- 边界：不能每次渲染都创建新 Store，否则用户正在编辑的状态会丢失。
- 自检：父组件重渲染后 Store 引用和交互状态保持不变。

### 第7题（10分）：订阅外部点击并对称清理
- 文件：`WorkspaceSwitcher.tsx`
- 目标：定义内外点击判断、条件注册和 cleanup。
- 边界：`ref` 为空或点击内部时不关闭；添加和移除必须使用同一个 handler 引用。
- 自检：反复开关菜单不会累积 `mousedown` 监听器。

### 第8题（10分）：把 Store 状态与动作接到输入框
- 文件：`WorkspaceSwitcher.tsx`
- 目标：补齐输入框的禁用态、受控值、change 和 keydown 四个绑定。
- 边界：传递函数引用，不要在渲染期间调用处理器。
- 自检：第1、2题的状态和动作能从真实 UI 被触发。
