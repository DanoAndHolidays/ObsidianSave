# 建立早返回边界
> Last Format Time：8/13/2026 15:14:03

“建立早返回边界”一般就是指：**在函数开头尽早判断那些“不需要继续执行”的情况，然后直接 `return` 掉**。

比如你原来可能会这样写：
```js
function handleUser(user) {
  if (user) {
    if (user.active) {
      if (user.age >= 18) {
        console.log("开始处理用户");
      }
    }
  }
}
```

这种代码会一层一层往里缩进。

改成“早返回”：
```js
function handleUser(user) {
  if (!user) return;
  if (!user.active) return;
  if (user.age < 18) return;

  console.log("开始处理用户");
}
```

这里前面这几句：

```js
if (!user) return;
if (!user.active) return;
if (user.age < 18) return;
```

就可以理解成在建立一个个**边界**。

意思是：

> 不满足条件的人，到这里就别往下走了。

这样真正的核心逻辑：

```js
console.log("开始处理用户");
```

就不需要被很多 `if` 包起来。

你可以把它理解成门卫：

```text
进入函数
  ↓
user 不存在？ ── 是 → return
  ↓ 否
user 未激活？ ── 是 → return
  ↓ 否
未成年？ ───── 是 → return
  ↓ 否
执行核心逻辑
```

这种写法也经常叫 **guard clause（守卫语句）**。

前端里非常常见，比如 React 事件：
```js
const handleClick = (event) => {
  const target = event.target;

  if (!(target instanceof HTMLElement)) return;

  if (target.closest("button")) return;

  navigate("/detail");
};
```

这里就是：
```js
if (!(target instanceof HTMLElement)) return;
```

建立第一道边界：不是 HTMLElement，不处理。

```js
if (target.closest("button")) return;
```

建立第二道边界：点到了按钮，不执行行跳转。

最后剩下：
```js
navigate("/detail");
```

就是正常主流程。

所以你以后看到别人说：

> “这里应该建立一个早返回边界。”

基本就是在说：

**把异常情况、非法情况、不需要处理的情况提前 `return`，让后面的代码只处理正常情况。**

它最大的价值不是“少写代码”，而是让代码从：

```js
if (A) {
  if (B) {
    if (C) {
      // 真正逻辑
    }
  }
}
```

变成：

```js
if (!A) return;
if (!B) return;
if (!C) return;

// 真正逻辑
```

后者通常会明显更容易读。
