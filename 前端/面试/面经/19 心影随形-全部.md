6/10/26
本次会议是一场面试交流，面试官丰荣成与求职者吴明祥围绕吴明祥的个人情况、技术学习、agent 相关知识及应用等方面展开交流，探讨了 agent 与工作流的区别、游戏 agent 的设计等内容，内容如下：

- **个人情况介绍**
    
    - **教育背景**：吴明祥是中国矿业大学徐州校区在读大三学生，专业为计算机科学技术。
        
    - **实习经历**：曾在字节实习三个月，负责火山账号管理和芭比预算平台业务，进行线上 bug 修正和简单业务需求处理。
        
    - **学习方向**：对前端方向感兴趣，大二开始学习前端知识，做过学习项目，近期在学习 agent 相关知识，尝试将其融入编程环境提高效率，还在开源社区有贡献。
        
- **Agent 知识探讨**
    
    - **学习内容**
        
        - 相关技术：吴明祥学习了 agent 有关的 skill、MCP 工具、经典范式及解决问题的常规套路，正在搭建一个 agent 框架，已实现工具调用和 agent 范式部分。
            
        - 经典范式：介绍了 React 范式、plan and solve 范式及在此基础上的反思范式，还可对这些范式进行组合或线性排列实现更复杂的 agent 范式。

    - **与工作流的区别**
        
        - 灵活程度：丰荣成以邮件汇总为例说明工作流和 agent 都能实现相关功能。吴明祥认为 agent 比工作流更灵活，可在基础工作流功能上扩展，工作流是流水线形式，依赖上一阶段任务完成后执行下一阶段，流程较确定，但具体业务场景不同会有差异。
            
        - 应用场景：在简单任务场景使用工作流即可，若场景中有 agent 已有条件和基础架构，接入 agent 未来有更多可扩展空间。

- **游戏 Agent 设计**
    
    - **设计思路**
        
        - 初步想法：丰荣成提出让吴明祥设计一个根据用户简单需求描述自动生成 H5 小游戏的 agent。吴明祥最初想先让 agent 跑一个静态页面供用户查看设计，后在丰荣成提示下，提出构建提示词模板，使用 plan and sold agent 生成计划并依次执行，再接入验收 agent 根据用户提示词生成验收标准进行检查。

        - 改进方案：考虑到游戏设计包含美术、音乐、关卡策划等多方面，吴明祥提出将各方面设计做成子 agent，由游戏策划 agent 给子 agent 发布任务，完成任务后进入编码执行环节，但验收部分暂时没有思路。
            
    - **存在问题及解决方法**
        
        - 上下文问题：丰荣成指出加载过多提示词会导致上下文稀释严重，吴明祥提出将部分提示词内容提到 Skill 中，采用间接式披露形式动态加载，还可用上下文压缩的子 agent 进行总结归纳。
            
        - 素材生成问题：丰荣成提到模型现场生成游戏素材时间长，吴明祥表示知晓需涉及 rag 东西，从常用素材库召回素材。
            
- **其他交流**
    
    - **写码工具**：吴明祥平时写码使用国内的 trae 及相关插件，国外用 claude code（CLI），之前用订阅账号，被封后用 cc switch 转接国内模型。
        
    - **Harness 应用**：吴明祥表示自己搭建的 agent 仅实现了记忆系统和工具，还不能称为完整的 harness，harness 是 agent 减去大模型客户端外的所有内容，包括提示词工程、上下文工程等。
        
    - **实习相关**
        
        - 实习周期：吴明祥实习周期约 4 个月，最快 7 月 10 号左右入职，因学校考试和课程安排暂无法确定具体时间。
            
        - 待遇要求：吴明祥表示待遇符合公司制度即可。
            
- **后续工作计划**：后续 HR 会与吴明祥沟通实习相关事宜。
