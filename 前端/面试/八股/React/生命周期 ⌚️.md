# 生命周期⌚️
在 React 中，函数式组件本身没有传统类组件那样的生命周期方法。但是，通过引入 Hooks（特别是 `useEffect`），我们可以完美地模拟和实现这些生命周期行为。

以下是常见生命周期方法在函数式组件中的对应实现方式：

### 1. 模拟 `componentDidMount`（组件挂载后）

当组件首次渲染并挂载到 DOM 后执行某些操作（如发送网络请求、初始化数据）。 **实现方式：** 使用 `useEffect`，并将依赖项数组设置为空 `[]`，确保副作用函数仅在初始渲染时执行一次。

```javascript
useEffect(() => {
  console.log('组件已挂载');
  // 在这里发送 API 请求或设置订阅
}, []); 
```

### 2. 模拟 `componentDidUpdate`（组件更新后）

当组件的 `props` 或 `state` 发生变化导致重新渲染后执行某些操作。 **实现方式：** 使用 `useEffect`，并在依赖项数组中传入需要监听的变量。当这些变量改变时，回调函数会重新执行；如果不传第二个参数，则每次渲染后都会执行。

```javascript
const [count, setCount] = useState(0);

// 仅当 count 变化时执行
useEffect(() => {
  console.log('count 更新了:', count);
}, [count]); 
```

### 3. 模拟 `componentWillUnmount`（组件卸载前）

在组件即将被销毁前进行清理工作（如清除定时器、取消事件订阅等，防止内存泄漏）。 **实现方式：** 在 `useEffect` 的回调函数中返回一个“清理函数”（Cleanup function），该函数会在组件卸载前自动调用。

```javascript
useEffect(() => {
  const timer = setInterval(() => {
    console.log('定时器运行中...');
  }, 1000);

  // 返回清理函数
  return () => {
    clearInterval(timer);
    console.log('组件即将卸载，定时器已清理');
  };
}, []); 
```

### 4. 其他生命周期的替代方案

除了上述三个最常用的生命周期外，还有其他对应的 Hook 实现：

- **`constructor`（初始化状态）**：直接使用 `useState` 声明状态，或在组件顶层声明变量和函数即可。
- **`shouldComponentUpdate`（性能优化）**：可以使用 `React.memo` 包裹组件，或者结合 `useMemo`、`useCallback` 来避免不必要的重渲染。
- **`render`（定义 UI 结构）**：函数组件直接 `return` 的 JSX 就等同于类组件中的 `render` 方法。

总结来说，React Hooks 的设计哲学是将原本分散在各个生命周期中的逻辑，按照**“关注点分离”**的原则整合在一起。你不再需要把相关逻辑拆分到 `componentDidMount` 和 `componentWillUnmount` 中，而是通过 `useEffect` 将它们集中管理，使代码更加简洁且易于维护。

在 React 中，`useEffect` 的第二个参数（依赖项数组）是控制副作用执行时机的核心机制。根据传入内容的不同，主要分为以下三种情况：

### `useEffect` 依赖项规则表

|依赖项写法|执行时机|典型使用场景|
|:--|:--|:--|
|**不传** (省略第二个参数)|组件初始渲染后执行一次，且在**每次**组件重新渲染（更新）后都会再次执行。|极少使用。仅适用于需要实时响应所有状态或 props 变化的场景（如某些 DOM 操作）。频繁触发易导致性能问题或无限循环。|
|**空数组** `[]`|仅在组件**首次挂载**时执行一次，卸载时执行清理函数。|初始化数据请求、注册全局事件监听器、初始化第三方库等“一生只执行一次”的操作。|
|**包含变量** `[dep1, dep2]`|组件首次挂载时执行一次，并在数组中**任意一个依赖项发生变化**时重新执行。|需要根据特定状态（state）或属性（props）的变化来同步更新的副作用，如根据用户 ID 变化重新拉取数据。|

### ⚠️ 核心避坑指南与最佳实践

在使用依赖项数组时，有几个极易踩坑的关键点需要特别注意：

#### 1. 警惕“闭包陷阱”（旧值问题）

当使用**空数组 `[]`** 时，如果副作用内部引用了组件的状态（state）或属性（props），这些变量的值会被“冻结”为组件首次挂载时的初始值。后续即使状态更新，副作用内拿到的依然是旧值。

- **错误示例**：在 `setInterval` 中使用 `count`，但依赖项为空，会导致定时器永远打印初始值。
- **解决方案**：
    - 将用到的变量加入依赖项数组（如 `[count]`），但这会导致定时器被频繁重建和清除。
    - 使用 `useRef` 保存最新值，绕过闭包限制。
    - 在更新状态时使用**函数式更新**（如 `setCount(prev => prev + 1)`），这样无需依赖外部变量即可获取最新状态。

#### 2. 引用类型导致的“无限循环”

React 对依赖项的比较是基于**浅比较（引用相等性）**的。对于对象、数组或函数，只要内存地址改变，React 就会认为依赖发生了变化。

- **错误示例**：将组件内部定义的对象或函数直接作为依赖项。因为每次渲染都会创建新的对象/函数，导致 `useEffect` 不断触发，进而引发无限重渲染。
- **解决方案**：
    - 提取关键的基础类型属性作为依赖（如用 `user.id` 代替整个 `user` 对象）。
    - 使用 `useMemo` 缓存复杂对象，或使用 `useCallback` 缓存函数，以保持引用的稳定性。

#### 3. 严格遵守“完整性原则”

副作用函数中引用的所有外部变量（包括 state、props、普通变量等），**必须全部声明在依赖项数组中**，绝不能为了“防止频繁执行”而故意遗漏。

- **建议**：务必开启 ESLint 的 `react-hooks/exhaustive-deps` 规则，它会在开发阶段自动检测并警告你遗漏的依赖项，这是保障代码健壮性的最有效手段。

#### 4. 依赖数组必须是静态结构

依赖数组必须是一个固定长度的数组字面量（如 `[a, b]`），**绝对不能**传入动态生成的数组变量（如 `items` 或 `[...items]`）。React 要求依赖数组的结构在每次渲染中保持绝对稳定，否则会导致不可预测的行为和潜在的内存泄漏。
