# 值导入与类型导入
> Last Format Time：8/13/2026 15:14:03

一般来说，**不会立刻出问题**，但最好写成 `import type`。具体影响取决于你的 TypeScript 配置和构建工具。

假设你导出了一个类型：

```ts
// user.ts
export type User = {
  name: string;
};
```

你这样导入：

```ts
import { User } from "./user";

const user: User = {
  name: "Dano",
};
```

---
## 默认情况下：通常没有运行时影响
TypeScript 能识别到 `User` 只被当作类型使用，因此编译成 JavaScript 时，会把整个导入删除：

```js
const user = {
  name: "Dano",
};
```

这种行为叫做 **import elision（导入消除）**。因此大多数默认配置下：

* 不会真的在运行时加载 `User`
* 不会增加打包体积
* 一般也不会造成运行时错误

([TypeScript][1])

---
## 开启 `verbatimModuleSyntax` 时会报错
如果 `tsconfig.json` 中配置了：

```json
{
  "compilerOptions": {
    "verbatimModuleSyntax": true
  }
}
```

那么 TypeScript 会要求你明确区分“值导入”和“类型导入”。此时下面的写法可能产生 `TS1484` 错误：

```ts
import { User } from "./user";
```

应该改成：

```ts
import type { User } from "./user";
```

`verbatimModuleSyntax` 的规则可以简单理解为：

```ts
// 带 type：编译后删除
import type { User } from "./user";

// 不带 type：按照运行时导入处理并保留
import { createUser } from "./user";
```

([TypeScript][1])

---
## 为什么推荐写 `import type`
### 明确告诉别人它只用于类型
```ts
import type { User } from "./user";
```

一眼就能知道，`User` 不会在运行时存在。

### 避免某些构建工具处理错误
TypeScript 自己通常能判断类型，但 Babel、SWC、esbuild 等工具可能是逐文件编译，不一定拥有完整的 TypeScript 类型信息。明确写 `import type` 更稳定。

### 避免意外保留模块及其副作用
假设模块中存在运行时代码：

```ts
// user.ts
console.log("user 模块被加载");

export type User = {
  name: string;
};
```

使用 `import type` 可以明确保证这个导入会从输出 JavaScript 中完全删除：

```ts
import type { User } from "./user";
```

但要注意：你不能通过类型导入来触发模块副作用。需要模块执行时，应单独写：

```ts
import "./user";
```

TypeScript 官方也指出，类型导入会被完全擦除，而普通导入是否保留会受到编译配置影响。([TypeScript][2])

---
## 类型和值一起导入
可以分开写：

```ts
import { createUser } from "./user";
import type { User } from "./user";
```

也可以写在一起：

```ts
import { createUser, type User } from "./user";
```

第二种现在很常见。

---
## 结论
```ts
import { User } from "./user";
```

在默认配置下通常没影响，TypeScript 会自动删除它。

不过，只要确定导入的是纯类型，建议写：

```ts
import type { User } from "./user";
```

或者：

```ts
import { createUser, type User } from "./user";
```

这样语义更清楚，并且兼容开启了 `verbatimModuleSyntax` 的项目。
