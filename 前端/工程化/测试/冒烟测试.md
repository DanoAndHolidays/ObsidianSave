# 冒烟测试
> Last Format Time：8/13/2026 15:14:03

在前端里，**冒烟测试（Smoke Test）**可以理解成：

> **先快速确认这个版本“最基本的核心功能能不能跑起来”，如果连这些都不行，就没必要继续做更细的测试了。**

它不追求测得很细，而是测“这个版本是不是已经冒烟起火了”。

比如你刚改完一个前端项目，准备提测。冒烟测试可能只检查：

* 页面能不能正常打开
* 登录能不能成功
* 核心列表能不能加载
* 新增按钮能不能打开弹窗
* 表单能不能提交
* 详情页能不能进入
* 页面有没有直接白屏、报错
* 接口有没有大面积 500 / 404

假设你现在有一个 MCP Connection 页面：

```text
MCP Connections
├── 列表
├── 创建连接
├── 查看详情
├── 删除连接
└── 筛选
```

一个典型的冒烟测试可能是：

```text
1. 打开 /mcp/connections
   ✅ 页面正常展示

2. 点击“创建”
   ✅ Dialog 正常打开

3. 填写必要字段并提交
   ✅ 创建成功
   ✅ 列表出现新数据

4. 点击刚创建的数据
   ✅ 能进入详情页

5. 返回列表
   ✅ 页面没有崩溃
```

到这里就差不多了。

你不会在冒烟测试里特别仔细地测试：

```text
输入 255 个字符怎么样？
输入特殊字符怎么样？
连续点 20 次按钮怎么样？
分页到第 100 页怎么样？
接口延迟 10 秒怎么样？
屏幕宽度 321px 怎么样？
```

这些属于更深入的功能测试、边界测试、异常测试等。


可以把整个测试过程想象成这样：

```text
代码完成
   ↓
构建成功
   ↓
冒烟测试
   ↓
“基本能用吗？”
   ↓
  否 ──→ 打回修 Bug
   ↓ 是
功能测试
   ↓
边界测试
   ↓
回归测试
   ↓
上线
```

所以冒烟测试实际上是一层**非常便宜的第一道防线**。

---
## 为什么叫“冒烟测试”？
这个词最早来自硬件测试。

比如造了一个新的电路板：

```text
接通电源
↓
看看冒不冒烟
```

如果一通电就：

```text
💥 啪
🔥 冒烟
```

那后面的性能测试就完全没必要进行了。

软件行业借用了这个概念：

```text
启动软件
↓
核心流程走一下
↓
没“冒烟”
↓
继续测试
```

---
## 前端项目里，冒烟测试通常测什么？
一般抓住几个词：

**启动 + 渲染 + 核心路径。**

比如一个后台管理系统：

```text
✅ 应用能启动
✅ 首页能打开
✅ 用户能登录
✅ 菜单能跳转
✅ 核心列表能加载
✅ 核心创建流程能完成
✅ 没有白屏
```

通常不会要求覆盖所有功能。

---
## 冒烟测试不等于单元测试
这个区别很重要。

比如你之前写 Vitest：

```ts
it("caps list queries at 50 rows", () => {
  expect(
    mcpPageInputSchema.safeParse({ limit: 51 }).success
  ).toBe(false);
});
```

这属于**单元测试**。

它在验证一个很具体的逻辑：

```text
limit > 50
↓
Schema 应该拒绝
```

而冒烟测试更像：

```text
启动整个前端
↓
打开 MCP 页面
↓
创建一个 MCP Connection
↓
看看整个流程能不能走通
```

区别可以简单记成：

| 测试     | 关注点         |
| ------ | ----------- |
| 单元测试   | 一个函数/组件对不对  |
| 冒烟测试   | 整个系统基本能不能用  |
| 集成测试   | 几个模块组合后对不对  |
| E2E 测试 | 用户完整操作流程对不对 |
| 回归测试   | 新修改有没有搞坏旧功能 |

而且有一个容易混淆的地方：

> **冒烟测试描述的是“测试目的和范围”，不是某一种固定的技术。**

所以冒烟测试既可以人工做，也可以用 E2E 自动化做。

例如 Playwright：

```ts
test("smoke: MCP connections page works", async ({ page }) => {
  await page.goto("/mcp/connections");

  await expect(
    page.getByRole("heading", { name: "MCP Connections" })
  ).toBeVisible();

  await page.getByRole("button", { name: "Create" }).click();

  await expect(
    page.getByRole("dialog")
  ).toBeVisible();
});
```

这个测试并没有把创建页面的所有细节都测一遍，只检查：

```text
页面能打开
+
核心按钮能用
+
弹窗能出现
```

所以它就很适合作为 **Smoke Test**。

你以后在 PR、CI 里看到：

```text
unit
lint
typecheck
smoke
e2e
```

其中 `smoke` 基本可以理解成：

> **用几条最关键的测试，快速判断这个版本有没有明显挂掉。**

对于前端，我建议你先牢牢记住一句：

> **冒烟测试 = 不求测全，只求快速确认“核心功能基本活着”。**
