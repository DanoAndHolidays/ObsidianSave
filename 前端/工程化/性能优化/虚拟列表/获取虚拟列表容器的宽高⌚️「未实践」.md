
> **如何获取虚拟列表外层滚动容器在屏幕上实际占据的高度和宽度，从而计算当前需要渲染多少个节点。**

这里确实更接近 `ResizeObserver` 的使用场景，而不是 `IntersectionObserver`。

---

## 面试时可以这样回答

虚拟列表首先要知道它的滚动容器尺寸，比如容器的 `clientHeight`。有了容器高度和单个列表项的预估高度，才能计算可视区域大概需要渲染多少项：

```
visibleCount = Math.ceil(containerHeight / itemHeight);
```

实际项目中，如果允许使用 Observer API，我会优先使用 `ResizeObserver` 监听滚动容器尺寸变化，因为容器大小不一定只会因为浏览器窗口变化，也可能受到侧边栏展开、布局变化、父元素尺寸变化等影响。

如果不使用 `ResizeObserver`，我会给滚动容器绑定 `ref`，在 DOM 挂载完成后通过 `clientHeight` 或 `getBoundingClientRect()` 获取实际尺寸：

```
const containerRef = useRef<HTMLDivElement>(null);
const [containerHeight, setContainerHeight] = useState(0);

useLayoutEffect(() => {
  const element = containerRef.current;

  if (!element) {
    return;
  }

  const updateSize = () => {
    setContainerHeight(element.clientHeight);
  };

  updateSize();

  window.addEventListener('resize', updateSize);

  return () => {
    window.removeEventListener('resize', updateSize);
  };
}, []);
```

然后根据容器高度和行高计算需要渲染的节点数量：

```
const visibleCount = Math.ceil(containerHeight / rowHeight);
const renderCount = visibleCount + overscan * 2;
```

如果容器尺寸变化不仅来自浏览器窗口变化，比如项目中的侧边栏展开、面板拖拽或者布局切换，我会在这些布局状态变化之后主动调用一次 `updateSize`，或者让父级把布局尺寸通过状态传下来。

不过这种方式需要自己维护所有可能导致尺寸变化的场景。如果容器尺寸变化来源比较复杂，还是优先使用 `ResizeObserver`，它能直接监听元素本身的实际尺寸变化，可靠性更高。

## 更完整的实现思路

```
function VirtualList() {
  const containerRef = useRef<HTMLDivElement>(null);
  const [viewportHeight, setViewportHeight] = useState(0);

  useLayoutEffect(() => {
    const container = containerRef.current;

    if (!container) {
      return;
    }

    const measure = () => {
      const nextHeight = container.getBoundingClientRect().height;

      setViewportHeight((previousHeight) => {
        return previousHeight === nextHeight ? previousHeight : nextHeight;
      });
    };

    measure();

    const handleWindowResize = () => {
      measure();
    };

    window.addEventListener('resize', handleWindowResize);

    return () => {
      window.removeEventListener('resize', handleWindowResize);
    };
  }, []);

  const rowHeight = 32;
  const overscan = 5;
  const visibleCount = Math.ceil(viewportHeight / rowHeight);
  const renderCount = visibleCount + overscan * 2;

  return (
    <div ref={containerRef} className="h-full overflow-auto">
      {/* 根据 viewportHeight、renderCount 和 scrollTop 渲染节点 */}
    </div>
  );
}
```

你可以这样表达：

> 在 Daedalus 的文件树场景中，文件节点数量可能达到 500 个以上。我不会直接把整棵树全部渲染出来，而是先把展开后的树结构扁平化，再根据滚动容器的实际高度、单行高度和当前 `scrollTop` 计算可视区间，最后额外渲染一部分 `overscan` 节点。
>

## 如果面试官追问：不用 `ResizeObserver` 有什么问题？

可以回答：

> 只监听 `window.resize` 只能覆盖浏览器窗口变化，不能覆盖所有元素尺寸变化。例如侧边栏展开、父容器变化、CSS 布局变化或者拖拽调整面板，都可能导致虚拟列表容器尺寸变化，但浏览器窗口本身没有变化。所以不用 `ResizeObserver` 时，需要明确知道项目中有哪些布局变化，并在这些变化发生后主动触发测量，否则可能出现可视区域计算不准确、底部空白或者滚动位置异常。

---

## 最推荐你在面试中记住的核心版本

> 虚拟列表需要先拿到滚动容器的实际 `clientHeight`，再结合行高和 `overscan` 计算渲染数量。  
> 如果不用 `ResizeObserver`，我会通过 `ref` 获取 DOM，在 `useLayoutEffect` 中用 `clientHeight` 或 `getBoundingClientRect()` 做首次测量，并监听 `window.resize`。对于侧边栏展开、布局切换、面板拖拽等非窗口变化，则在对应状态更新后主动重新测量。  
> 如果容器尺寸变化来源复杂，`ResizeObserver` 会是更稳妥的方案；`IntersectionObserver` 主要用于判断元素是否进入视口，不适合用来获取容器尺寸。
