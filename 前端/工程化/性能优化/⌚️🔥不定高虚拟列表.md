# ⌚️🔥不定高虚拟列表
> Last Format Time：9/16/2026 19:24:53

固定高度虚拟列表可以直接通过，计算当前应该从哪一项开始渲染：
```js
startIndex = Math.floor(scrollTop / itemHeight)
```

但如果每一项高度不固定：
```text
item0 -> 80px
item1 -> 120px
item2 -> 63px
item3 -> 200px
```

就不能再通过 `scrollTop / itemHeight` 计算，因为每个 item 的位置取决于前面所有 item 的累计高度。

---
## 核心思路
不定高虚拟列表的整体流程：
```text
estimate（预估高度）
    ↓
render（渲染）
    ↓
measure（测量真实高度）
    ↓
cache（缓存高度）
    ↓
correct offset（修正位置）
```

不定高虚拟列表 = 高度预估 + 真实测量 + 高度缓存 + offset 累计 + 二分查找

已经测量过的 item 使用真实高度：
```js
const heights = new Map()

heights.set(0, 80)
heights.set(1, 120)
```

没有测量过的 item 使用预估高度：
```js
const estimatedHeight = 100

function getHeight(index) {
  return heights.get(index) ?? estimatedHeight
}
```

通常会维护类似的数据：
```js
[
  {
    index: 0,
    start: 0,
    size: 80,
    end: 80
  },
  {
    index: 1,
    start: 80,
    size: 120,
    end: 200
  },
  {
    index: 2,
    start: 200,
    size: 63,
    end: 263
  }
]
```

其中：
```text
start = 前面所有 item 高度之和

end = start + size
```

例如：
```text
item0: start = 0
item1: start = 80
item2: start = 80 + 120 = 200
```

本质上就是维护 prefix sum（前缀和）。

固定高度时：
```text
scrollTop / itemHeight
```

不定高度时，需要查找：
```text
item.start <= scrollTop < item.end
```

例如：
```text
item0: 0 ~ 80
item1: 80 ~ 200
item2: 200 ~ 263

scrollTop = 210
```

此时当前项就是：
```text
item2
```

如果维护了所有 item 的 `start`：
```js
[0, 80, 200, 263, ...]
```

就可以通过 binary search（二分查找）寻找当前 `startIndex`。

整体过程：
```text
scrollTop
   ↓
item offsets
   ↓
binary search
   ↓
startIndex
```

第一次渲染前不知道 DOM 的真实高度，因此只能先使用：
```js
estimatedHeight
```

渲染完成后再测量：
```js
element.getBoundingClientRect().height
```

但实际项目中 item 高度可能还会变化，例如：
* 图片加载完成
* 文本换行
* 字体加载
* 异步内容加载
* 展开 / 收起

因此更适合使用 `ResizeObserver` 监听 DOM 尺寸变化：
```js
const observer = new ResizeObserver(entries => {
  for (const entry of entries) {
    const index = Number(entry.target.dataset.index)

    heights.set(
      index,
      entry.contentRect.height
    )
  }
})
```

假设第一次不知道真实高度：

```text
item0 -> 100
item1 -> 100
item2 -> 100
```

预估位置：
```text
item0 start = 0
item1 start = 100
item2 start = 200
```

渲染后测量得到：
```text
item0 -> 80
item1 -> 140
item2 -> 60
```

重新计算：
```text
item0 start = 0
item1 start = 80
item2 start = 220
```

因此虚拟列表实际上一直在：
```text
预估
↓
渲染
↓
测量
↓
校正
```

## Scroll Anchoring（滚动锚定）
不定高虚拟列表还有一个重要问题：

> 前面的 item 高度变化可能导致用户当前看到的内容发生跳动。

例如：
```text
item 100 原来预估 100px

实际测量：
300px
```

高度差：
```text
delta = 300 - 100
      = 200px
```

后面所有 item 的位置都会向下移动 `200px`。

如果用户已经滚动到列表中间，就可能看到页面突然跳动。

因此成熟的虚拟列表通常还需要做：
```text
scroll anchoring（滚动锚定）
```

核心思想：

> 前面的高度发生变化时，尽量保持当前 viewport 中的内容位置不变。

必要时修正：
```js
scrollTop += delta
```

真实实现还需要判断发生尺寸变化的元素是否位于当前 viewport 之前。

## 不定高虚拟列表的核心数据
可以把每个 item 看成：
```ts
type Measurement = {
  index: number
  start: number
  size: number
  end: number
}
```

例如：
```js
{
  index: 10,
  start: 860,
  size: 120,
  end: 980
}
```

## 完整流程
```text
                scrollTop
                    ↓
            查找 measurement
                    ↓
              binary search
                    ↓
               startIndex
                    ↓
            加上 overscan 范围
                    ↓
              render items
                    ↓
             ResizeObserver
                    ↓
            获取真实 itemSize
                    ↓
             更新高度缓存
                    ↓
           修正后续 item offset
                    ↓
       必要时修正 scroll position
```

---
## 与固定高度虚拟列表的区别
固定高度：
```text
scrollTop
   ↓
scrollTop / itemHeight
   ↓
startIndex
```

不定高度：
```text
scrollTop
   ↓
height / offset cache
   ↓
binary search
   ↓
startIndex
```

固定高度的关键数据只有：
```text
itemHeight
```

不定高度则需要维护：
```text
estimatedSize
真实 size
start
end
measurement cache
```

---
## 最终记忆
### 固定高度
```text
startIndex
=
scrollTop / itemHeight
```

### 不定高度
```text
estimate
+
measure
+
cache
+
prefix offset
+
binary search
```

核心一句：

> 固定高度虚拟列表通过 `scrollTop / itemHeight` 找到起始项；不定高度虚拟列表则通过“高度测量缓存 + 累积 offset + 二分查找”找到起始项，并利用 `ResizeObserver` 持续校正真实高度。

## 闪动问题
### 首次渲染
动态高度虚拟列表第一次只能猜：
```text
预估高度：100px
↓
浏览器布局
↓
实际测出来：180px
↓
重新计算 offset
↓
重新布局
```

如果浏览器已经把 `100px` 那一版画出来，然后你才改成 `180px`，特别容易看到闪动。

如果这样测：
```js
useLayoutEffect(() => {
  const height = ref.current.getBoundingClientRect().height
  // 更新 measurement
}, [])
```

大致顺序是：
```text
React render
↓
DOM 更新
↓
useLayoutEffect
↓
测量
↓
同步更新位置
↓
浏览器 paint
```

如果虚拟列表同时测几十上百个节点，再不断 setState，就可能造成一帧时间变长。

### ResizeObserver
对于动态高度列表，通常还会用：
```js
ResizeObserver
```

因为 item 后续可能发生：
```text
图片加载
异步数据回来
展开内容
字体变化
容器宽度变化导致换行
```

这种变化 `useLayoutEffect` 管不了，因为它不是 React render 本身直接导致的。所以一般是：
```text
首次：
estimate
↓
render
↓
measure

之后：
ResizeObserver
↓
发现 size 变化
↓
更新 measurement
```

`ResizeObserver` 的通知发生在浏览器布局相关阶段，通常能够在绘制前参与尺寸修正，因此不会像 `useEffect` 那么天然容易产生“一帧错误 UI”。

但这**不代表动态虚拟列表绝对不会跳**。

### 滚动跳动
假设用户现在看到：
```text
item 100
item 101
item 102
```

而屏幕上方有一个：
```text
item 50
```

全部都应该向下移动 `200px`。

如果虚拟列表只是更新：
```js
item.start += 200
```

用户就会看到：
```text
item 100
突然往下跳了 200px
```

所以成熟虚拟列表需要：
```text
高度发生变化
↓
计算 delta
↓
发现这个 item 在 viewport 上方
↓
同时调整 scrollTop
```

比如：
```js
scrollTop += delta
```

效果就是两者抵消：
```text
item 本身向下 200px
+
scrollTop 同时向下 200px
```

用户看到的：
```text
当前内容基本没动
```

> **动态高度虚拟列表确实存在闪动/跳动风险。`useLayoutEffect` 类似的“paint 前测量”可以解决首屏布局闪烁，而 scroll anchoring（滚动锚定）主要解决滚动过程中前方元素高度变化导致的视口跳动。**
