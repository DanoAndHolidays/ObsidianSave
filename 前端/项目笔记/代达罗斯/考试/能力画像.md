## 下一次出题优先级
1. 用 10–15 分钟专项复测 `ResultAsync`：第二步返回 void、第三步仍需第一步实体，并预测 map 前后类型。
2. 补一条失败路径单测，要求用 `vi.fn()` 同时断言“不调用副作用”和最终 Store 状态。
3. 对比 `useEffect` 与 `useSyncExternalStore` 的 cleanup 调用者、触发时机和稳定函数引用。
4. 用完整 Issue 复测 queryKey 工厂、查询与失效一致性，以及 mutation 成功后的可观察刷新。
5. 提交前运行格式检查并清理 TODO、console、探索性注释，避免整文件格式漂移。

## 学习偏好与后续出题约束
- 默认使用引导式挖空：沿一条真实多文件前端链路设置 6–10 个小空，前两题可快速启动，并保留 Issue 背景、行为验收和端到端联调。
- 旧知识至少占一半；开放式真实任务只在用户明确选择时使用，不因形式更接近工作而牺牲答题动力。
- 评分认可行为等价实现，同时通过短追问和微型变化题区分代码通过、引导完成与独立掌握。
- 填空只删除核心逻辑，保留 import、类型、签名、复杂样式和大部分 JSX，不考寻找文件的体力。
- 允许使用 IDE、类型跳转、仓库搜索和现有测试；要求说明证据来源，区分独立实现与直接恢复答案。
- UI 任务继续不考生僻 className 和翻译 key，但必须考察状态反馈、事件边界、受控数据和可访问语义。
