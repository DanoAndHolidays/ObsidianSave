# EXAM-20260730-02：仓库导入的分支与异步一致性

## 历史选题依据

最近练习已经能写出基本异步三态和提交边界，但仍需要证明以下能力可以迁移到新场景：

- 分清界面默认值、用户显式输入和接口返回值谁是当前数据源；
- 在组件关闭或身份变化后，阻止过期异步结果污染下一次交互；
- 从前端类型与调用点确认 payload，而不是用断言或猜测掩盖接口关系；
- 用自动化测试验证竞态与错误路径，并在提交前清理调试遗留。

## Issue 背景

用户通过顶部入口导入 GitHub 仓库时，会先校验仓库，再确认分支并创建项目。这个流程必须保证最终导入的分支与用户看到的一致，也不能让已经关闭的旧请求影响下一次打开弹窗。

## 当前现象

从 Header 打开 “Import Repository” 弹窗，可以观察到两个问题：

1. 当仓库默认分支不是 `main`，用户没有主动指定分支时，校验结果已经返回真实默认分支，但确认界面和最终导入仍可能继续使用 `main`。
2. 校验请求尚未结束时关闭弹窗，请求稍后完成仍可能写入旧预览；再次打开时可能看到上一轮仓库的状态。

## 验收标准

- [ ] 用户未显式填写分支时，校验成功后展示接口返回的分支，并在导入 payload 中提交同一个值。
- [ ] 用户在校验前显式填写了分支时，校验成功不得覆盖该选择，最终导入使用用户填写值。
- [ ] 校验请求进行中关闭弹窗后，该请求无论成功还是失败，都不能在关闭后或下一次打开时恢复旧预览、旧错误或旧 loading 状态。
- [ ] 返回编辑、修改仓库地址并重新校验时，只允许最新一次有效校验结果进入确认界面。
- [ ] 校验失败时用户能感知错误并可修改输入后重试；现有凭据缺失/失效的恢复入口保持可用。
- [ ] validation/import pending 期间不会因重复点击发出重复业务请求，按钮状态与可见文案能够表达当前阶段。
- [ ] 至少新增两条自动化回归测试，分别覆盖“接口默认分支被采用”和“关闭或新一轮校验后旧结果被忽略”；测试只验证前端行为或可测试状态逻辑。
- [ ] 目标范围通过 TypeScript 检查、lint、相关测试和 `git diff --check`，不留下临时日志、注释代码或无理由类型断言。
