# 2472 不重叠回文子字符串的最大数目
> Last Format Time：9/16/2026 19:24:50

#困难

https://leetcode.cn/problems/maximum-number-of-non-overlapping-palindrome-substrings/description

**你和官方的「选择子串」DP 是一样的，但「判断回文」的成本不一样：你的最坏时间复杂度是 O(n3)O(n^3)，官方是 O(n2)O(n^2)。**

你的代码实际上包含了三层遍历，第三层藏在 `isPalindrome` 里面：
```ts
for (let i = 1; i <= n; i++) {        // 第一层
    for (let j = 0; j <= i; j++) {    // 第二层
        const subStr = s.slice(j, i)
        if (isPalindrome(subStr)) {  // 内部还有双指针循环
            // ...
        }
    }
}
```

前两层枚举了 O(n2)O(n^2) 个子串，每次判断回文最坏需要 O(n)O(n)，所以总体是 **O(n3)O(n^3)**。

例如字符串全是 `"a"`，每次判断都必须检查到中间，无法提前返回。假设 `n = 2000`，你的回文判断累计就需要约 **6.67 亿次字符比较**。`slice` 还可能带来额外的字符串构造开销。


官方把「判断回文」也做成了一次 DP，提前保存所有区间的判断结果：
```ts
isPalindrome[left][right] =
    s[left] === s[right] &&
    (len <= 2 || isPalindrome[left + 1][right - 1])
```

它利用的是这条规律：

> 一个长度大于 2 的字符串是回文，当且仅当：两端字符相等，并且中间部分也是回文。

比如判断 `"abcba"`：
```ts
// 只比较两端，中间的 "bcb" 直接查之前算好的结果
pal[0][4] = s[0] === s[4] && pal[1][3]
```

因为官方按照**子串长度从短到长**计算，所以判断外层时，内层的结果已经存在，因此：
- **预处理：**O(n2)O(n^2) 个区间，每个区间只需要 O(1)O(1)，合计 O(n2)O(n^2)。
- **选择子串：**仍然枚举 O(n2)O(n^2) 个区间，但判断回文变成查表，只需 O(1)O(1)，合计 O(n2)O(n^2)。
    

两部分是先后执行，复杂度相加：

O(n2)+O(n2)=O(n2)O(n^2) + O(n^2) = O(n^2)

|对比|你的代码|官方代码|
|---|---|---|
|判断一个区间是否回文|双指针重新扫描，最坏 O(n)O(n)|预处理后查表，O(1)O(1)|
|总时间复杂度|O(n3)O(n^3)|O(n2)O(n^2)|
|额外空间复杂度|O(n)O(n)|O(n2)O(n^2)|

你的代码还有一个小问题：

```ts
if (isPalindrome(subStr) && subStr.length >= k)
```

`&&` 从左往右执行，导致**长度不足 `k` 的子串也先判断了回文**。可以直接限制枚举范围：
```ts
for (let j = 0; j + k <= i; j++) {
    const subStr = s.slice(j, i)
    if (isPalindrome(subStr)) {
        dp[i] = Math.max(dp[i], dp[j] + 1)
    }
}
```

这能减少无效检查，但最坏仍然是 O(n3)O(n^3)；要达到官方的 O(n2)O(n^2)，关键还是**复用已经算过的回文结果**。

```ts
function maxPalindromes(s: string, k: number): number { 
    const n = s.length 
    const dp = new Array(n + 1).fill(0) 
 
    // console.log(dp) 
 
    dp[0] = 0 
 
    // 遍历每一个子串的长度，从0开始构建dp 
    for (let i = 1; i < n + 1; i++) { 
        dp[i] = dp[i - 1] 
        for (let j = 0; j <= i; j++) {
 ```

 ```ts
function isPalindrome(str: string) { 
    let left = 0 
    let right = str.length - 1 
 
    while (left < right) { 
        // console.log(str[left], str[right]) 
        if (str[left] !== str[right]) return false 
        left++ 
        right-- 
    } 
    return true 
} 

// 我这个算法会超时，但是官方的就不会，我们的算法都一样的，为什么？

var maxPalindromes = function(s, k) {
    const n = s.length;
    const isPalindrome = Array.from({ length: n }, () => Array(n).fill(false));

    for (let len = 1; len <= n; ++len) {
        for (let left = 0; left + len <= n; ++left) {
            const right = left + len - 1;
            isPalindrome[left][right] = s[left] === s[right] &&
                (len <= 2 || isPalindrome[left + 1][right - 1]);
        }
    }

    const dp = Array(n + 1).fill(0);
    for (let i = 1; i <= n; ++i) {
        dp[i] = dp[i - 1];
        for (let j = 0; j + k <= i; ++j) {
            if (isPalindrome[j][i - 1]) {
                dp[i] = Math.max(dp[i], dp[j] + 1);
            }
        }
    }

    return dp[n];
};
```
