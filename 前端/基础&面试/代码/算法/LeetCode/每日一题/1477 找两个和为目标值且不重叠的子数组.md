function minSumOfLengths(arr: number[], target: number): number {
    const n = arr.length
    const prefix = new Array(n).fill(Infinity)
    let left = 0
    let sum = 0
    let best = Infinity

    for (let right = 0; right < n; right++) {
        sum += arr[right]

        while (sum > target) {
            sum -= arr[left]
            left++
        }

        if (sum === target) {
            best = Math.min(best, right - left + 1)
        }

        prefix[right] = best
    }

    const suffix = new Array(n).fill(Infinity)

    let right = n - 1
    sum = 0
    best = Infinity

    for (let left = n - 1; left >= 0; left--) {
        sum += arr[left]

        while (sum > target) {
            sum -= arr[right]
            right--
        }

        if (sum === target) {
            best = Math.min(best, right - left + 1)
        }

        suffix[left] = best

---
## 双区间 / 不重叠子数组题技巧
核心思想：

> 先把“两个区间一起选”的问题，拆成“左边最优 + 右边最优”。

对于这道题：

```text
prefix[i] = arr[0...i] 中，满足条件的最短子数组长度
suffix[i] = arr[i...n-1] 中，满足条件的最短子数组长度
```

然后枚举分割点：

```ts
prefix[i] + suffix[i + 1]
```

这样天然保证两个子数组不重叠。

---
## 什么时候想到 Prefix / Suffix
看到这些关键词要敏感：

- 选两个区间
    
- 两个区间不能重叠
    
- 求两个区间的最小值 / 最大值之和
    
- 可以用某个位置把数组分成左右两部分
    

常见套路：

```text
左侧最优结果
+
右侧最优结果
```

比如：

```text
prefixMax + suffixMax
prefixMin + suffixMin
prefixBest + suffixBest
```

本质是**预处理局部最优结果，然后枚举分界线**。

---
## Prefix 不要重复计算
最开始容易写成：

```ts
for (let i = 0; i < n; i++) {
    // 重新计算 arr[0...i]
}
```

这样会产生大量重复计算。

正确思维应该是：

```text
prefix[i]
=
利用 prefix[i - 1]
+
处理当前 arr[i]
```

也就是：

> 扫描一次数组，同时维护“到目前为止的最优答案”。

例如：

```ts
best = Math.min(best, 当前合法区间长度)
prefix[right] = best
```

## 滑动窗口的本质
这道题数组元素都是正数，因此可以使用滑动窗口。

维护：

```ts
let left = 0
let sum = 0
```

右边界负责扩展：

```ts
sum += arr[right]
```

当窗口不合法时，左边界收缩：

```ts
while (sum > target) {
    sum -= arr[left]
    left++
}
```

不要这样：

```ts
arr.slice(left, right + 1).reduce(...)
```

因为每次重新计算区间和，会把本来 `O(n)` 的滑动窗口搞成更高复杂度。

关键 mental model：

```text
窗口扩大 → 增量更新 sum
窗口缩小 → 减掉离开窗口的元素
```

而不是重新计算整个窗口。

---
## 反向滑动窗口最容易写错
正向：

```text
left        right
  →           →
```

`right` 扩展，`left` 收缩。

反向：

```text
left        right
  ←           ←
```

`left` 扩展，`right` 收缩。

所以反向扫描时：

```ts
sum += arr[left]

while (sum > target) {
    sum -= arr[right]
    right--
}
```

一个很好记的方法：

> **谁负责扩展窗口，就加谁；谁负责缩小窗口，就减谁。**

---
## 分割点注意边界
如果定义：

```text
prefix[i] 负责 [0...i]
suffix[i] 负责 [i...n-1]
```

那么两个不重叠区间应该组合：

```ts
prefix[i] + suffix[i + 1]
```

而不是：

```ts
prefix[i] + suffix[i]
```

否则左右两边可能同时使用下标 `i`。

可以直接把它想成：

```text
0 1 2 3 | 4 5 6
      i   i+1
```

---
## Infinity 很适合表示“不存在”
这种最小值 DP / 预处理题里：

```ts
let best = Infinity
```

非常方便。

如果当前位置之前没有合法答案：

```ts
prefix[i] = Infinity
```

最终：

```ts
Infinity + 3 === Infinity
```

自然不会成为最优答案。

最后统一：

```ts
return ans === Infinity ? -1 : ans
```

比自己设计 `-1`、`n + 1` 之类的哨兵值通常更清晰。

## 做这类题的思考顺序
以后遇到类似题，可以按这个顺序想：

```text
两个区间不能重叠
        ↓
能不能枚举一个分割点？
        ↓
分割点左边最优是什么？
分割点右边最优是什么？
        ↓
能不能预处理 prefix / suffix？
        ↓
单侧最优怎么快速计算？
        ↓
滑动窗口 / 前缀和 / DP / 单调结构
```

这道题最终就是：

```text
不重叠
→ 分割数组
→ prefix + suffix
→ 每侧找 target 子数组
→ 正数数组
→ 滑动窗口
→ O(n)
```

这是一个很值得记住的组合套路：

> **“不重叠区间” → 枚举分割点；“左右最优” → Prefix/Suffix；“正数连续子数组和” → 滑动窗口。**
