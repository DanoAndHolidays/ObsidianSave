# 区间划分 DP
> Last Format Time：9/18/2026 00:43:42

![[Pasted image 20260917204002.png]]
对，这道题非常适合 **DP**，而且是很典型的「**把数组划分成 K 段，使每段代价之和最小**」的区间划分 DP。

因为数组已经是**非降序**的，而且要求划分成连续区间，所以核心结构就是：

> 前 `i` 个数，划分成若干段，最后一段从哪里开始？

假设定义：

```text
dp[k][i] = 前 i 个数恰好划分成 k 个区间的最小误差
```

如果最后一个区间是：

```text
[j + 1 ... i]
```

那么前 `j` 个数需要分成 `k - 1` 段：

```text
dp[k][i]
=
min(
    dp[k - 1][j] + cost(j + 1, i)
)
```

其中：

```text
cost(l, r)
```

就是区间 `[l,r]` 全部用其中位数作为代表值时的误差。

---
## 最关键的是怎么算 `cost(l, r)`
由于数组已经排序：

```text
a[l], a[l+1], ..., a[r]
```

中位数的位置直接就是：

```text
m = floor((l + r) / 2)
```

因为题目要求偶数长度取**靠左的中位数**。

例如：

```text
[1, 2, 10, 11]

m = 2
median = 2
```

于是：

```text
cost(l,r)
=
Σ |a[i] - a[m]|
```

当然不能每次真的遍历区间算，否则 DP 会变成 `O(KN³)`。

可以用**前缀和**做到 `O(1)` 求一个区间的 cost。

设：

```text
sum[i] = a[1] + ... + a[i]
```

左半边：

```text
a[m] * (m-l+1)
- (sum[m] - sum[l-1])
```

右半边：

```text
(sum[r] - sum[m])
- a[m] * (r-m)
```

所以：

```text
cost(l,r) =
a[m] * (m-l+1) - (sum[m] - sum[l-1])
+
(sum[r] - sum[m]) - a[m] * (r-m)
```

这样 `cost` 是 `O(1)`。


整个 DP 就变成：

```ts
for (let k = 1; k <= K; k++) {
    for (let i = 1; i <= N; i++) {
        for (let j = k - 1; j < i; j++) {
            dp[k][i] = Math.min(
                dp[k][i],
                dp[k - 1][j] + cost(j + 1, i)
            )
        }
    }
}
```

复杂度：

```text
时间：O(KN²)
空间：O(KN)
```

空间还可以滚动到：

```text
O(N)
```


还有一个容易卡住的地方：题目说的是**至多 K 个区间**，不是恰好 K 个。

实际上这题可以直接考虑恰好 `K` 段（当 `K <= N`）。

因为把一个区间继续拆开，最优误差**不会变大**。例如：

```text
[1, 2, 10]

一段：
median = 2
cost = 1 + 0 + 8 = 9

拆：
[1,2] + [10]
cost = 1 + 0 = 1
```

所以既然允许最多 K 段，没有额外的“每增加一段的成本”，最优解自然可以一直拆到 `min(K,N)` 段。


这题你可以把它直接归类成一个很重要的 DP 模板：

> **连续分段 DP**

看到：

```text
数组
连续划分
最多 / 恰好 K 段
每段有自己的 cost
求总 cost 最小
```

第一反应就可以是：

```text
dp[k][i]
= 前 i 个元素分成 k 段

枚举最后一段的起点 j：

dp[k][i]
= min(dp[k-1][j] + cost(j+1,i))
```

这道题真正稍微难一点的地方其实不是 DP，而是利用「**数组有序 + 中位数 + 前缀和**」把 `cost(l,r)` 优化成 `O(1)`。这两部分一拼起来，题基本就出来了。
