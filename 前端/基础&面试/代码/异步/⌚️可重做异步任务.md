# ⌚️可重做异步任务
> Last Format Time：9/16/2026 19:24:50

---
## 核心问题
所谓“可重做异步任务”，并不是让同一个 Promise 重新执行。

因为：

```js
const promise = new Promise(...)
```

一个 Promise 一旦创建：

- 最终只能 `resolve` 一次
    
- 或 `reject` 一次
    
- 状态一旦确定就无法重置
    
- Promise 本身没有 `restart()` 能力
    

所以：

> Restart 的本质不是“重启 Promise”，而是重新执行 `task()`。

---
## 最大难点：旧任务仍然在运行
例如：

```text
task1 开始
   ↓
restart()
   ↓
task2 开始
```

此时：

```text
task1 ─────────→ 完成
task2 ───────────────→ 完成
```

调用 `restart()` 并不会自动停止 `task1`。

因此必须解决：

> 如果旧任务后来完成了，不能让它影响最终结果。

---
## 使用 runId / version 标记任务版本
维护一个版本号：

```js
let runId = 0;
```

每次执行任务：

```js
const currentRunId = ++runId;
```

例如：

```text
第一次运行：
runId = 1

restart：
runId = 2

再次 restart：
runId = 3
```

每个任务都会记住自己启动时的版本号。

---
## 任务完成时判断自己是否过期
```js
if (currentRunId !== runId) {
  return;
}
```

例如：

```text
task1:
currentRunId = 1

restart 后：
runId = 2
```

此时 task1 完成：

```js
1 !== 2
```

说明：

```text
task1 已经不是最新任务
→ 忽略结果
```

而 task2：

```js
currentRunId = 2
runId = 2
```

说明：

```text
task2 仍然是最新任务
→ 可以提交结果
```

---
## 为什么不能在 restart 中重新创建 Promise
错误思路：

```js
function restart() {
  const promise = new Promise(...)
}
```

因为这个 `promise` 只是 `restart()` 内部的局部变量。

外部最开始拿到的是：

```js
const {
  promise,
  restart
} = createRestartableTask(...)
```

也就是说：

```text
外部拿到 promise1

restart()
    ↓
创建 promise2
    ↓
但外部根本拿不到 promise2
```

因此没意义。

---
## 正确设计：外层 Promise 只创建一次
先保存：

```js
let resolvePromise;
let rejectPromise;
```

创建一个对外暴露的 Promise：

```js
const promise = new Promise((resolve, reject) => {
  resolvePromise = resolve;
  rejectPromise = reject;
});
```

之后无论重新执行多少次 `task()`：

```text
task1
task2
task3
```

最终都由最新任务决定什么时候调用：

```js
resolvePromise(result);
```

或者：

```js
rejectPromise(error);
```

---
## 完整实现
```js
function createRestartableTask(task, maxRestarts) {
  let restartsLeft = maxRestarts;
  let status = "pending";

  let runId = 0;

  let resolvePromise;
  let rejectPromise;

  const promise = new Promise((resolve, reject) => {
    resolvePromise = resolve;
    rejectPromise = reject;
  });

  function run() {
    const currentRunId = ++runId;

    Promise.resolve()
      .then(() => task())
      .then(
        (result) => {
          // 旧任务已经过期
          if (currentRunId !== runId) return;

          status = "resolved";
          resolvePromise(result);
        },
        (error) => {
          // 旧任务已经过期
          if (currentRunId !== runId) return;

          status = "rejected";
          rejectPromise(error);
        }
      );
  }

  function restart() {
    // 已经结束后不能再 restart
    if (status !== "pending") {
      return false;
    }

    // restart 次数耗尽
    if (restartsLeft <= 0) {
      return false;
    }

    restartsLeft--;

    run();

    return true;
  }

  // 第一次启动
  run();

  return {
    promise,
    restart,
  };
}
```

---
## 为什么使用 Promise.resolve().then(task)
可以直接写：

```js
task().then(...)
```

但如果：

```js
function task() {
  throw new Error("error");
}
```

这是同步异常。

而：

```js
Promise.resolve()
  .then(() => task())
```

可以把：

```js
task()
```

的同步 `throw` 也转换成 Promise rejection。

因此更加健壮。

---
## 状态变量为什么必须使用 let
错误：

```js
const status = "pending";
```

后面却：

```js
status = "resolved";
```

会报错。

因为这些状态都会发生变化：

```js
let status = "pending";
let restartsLeft = maxRestarts;
let runId = 0;
```

---
## Restart 和 Cancel 的区别
当前这种实现：

```text
restart
=
启动一个新任务
+
忽略旧任务的结果
```

它并没有真正停止旧任务。

例如旧任务是：

```js
fetch(...)
```

即使 restart：

```text
旧 HTTP 请求仍然可能继续发送
```

只是最终结果被忽略。

如果需要真正取消任务，需要任务本身支持取消，例如：

```js
AbortController
```

## Mental Model
可以把整个过程理解成：

```text
run #1
   │
   ├────────────── running
   │
restart
   │
run #2
   │
   ├──────── running
   │
run #1 resolve
   │
   └── version 不匹配
       → discard

run #2 resolve
   │
   └── version 匹配
       → commit
```

即：

```text
旧任务可以继续执行
但不能提交结果
```

---
## 一句话总结

> Restartable Async Task 的核心不是重新创建 Promise，而是重新执行异步任务，并通过 version / runId 判断结果是否仍然有效，旧任务即使完成也要被忽略。

这个思想本质上就是：

```text
start new work
      ↓
old work becomes stale
      ↓
ignore stale result
      ↓
only latest work can commit
```

这题最值得记住的是 **`runId / version` 这个技巧**，后面做搜索联想、请求竞态、防止旧请求覆盖新请求时都会反复用到。
