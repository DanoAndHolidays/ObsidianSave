# 异步任务依赖调度⌚️🔥
> Last Format Time：9/16/2026 19:24:50

结合了四个知识点：

- Promise 与异步编程
- 有向无环图（DAG）
- 拓扑排序
- 并发控制与任务生命周期管理

一个异步任务可能依赖其他任务，只有当它的所有依赖任务都执行完成后，当前任务才能拿到依赖结果并执行自己的逻辑

假设有四个任务：

|任务|工作内容|依赖|
|---|---|---|
|A|获取用户信息|无|
|B|获取订单数据|无|
|C|根据用户和订单生成报表|A、B|
|D|上传生成的报表|C|

![[Pasted image 20261019150218.png]]


你可能首先想到：
```ts
await Promise.all([
  taskA(),
  taskB(),
  taskC(),
  taskD()
]);
```

但这样四个任务都会立即被启动，问题是 `taskC` 启动时，`taskA` 和 `taskB` 可能还没有执行完成

你也许会改成：
```ts
await taskA();
await taskB();
await taskC();
await taskD();
```

这样虽然保证了依赖顺序，却失去了 A 和 B 可以并发执行的优势，当然，针对这个具体例子，你可以手动写：
```ts
await Promise.all([taskA(), taskB()]);
await taskC();
await taskD();
```

但如果存在 100 个任务，而且每个任务的依赖关系都是动态的呢？不可能要求开发者手动组织所有 `await`

因此，调度器需要自动做到两件事：

- 依赖控制： 只有所有前置任务成功完成，才能执行当前任务
- 并发控制： 同时运行的任务数量不超过指定上限


---
## 核心算法
拓扑排序 + 入度

这个依赖关系，其实就是数据结构中的有向图

例如：
```
A → C
B → C
C → D
```

其中：

- 节点：任务
- 有向边：任务之间的依赖关系
- 入度：一个任务还需要等待多少个前置任务

以上图为例：

|任务|初始入度|是否可以执行|
|---|---|---|
|A|0|可以|
|B|0|可以|
|C|2|不可以|
|D|1|不可以|

任务 A 执行成功后，C 的剩余入度减一，从 2 变成 1

任务 B 也完成后，C 的剩余入度再次减一，从 1 变成 0

这时 C 才能开始执行

这正是经典的 Kahn 拓扑排序算法 的思想

### 代码实现
```ts
type Task = {
  id: string;
  deps?: string[];
  run: (results: ReadonlyMap<string, unknown>) => Promise<unknown> | unknown;
};
```

```ts
async function runTasks(
  tasks: Task[],
  concurrency = 2
): Promise<Map<string, unknown>> {
  if (!Number.isInteger(concurrency) || concurrency < 1) {
    throw new Error("并发数必须是正整数");
  }

  // 1. 建立任务索引
  const taskMap = new Map<string, Task>();

  for (const task of tasks) {
    if (taskMap.has(task.id)) {
      throw new Error(`重复任务: ${task.id}`);
    }
    taskMap.set(task.id, task);
  }

  // 2. 构建入度表和后继任务表
  const indegree = new Map<string, number>();
  const dependents = new Map<string, string[]>();

  for (const task of tasks) {
    dependents.set(task.id, []);
  }

  for (const task of tasks) {
    const deps = task.deps ?? [];

    if (new Set(deps).size !== deps.length) {
      throw new Error(`任务 ${task.id} 的依赖重复`);
    }

    for (const dep of deps) {
      if (!taskMap.has(dep)) {
        throw new Error(`未知依赖: ${dep}`);
      }

      dependents.get(dep)!.push(task.id);
    }

    indegree.set(task.id, deps.length);
  }

  // 3. 预先检测循环依赖
  const tempDegree = new Map(indegree);

  const queue = tasks
    .filter(t => tempDegree.get(t.id) === 0)
    .map(t => t.id);

  for (let i = 0; i < queue.length; i++) {
    const id = queue[i];

    for (const next of dependents.get(id)!) {
      const d = tempDegree.get(next)! - 1;
      tempDegree.set(next, d);

      if (d === 0) queue.push(next);
    }
  }

  if (queue.length !== tasks.length) {
    throw new Error("依赖图存在环");
  }

  // 4. 初始化调度状态
  const results = new Map<string, unknown>();

  const ready = tasks
    .filter(t => indegree.get(t.id) === 0)
    .map(t => t.id);

  let head = 0;
  let running = 0;
  let completed = 0;
  let failed = false;

  // 5. 启动调度器
  return new Promise((resolve, reject) => {
    if (tasks.length === 0) {
      return resolve(results);
    }

    const pump = () => {
      while (
        !failed &&
        running < concurrency &&
        head < ready.length
      ) {
        const id = ready[head++];
        running++;

        Promise.resolve()
          .then(() => taskMap.get(id)!.run(results))
          .then(value => {
            if (failed) return;

            results.set(id, value);
            completed++;

            // 当前任务完成，释放依赖它的任务
            for (const next of dependents.get(id)!) {
              const d = indegree.get(next)! - 1;
              indegree.set(next, d);

              if (d === 0) ready.push(next);
            }
          })
          .catch(error => {
            if (!failed) {
              failed = true;
              reject(error);
            }
          })
          .finally(() => {
            running--;

            if (failed) return;

            if (completed === tasks.length) {
              resolve(results);
            } else {
              pump();
            }
          });
      }
    };

    pump();
  });
}
```

### 循环检测
还是 A、B、C、D：
```
indegree = {
  A: 0,
  B: 0,
  C: 2,
  D: 1
};
```

先找出所有入度为 0 的任务：
```
queue = ["A", "B"];
```

然后开始模拟移除任务。

处理 A：
```
移除 A
  ↓
C 的入度 2 → 1
```

处理 B：
```
移除 B
  ↓
C 的入度 1 → 0
  ↓
C 加入 queue
```

于是：
```
queue = ["A", "B", "C"];
```

处理 C：
```
移除 C
  ↓
D 的入度 1 → 0
  ↓
D 加入 queue
```

最终：
```
queue = ["A", "B", "C", "D"];
```

所有任务都能够被移除，说明没有循环依赖。反之，如果存在一个环，那么环中的节点始终无法全部变成入度为 0，最终处理的节点数量就会小于任务总数。

### 任务执行失败
这里要区分不同的失败策略。

|策略|行为|
|---|---|
|Fail Fast|某任务失败后，不再调度新任务，整体任务返回失败|
|继续执行独立任务|失败只影响依赖它的下游任务，其他无关任务继续执行|
|自动重试|对可重试失败按照指定次数和退避策略重新执行|
|跳过失败任务|根据业务约定跳过任务，必要时提供默认结果|

上面的代码使用了第一种策略。

有个细节：`Promise` 一旦启动，不能仅通过 `reject` 将它真正取消。

因此，失败后我们虽然不再调度新的任务，但已经启动的任务仍然可能继续执行。

如果面试官进一步要求真正的取消机制，可以增加 `AbortController` 和 `AbortSignal`，让支持取消的任务主动响应中断信号。
