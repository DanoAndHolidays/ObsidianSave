# 04 文本语义
> Last Format Time：9/16/2026 19:24:51

*实际开发没啥用，我觉得*

核心 mental model：

> HTML 文本标签描述的是“这段文字为什么特殊”，而不是“它应该长什么样”。

所以不能简单记：

```text
strong = 粗体
em = 斜体
mark = 黄色
small = 小字号
```

而应该理解成：

```text
strong = 重要性 / 严重性 / 紧迫性
em = 重读强调
mark = 当前上下文中的相关性
small = 次要说明 / 附加信息
```


`<p>` 表示一个 paragraph（段落），即围绕同一个意思组织的一段文本。

```html
<p>付款成功后 24 小时内发货。</p>
<p>节假日可能顺延。</p>
```

不要为了换行或制造间距乱用 `p`。

```html
<!-- 两个自然段 -->
<p>第一段。</p>
<p>第二段。</p>
```

而不是：

```html
<p>
  第一段。
  <br><br>
  第二段。
</p>
```

`p` 也不能随便包 `div` 等块级结构：

```html
<!-- 不合理 -->
<p>
  text
  <div>...</div>
</p>
```

浏览器解析时可能自动结束 `p`，导致 DOM 和源码认知不一致。


`<strong>` 表示 strong importance（强重要性）、严重性或紧迫性：

```tsx
<p>
  删除后将<strong>永久无法恢复</strong>。
</p>
```

关键是：

```text
strong = 这部分内容本身更重要
```

而不是“设计稿要求粗体”。

`strong` 可以嵌套，语义上可以表达更高一级的重要程度，但不要依赖屏幕阅读器一定明显读出这种层级。


`<b>` 表示：

> 需要把读者注意力吸引到这段文字，但不表示它比周围内容更加重要。

例如关键词、产品名等：

```html
<p>
  本章介绍 <b>React</b> 和 <b>Vue</b>。
</p>
```

区别：

```text
<strong>
内容的重要性更高

<b>
视觉/阅读注意力需要被吸引到这里，
但不增加重要性
```

如果只是纯视觉加粗：

```html
<span class="font-bold">用户名</span>
```

或者直接给本来就存在的元素加 CSS，不要为了样式硬塞 `strong` / `b`。


`<em>` 表示 stress emphasis（重读强调）。

重点不是斜体，而是：

> 如果说这句话，这个词应该被重读，而且重读位置可能改变语气或含义。

```html
<p>
  必须在<em>今天</em>完成。
</p>
```

相当于口语里的：

> 必须在 **今天** 完成，不是明天。

所以：

```text
em = 语言中的重音
```

`em` 也可以嵌套，表达更强的强调程度。


`<i>` 表示与普通叙述有所区别的一段文字，例如：

* 技术术语
* 外语表达
* 特殊语气
* 分类学名称等

```html
<p>
  这种问题叫做 <i>hydration mismatch</i>。
</p>
```

区别：

```text
<em>
这个词需要重读

<i>
这段文字具有不同的文本性质 / 语气
```

纯粹为了斜体仍然应该使用 CSS。


`<mark>` 表示：

> 这段文字因为当前上下文而特别 relevant（相关）。

最典型就是搜索高亮：

```tsx
<p>
  深入学习 <mark>React</mark> Fiber
</p>
```

这里 React 并没有变得“更重要”，只是因为用户当前搜索了 React，所以它与当前上下文特别相关。

区别：

```text
<strong>
内容本身重要

<mark>
当前上下文中相关
```

因此搜索结果关键词通常比 `strong` 更适合 `mark`。


`<small>` 不是“小字号标签”。

它表示 side comment / small print（附带说明、次要信息、小字条款）。

例如：

```html
<small>
  最终价格以结算页面为准。
</small>
```

或：

```html
<footer>
  <small>© 2026 Example Inc.</small>
</footer>
```

不能因为 UI 中一段提示文字字号是 `12px`，就自动使用 `small`。

例如：

```text
密码至少需要 8 位
```

这是用户完成表单所必需的信息，就未必属于 `small`。

判断依据是信息地位，不是字号。


`<code>` 表示 computer code（计算机代码性质的内容），不仅仅指编程语言源码。

例如：

```html
<code>npm install</code>
```

```html
<code>Array.prototype.map()</code>
```

```html
<code>&lt;button&gt;</code>
```

非常适合技术文档中的 inline code（行内代码）。


`<pre>` 表示 preformatted text（预格式化文本）。

核心语义：

> 文本中的空格、换行、缩进本身需要保留。

```html
<pre>
hello
    world
</pre>
```

`pre` 不等于“代码块”，因为它也可以用于：

```html
<pre>
 /\_/\
( o.o )
 > ^ <
</pre>
```


所以：

```html
<pre><code>function add(a, b) {
  return a + b;
}</code></pre>
```

两层分别表达：

```text
code
→ 这些内容是代码

pre
→ 这些代码的换行、缩进和空格需要保留
```

所以：

```text
code vs pre
不是 inline vs block 的关系。

它们描述的是两个不同维度。
```

常见：

```html
<!-- 行内代码 -->
<p>运行 <code>npm install</code>。</p>

<!-- 代码块 -->
<pre><code>npm install
npm run dev</code></pre>
```


`<q>` 和 `<blockquote>` 都表示 quotation（引用）。

`q`：inline quotation（行内引用）。

```html
<p>
  他说：<q>明天再解决。</q>
</p>
```

`blockquote`：整块引用内容。

```html
<blockquote>
  <p>Context 一定会造成严重性能问题。</p>
</blockquote>
```

所以：

```text
q
= 引用嵌在当前句子里

blockquote
= 整个内容区域是引用
```


`cite` 属性和 `<cite>` 元素完全不同。

引用元素的：

```html
<blockquote cite="https://example.com/article">
```

其中：

```text
cite=""
= 引用来源的 URL
```

而：

```html
<cite>Clean Code</cite>
```

表示：

> creative work（作品）的标题。

例如：

* 书名
* 电影名
* 文章名
* 歌曲名等

不要因为某个人是作者就写：

```html
<cite>Martin Fowler</cite>
```

单纯作者姓名并不是 `cite` 的语义。

记：

```text
cite 属性 → 来源 URL
<cite>     → 作品标题
```


`<time>` 表示：

> 这段文本具有时间 / 日期语义。

```html
<time>2026-09-08</time>
```

更常见：

```html
<time datetime="2026-09-08">
  2026 年 9 月 8 日
</time>
```

这里：

```text
元素文本
→ 给人看的

datetime
→ machine-readable（机器可读）的标准时间值
```

尤其人类文本比较模糊时：

```tsx
<time dateTime="2026-09-08T20:30:00+09:00">
  2 小时前
</time>
```

`2 小时前` 对人很好理解，但机器无法脱离上下文稳定确定真实时间，所以需要 `datetime`。

React / JSX 中写：

```tsx
dateTime=""
```

原生 HTML 是：

```html
datetime=""
```


`<address>` 并不是：

```text
“邮寄地址标签”
```

它表示：

> 当前页面或 `article` 所对应作者 / 组织的 contact information（联系信息）。

例如：

```html
<address>
  邮箱：
  <a href="mailto:support@example.com">
    support@example.com
  </a>
</address>
```

里面可以有：

* Email
* 电话
* 联系地址
* 其他联系方式

但：

```text
商品产地：广东省深圳市……
```

只是普通地点信息，不应该因为“看起来像地址”就使用 `address`。

核心：

```text
address
≠ 任意现实世界地址

address
= 当前页面 / article 相关实体的联系方式
```


`<br>` 表示 line break（有语义的换行）。

适用于：

```text
换行位置本身属于内容
```

例如诗歌：

```html
<p>
  Roses are red,<br>
  Violets are blue.
</p>
```

或地址：

```html
<address>
  Example Inc.<br>
  1-2-3 Shibuya<br>
  Tokyo
</address>
```

不适合：

```html
标题
<br><br><br>
正文
```

也不应该用来制造布局间距。

判断：

```text
删掉所有 CSS 后，
这里仍然必须在这个位置换行吗？

是 → br 可能合理
否 → 通常应该交给 CSS 或其他结构元素
```


`<span>` 是 generic phrasing container（通用行内容器），自身没有额外语义。

例如：

```html
<p>
  当前价格：
  <span class="price">¥99</span>
</p>
```

适合：

* CSS hook
* JS hook
* 局部文本容器
* 没有更准确语义的内容

但是已有语义时不要用 `span` 模拟：

```html
<!-- 差 -->
<span class="important">无法恢复</span>

<!-- 更准确 -->
<strong>无法恢复</strong>
```

```html
<!-- 差 -->
<span class="date">2026-09-08</span>

<!-- 更准确 -->
<time datetime="2026-09-08">2026-09-08</time>
```


`div` / `span` 的共同特点：

```text
div  = 无额外语义的 flow container
span = 无额外语义的 phrasing container
```

所以：

```text
p vs div

p
= 这是一个自然段

div
= 我只是需要一个结构分组
```

文章正文如果确实是一段文字：

```html
<p>React 使用 Fiber 管理更新。</p>
```

一般比：

```html
<div>React 使用 Fiber 管理更新。</div>
```

语义更准确。


实际项目可以这样判断：

```text
文章正文
→ p

危险 / 不可逆操作的重要信息
→ strong

只是吸引读者注意，但没有提高重要程度
→ b

说话时需要重读
→ em

技术术语 / 外语 / 特殊文本语气
→ i

搜索结果关键词高亮
→ mark

版权 / 条款 / 次要附注
→ small

inline code
→ code

code block
→ pre + code

句中短引用
→ q

整块引用
→ blockquote

引用来源 URL
→ cite 属性

作品标题
→ cite 元素

发布时间
→ time + 合理的 datetime

页面 / article 的联系方式
→ address

内容本身要求换行
→ br

没有更具体语义的行内容器
→ span
```

Accessibility（无障碍）上要记住：

> Semantic HTML 能把更准确的信息提供给浏览器和 Accessibility Tree（无障碍树），辅助技术可以利用这些信息。

但不要机械理解成：

```text
<strong>
→ 屏幕阅读器一定会重读

<em>
→ 屏幕阅读器一定会改变语气
```

不同浏览器、操作系统、Screen Reader（屏幕阅读器）处理可能不同。

因此：

```text
语义正确
≠
可以依赖某一种具体听觉效果
```

例如动态表单错误不能只写：

```html
<strong>提交失败</strong>
```

然后认为无障碍完成了。

动态通知还涉及 `role="alert"`、live region（实时区域）等，后面的 Accessibility 章节再系统讲。

SEO 也同理，不要理解成：

```text
strong 权重大
mark 提升关键词排名
b 权重低
```

正确理解是：

> 语义 HTML 可以帮助浏览器、搜索引擎和辅助技术理解文档结构和内容关系，但标签不是 SEO 加分按钮。

最后把这一章最重要的几个区别压缩成一张表：

| 对比                      | 核心区别              |
| ----------------------- | ----------------- |
| `strong` vs `b`         | 重要性 vs 吸引注意       |
| `em` vs `i`             | 重读强调 vs 特殊文本语气/术语 |
| `mark` vs `strong`      | 上下文相关性 vs 内容自身重要性 |
| `code` vs `pre`         | 内容是代码 vs 保留文本格式   |
| `blockquote` vs `q`     | 块级引用 vs 行内引用      |
| `cite=""` vs `<cite>`   | 来源 URL vs 作品标题    |
| `time` 文本 vs `datetime` | 人类展示文本 vs 机器可读时间  |
| `address` vs 普通地址       | 联系信息 vs 普通地点文本    |
| `p` vs `div`            | 段落语义 vs 通用结构容器    |
| `br` vs 新段落             | 内容内部换行 vs 新思想单元   |
| `span` vs 语义标签          | 无额外语义 vs 明确内容关系   |

这一章最值得记住的一句话就是：

> **先判断文字为什么特殊，再选择标签；不要先看它最后是粗体、斜体、黄色还是小字号。**
