React 里的“闭包陷阱”，通常说的就是 **stale closure（过期闭包）**：

> 某个函数记住了“创建它那次 render 的变量”，之后变量虽然更新了，但这个函数仍然读到旧值。

这不是 React 发明的问题，**本质是 JavaScript 闭包 + React 每次 render 都会创建一套新的变量环境**。

比如：

```tsx
function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setTimeout(() => {
      console.log(count);
    }, 3000);
  };

  return (
    <>
      <div>{count}</div>
      <button onClick={handleClick}>打印</button>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </>
  );
}
```

假设现在：

```text
count = 0
```

你点击“打印”，此时创建的定时器回调闭包记住的是：

```js
count = 0
```

然后 3 秒内疯狂点击 `+1`：

```text
页面 count 已经变成 5
```

但 3 秒后：

```js
console.log(count);
// 0
```

你可能会觉得：

> `count` 明明已经是 5 了，为什么还是 0？

关键就在于：**React 的每次 render，可以理解为一次新的函数调用。**

第一次：

```js
Counter()

// 这一轮自己的变量
count = 0

handleClick = () => {
  console.log(count);
}
```

第二次：

```js
Counter()

// 新的一轮变量
count = 1

handleClick = () => {
  console.log(count);
}
```

第三次：

```js
Counter()

count = 2

handleClick = () => {
  console.log(count);
}
```

可以把它理解成：

```text
Render #1
count₁ = 0
function₁ → 闭包引用 count₁

Render #2
count₂ = 1
function₂ → 闭包引用 count₂

Render #3
count₃ = 2
function₃ → 闭包引用 count₃
```

注意：

```text
count₁
count₂
count₃
```

从闭包的角度来看，并不是“同一个变量不断被修改”。

而是 **每次 render 都产生了新的变量环境**。

所以旧函数：

```js
function₁
```

还是引用：

```js
count₁
```

React 不会神奇地把它修改成：

```js
count₃
```

这就是所谓的闭包陷阱。


另一个非常经典的例子是：

```tsx
useEffect(() => {
  const timer = setInterval(() => {
    console.log(count);
  }, 1000);

  return () => clearInterval(timer);
}, []);
```

假设第一次 render：

```js
count = 0
```

因为：

```js
[]
```

effect 只执行一次，于是里面的回调是第一次 render 创建的：

```text
interval callback
      ↓
   闭包
      ↓
count₁ = 0
```

之后哪怕：

```text
count = 1
count = 2
count = 3
```

这个 interval 里的函数仍然属于第一次 render：

```js
console.log(count₁);
```

于是一直打印：

```text
0
0
0
0
```

这就是最典型的 **stale closure**。


### 为什么 `useCallback` 也很容易产生闭包陷阱？
例如：

```tsx
const handleClick = useCallback(() => {
  console.log(count);
}, []);
```

第一次 render：

```js
count = 0
```

创建：

```js
() => {
  console.log(count);
}
```

因为依赖数组：

```js
[]
```

React 后面永远复用这个函数。

于是：

```text
stable function
      ↓
   闭包
      ↓
count₁ = 0
```

即使组件已经：

```text
count = 100
```

它还是：

```js
console.log(0);
```

所以不是：

> `useCallback` 导致闭包失效。

而恰恰相反：

> `useCallback` 把旧函数保留下来了，所以旧函数的闭包也一起被保留下来了。

正确写法：

```tsx
const handleClick = useCallback(() => {
  console.log(count);
}, [count]);
```

这样：

```text
count 改变
   ↓
useCallback 重新创建函数
   ↓
新函数形成新闭包
   ↓
读到最新 count
```


这也能解释你刚才问的 `useRef`：

```tsx
const cbRef = useRef(cb);

cbRef.current = cb;

const handler = useCallback(() => {
  cbRef.current();
}, []);
```

这个 `handler` **其实仍然有闭包**。

它闭包捕获的是：

```js
cbRef
```

而不是某一次的：

```js
cbRef.current
```

区别非常关键：

```text
cbRef
↓
是一个始终相同的对象
```

大概可以理解成：

```js
const cbRef = {
  current: cb1
};
```

下一次 render：

```js
cbRef.current = cb2;
```

还是原来的对象：

```text
handler
   ↓ 闭包
cbRef ───────────┐
                 ↓
          { current: cb2 }
```

之后：

```js
cbRef.current = cb3;
```

变成：

```text
handler
   ↓
cbRef ───────────┐
                 ↓
          { current: cb3 }
```

所以：

```js
handler()
```

执行的时候才去读取：

```js
cbRef.current
```

自然拿到最新值。

这就是为什么 `useRef` 经常被用来解决 stale closure。


你可以把 React 闭包陷阱浓缩成一句：

> **React 每次 render 都是一张快照，函数闭包会记住创建它的那张快照。**

例如：

```text
Render 1
count = 0
       ↑
       │
    callback1


Render 2
count = 1
       ↑
       │
    callback2


Render 3
count = 2
       ↑
       │
    callback3
```

如果某个地方还持有：

```js
callback1
```

它看到的就是：

```js
count = 0
```

而不是最新的：

```js
count = 2
```

所以闭包陷阱最常出现在：

- `setTimeout`
    
- `setInterval`
    
- `useEffect`
    
- `useCallback`
    
- DOM/event listener
    
- WebSocket 回调
    
- Promise / async 回调
    

尤其是这种组合：

```js
useEffect(() => {
  // 使用了某个 state
}, []);
```

或者：

```js
useCallback(() => {
  // 使用了某个 state
}, []);
```

看到这里就要警觉：

> **这个函数是不是永远拿着第一次 render 的值？**

最后给你一个判断口诀：

```text
普通变量
→ 每次 render 是新的一份
→ 闭包容易拿到旧快照

useRef
→ 每次 render 拿到同一个对象
→ 读取 .current 可以拿到最新值
```

所以 **闭包陷阱不是“闭包出错了”**，而是闭包工作得完全正确，只不过它保留的恰好是 React 某一次 render 的旧快照。

## 闭包、`useCallback` 与 `useRef`
### 什么是闭包
**闭包：函数可以访问它定义时所在词法作用域中的变量，即使外层函数已经执行结束。**

```js
function outer() {
  let count = 0;

  return function inner() {
    count++;
    console.log(count);
  };
}

const fn = outer();

fn(); // 1
fn(); // 2
```

虽然 `outer()` 已经执行完，但 `inner` 仍然可以访问 `count`。

可以理解为：

```text
inner 函数
   │
   └── 闭包 ──► count
```

闭包保存的是对**变量绑定**的访问能力，而不是把函数体里的所有表达式提前计算一遍。

---
## 闭包不会提前执行表达式
例如：

```js
const obj = {
  value: 1,
};

const fn = () => {
  console.log(obj.value);
};

obj.value = 2;

fn(); // 2
```

`fn` 创建时，闭包引用的是：

```text
obj
```

而不是提前保存：

```text
obj.value = 1
```

真正调用 `fn()` 时，才执行：

```js
obj.value
```

所以读取到的是当前的 `2`。

也就是说：

```js
() => obj.value
```

可以理解为：

```js
() => {
  // 调用函数时才执行
  return obj.value;
}
```

而不是：

```js
// ❌ 不是创建函数时就读取
const value = obj.value;

() => value;
```


# 闭包陷阱详解
> Last Format Time：9/16/2026 19:24:51

React 函数组件每次 render，本质上都会重新执行组件函数。

例如：

```tsx
function App() {
  const [count, setCount] = useState(0);

  // ...
}
```

可以粗略理解为：

```text
第 1 次 render：
count₁ = 0

第 2 次 render：
count₂ = 1

第 3 次 render：
count₃ = 2
```

每次 render 中的变量其实属于**这一次 render 的作用域**。

所以：

```tsx
const handler = useCallback(() => {
  console.log(count);
}, []);
```

`handler` 只在第一次 render 创建。

它闭包捕获的是：

```text
handler
   │
   └──► 第一次 render 的 count
                   ↓
                   0
```

后面虽然 React 又执行了组件：

```text
第二次 render → count = 1
第三次 render → count = 2
```

但原来的 `handler` 没有重新创建，所以它仍然访问第一次 render 的 `count`。

这就是：

**Stale Closure（陈旧闭包）**


# 4. `useCallback` 本身并不能解决陈旧闭包

例如：

```tsx
const stableHandler = useCallback(() => {
  cb();
}, []);
```

因为依赖是：

```tsx
[]
```

所以函数只在第一次 render 创建。

它捕获的是第一次 render 中的：

```text
cb₁
```

之后：

```text
render 1 → cb₁
render 2 → cb₂
render 3 → cb₃
```

但是：

```text
stableHandler
     │
     └──► cb₁
```

所以调用的还是旧函数。

因此：

> `useCallback` 的作用是稳定函数引用，不是自动获取最新变量。


# 5. `useRef` 为什么可以解决这个问题

来看：

```tsx
const useHandler = (cb) => {
  const cbRef = useRef(cb);

  cbRef.current = cb;

  const stableHandler = useCallback((...args) => {
    return cbRef.current(...args);
  }, []);

  return stableHandler;
};
```

关键在于：

```tsx
const cbRef = useRef(cb);
```

`useRef` 在组件整个生命周期中都会返回**同一个 ref 对象**。

例如：

```text
render 1
        ┐
render 2 ├──► 同一个 cbRef 对象
render 3 ┘
```

只是：

```tsx
cbRef.current
```

可以修改。

---
## 每次 render 都更新 `current`
第一次：

```text
cbRef
  │
  ▼
{
  current: cb₁
}
```

第二次 render：

```tsx
cbRef.current = cb₂;
```

变成：

```text
cbRef
  │
  ▼
{
  current: cb₂
}
```

第三次：

```text
cbRef
  │
  ▼
{
  current: cb₃
}
```

注意：

**`cbRef` 没有变，只有 `cbRef.current` 在变。**


# 7. `stableHandler` 闭包到底保存了什么

代码：

```tsx
const stableHandler = useCallback((...args) => {
  return cbRef.current(...args);
}, []);
```

闭包捕获的是：

```text
cbRef
```

不是：

```text
cbRef.current
```

更不是：

```text
cbRef.current()
```

因为：

```tsx
cbRef.current(...args)
```

属于函数体里的代码，只有调用：

```tsx
stableHandler()
```

时才会真正执行。

所以执行流程是：

```text
stableHandler()
      │
      ▼
读取 cbRef
      │
      ▼
读取 cbRef.current
      │
      ▼
拿到当前最新 cb
      │
      ▼
执行 cb()
```


# 8. 为什么不是保存 `cbRef.current`

对比这两种写法最容易理解。

### 写法一：运行时读取
```tsx
const handler = () => {
  cbRef.current();
};
```

闭包：

```text
handler
   │
   ▼
 cbRef
   │
   ▼
current ← 每次调用时读取
```

所以能拿到最新值。


### 写法二：提前读取
```tsx
const currentCb = cbRef.current;

const handler = () => {
  currentCb();
};
```

这里在创建 `handler` 之前就已经执行了：

```tsx
cbRef.current
```

假设当时：

```tsx
cbRef.current === cb1
```

于是：

```text
currentCb → cb1

handler
   │
   ▼
currentCb
   │
   ▼
 cb1
```

之后即使：

```tsx
cbRef.current = cb2;
```

也没有作用。

因为：

```text
currentCb → cb1
```

没有改变。

这就再次产生了陈旧闭包。


# 9. `useCallback + useRef` 各自负责什么

这两个 Hook 的职责完全不同。

```tsx
const cbRef = useRef(cb);

cbRef.current = cb;

const stableHandler = useCallback((...args) => {
  return cbRef.current(...args);
}, []);
```

### `useCallback`
负责：

> **让 `stableHandler` 的函数引用保持稳定。**

```text
render 1 ─┐
render 2 ─┼──► 同一个 stableHandler
render 3 ─┘
```

### `useRef`
负责：

> **让这个稳定函数可以获取最新的 `cb`。**

```text
stableHandler
      │
      ▼
    cbRef
      │
      ▼
.current
      │
      ▼
 最新 cb
```

最终形成：

```text
                 每次 render 更新
                       │
                       ▼
cb₁ ──► cb₂ ──► cb₃ ──► cbRef.current
                         ▲
                         │
                   stableHandler
                    永远不变
```


# 10. 最终总结

这个模式：

```tsx
const cbRef = useRef(cb);

cbRef.current = cb;

const stableHandler = useCallback((...args) => {
  return cbRef.current(...args);
}, []);
```

本质上是在创建一个：

**引用稳定，但行为始终最新的代理函数。**

记住三个核心点：

1. **闭包不会保存整个表达式的计算结果，而是保留对外部变量绑定的访问。**
2. `cbRef.current` 是在 `stableHandler` **被调用时**才读取，因此能获得最新值。
3. `useCallback` 保证函数引用稳定，`useRef` 保存最新数据，两者配合解决 stale closure。

一句话记忆：

> **闭包没有被绕过。`stableHandler` 仍然是闭包，只不过它没有直接闭包旧的 `cb`，而是闭包了一个始终不变的 `ref` 对象，再在执行时通过 `ref.current` 获取最新的 `cb`。**
