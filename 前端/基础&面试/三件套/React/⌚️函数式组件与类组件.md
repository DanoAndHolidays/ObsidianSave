# ⌚️函数式组件与类组件
> Last Format Time：9/16/2026 19:24:51

React 从类组件转向函数组件，不只是因为“函数语法更简单”，而是因为函数组件 + Hooks 更符合 React 的整体设计模型。

核心思想可以理解为：`UI = f(props, state)`

函数组件天然就是“一次 render，根据当前 props 和 state 计算 UI”。长期状态由 React/Fiber 保存，组件函数本身只负责计算 UI。

---
## 类组件
问题主要有：
- `this` 心智负担较重，需要处理 `this.state`、`this.props`、方法绑定等问题。
- 同一业务逻辑经常被拆散到 `componentDidMount`、`componentDidUpdate`、`componentWillUnmount` 等生命周期中。
- 状态逻辑复用困难，过去主要依赖 HOC、Render Props，容易增加组件嵌套。
- 类组件依赖长期存在的组件实例，编程模型偏向“可变对象”。

---
## 函数组件
与Hooks 的优势：
- 没有组件实例 `this`，代码更直接。
- 可以按照“业务逻辑”组织代码，而不是按照生命周期组织。
- 可以通过自定义 Hook 复用状态逻辑，不增加组件层级。
- 更容易拆分、组合复杂逻辑。
- 每次 render 都可以看作独立的 render snapshot（渲染快照），更符合 React 的并发渲染模型。
- render 可以暂停、打断、丢弃、重新执行，而函数式计算模型对此更自然。
- 函数代码更容易被 React Compiler 等工具静态分析和优化。

函数组件中 state 不会因为函数执行结束而消失，因为 state 不保存在函数的局部变量中，而是保存在对应 Fiber 的 Hook 链表中：`Fiber → memoizedState → Hook → Hook → Hook`

因此现代 React 的模型可以理解为：`Fiber 保存长期状态 + 函数组件根据当前状态计算 UI`
