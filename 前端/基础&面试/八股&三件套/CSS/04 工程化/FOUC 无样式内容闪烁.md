FOUT 和 FOIT 都是 Web 字体（Web Font）加载过程中出现的现象，核心区别在于：自定义字体还没加载完成时，浏览器是先显示备用字体，还是暂时隐藏文字。

## 1. FOUT：无样式文本闪烁

FOUT（Flash of Unstyled Text）：字体加载完成前，先使用备用字体显示文字；加载完成后，再切换为自定义字体。

示意：字体外观改变。实际切换时文字宽度和换行位置也可能发生变化。

可能引发 CLS 的原因： 两种字体的字宽、字高不同，切换后可能导致文本重新换行、元素高度变化，进而推动周围元素。

## 2. FOIT：不可见文本闪烁

FOIT（Flash of Invisible Text）：自定义字体加载期间，浏览器暂时不显示文字，等待字体加载完成后再显示。

FOIT 的主要问题是用户在字体加载期间看不到文字，并不意味着一定发生 CLS。

## 3. 如何解决？`font-display`

可以通过 CSS 的 `font-display` 属性控制字体加载期间的显示策略。

```
@font-face {
  font-family: "MyFont";
  src: url("/fonts/myfont.woff2") format("woff2");
  font-display: swap;
}

body {
  font-family: "MyFont", Arial, sans-serif;
}
```

常见取值：

|属性值|主要行为|
|---|---|
|`auto`|浏览器自行决定|
|`block`|短暂隐藏文字，倾向等待自定义字体|
|`swap`|极短的隐藏期后显示备用字体，加载成功再替换|
|`fallback`|极短隐藏期 + 短暂替换窗口，超时则本次不再替换|
|`optional`|极短隐藏期，浏览器可以直接放弃本次字体替换|

其中，`swap` 能减少文字不可见时间，但可能产生 FOUT 和 CLS；`optional` 通常更有利于减少字体切换带来的布局偏移，但不能保证每次都显示自定义字体。

## 4. 与 FOUC、CLS 的区别

| 概念   | 含义      | 典型表现                  |
| ---- | ------- | --------------------- |
| FOUC | 无样式内容闪烁 | 页面先显示未应用完整 CSS 的样式    |
| FOUT | 无样式文本闪烁 | 备用字体突然切换为自定义字体        |
| FOIT | 不可见文本闪烁 | 文字暂时不显示               |
| CLS  | 累积布局偏移  | 页面元素在用户没有预期的情况下发生位置移动 |

注意：FOUT、FOIT、FOUC 是现象，CLS 是衡量页面视觉稳定性的性能指标。 它们不属于同一分类层级。

另外，你原来的笔记有两处值得修正：

- `<style>` 放在页面末尾，并不一定会产生 FOUC。浏览器可能在首次绘制前就解析完 CSS。问题在于晚发现样式可能导致额外的样式计算、重排或闪烁。
    
- `will-change` 和 `translateZ(0)` 不能通用地解决 CLS。它们主要涉及合成层与绘制性能，滥用反而增加内存和渲染成本。优先使用 `transform` / `opacity` 实现不影响布局的动画。
    

面试记忆：FOUT 是先显示备用字体再切换；FOIT 是先隐藏文字再显示。字体切换可能引发 CLS，而减少字体切换、匹配备用字体指标可以改善视觉稳定性。
