## submitter 与多提交按钮
一个 form 可以有多个提交按钮：
```html
<button type="submit" name="action" value="draft">保存草稿</button>
<button type="submit" name="action" value="publish">发布</button>
```

真正触发本次提交的按钮叫 **submitter**。

```js
form.addEventListener("submit", (e) => {
  console.log(e.submitter);
});
```

只有当前 submitter 自己的 `name=value` 会参与提交。

```text
点击“保存草稿”
→ action=draft

点击“发布”
→ action=publish
```

submitter 可以覆盖 form 本次提交的配置：
```text
formaction
→ 覆盖 action

formmethod
→ 覆盖 method

formenctype
→ 覆盖 enctype

formtarget
→ 覆盖 target

formnovalidate
→ 本次提交跳过原生验证
```

核心：
```text
form
→ 默认提交配置

submitter
→ 本次是谁提交
→ 可覆盖本次提交配置
```

## requestSubmit() vs submit()
### requestSubmit()
```js
form.requestSubmit();
```

接近用户正常点击提交按钮：
```text
✅ 执行 Constraint Validation
✅ 触发 submit 事件
✅ 可以被 preventDefault()
✅ 可以指定 submitter
```

可以：
```js
form.requestSubmit(button);
```

相当于使用这个 button 作为本次 submitter。

### submit()
```js
form.submit();
```

直接提交：
```text
❌ 不执行 Constraint Validation
❌ 不触发 submit 事件
❌ 没有 submitter
→ 直接提交
```

因此一般程序化正常提交：
```js
form.requestSubmit();
```

优先于：
```js
form.submit();
```

注意避免：
```html
<input name="submit">
```

因为可能覆盖：
```js
form.submit
```

导致：
```text
form.submit is not a function
```

##  FormData
```js
const data = new FormData(form);
```

含义：

> 按照浏览器原生表单提交规则，收集当前 form 中会被提交的数据。

不是读取所有 DOM 控件。

以下通常不会进入 FormData：
```text
没有 name
disabled
未选中的 checkbox
未选中的 radio
```

### 常用 API
```js
data.get("name");
```

获取一个值。

```js
data.getAll("name");
```

获取同名字段的所有值。

```js
data.has("name");
```

判断字段是否存在。

```js
data.set("name", value);
```

追加同名值。

```js
data.append("name", value);
```

删除字段。

```js
data.delete("name");
```

遍历：
```js
for (const [key, value] of data) {
  console.log(key, value);
}
```

### 多值字段
例如：
```text
skills=html
skills=react
```

应该：
```js
data.getAll("skills");
```

得到：
```js
["html", "react"]
```

注意：
```js
Object.fromEntries(data);
```

遇到多个同名字段时可能丢值，因此 checkbox group、`select multiple` 等场景不能无脑转换。

FormData 的值主要是：
```text
string | File
```

## 文件上传
```html
<input type="file" name="avatar">
```

JS：
```js
input.files
```

得到：
```text
FileList
```

即使只允许选择一个文件，也是 FileList，获取文件：
```js
const file = input.files[0];
```

File 常见属性：
```js
file.name
file.size
file.type
file.lastModified
```

### multiple
```html
<input type="file" multiple>
```

允许选择多个文件。

```js
for (const file of input.files) {
  console.log(file.name);
}
```

### accept
```html
<input type="file" accept="image/*">
```

或者：
```html
accept=".png,.jpg,.jpeg"
```

作用：
```text
提示 / 筛选用户选择的文件类型
```

但：
```text
accept ≠ 安全验证
```

前端可以验证：
```js
file.size
file.type
```

但后端必须重新验证文件。

## multipart/form-data
上传文件的原生 form 通常需要：
```html
<form
  method="post"
  enctype="multipart/form-data"
>
```

mental model：
```text
multipart/form-data
→ 把请求拆成多个 part

文本字段
→ 一个 part

文件
→ 一个 part
```

各个 part 通过 boundary 分隔。

### fetch + FormData
推荐：
```js
const data = new FormData(form);

fetch("/upload", {
  method: "POST",
  body: data
});
```

不要手动设置：
```js
"Content-Type": "multipart/form-data"
```

因为浏览器需要自动加入：
```text
boundary
```

正确原则：
```text
fetch + FormData
→ 让浏览器自动设置 Content-Type
```

## Constraint Validation JS API
HTML 负责声明验证规则：
```html
<input
  type="email"
  required
  minlength="5"
>
```

JS 可以读取和控制验证状态。

### checkValidity()
```js
input.checkValidity();
form.checkValidity();
```

返回：
```text
true / false
```

作用：
```text
只检查是否合法
不主动显示浏览器错误 UI
```

### reportValidity()
```js
input.reportValidity();
form.reportValidity();
```

作用：
```text
检查是否合法
+
失败时显示浏览器原生错误提示
```

区别：
```text
checkValidity()
→ 只检查

reportValidity()
→ 检查 + 展示错误
```

### validity / ValidityState
```js
input.validity
```

可以知道具体为什么验证失败，常见：
```text
valueMissing
→ required 但为空

typeMismatch
→ email / url 等类型格式错误

patternMismatch
→ 不符合 pattern

tooShort
→ 小于 minlength

tooLong
→ 大于 maxlength

rangeUnderflow
→ 小于 min

rangeOverflow
→ 大于 max

stepMismatch
→ 不符合 step

badInput
→ 浏览器无法解释输入值

customError
→ 存在自定义验证错误

valid
→ 所有验证规则都通过
```

原则：
```text
HTML 定义规则
浏览器负责判断
JS 读取 validity

不要在 JS 中重复造一套原生验证逻辑
```

### validationMessage
```js
input.validationMessage
```

获得当前浏览器的错误提示文本，例如：
```text
请填写此字段。
```

具体文案可能受：
```text
浏览器
操作系统
语言
```

```text
判断错误类型
→ validity

显示错误文案
→ validationMessage
```

不要依赖固定的 `validationMessage` 文本做业务判断。

### setCustomValidity()
用于把业务规则加入原生验证系统，例如：
```js
username.setCustomValidity("用户名已存在");
```

此时：
```js
username.checkValidity();
// false
```

并且：
```js
username.validity.customError;
// true
```

清除错误必须：
```js
username.setCustomValidity("");
```

非常重要：
```text
非空字符串
→ 设置 customError

空字符串 ""
→ 清除 customError
```

否则控件会一直处于 invalid 状态。

### invalid 事件
控件验证失败时：
```js
input.addEventListener("invalid", (e) => {
  console.log(e.target.validity);
});
```

可以获取失败控件以及具体验证原因。

## novalidate
```html
<form novalidate>
```

表示：
```text
提交时
→ 不执行浏览器自动验证流程
```

但：
```text
HTML 上的验证规则仍然存在
```

JS 仍可以：
```js
form.checkValidity();
input.validity;
```

所以：
```text
novalidate
≠ 删除验证规则

novalidate
= 关闭提交时的自动验证
```
