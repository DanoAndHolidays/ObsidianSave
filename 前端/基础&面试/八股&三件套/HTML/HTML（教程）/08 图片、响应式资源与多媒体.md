## img 与 picture
`<img>` 用于表示文档中的图片内容，属于 replaced element（替换元素）。

```text
<img
  src="photo.jpg"
  alt="图片描述"
  width="800"
  height="600"
>
```

`src` 指定图片资源地址。`alt` 是替代文本，描述图片在当前上下文中的语义作用，而不只是“图片长什么样”。

装饰性图片：
```text
<img src="decoration.svg" alt="">
```

`alt=""` 表示图片没有需要传达给辅助技术的信息，不等于省略 `alt`。

`width / height` 不只是控制尺寸，还可以让浏览器提前知道图片宽高比，提前预留空间，减少 layout shift / CLS。

### 图片加载
```text
<img src="photo.jpg" loading="lazy">
```

`loading="lazy"`：
```text
图片接近视口时再加载
```

适合非首屏图片，首屏重要图片不要随意 lazy，否则可能延迟 LCP。

```text
<img src="hero.jpg" loading="eager">
```

`eager` 表示尽快加载（默认值）

`decoding` 控制图片解码提示：
```text
<img src="photo.jpg" decoding="async">
```

常见值：
```text
auto
sync
async
```

属于浏览器提示，不是严格命令。

### `srcset`
给浏览器提供多个候选图片：
```text
<img
  src="photo-800.jpg"
  srcset="
    photo-400.jpg 400w,
    photo-800.jpg 800w,
    photo-1200.jpg 1200w
  "
  alt=""
>
```

`400w / 800w / 1200w` 表示资源自身宽度，浏览器结合自己的情况选择合适的图片：
```text
显示尺寸
DPR
视口
设备情况
```

也可以使用像素密度：
```text
<img
  src="avatar.png"
  srcset="
    avatar.png 1x,
    avatar@2x.png 2x
  "
>
```

适合固定显示尺寸的头像、Logo 等。

### `sizes`
```text
<img
  srcset="
    photo-400.jpg 400w,
    photo-800.jpg 800w,
    photo-1200.jpg 1200w
  "
  sizes="(max-width: 600px) 100vw, 800px"
>
```

核心：
```text
srcset
→ 有哪些候选资源

sizes
→ 图片预计会显示多宽

浏览器
→ 决定下载哪个资源
```

### `<picture>`
用于根据条件切换图片资源。

```text
<picture>
  <source
    media="(max-width: 600px)"
    srcset="mobile.jpg"
  >

  <img src="desktop.jpg" alt="">
</picture>
```

适合手机和桌面使用不同构图，即 art direction，也可以根据图片格式切换：
```text
<picture>
  <source srcset="photo.avif" type="image/avif">
  <source srcset="photo.webp" type="image/webp">

  <img src="photo.jpg" alt="">
</picture>
```

浏览器从上往下寻找能使用的 `source`，最后的 `img` 负责兜底。

核心区别：
```text
srcset
→ 同一图片，不同尺寸，让浏览器选择

picture
→ 根据条件切换图片或资源组
```

真实项目里常见：
```text
AVIF
↓ 不支持

WebP
↓ 不支持

JPEG / 原图 fallback
```

B 站的视频封面就是这种结构。

## HTML 多媒体元素
### `<video>`
用于在页面中嵌入视频内容，`controls` 用于显示浏览器原生播放控件，例如播放、暂停、进度条、音量和全屏。

```html
<video src="movie.mp4" controls></video>
```

### `poster`
用于指定视频开始播放前显示的封面图片。

```html
<video
  src="movie.mp4"
  poster="cover.jpg"
  controls
></video>
```

### `autoplay / muted / loop`
`autoplay` 表示尝试自动播放，现代浏览器通常会限制带声音媒体的自动播放，因此背景视频常配合 `muted` 使用，`loop` 表示播放结束后重新播放。

```html
<video
  src="background.mp4"
  autoplay
  muted
  loop
></video>
```

### `preload`
`preload` 用于提示浏览器在正式播放前预加载多少媒体内容。

常见值：

- `none`：尽量不提前加载。
- `metadata`：主要加载时长、尺寸等元数据。
- `auto`：允许浏览器提前加载更多媒体数据。

它只是浏览器提示，不保证严格执行。

```html
<video
  src="movie.mp4"
  preload="metadata"
  controls
></video>
```

### Boolean Attribute
`controls`、`autoplay`、`muted`、`loop`、`default` 等属于 Boolean Attribute。

属性存在就是 true，不存在就是 false。

因此 `controls="false"` 并不会关闭 controls。

```html
<!-- 开启 controls -->
<video controls></video>

<!-- 仍然是开启 controls -->
<video controls="false"></video>

<!-- 关闭 controls -->
<video></video>
```

### `<audio>`
用于嵌入音频，使用方式与 `<video>` 基本一致。

```html
<audio src="music.mp3" controls></audio>
```

### `<source>`
`<source>` 用于给父级媒体元素提供候选资源，本身不负责播放或显示。

可以用于：

- `<video>`
- `<audio>`
- `<picture>`

浏览器会选择自己支持的格式。

```html
<video controls>
  <source src="movie.webm" type="video/webm">
  <source src="movie.mp4" type="video/mp4">
</video>
```

父元素负责呈现内容，`source` 负责提供候选资源。

### `<track>`
*没啥用，我看了视频网站，人家都不用*
用于为视频或音频提供与时间同步的文本内容，最常见的是字幕。

通常使用 WebVTT（`.vtt`）文件，常见属性：
- `src`：轨道文件地址。
- `kind`：轨道类型。
- `srclang`：语言。
- `label`：展示给用户的名称。
- `default`：默认启用。

```html
<video src="movie.mp4" controls>
  <track
    src="zh.vtt"
    kind="subtitles"
    srclang="zh"
    label="中文"
    default
  >
</video>
```

## iframe
用于在当前页面中嵌入另一个独立页面，它不是普通的 DOM 容器，而是会创建一个新的 **Browsing Context（浏览上下文）**。

iframe 内部拥有自己的：

- `window`
- `document`
- DOM
- CSS
- JavaScript 环境

```html
<iframe src="https://example.com"></iframe>
```

### 常用属性
`src` 指定要加载的页面。

```html
<iframe src="/page.html"></iframe>
```

`title` 为 iframe 提供可访问名称，方便屏幕阅读器识别内容。

```html
<iframe
  src="/map.html"
  title="公司位置地图"
></iframe>
```

`loading` 控制 iframe 加载时机。

```html
<iframe
  src="/video.html"
  loading="lazy"
></iframe>
```

- `eager`：立即加载
- `lazy`：接近视口时加载

`srcdoc` 直接提供 iframe 内部的 HTML，而不是从 URL 加载页面。 

```html
<iframe srcdoc="<p>Hello</p>"></iframe>
```

不要直接把不可信的用户输入放入 `srcdoc`，否则可能产生 XSS 风险。

### sandbox
`sandbox` 用于限制 iframe 的能力。

```html
<iframe
  src="/page.html"
  sandbox
></iframe>
```

添加 `sandbox` 后，会默认限制很多能力，再通过 `allow-*` 按需开放，常见权限：
```text
allow-scripts
允许执行 JavaScript

allow-forms
允许提交表单

allow-popups
允许打开弹窗

allow-same-origin
允许保持正常的 Origin 身份
```

示例：
```html
<iframe
  src="/app.html"
  sandbox="allow-scripts allow-forms"
></iframe>
```

可以理解为：
```text
sandbox
= 默认限制能力

allow-*
= 逐个开放能力
```

对于不可信页面，`allow-scripts` 和 `allow-same-origin` 的组合需要谨慎。

### allow
`allow` 用于控制 iframe 是否能够使用某些浏览器功能，例如：
```html
<iframe
  src="/video.html"
  allow="autoplay; fullscreen"
></iframe>
```

常见权限：
```text
camera
microphone
geolocation
fullscreen
autoplay
```

简单区分：
```text
sandbox
→ 限制页面本身的能力

allow
→ 控制浏览器功能权限
```

## iframe 与同源策略
如果父页面和 iframe 同源：
```text
https://example.com/a

https://example.com/b
```

父页面可以访问 iframe 的 DOM 和 `window`。

```js
iframe.contentWindow
iframe.contentDocument
```

如果不同源：
```text
https://a.com

https://b.com
```

浏览器的 **Same-Origin Policy（同源策略）** 会阻止双方直接读取对方 DOM，跨域 iframe 通信通常使用：
```js
window.postMessage()
```

核心关系：
```text
同源
→ 可以直接进行一定程度的 JS / DOM 访问

跨源
→ 同源策略限制
→ 使用 postMessage 通信
```

### iframe 的性能特点
iframe 相比普通 DOM 元素更重，因为它基本需要运行一个独立页面环境。

```text
iframe
├─ Window
├─ Document
├─ DOM
├─ CSS
├─ JavaScript
└─ 网络资源
```

因此大量 iframe 会增加性能开销，常见优化方式：
```html
<iframe loading="lazy"></iframe>
```

或者用户真正需要时再创建 iframe。

### iframe 的使用场景
比较适合：
```text
第三方视频
地图
广告
支付页面
在线编辑器
第三方系统
不可信内容预览
部分微前端场景
```

不推荐用 iframe 做普通页面布局，因为不同 iframe 之间：

- CSS 难共享
- JS 状态难共享
- 路由管理复杂
- 高度同步麻烦
- 通信成本高

## Shadow DOM
Shadow DOM 是浏览器提供的一种 **组件级 DOM 和 CSS 封装机制**。

一个普通元素可以拥有自己的内部 Shadow Tree：
```text
<my-card>              ← Shadow Host
  #shadow-root         ← Shadow Root
    <button>
```

创建方式：
```js
const shadowRoot = element.attachShadow({
  mode: "open"
})
```

Shadow DOM 主要提供两种封装：
```text
DOM 封装
外部 querySelector 不会默认穿透 Shadow DOM

CSS 封装
外部 CSS 不会像普通 DOM 一样直接匹配内部元素
```

Shadow DOM 常用于 **Web Components**。

### Shadow DOM 与 iframe
两者都有“隔离”，但级别完全不同。

```text
Shadow DOM
├─ 同一个 window
├─ 同一个 document
├─ DOM / CSS 封装
└─ 组件级隔离

iframe
├─ 独立 window
├─ 独立 document
├─ 同源策略
└─ 页面级隔离
```
