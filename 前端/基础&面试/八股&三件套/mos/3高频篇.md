## 高频篇
### CSS
##### 盒模型
* **Q: 盒模型**
  A: CSS 盒模型描述每个元素在页面中占据的矩形区域，由 content、padding、border、margin 四层组成。标准盒模型（`box-sizing: content-box`）下，`width`/`height` 只限定 content 区，实际占用尺寸需额外加上 padding 和 border；IE 盒模型（`box-sizing: border-box`）下，`width`/`height` 已经包含 content + padding + border，更符合直觉。背景与原因：早期 Web 标准选择 content-box 是为了让内容尺寸与作者预期一致，但现代布局中 border-box 能显著降低心智负担。实际应用：全局重置 `* { box-sizing: border-box; }` 是主流做法；设计稿量尺寸时可直接按 border-box 计算，无需手动扣除 padding/border。注意：margin 不参与盒模型尺寸计算，它控制的是元素与其他元素之间的外部间距。

##### BFC
* **Q: BFC**
  A: BFC（Block Formatting Context，块级格式化上下文）是页面中一块独立的渲染区域，内部子元素的布局不会影响到外部元素，反之亦然。触发条件包括 `float` 不为 `none`、`overflow` 不为 `visible`、`display` 为 `inline-block`/`flex`/`grid`/`table-cell`、以及 `position` 为 `absolute`/`fixed`。底层原因：BFC 让浏览器在局部建立一个独立的布局上下文，从而解决浮动、margin 折叠等典型布局副作用。常见应用：1）清除浮动（父元素触发 BFC 后可包裹浮动子元素，避免高度塌陷）；2）防止相邻块级元素的垂直 margin 折叠；3）实现左侧固定、右侧自适应的两栏布局。注意：使用 `overflow: hidden` 触发 BFC 会裁剪溢出内容，应根据场景选择合适方案。

##### 选择器权重计算方式
* **Q: 选择器权重计算方式**
  A: CSS 选择器优先级用 `(a, b, c, d)` 四位元组比较，可近似看成千、百、十、个位：`inline style`（a=1，1000 级）、`ID` 选择器（b=1，100 级）、`class`/`属性`/`伪类`（c=1，10 级）、`元素`/`伪元素`（d=1，1 级）。`!important` 拥有最高优先级，可覆盖任何声明；同权重时后声明的规则生效。设计原因：这种层级结构让浏览器在冲突时能确定性决策，同时保持作者样式、用户样式、浏览器默认样式之间的可预测性。实际应用：避免滥用 `!important` 和过深嵌套；BEM 等命名规范能显著降低权重冲突。注意：通配符 `*`、组合器（`>`、`+`、`~`）不增加权重；伪类 `:not()` 本身不计权重，但其内部的选择器会计入。

##### 清除浮动
* **Q: 清除浮动**
  A: 浮动元素脱离文档流，父元素若只包含浮动子元素会发生高度塌陷，因此需要清除浮动。推荐方案：1）伪元素 clearfix（最常用）：父元素添加 `::after { content: ""; display: table; clear: both; }`，无额外 DOM，兼容性好；2）触发父元素 BFC，如 `overflow: hidden/auto`，副作用是会裁剪溢出内容；3）双伪元素法：同时用 `::before` 和 `::after` 清除，还能抑制 margin 折叠；4）额外空标签 `<div style="clear: both"></div>`，简单但增加无意义标签。实际应用：clearfix 是目前工程实践的标准做法；如果布局使用 flex/grid 则基本无需处理浮动。注意：clear 属性只对块级元素生效，且只能清除同一 BFC 内的浮动。

##### 垂直居中的方案
* **Q: 垂直居中的方案**
  A: 垂直居中方案取决于是否知道元素尺寸以及浏览器兼容要求。常用方案：1）Flex：`display: flex; align-items: center; justify-content: center`，最推荐，代码简洁且兼容性良好；2）Grid：`display: grid; place-items: center`；3）绝对定位 + transform（未知宽高）：`top: 50%; left: 50%; transform: translate(-50%, -50%)`；4）绝对定位 + 负 margin（已知宽高）；5）`display: table-cell` 配合 `vertical-align: middle`；6）行内块 + `line-height` 近似居中。实际应用：现代项目优先 flex/grid；需要兼容旧浏览器时使用 table-cell 或绝对定位。注意：transform 方案在部分浏览器中可能导致字体模糊，可用 `transform: translate3d(-50%, -50%, 0)` 开启硬件加速改善。

##### CSS3的新特性
* **Q: CSS3的新特性**
  A: CSS3 是一次模块化的重大升级，主要新增：1）选择器：`[attr^=value]`、`nth-child`、`nth-of-type`、`:not()` 等；2）盒模型与外观：`box-sizing`、`border-radius`、`box-shadow`、`border-image`；3）背景与渐变：`background-size`、`background-origin`、线性/径向渐变；4）变换：`transform`（translate/rotate/scale/skew）及 3D 变换；5）过渡与动画：`transition`、`@keyframes + animation`；6）布局：Flexbox、Grid、多列布局；7）响应式：`@media` 媒体查询；8）字体：`@font-face`；9）滤镜：`filter`（blur、grayscale 等）；10）自定义属性：`--var` 与 `var()`。实际应用：动画优先使用 `transform` 和 `opacity`，因为它们可由 GPU 合成，避免重排。

##### CSS动画和过渡
* **Q: CSS动画和过渡**
  A: `transition` 用于在两个状态之间做平滑过渡，需要触发条件（如 `:hover`），只有起始和结束两个状态；`animation` 通过 `@keyframes` 定义多个关键帧，可自动播放、循环、反向、暂停，控制更精细。原因：`transition` 适合简单交互反馈，实现成本低；`animation` 适合复杂、持续的动画。实际应用：按钮 hover 变色用 transition，loading、轮播、进场动画用 animation。性能注意：两者都应优先动画 `transform` 和 `opacity`，它们只触发合成层，不引起布局重排；`width`、`height`、`margin` 等属性动画会触发重排，性能较差。

##### 隐藏页面元素的方式
* **Q: 隐藏页面元素的方式**
  A: 常见隐藏方式及差异：1）`display: none`：元素从渲染树移除，不占据空间、不可交互，会触发重排；2）`visibility: hidden`：不可见但占据空间，不可交互，触发重绘；3）`opacity: 0`：不可见但占据空间且可交互（可点击），触发重绘；4）`clip-path: polygon(0 0, 0 0, 0 0, 0 0)`：裁剪为零，元素仍在布局中；5）`transform: scale(0)`：缩放为 0，占据空间；6）`position: absolute; left: -9999px`：移出可视区；7）`aria-hidden="true"`：仅对读屏软件隐藏。实际应用：完全移除用 `display:none`；保留占位且不可交互用 `visibility:hidden`；淡出动画用 `opacity`；语义隐藏用 `aria-hidden`。

##### em/px/rem/vh/vw区别
* **Q: em/px/rem/vh/vw区别**
  A: `px` 是绝对单位，与设备像素相关（CSS 像素会经 DPR 换算）；`em` 相对父元素 `font-size`，用于 `padding/margin` 时通常基于自身 `font-size` 计算，多层嵌套下容易失控；`rem` 相对根元素（`<html>`）`font-size`，通过媒体查询或 JS 调整根字体即可实现全局缩放，是移动端适配常用单位；`vh`/`vw` 分别相对视口高度/宽度的 1%，`vmin`/`vmax` 取二者较小/较大值。设计原因：px 适合固定尺寸，rem/vw 适合响应式，em 适合组件内局部比例关系。实际应用：移动端常用 `rem`（配合 flexible.js）或 `vw` 方案；大屏适配可用 `vw/vh`。

##### flex布局
* **Q: flex布局**
  A: Flexbox 是一维布局模型，通过 `display: flex` 触发。容器属性：`flex-direction`（主轴方向）、`flex-wrap`（换行）、`justify-content`（主轴对齐）、`align-items`（交叉轴单行长对齐）、`align-content`（多行整体对齐）。项目属性：`flex`（`flex-grow flex-shrink flex-basis` 缩写）、`align-self`、`order`。核心考点：`flex: 1` 等价于 `flex: 1 1 0%`，表示项目可以增长、可以收缩、基准尺寸为 0，因此会均分剩余空间。实际应用：垂直居中、圣杯布局、等高布局、卡片列表都可用 flex 优雅实现。注意：`align-items` 控制单行，`align-content` 只在多行时生效；使用 `gap` 可替代 margin 控制项目间距。

##### CSS性能优化方法
* **Q: CSS性能优化方法**
  A: CSS 性能优化核心目标是减少重排重绘、降低选择器复杂度、优化加载。策略：1）动画优先使用 `transform`/`opacity`，避免动画 `width/height/top/left`；2）选择器避免过深嵌套（建议不超过 3 层），减少通配符和昂贵伪类；3）使用简写属性减少声明数；4）合理使用 `will-change` 提前告知浏览器优化，但用完后及时移除；5）压缩 CSS、移除未使用样式（PurgeCSS）；6）关键 CSS 内联，非关键 CSS 异步加载；7）使用 `content-visibility` 和 `contain` 隔离渲染区域；8）避免 `@import`，因为它会阻塞并行下载。实际应用：配合 Lighthouse 和 DevTools Performance 面板定位瓶颈。

* **Q: 画0.5px线**
  A: 在 Retina 等高分屏上，1 个物理像素对应 CSS 0.5px，因此有时需要绘制 0.5px 的细线。实现方案：1）`transform: scale(0.5)`：给伪元素设置 1px 边框后 `scaleY(0.5)`，最通用；2）`box-shadow: 0 0.5px 0 #000` 模拟细线；3）直接写 `border-width: 0.5px`（部分浏览器支持）；4）SVG `<line stroke-width="0.5">`；5）viewport `initial-scale=0.5`（影响整个页面，不推荐）。实际应用：推荐伪元素 + transform 方案，兼容性好且不影响布局。注意：scale 会使元素占用空间按变换前计算，必要时需用 `transform-origin` 调整位置。

* **Q: 画三角形**
  A: 利用 CSS 边框相交形成斜角的特性：将元素宽高设为 0，设置四个方向边框，保留目标方向相邻两边颜色即可。例如朝上三角形：`width: 0; height: 0; border: 50px solid transparent; border-bottom-color: red;`。原理：当宽高为 0 时，四个边框退化为四个三角形，通过透明化三边保留一边。实际应用：气泡对话框尖角、下拉箭头、提示角标。进阶：用 `clip-path: polygon(...)` 可绘制任意三角形，更灵活且不受边框宽度限制。

* **Q: 两栏布局方案**
  A: 左侧固定、右侧自适应的两栏布局常用方案：1）Flex：父 `display: flex`，左侧固定宽，右侧 `flex: 1`，最推荐；2）Grid：`grid-template-columns: 200px 1fr`；3）Float + BFC：左侧 `float: left`，右侧 `overflow: hidden` 触发 BFC；4）Float + margin：左侧浮动，右侧 `margin-left` 等于左侧宽度；5）绝对定位 + margin：左侧绝对定位，右侧 `margin-left`。实际应用：后台管理系统侧边栏 + 内容区最常用 flex/grid；需要兼容旧浏览器时用 float + BFC。注意：float 方案需清除浮动，BFC 方案会裁剪右侧溢出内容。

### JavaScript
* **Q: typeof类型判断**
  A: `typeof` 操作符返回操作数类型的字符串，可能值为 `undefined`、`boolean`、`number`、`string`、`symbol`、`bigint`、`function`、`object`。注意：`typeof null === "object"` 是 JS 历史 bug（null 的二进制前三位为 0，被误判为对象）；`typeof []` 和 `typeof {}` 都返回 `object`，无法区分数组与普通对象；`typeof NaN` 返回 `number`。实际应用：`typeof` 适合判断基本类型和函数；判断数组、日期、正则等具体对象类型应使用 `Object.prototype.toString.call()`，返回形如 `[object Array]`。注意：`typeof` 对未声明变量不会报错，而是返回 `undefined`。

* **Q: 类型转换**
  A: JS 是弱类型语言，类型转换分为显式转换（`Number()`、`String()`、`Boolean()`、`parseInt()`、`parseFloat()`）和隐式转换。隐式转换常发生在：1）`+` 操作符有一方为字符串时进行拼接；2）`==` 比较会尝试类型转换（如 `null == undefined` 为 true，`0 == ""` 为 true）；3）条件判断将值转布尔；4）算术运算 `-`、`*`、`/` 将操作数转数字。对象转原始值会先调用 `valueOf()`，再调用 `toString()`。实际应用：优先使用 `===` 和 `!==` 避免隐式转换坑；处理用户输入时用显式转换并做 NaN 校验。

* **Q: 闭包**
  A: 闭包是指函数能够访问并记住其词法作用域中的变量，即使该外部函数已经执行完毕并退出调用栈。原因：JS 函数在创建时会保存对其词法环境的引用，形成作用域链。经典应用：1）函数柯里化；2）数据私有化/模块模式；3）循环中的异步操作保存当前索引；4）回调与事件处理保持上下文。注意：闭包会阻止被引用变量被垃圾回收，使用完毕后应手动解除引用（如赋值为 `null`），避免内存泄漏。

* **Q: 原型与原型链**
  A: 每个函数都有 `prototype` 属性，指向原型对象；每个对象都有 `__proto__` 属性（标准用法为 `Object.getPrototypeOf()`），指向构造函数的 `prototype`。当访问对象属性时，若对象本身没有，会沿 `__proto__` 链向上查找，直到找到或到达原型链终点 `Object.prototype`（其 `__proto__` 为 `null`）。原因：原型链让实例共享方法，节省内存，并实现基于原型的继承。实际应用：`instanceof` 就是检查构造函数的 `prototype` 是否出现在对象原型链上；不要过度修改内置对象原型，以免污染全局。

* **Q: 原型继承和Class继承**
  A: ES5 原型继承通过设置子构造函数的 `prototype` 为父类实例实现：`Child.prototype = Object.create(Parent.prototype)`，子类通过原型链共享父类方法，但父类的引用类型属性会被所有子实例共享。ES6 `class` 是语法糖，底层仍是原型链：`class Child extends Parent` 自动设置好原型链，`constructor` 中必须先调用 `super()` 才能使用 `this`，因为子类实例由父类构造。原因：`class` 提供更清晰、更接近传统面向对象的写法，同时解决了 ES5 继承中 `constructor` 指向混乱、静态方法继承不便等问题。实际应用：现代项目优先使用 `class extends`。

* **Q: 模块化**
  A: JS 模块化演进：IIFE（避免全局污染）→ CommonJS（Node 使用，`require/module.exports`，运行时同步加载，值拷贝）→ AMD/CMD（RequireJS/SeaJS，浏览器异步加载）→ ES Module（ES6 官方标准，`import/export`，编译时静态分析，值引用，支持 tree-shaking）。核心区别：CommonJS 是运行时加载、输出值的拷贝；ESM 是编译时加载、输出值的引用。实际应用：浏览器与现代工程使用 ESM；Node.js 也逐渐向 ESM 迁移。注意：ESM 中 `import` 语句会提升并优先执行，`this` 为 `undefined`；CommonJS 中 `this` 指向当前模块。

* **Q: 事件机制**
  A: DOM 事件传播分三个阶段：捕获阶段（从 `window` 向下到目标元素）、目标阶段、冒泡阶段（从目标元素向上到 `window`）。`addEventListener` 第三个参数为 `true` 时监听捕获阶段，默认 `false` 监听冒泡阶段。事件委托利用冒泡机制，在父元素上统一监听子元素事件，减少内存占用并支持动态子元素。方法：`stopPropagation()` 阻止事件继续传播，`stopImmediatePropagation()` 同时阻止该元素上其他同类型监听，`preventDefault()` 阻止默认行为。实际应用：列表项点击、表格操作常用事件委托；React/Vue 的合成事件也基于委托实现。

* **Q: 箭头函数**
  A: 箭头函数是 ES6 引入的简洁函数写法，与普通函数的关键区别：1）没有自己的 `this`，`this` 继承定义时外层词法作用域，且不能通过 `call/apply/bind` 改变；2）不能用作构造函数，不能 `new`；3）没有 `arguments` 对象，可用剩余参数 `...args`；4）不能作为 Generator 函数（不能用 `yield`）；5）没有 `prototype`。实际应用：适合短回调（`map`、`filter`）、外层 `this` 需要保留到内层的场景。注意：不适合作为对象方法或需要动态 `this` 的事件回调。

* **Q: JS内存泄露检测**
  A: 常见内存泄漏场景：1）未声明就赋值的全局变量；2）闭包长期持有外部变量引用；3）DOM 引用未清除（JS 仍持有已移除 DOM 的引用）；4）定时器/事件监听未清理；5）Map/Set/WeakMap 使用不当。检测方法：Chrome DevTools Memory 面板拍摄堆快照对比，Allocation Timeline 追踪分配，Performance 面板观察内存曲线。实际应用：组件卸载时清理定时器和监听；长列表使用对象池或虚拟滚动；需要缓存 DOM 引用时考虑使用 `WeakMap`/`WeakSet`。

* **Q: async/await异步总结**
  A: `async/await` 是 ES2017 引入的异步语法糖，基于 Promise。`async` 函数始终返回 Promise，内部 `await` 会暂停当前函数执行直到 Promise 落定。错误处理可用 `try/catch`，比 `.catch` 更直观。原因：它让异步代码看起来像同步代码，降低阅读和维护成本。实际应用：1）无依赖的多个异步任务用 `Promise.all` 并行，避免顺序 `await` 导致串行；2）循环中 `await` 会顺序执行，需要并发时先用 `Promise.all` 映射；3）`for await...of` 可遍历异步迭代器。注意：`await` 只能出现在 `async` 函数或顶层模块中。

* **Q: Promise异步总结**
  A: Promise 是 ES6 引入的异步解决方案，有三种状态：`pending`、`fulfilled`、`rejected`，状态一旦改变不可回退。核心 API：`then`（链式调用，返回新 Promise）、`catch`、`finally`。静态方法：`Promise.all`（全部成功或一个失败）、`Promise.race`（最快一个）、`Promise.allSettled`（全部完成不论结果）、`Promise.any`（第一个成功）。原因：Promise 将回调组织为链式结构，解决回调地狱，并提供统一的错误处理。注意：`then/catch/finally` 回调属于微任务，在当前宏任务结束后、下一个宏任务前执行；链式调用中不要忘记 `return` 新 Promise，否则后续 `then` 拿不到异步结果。

* **Q: Event Loop执行机制**
  A: JS 是单线程语言，Event Loop 负责调度同步与异步代码。执行流程：1）执行当前宏任务中的同步代码；2）清空微任务队列；3）渲染 UI（如果需要）；4）取出下一个宏任务执行。宏任务包括 `script` 整体、`setTimeout/setInterval`、I/O、UI 渲染、`setImmediate`（Node）等；微任务包括 `Promise.then/catch/finally`、`MutationObserver`、`queueMicrotask`，Node 还有 `process.nextTick`（优先级高于 Promise 微任务）。原因：微任务设计用于让高优先级异步操作尽快执行，避免 UI 渲染被频繁打断。注意：每轮 Event Loop 中微任务产生的新微任务会连续执行，直到队列为空。

### 浏览器
* **Q: 储存**
  A: 浏览器主要存储方案对比：1）Cookie：4KB 左右，每次同源请求自动携带，可设过期时间，常用于会话标识；2）localStorage：约 5-10MB，持久化，不随请求发送，适合用户偏好；3）sessionStorage：同 localStorage，但会话级，关闭标签页清除；4）IndexedDB：异步、结构化、支持索引，容量大（通常数百 MB），适合离线应用；5）Cache API：配合 Service Worker 缓存资源。选择建议：小数据用 localStorage；复杂查询/大数据用 IndexedDB；离线缓存用 Cache API。注意：localStorage 只能存字符串，存对象需 `JSON.stringify`；敏感信息不要放 localStorage，易被 XSS 读取。

* **Q: 浏览器缓存机制**
  A: 浏览器缓存分强缓存和协商缓存。强缓存：服务器通过 `Cache-Control`（优先级高）或 `Expires` 响应头告知浏览器在有效期内直接使用本地缓存，状态码显示 `200 from disk/memory cache`。协商缓存：强缓存过期后，浏览器携带 `If-Modified-Since`（对应 `Last-Modified`）或 `If-None-Match`（对应 `ETag`）请求服务器，未修改返回 `304 Not Modified`。原因：强缓存减少请求次数，协商缓存保证内容更新后能及时发现。实际应用：`ETag` 优先级高于 `Last-Modified`，更精确但服务端计算有开销；推荐 `Cache-Control` + `ETag` 组合；静态资源用长期强缓存并配合文件名 hash。

* **Q: 从输入URL到网页显示的过程**
  A: 完整流程：1）DNS 解析（浏览器缓存→系统缓存→DNS 服务器）得到 IP；2）TCP 连接（三次握手），HTTPS 还需 TLS 握手；3）发送 HTTP 请求；4）服务器处理并返回响应；5）浏览器解析 HTML 构建 DOM 树，解析 CSS 构建 CSSOM；6）遇到同步 `<script>` 会阻塞解析；7）合并 DOM 与 CSSOM 生成 Render Tree；8）Layout（回流）计算节点几何位置；9）Paint（绘制）生成像素；10）Composite（合成）将图层提交到 GPU。优化点：关键 CSS 内联、JS 加 `defer/async`、减少重排重绘、启用 HTTP/2、使用 CDN。

* **Q: 前端攻击方式**
  A: 常见前端攻击与防御：1）XSS（跨站脚本）：注入恶意脚本，防御是输入校验、输出转义、CSP、HttpOnly Cookie；2）CSRF（跨站请求伪造）：利用用户登录态发起恶意请求，防御是 CSRF Token、SameSite Cookie、校验 Origin/Referer；3）点击劫持：透明 iframe 覆盖诱导点击，防御是 `X-Frame-Options` 或 CSP `frame-ancestors`；4）中间人攻击：HTTPS + HSTS；5）DOM Clobbering：污染全局变量。实际应用：富文本内容使用 DOMPurify 过滤；关键操作加二次确认或验证码；敏感 Cookie 设置 `SameSite=Lax/Strict`。

* **Q: 跨域方案**
  A: 跨域由同源策略限制（协议、域名、端口任一不同）。解决方案：1）CORS：后端设置 `Access-Control-Allow-Origin` 等响应头，最标准；2）JSONP：利用 `<script>` 无跨域限制，仅支持 GET，不安全已少用；3）代理服务器：开发环境 webpack-dev-server proxy，生产环境 Nginx 反向代理；4）`postMessage` + iframe：跨窗口通信；5）WebSocket：天然支持跨域；6）`document.domain`：仅同主域。实际应用：现代项目首选 CORS；开发环境用代理解决本地跨域；避免生产环境 JSONP。

* **Q: 移动端300ms延迟解决**
  A: 移动端 300ms 点击延迟源于浏览器需判断用户是单击还是双击缩放。解决方案：1）`<meta name="viewport" content="width=device-width, initial-scale=1">`：现代浏览器在 viewport 不可缩放时默认取消延迟；2）`touch-action: manipulation` CSS 属性禁止双击缩放；3）FastClick 库通过 touch 事件模拟 click；4）直接使用 `touchstart`/`touchend`。原因：iOS 9.3+ 和 Android Chrome 32+ 已原生修复，设置正确 viewport 后通常无需额外库。注意：某些旧系统或特殊 WebView 仍需 FastClick。

* **Q: 多标签通讯**
  A: 同源多标签页通信方案：1）BroadcastChannel API：推荐，使用同名频道 `postMessage/onmessage`，同源标签间收发；2）`localStorage + storage` 事件：一个标签修改，其他标签监听 `window.onstorage`；3）SharedWorker：多标签共享后台线程；4）Service Worker：作为消息中转；5）`postMessage` + `window.open`/`iframe`；6）WebSocket 服务器中转。实际应用：简单场景用 BroadcastChannel 或 localStorage；需要复杂协调用 Service Worker 或 SharedWorker。注意：BroadcastChannel 兼容性略逊于 localStorage，且必须同源。

* **Q: requestIdleCallback与requestAnimationFrame区别**
  A: `requestAnimationFrame`（rAF）在浏览器重绘前执行，频率与屏幕刷新率同步（通常 60fps），适合动画和视觉更新；`requestIdleCallback`（rIC）在浏览器空闲时执行，不阻塞关键渲染路径，适合低优先级任务（数据上报、预计算、分片渲染）。原因：rAF 保证视觉流畅，rIC 保证主线程不被长任务阻塞。实际应用：动画用 rAF；大数据分批处理或上报用 rIC，并通过 `IdleDeadline.timeRemaining()` 控制每次执行时间。注意：rIC 回调可能在几秒后才执行，不适合紧急任务；React Scheduler 模拟了类似 rIC 的能力以兼容旧浏览器。

* **Q: script标签defer与async区别**
  A: 两者都使脚本异步加载（不阻塞 HTML 解析），但执行时机不同：`defer` 在 HTML 解析完成后、DOMContentLoaded 前按出现顺序执行；`async` 在下载完成后立即执行，不保证顺序。原因：`defer` 保证依赖顺序，适合需要等待 DOM 或依赖其他脚本的业务代码；`async` 适合独立脚本（广告、统计）。注意：多个 `async` 脚本之间不要相互依赖；没有这两个属性时，普通 `<script>` 会阻塞解析直到下载并执行完成。

### Vue2
* **Q: 响应式原理**
  A: Vue2 响应式基于 `Object.defineProperty`。初始化时 Observer 递归遍历 `data` 对象的每个属性，将其转为 getter/setter。每个属性对应一个 Dep，getter 中通过 `Dep.target`（当前 Watcher）收集依赖，setter 中通知 Dep 中所有 Watcher 更新。数组通过重写 `push/pop/shift/unshift/splice/sort/reverse` 七个方法实现响应式。局限：无法检测对象新增/删除属性（需 `Vue.set`/`Vue.delete`）、无法检测数组索引和长度直接修改、深层递归有性能开销。Vue3 使用 Proxy 解决这些问题。

* **Q: vdom和diff算法**
  A: 虚拟 DOM 是用 JS 对象描述真实 DOM 结构，通过 diff 找出最小差异后批量更新真实 DOM。Vue2 diff 基于 Snabbdom，采用双端比较：从新旧子节点数组两端向中间遍历，比较策略为头头、尾尾、头尾、尾头，若都不匹配则通过 key 查找。原因：双端比较能更快处理头尾插入/删除等常见列表操作，时间复杂度 O(n)。实际应用：`key` 必须稳定且唯一，避免用数组索引作为 key，否则会导致复用错乱和状态丢失。

* **Q: 模板编译**
  A: Vue2 模板编译分三阶段：1）Parse：用正则和栈将 template 解析为 AST；2）Optimize：遍历 AST 标记静态节点，diff 时直接跳过；3）Generate：将 AST 转为 `render` 函数字符串，再通过 `new Function` 生成 render 函数。运行时 render 函数返回 vnode。原因：将模板编译为 JS 函数可在运行时高效执行，同时支持构建时预编译（vue-loader）。实际应用：生产环境使用 vue-loader 预编译模板，减少运行时开销。

* **Q: Vue组件渲染过程**
  A: Vue2 组件渲染流程：1）合并选项；2）`beforeCreate`；3）`created`（响应式初始化完成）；4）编译模板或直接使用 render；5）`beforeMount`；6）创建渲染 Watcher，执行 render 生成 vnode；7）patch 将 vnode 转为真实 DOM；8）`mounted`。数据变化时，响应式系统通知渲染 Watcher 重新 render，生成新 vnode 后 patch 更新 DOM。注意：`mounted` 不保证子组件也已挂载，若需等待可用 `this.$nextTick` 或在 `updated` 中处理。

* **Q: 组件通信方式**
  A: Vue2 组件通信：1）`props/$emit`：父子通信，单向数据流；2）`$parent/$children`：直接访问实例，不推荐；3）`$refs`：调用子组件方法或访问属性；4）`provide/inject`：跨层级（适合主题/配置）；5）eventBus：全局 Vue 实例做事件总线，小项目可用；6）Vuex：集中式状态管理；7）`$attrs/$listeners`：透传属性和事件。实际应用：优先 props + events；跨层级或全局状态用 Vuex/Pinia；eventBus 在大型项目中易导致事件流难以追踪。

* **Q: 生命周期方法**
  A: Vue2 生命周期：创建阶段 `beforeCreate → created`、挂载阶段 `beforeMount → mounted`、更新阶段 `beforeUpdate → updated`、销毁阶段 `beforeDestroy → destroyed`。父子组件执行顺序：父 beforeCreate → 父 created → 父 beforeMount → 子 beforeCreate...子 mounted → 父 mounted；销毁顺序由子到父。实际应用：`created` 发起数据请求；`mounted` 操作 DOM；`beforeDestroy` 清理定时器、事件监听、订阅；`updated` 中避免再次修改响应式数据导致死循环。

* **Q: 统一监听报错**
  A: Vue2 统一错误处理：1）`Vue.config.errorHandler`：捕获组件渲染和观察者中的同步错误；2）`errorCaptured` 生命周期：捕获后代组件错误，返回 `false` 阻止继续传播；3）`window.onerror`：捕获未 `try/catch` 的运行时错误；4）`unhandledrejection`：捕获未处理的 Promise 拒绝。原因：不同错误来源需要不同兜底。实际应用：生产环境组合使用上述方案，并将错误上报到 Sentry 等监控平台。

* **Q: Vue优化实践**
  A: Vue2 性能优化：1）`v-if` vs `v-show`（频繁切换用 show，条件稳定用 if）；2）`v-for` 必加 key，避免与 `v-if` 同用；3）大数据用 `Object.freeze` 冻结，避免响应式劫持开销；4）函数式组件减少实例化成本；5）`keep-alive` 缓存组件；6）异步组件和路由懒加载；7）`computed` 缓存计算结果；8）虚拟滚动处理长列表；9）事件委托减少监听数量；10）`v-once` 标记静态内容。注意：优化应基于性能数据，不要过早优化。

### Vue3
* **Q: vue3对vue2优势**
  A: Vue3 主要优势：1）Proxy 响应式：支持新增/删除属性、数组索引和长度变化监听；2）Composition API：按功能组织代码，解决 Options API 逻辑分散问题；3）性能提升：更小的打包体积、更快的初次渲染和更新；4）Tree-shaking：未使用的 API 不会打包；5）TypeScript 重写，类型支持更好；6）新增 Fragment、Teleport、Suspense 等内置组件；7）PatchFlag 编译优化；8）更好的 SSR 性能。实际应用：新项目优先 Vue3；旧项目可渐进升级或在新模块使用 Composition API。

* **Q: 生命周期区别**
  A: Vue3 生命周期与 Vue2 对应：`beforeCreate/created` 合并为 `setup()`；`beforeMount → onBeforeMount`；`mounted → onMounted`；`beforeUpdate → onBeforeUpdate`；`updated → onUpdated`；`beforeDestroy → onBeforeUnmount`；`destroyed → onUnmounted`。新增 `onRenderTracked` 和 `onRenderTriggered` 用于调试依赖追踪。原因：`setup` 在实例创建之初执行，已能完成 beforeCreate/created 的工作；unmounted 命名比 destroyed 更准确。注意：所有组合式生命周期必须在 `setup` 中调用。

* **Q: Composition API与Options API理解**
  A: Options API 按 `data`、`methods`、`computed`、`watch` 等选项组织代码，简单组件清晰，但复杂组件中同一功能逻辑被拆散。Composition API 在 `setup` 中按功能聚合逻辑，使用 `ref/reactive` 定义状态、`computed` 派生状态、`watch/watchEffect` 处理副作用。原因：提升代码可维护性和逻辑复用能力。实际应用：复杂组件、逻辑复用场景优先 Composition API；简单组件仍可用 Options API，两者可混用。

* **Q: ref使用**
  A: `ref` 接收一个值并返回响应式对象，通过 `.value` 访问和修改。基本类型被包装为对象后具备响应式能力，对象类型内部会调用 `reactive`。模板中 ref 会自动解包，无需 `.value`；但在 `setup`、`computed`、事件回调中需要 `.value`。实际应用：1）定义响应式基本类型；2）获取 DOM 引用 `<div ref="box">`；3）获取组件引用（需子组件 `defineExpose` 暴露）。注意：不要对解构后的 `ref` 对象直接赋值，会丢失响应式。

* **Q: toRef/toRefs使用**
  A: `toRef(reactiveObj, 'key')` 基于响应式对象的某个属性创建 ref，并保持与原属性的双向响应式连接；`toRefs(reactiveObj)` 将对象所有属性转为 ref，返回普通对象。原因：`reactive` 对象直接解构会丢失响应式，因为解构得到的是普通值。实际应用：在组合式函数中返回响应式状态时，常用 `toRefs` 包装后让调用方可以解构而不丢失响应式。注意：`toRef` 访问的属性即使原对象中不存在，也会建立响应式连接。

* **Q: 为何需要ref/toRef/toRefs**
  A: 根本原因是 JS 中基本类型按值传递，无法直接建立引用关系来实现响应式。`ref` 通过把基本类型包装成 `{ value: ... }` 对象实现响应式；`toRefs` 解决 `reactive` 对象解构后响应式丢失的问题；`toRef` 则针对单个属性。三者共同保证响应式数据在函数传参、解构、返回过程中连接不中断。实际应用：组合式函数返回多个响应式值时，返回 `toRefs(state)` 让调用方方便解构。

* **Q: vue3重要功能升级**
  A: Vue3 重要升级：1）Proxy 响应式；2）Composition API；3）Teleport（将组件渲染到任意 DOM 节点，常用于模态框）；4）Suspense（等待异步依赖加载状态）；5）Fragments（多根节点组件）；6）`emits` 选项显式声明事件；7）自定义指令钩子与组件生命周期对齐；8）`v-model` 支持多个绑定和自定义修饰符；9）`defineAsyncComponent` 异步组件；10）全局 API tree-shaking。实际应用：Teleport 解决模态框 z-index 和嵌套限制问题；Suspense 简化异步组件加载态。

* **Q: Composition API逻辑复用**
  A: Composition API 通过自定义 Composable 函数（以 `use` 开头）实现逻辑复用。一个 Composable 内部可使用 `ref/reactive/computed/watch` 等，最后返回暴露的状态和方法。原因：替代 Vue2 的 mixins，避免命名冲突、来源不明、隐式依赖等问题。实际应用：`useMouse`、`useFetch`、`useLocalStorage` 等。注意：Composable 应只暴露必要状态，保持单一职责；可在 Composable 内部调用其他 Composable。

* **Q: Vue3响应式实现**
  A: Vue3 响应式基于 `Proxy` 和 `Reflect`。`reactive` 使用 Proxy 拦截对象的 `get/set/deleteProperty/has/ownKeys` 等操作：`get` 时调用 `track` 收集依赖，`set` 时调用 `trigger` 触发更新。依赖存储结构为 `WeakMap<target, Map<key, Set<effect>>>`。`ref` 对基本类型创建 `{ value }` 对象并用 reactive 处理或单独实现 RefImpl。`effect` 是最底层副作用单元，`watchEffect` 和 `computed` 都基于它。原因：Proxy 可代理整个对象而非逐个属性，天然支持新增属性、数组索引和嵌套对象。

* **Q: Proxy基本使用**
  A: `Proxy` 是 ES6 元编程特性，语法 `new Proxy(target, handler)`，用于拦截对象基本操作。常用 trap：`get`（读取）、`set`（设置）、`deleteProperty`（删除）、`has`（`in` 操作符）、`ownKeys`（`Object.keys`/`for...in`）、`apply`（函数调用）、`construct`（`new`）。`Reflect` 是与 Proxy 配套的 API，在 trap 中调用 `Reflect.xxx` 可保持默认行为并正确传递 `receiver`。原因：Proxy 提供统一且强大的对象行为自定义能力。实际应用：响应式系统、数据校验、默认值、私有属性保护。

* **Q: vue3用Proxy实现响应式**
  A: 核心思路：
  ```javascript
  function reactive(target) {
    return new Proxy(target, {
      get(target, key, receiver) {
        track(target, key);
        const res = Reflect.get(target, key, receiver);
        return isObject(res) ? reactive(res) : res;
      },
      set(target, key, value, receiver) {
        const res = Reflect.set(target, key, value, receiver);
        trigger(target, key);
        return res;
      },
      deleteProperty(target, key) {
        const res = Reflect.deleteProperty(target, key);
        trigger(target, key);
        return res;
      }
    });
  }
  ```
  `track` 将当前 `activeEffect` 存入 WeakMap；`trigger` 从 WeakMap 中取出所有 effect 执行。优势：无需递归初始化，只在 `get` 时惰性代理深层对象；新增/删除属性自动响应。

* **Q: v-model参数用法**
  A: Vue3 中 `v-model` 默认展开为 `modelValue` prop 和 `update:modelValue` 事件。支持多个 `v-model`：`<Child v-model:title="title" v-model:content="content" />`，分别对应 `title/update:title`、`content/update:content`。支持自定义修饰符：`v-model.capitalize` 会在 props 中传入 `modelModifiers`。原因：统一并扩展了 Vue2 的 `v-model` 和 `.sync`。实际应用：封装表单组件、可折叠面板等双向绑定场景。

* **Q: watch与watchEffect区别**
  A: `watch` 是惰性的，需显式指定监听源，只在源变化时执行回调，可获取旧值和新值；`watchEffect` 自动追踪回调中用到的所有响应式依赖，立即执行一次，依赖变化时重新执行。原因：`watch` 适合需要精确控制和对比新旧值的场景，`watchEffect` 适合自动收集依赖的简单副作用。实际应用：监听路由参数变化用 `watch`；根据多个状态同步更新 localStorage 用 `watchEffect`。注意：`watchEffect` 拿不到旧值，可通过 `watch` 或手动保存旧值实现。

* **Q: setup中获取实例**
  A: Vue3 中可通过 `getCurrentInstance()` 获取当前组件实例，返回对象包含 `props`、`slots`、`emit`、`proxy` 等。更推荐的方式是直接使用 `setup(props, { attrs, slots, emit })` 解构出 `attrs/slots/emit`。子组件实例可通过 `ref` 获取（需子组件 `defineExpose` 暴露）。原因：`getCurrentInstance` 是内部 API，官方不建议在业务代码中依赖。实际应用：需要访问全局属性或内部方法时临时使用，常规通信用 props/emit。

* **Q: Vue3更快原因**
  A: Vue3 更快的原因：1）Proxy 响应式惰性初始化，无需递归劫持所有属性；2）PatchFlag 编译时标记动态节点，diff 只对比变化部分；3）HoistStatic 将静态节点提升到 render 函数外复用；4）CacheHandler 缓存内联事件函数引用；5）Tree-shaking 减少打包体积；6）Fragment 减少无意义包裹元素；7）更高效的组件初始化。实际应用：复杂列表、大型表单、频繁更新的场景性能提升明显。

* **Q: PatchFlag**
  A: PatchFlag 是 Vue3 编译优化标志，编译器会分析模板中每个动态节点的具体类型，生成位掩码。常见值：`TEXT(1)`、`CLASS(2)`、`STYLE(4)`、`PROPS(8)`、`FULL_PROPS(16)` 等。diff 时通过位运算快速判断节点哪些部分需要对比，只更新变化部分。原因：避免对静态节点和未变化属性做无意义比较。实际应用：开发者通常无需手动处理，由编译器自动生成的优化代码生效。

* **Q: HoistStatic与CacheHandler**
  A: HoistStatic（静态提升）将模板中无绑定的静态节点创建逻辑提升到 render 函数外部，模块作用域内只创建一次，后续渲染复用。CacheHandler（事件缓存）缓存模板中的内联事件处理函数引用，避免每次渲染生成新函数导致子组件不必要的更新。原因：减少对象创建和引用变化带来的 diff 开销。实际应用：这两个优化由编译器自动完成，在大量静态内容或内联事件的组件中效果更明显。

* **Q: SSR与Tree-shaking优化**
  A: Vue3 SSR 优化：编译时将静态内容直接输出为字符串，减少 vnode 创建；水化时只对动态节点激活。Tree-shaking：Vue3 核心库使用 ESM 编写，未使用的全局 API（如 `nextTick`、`keep-alive`、`transition`）不会被打包。实际应用：配合 Vite 或 Webpack 的 `sideEffects` 配置可获得更小的产物；SSR 场景使用 `@vue/server-renderer` 提升首屏性能。

* **Q: Vite启动快的原因**
  A: Vite 开发模式利用浏览器原生 ESM，避免传统打包器全量打包。启动快的原因：1）依赖预构建使用 esbuild（Go 编写，比 JS 打包器快 10-100 倍）；2）源码按需编译，浏览器请求哪个模块就编译哪个；3）利用浏览器原生模块加载，无需打包整个应用；4）HMR 只更新变更模块；5）生产模式用 Rollup 打包。实际应用：大型项目开发体验提升明显，冷启动和热更新速度受项目规模影响小。

* **Q: Composition API与React Hooks对比**
  A: 相似点：都支持在函数中组织状态和副作用，实现逻辑复用。关键区别：1）React Hooks 有严格调用顺序要求（不能放在条件/循环中），依赖数组需手动维护；Composition API 无调用顺序限制，依赖自动追踪。2）React Hooks 每次渲染重新执行，闭包陷阱常见；Vue `setup` 只执行一次，响应式系统管理更新。3）React 需要 `useMemo/useCallback` 手动缓存；Vue 响应式自动处理依赖。原因：Vue 基于可变响应式数据，React 基于不可变数据 + 显式依赖。实际应用：根据团队技术栈选择。

### React
* **Q: JSX本质**
  A: JSX 是 JavaScript 语法扩展，本质是 `React.createElement(type, props, ...children)` 的语法糖。Babel 将 JSX 编译为 `React.createElement` 调用，返回 React Element（即 vnode）。React 17+ 引入新 JSX Transform，可直接调用 `jsx()` 函数而无需显式 `import React`。原因：JSX 让 UI 结构与逻辑写在一起，提升可读性，同时保持 JS 完整表达能力。实际应用：花括号 `{}` 中可写任意 JS 表达式，但不能写语句。

* **Q: 合成事件机制**
  A: React 合成事件（SyntheticEvent）是对原生事件的跨浏览器封装。核心机制：1）事件委托：React 17+ 在 root 容器统一监听，17 之前在 document；2）事件对象复用：React 16 使用事件池，事件回调结束后属性被清空，异步访问需 `e.persist()`，React 17 已移除事件池；3）抹平浏览器差异。原因：统一 API、减少内存占用、提升性能。注意：合成事件 `e.stopPropagation()` 不能阻止原生事件冒泡，两者独立；如需访问原生事件用 `e.nativeEvent`。

* **Q: setState与batchUpdate机制**
  A: `setState` 的同步/异步由批量更新（batching）机制决定。React 17 中，生命周期和合成事件内多个 `setState` 会被合并为一次更新；在 `setTimeout`、原生事件、Promise 回调中则是同步逐个执行。React 18 引入自动批处理（Automatic Batching），几乎所有场景下都会合并更新。原因：批处理减少渲染次数，提升性能。实际应用：需要基于旧状态更新时用函数式 `setState(prev => ...)`；React 18 中可用 `flushSync` 强制同步更新。

* **Q: jsx转vnode与render函数**
  A: JSX 经 Babel 编译为 `React.createElement`，返回 React Element `{ type, props, key, ref, $$typeof }`。函数组件或类组件的 `render` 方法执行时生成整棵 vnode 树，React Reconciler 对比新旧 vnode 树找出差异，再 commit 到真实 DOM。原因：Element 是不可变描述对象，让 React 能在不操作 DOM 的情况下计算最小变更。注意：React 17+ 新 JSX Transform 不再需要 `import React`。

* **Q: 虚拟DOM是否快**
  A: 虚拟 DOM 不是绝对比原生 DOM 操作快。它的核心价值是声明式编程：开发者描述 UI 状态，React 负责高效映射到 DOM。优势：1）跨平台（React Native）；2）批量最小化 DOM 操作；3）diff 复用节点；4）抽象 DOM 操作细节。原因：手动优化原生 DOM 在简单场景下可能更快，但复杂应用中人难以持续写出最优更新逻辑。实际应用：极高频动画场景可考虑 Canvas/WebGL 或直接操作 DOM；普通应用使用虚拟 DOM 即可。

* **Q: react组件渲染过程**
  A: React 渲染分三阶段：1）Trigger：state/props/forceUpdate 触发；2）Render：生成 vnode 树，执行 diff，计算 effects；3）Commit：将 effects 应用到真实 DOM。React 16+ 的 Fiber 架构将渲染拆分为可中断的工作单元，支持优先级调度。`useEffect` 在 commit 后异步执行，`useLayoutEffect` 在 commit 后同步执行。原因：Fiber 让高优先级更新（用户输入）可打断低优先级渲染，避免卡顿。注意：避免在 render 阶段产生副作用。

* **Q: setState经典面试题**
  A: 经典示例：同一事件内连续 `this.setState({ count: this.state.count + 1 })` 两次，结果只加 1，因为两次合并为一次，后一次覆盖前一次；若改为函数式 `this.setState(prev => ({ count: prev.count + 1 }))` 两次，则加 2。`setState` 后立刻读取 `this.state` 拿不到最新值，可在 `setState` 回调或 `componentDidUpdate` 中获取。React 18 自动批处理让 `setTimeout` 中多次 setState 也合并。原因：对象式 setState 是浅合并，函数式基于最新状态更新。

* **Q: useEffect闭包陷阱**
  A: `useEffect` 回调在创建时捕获了当前渲染的 state/props，后续即使 state 更新，未重新创建的 effect 仍使用旧值。示例：
  ```javascript
  useEffect(() => {
    const id = setInterval(() => setCount(count + 1), 1000);
    return () => clearInterval(id);
  }, []);
  ```
  这里 `count` 永远是初始值。解决方案：1）依赖数组加入 `count`（但会重置定时器）；2）函数式更新 `setCount(c => c + 1)`；3）用 `useRef` 保存最新值；4）使用 `useReducer`。原因：函数组件每次渲染都是独立闭包。实际应用：依赖数组必须完整，遇到“旧值”问题优先函数式更新。

* **Q: Vue与React diff算法区别**
  A: Vue2 diff 是双端比较：新旧子节点从两端向中间遍历，优先头头、尾尾、头尾、尾头匹配，再用 key 查找。React diff 是单端：从左到右遍历，找到第一个不同 key 的节点后处理剩余节点，通过 key 判断复用和移动。原因：两种策略针对不同列表操作优化，Vue 在头部/尾部插入删除更优，React 在尾部追加更优。实际应用：两者都需使用稳定 key，避免用 index。Vue3 引入 PatchFlag 进一步优化。

* **Q: 统一监听React报错**
  A: React 统一错误处理：1）Error Boundary：class 组件实现 `static getDerivedStateFromError` 和 `componentDidCatch`，捕获子组件渲染/生命周期/构造函数错误，不能捕获事件和异步错误；2）`window.onerror`：兜底运行时错误；3）`unhandledrejection`：兜底未处理 Promise 拒绝。原因：不同来源错误需分层处理。实际应用：Error Boundary 包裹路由或关键模块，配合全局监听上报到监控服务。

* **Q: React优化实践**
  A: React 性能优化：1）`React.memo` 避免不必要重渲染；2）`useMemo` 缓存昂贵计算；3）`useCallback` 缓存函数引用；4）避免 render 中创建新对象/函数；5）列表使用稳定 key；6）长列表虚拟滚动（react-window）；7）`React.lazy + Suspense` 代码分割；8）Context 按需拆分；9）`useRef` 保存不触发渲染的值；10）React 18 `startTransition`/`useDeferredValue` 标记非紧急更新。注意：不要滥用 memo/useMemo，它们本身也有开销。

* **Q: React真题**
  A: 高频考点补充：1）受控组件 vs 非受控组件；2）HOC / Render Props / Hooks 逻辑复用对比；3）Fiber 架构与并发模式；4）React 18 新特性；5）key 的作用；6）状态管理选型；7）SSR/CSR 对比；8）Redux 中间件原理；9）Immutable 数据在 React 中的应用。实际应用：面试中应结合项目经验回答，避免只背概念。

* **Q: React与Vue区别**
  A: 核心区别：1）设计哲学：React 偏向函数式/不可变数据/单向数据流；Vue 偏向声明式响应式/可变数据；2）模板：React 用 JSX，Vue 用模板指令；3）更新机制：React setState 触发重新渲染后由 diff 决定更新，Vue 响应式精确追踪依赖自动更新；4）状态管理：React 需第三方库，Vue 有官方 Vuex/Pinia；5）学习曲线：Vue 上手快，React 生态更灵活。原因：两者设计取舍不同，没有绝对优劣，适合不同团队和场景。

### React Hooks
* **Q: class组件问题**
  A: class 组件存在的问题：1）相关逻辑分散在不同生命周期中；2）`this` 绑定繁琐；3）逻辑复用依赖 HOC 导致嵌套地狱；4）render props 导致嵌套和闭包问题；5）压缩后体积较大；6）TypeScript 泛型较复杂。Hooks 解决了这些问题，让函数组件拥有状态和副作用能力，逻辑可按功能组织。

* **Q: useState实现state/setState**
  A: `useState(initialValue)` 返回 `[state, setState]`。`setState` 可接收新值或函数式更新 `prev => next`。与 class `setState` 不同，函数组件的 `setState` 是替换而非合并。每次渲染 state 是快照，函数式更新可基于最新状态。原因：函数组件没有实例，React 用链表按调用顺序保存 Hook 状态。注意：惰性初始化用 `useState(() => expensive())`；相同值（Object.is）不会触发重渲染。

* **Q: useEffect模拟生命周期**
  A: `useEffect(() => {}, [])` 模拟 `componentDidMount`；`useEffect(() => {})` 模拟 `componentDidUpdate`；`useEffect(() => { return () => {} }, [])` 的返回函数模拟 `componentWillUnmount`。但 useEffect 语义是“与状态同步的副作用”，不是生命周期。依赖数组决定 effect 何时重新执行。注意：没有依赖数组时每次渲染后都执行；依赖为空只在挂载和卸载时执行清理。

* **Q: useEffect模拟WillUnmount注意事项**
  A: 清理函数不仅在卸载时执行，在每次 effect 重新执行前也会执行，用于清理上一次 effect。因此不要在清理函数中假设只在卸载时执行。常见清理：清除定时器、取消订阅、取消网络请求（`AbortController`）。注意：清理函数中访问的 state/props 也是创建时的闭包值；React 18 Strict Mode 会故意双重调用 effect 和清理函数以检测副作用。

* **Q: useRef与useContext**
  A: `useRef` 返回可变对象，`.current` 改变不会触发重渲染，常用于访问 DOM、保存定时器 ID、缓存上一次的值。`useContext` 接收 Context 对象，返回当前 context 值，值变化时组件重渲染。原因：`useRef` 提供不引起渲染的持久化引用；`useContext` 提供跨层级数据共享。注意：不要在 render 期间修改 ref.current；context 值变化会导致所有消费组件重渲染，应合理拆分 context。

* **Q: useReducer能否代替redux**
  A: `useReducer + useContext` 可在中小型应用中实现类似 Redux 的状态管理，但不能完全替代 Redux。缺少：1）Redux DevTools；2）中间件机制；3）时间旅行调试；4）性能优化（context 默认全量更新）；5）标准化 action/reducer 规范。原因：`useReducer` 适合局部或跨几层组件的状态，Redux 适合复杂全局状态。实际应用：中小型项目可用 Zustand/Jotai/Recoil 替代 Redux。

* **Q: useMemo性能优化**
  A: `useMemo(() => compute(a, b), [a, b])` 缓存计算结果，依赖不变时返回缓存。使用场景：1）避免昂贵计算重复执行；2）缓存对象/数组保持引用稳定，配合 `React.memo`；3）避免 effect 因引用变化被触发。注意：简单计算不必用 useMemo，缓存本身有开销；不要把 useMemo 当作语义保证，React 可能在某些情况下丢弃缓存。

* **Q: useCallback性能优化**
  A: `useCallback(fn, deps)` 缓存函数引用，等价于 `useMemo(() => fn, deps)`。主要用于：1）将函数作为 prop 传给 `React.memo` 子组件；2）函数作为 effect 依赖；3）保持事件处理函数引用稳定。注意：不要对所有函数使用 useCallback；只有子组件使用了 memo 或函数作为 effect 依赖时才需要；配合 useMemo 缓存传入的对象效果更好。

* **Q: 自定义Hook定义**
  A: 自定义 Hook 是以 `use` 开头、内部调用其他 Hook 的函数，用于抽取和复用组件逻辑。规则：1）必须在顶层调用 Hook；2）只能在函数组件或自定义 Hook 中调用 Hook；3）可接收参数、返回任意值。示例：
  ```javascript
  function useWindowSize() {
    const [size, setSize] = useState({ width: window.innerWidth, height: window.innerHeight });
    useEffect(() => {
      const handler = () => setSize({ width: window.innerWidth, height: window.innerHeight });
      window.addEventListener('resize', handler);
      return () => window.removeEventListener('resize', handler);
    }, []);
    return size;
  }
  ```

* **Q: Hooks两条规则**
  A: 1）只在顶层调用 Hooks，不要在条件、循环、嵌套函数中调用；2）只在函数组件或自定义 Hook 中调用 Hooks。原因：React 通过 Hooks 调用顺序在 Fiber 链表上维护状态，条件调用会破坏顺序对应关系，导致状态错乱。ESLint 插件 `eslint-plugin-react-hooks` 可自动检查。

* **Q: Hooks依赖调用顺序原因**
  A: React 在 Fiber 节点上用单向链表 `memoizedState` 保存所有 Hook 状态。首次渲染按调用顺序创建节点，后续渲染按相同顺序读取。若条件调用导致某个 Hook 被跳过，后续 Hook 会读到错误位置的状态。原因：顺序索引是 O(1) 高性能方案，使用 key 或 Map 会增加复杂度和内存。

* **Q: class逻辑复用问题**
  A: class 组件复用逻辑的 HOC 和 Render Props 都有问题。HOC：Wrapper Hell、命名冲突、来源不明、静态方法丢失；Render Props：嵌套地狱、闭包陷阱、render 中创建函数导致浅比较失效。Hooks 通过自定义 Hook 以函数组合方式复用逻辑，避免嵌套和命名冲突。

* **Q: Hooks逻辑复用好处**
  A: 好处：1）无嵌套，避免 Wrapper Hell；2）来源清晰；3）无命名冲突，可重命名；4）可组合嵌套；5）细粒度控制；6）TypeScript 类型友好；7）Tree-shaking 友好。实际应用：将数据请求、窗口尺寸、本地存储等逻辑封装为自定义 Hook。

* **Q: Hooks使用注意事项**
  A: 注意事项：1）遵守 Hooks 规则；2）依赖数组完整；3）避免过早优化；4）用函数式更新避免闭包陷阱；5）`useEffect` 不要用 async 函数（返回 Promise 而非清理函数）；6）避免 effect 依赖中设置会引起循环更新的状态；7）一个 effect 只做一件事；8）共享状态考虑提升或使用状态管理库。

### Webpack
* **Q: hash/chunkhash/contenthash区别**
  A: `hash`：每次构建生成唯一 hash，所有文件共用，一个文件变化导致所有缓存失效；`chunkhash`：基于入口 chunk 生成，同一 chunk 内文件共享；`contenthash`：基于文件内容生成，常用于 CSS。原因：粒度越细，缓存越长效。实际应用：JS 用 `chunkhash`，CSS 用 `contenthash`；同时提取 `runtimeChunk` 避免业务代码变化影响 vendor hash。

* **Q: 常用插件总结**
  A: 常用插件：1）`HtmlWebpackPlugin` 生成 HTML 并注入资源；2）`MiniCssExtractPlugin` 提取 CSS；3）`CssMinimizerPlugin` 压缩 CSS；4）`TerserPlugin` 压缩 JS（webpack5 内置）；5）`DefinePlugin` 注入全局常量；6）`CopyWebpackPlugin` 复制静态资源；7）`CleanWebpackPlugin` 清理输出目录（webpack5 可用 `output.clean`）；8）`SplitChunksPlugin` 代码分割；9）`BundleAnalyzerPlugin` 分析体积；10）`IgnorePlugin` 忽略模块（如 moment 语言包）。

* **Q: 热更新原理**
  A: HMR 流程：1）webpack 监听文件变化重新编译；2）通过 WebSocket 将更新 hash 推送到浏览器；3）浏览器请求更新模块的 JS；4）HMR runtime 对比模块并执行 `module.hot.accept` 回调；5）React/Vue 等框架的 loader 在 accept 回调中重新渲染组件。原因：开发时无需刷新页面即可看到修改结果，保留应用状态。注意：HMR 只替换 accept 的模块，若未 accept 会回退到整页刷新。

* **Q: webpack原理简述**
  A: Webpack 是模块打包器，核心流程：1）初始化配置与插件；2）从 entry 递归解析依赖，调用 Loader 转换非 JS 资源；3）构建 Module 和 Dependency Graph；4）Seal 阶段将模块组织为 Chunk 并优化；5）Emit 阶段输出文件。核心概念：Entry、Output、Loader、Plugin、Module、Chunk。原因：将浏览器不能直接加载的资源（CSS、图片、TS 等）转换为可运行的 bundle。

* **Q: 构建速度优化**
  A: 优化策略：1）升级 webpack/Node；2）Loader 用 `include/exclude` 缩小范围，开启缓存；3）多进程：`thread-loader`、Terser 并行；4）解析优化：`resolve.alias`、`extensions`、`modules`；5）webpack5 持久化缓存；6）减少文件搜索；7）`webpack-bundle-analyzer` 分析；8）开发环境用轻量 source-map。实际应用：CI 构建重点关注缓存命中和 loader 范围。

* **Q: 产出代码优化**
  A: 产出优化：1）代码分割 SplitChunks；2）路由懒加载 `import()`；3）Tree-shaking 删除死代码；4）Terser/CssMinimizer 压缩；5）scope hoisting 减少闭包；6）合理使用 `chunkhash/contenthash`；7）图片压缩和转 WebP；8）分离 CSS；9）按需加载 polyfill。注意：Tree-shaking 依赖 ESM 和正确的 `sideEffects` 配置。

### HTTP
* **Q: HTTP基础总结**
  A: HTTP 是基于 TCP/IP 的应用层协议，默认端口 80。特点：无状态、请求-响应模式。HTTP/1.1 默认持久连接（keep-alive）。常用方法：GET、POST、PUT、DELETE、PATCH、HEAD、OPTIONS。状态码：1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务器错误。原因：无状态设计简化服务器实现，通过 Cookie/Token 维持会话。

* **Q: HTTP缓存**
  A: HTTP 缓存分强缓存和协商缓存。强缓存由 `Cache-Control`/`Expires` 控制，命中时直接读本地缓存；协商缓存由 `Last-Modified/If-Modified-Since` 或 `ETag/If-None-Match` 控制，命中返回 304。缓存位置优先级：Service Worker > Memory Cache > Disk Cache > Push Cache。实际应用：静态资源长期强缓存 + 文件名 hash；HTML 使用协商缓存或短缓存。

* **Q: HTTP 1.0/1.1/2.0区别**
  A: HTTP/1.0 默认短连接；HTTP/1.1 默认 keep-alive、支持 Pipeline（仍有队头阻塞）、Host 头、分块传输、断点续传；HTTP/2 二进制分帧、多路复用、头部压缩 HPACK、服务器推送、请求优先级。HTTP/2 仍有 TCP 层队头阻塞，HTTP/3 基于 QUIC/UDP 解决。实际应用：现代服务优先 HTTP/2 或 HTTP/3。

* **Q: WebSocket与HTTP区别**
  A: WebSocket 是全双工通信协议，通过 HTTP Upgrade 握手建立长连接；HTTP 是请求-响应模式。WebSocket 数据帧轻量，服务端可主动推送。原因：HTTP 半双工不适合实时场景。应用：聊天、游戏、股票行情、协同编辑。注意：WebSocket 需处理断线重连和心跳。

* **Q: TCP三次握手四次挥手**
  A: 三次握手：SYN → SYN+ACK → ACK，确保双方收发能力正常并同步序列号。四次挥手：FIN → ACK → FIN → ACK，主动方最后进入 TIME_WAIT（2MSL）确保被动方收到最后的 ACK。原因：握手三次是防止历史连接初始化；挥手四次是因为被动方可能还有数据要发。实际应用：大量短连接会导致 TIME_WAIT 堆积，可调整内核参数或使用连接池。

* **Q: 跨域时发送options请求原因**
  A: 非简单请求（PUT/DELETE、自定义头、Content-Type 为 application/json 等）会先发送 OPTIONS 预检请求，询问服务器是否允许跨域。响应需包含 `Access-Control-Allow-Methods/Headers/Max-Age`。原因：保护用户安全，避免跨域恶意请求。实际应用：服务端设置 `Max-Age` 缓存预检结果；合并自定义头减少预检次数。

* **Q: token/cookie/session区别**
  A: Cookie 是浏览器存储机制，自动携带到同源请求，4KB 限制；Session 是服务端存储的会话数据，通过 sessionID 关联；Token（如 JWT）是服务端签名的令牌，无状态，服务端不保存会话。区别：Session 有状态，Token 无状态更适合分布式；Cookie 易 CSRF，Token 需防 XSS。实际应用：前后端分离常用 Token + localStorage，传统 Web 用 Session + Cookie。

* **Q: HTTPS中间人攻击及预防**
  A: MITM 攻击方式：伪造证书、SSL 剥离、ARP/DNS 劫持。预防措施：1）严格证书链校验；2）HSTS 强制 HTTPS；3）证书透明度检测异常证书；4）避免连接不可信网络。原因：HTTPS 依赖 PKI 信任链，若证书校验被绕过则加密失效。注意：用户不应忽略浏览器安全警告。

### Node
* **Q: 浏览器与Node事件循环区别**
  A: 两者都是单线程事件循环，但阶段划分不同。浏览器：宏任务 → 微任务 → 渲染。Node（libuv）：timers → pending callbacks → idle/prepare → poll → check → close callbacks，每个阶段后清空微任务，`process.nextTick` 优先级高于 Promise 微任务。Node 11+ 后行为更接近浏览器。原因：Node 需要处理大量 I/O，阶段划分更细致。

* **Q: Node开启多进程及进程通信**
  A: Node 单线程但可通过 `child_process`（spawn/exec/execFile/fork）或 `cluster` 模块利用多核。`cluster` 基于 fork，主进程管理 worker 并负载均衡。进程通信：IPC（send/on('message')）、共享内存、消息队列、Unix socket。原因：多进程不共享内存，适合 CPU 密集型任务。实际应用：Web 服务用 cluster 扩展；CPU 密集计算用 worker_threads 或多进程。

### 手写题
* **Q: 防抖**
  A: 防抖在事件停止触发后延迟执行，期间再次触发则重新计时。适用于搜索输入、窗口 resize 等。
  ```javascript
  function debounce(fn, delay = 300, immediate = false) {
    let timer = null;
    return function (...args) {
      const context = this;
      if (immediate && !timer) fn.apply(context, args);
      clearTimeout(timer);
      timer = setTimeout(() => {
        if (!immediate) fn.apply(context, args);
        timer = null;
      }, delay);
    };
  }
  ```

* **Q: 节流**
  A: 节流在指定时间间隔内只执行一次，适用于滚动、拖拽等高频事件。
  ```javascript
  function throttle(fn, interval = 300, options = { leading: true, trailing: false }) {
    let lastTime = 0;
    let timer = null;
    return function (...args) {
      const context = this;
      const now = Date.now();
      if (!lastTime && !options.leading) lastTime = now;
      const remaining = interval - (now - lastTime);
      if (remaining <= 0) {
        if (timer) { clearTimeout(timer); timer = null; }
        fn.apply(context, args);
        lastTime = now;
      } else if (options.trailing && !timer) {
        timer = setTimeout(() => {
          fn.apply(context, args);
          lastTime = options.leading ? Date.now() : 0;
          timer = null;
        }, remaining);
      }
    };
  }
  ```

* **Q: New的过程**
  A: `new` 操作符创建空对象，绑定原型，执行构造函数并绑定 this，最后返回对象或构造函数的显式返回值。
  ```javascript
  function myNew(Constructor, ...args) {
    const obj = Object.create(Constructor.prototype);
    const result = Constructor.apply(obj, args);
    return (result !== null && (typeof result === 'object' || typeof result === 'function')) ? result : obj;
  }
  ```

* **Q: instanceOf原理**
  A: `instanceof` 检查构造函数的 `prototype` 是否出现在对象的原型链上。
  ```javascript
  function myInstanceOf(obj, Constructor) {
    if (typeof obj !== 'object' || obj === null) return false;
    let proto = Object.getPrototypeOf(obj);
    const prototype = Constructor.prototype;
    while (proto !== null) {
      if (proto === prototype) return true;
      proto = Object.getPrototypeOf(proto);
    }
    return false;
  }
  ```

* **Q: 实现call、apply、bind方法**
  A: 三者都用于改变函数执行上下文。call/apply 立即执行，bind 返回新函数。
  ```javascript
  Function.prototype.myCall = function (context = window, ...args) {
    const key = Symbol('fn');
    context[key] = this;
    const result = context[key](...args);
    delete context[key];
    return result;
  };
  Function.prototype.myApply = function (context = window, args = []) {
    return this.myCall(context, ...args);
  };
  Function.prototype.myBind = function (context = window, ...bindArgs) {
    const fn = this;
    return function (...callArgs) {
      return fn.apply(context, [...bindArgs, ...callArgs]);
    };
  };
  ```

* **Q: 发布订阅模式**
  A: 发布订阅模式解耦发布者和订阅者，通过事件中心中转消息。
  ```javascript
  class EventEmitter {
    constructor() { this.events = {}; }
    on(event, listener) {
      if (!this.events[event]) this.events[event] = [];
      this.events[event].push(listener);
      return () => this.off(event, listener);
    }
    off(event, listener) {
      if (!this.events[event]) return;
      this.events[event] = this.events[event].filter(l => l !== listener);
    }
    emit(event, ...args) {
      if (!this.events[event]) return;
      this.events[event].forEach(l => l(...args));
    }
    once(event, listener) {
      const wrapper = (...args) => { listener(...args); this.off(event, wrapper); };
      this.on(event, wrapper);
    }
  }
  ```

* **Q: 深拷贝（含数据类型与循环引用）**
  A: 深拷贝需处理 Date、RegExp、循环引用等特殊情况，使用 WeakMap 记录已拷贝对象。
  ```javascript
  function deepClone(obj, map = new WeakMap()) {
    if (obj === null || typeof obj !== 'object') return obj;
    if (obj instanceof Date) return new Date(obj);
    if (obj instanceof RegExp) return new RegExp(obj);
    if (map.has(obj)) return map.get(obj);
    const clone = Array.isArray(obj) ? [] : {};
    map.set(obj, clone);
    Reflect.ownKeys(obj).forEach(key => {
      clone[key] = deepClone(obj[key], map);
    });
    return clone;
  }
  ```

* **Q: LRU缓存实现**
  A: LRU（最近最少使用）缓存，可用 Map 保持插入顺序实现 O(1) 读写。
  ```javascript
  class LRUCache {
    constructor(capacity) {
      this.capacity = capacity;
      this.cache = new Map();
    }
    get(key) {
      if (!this.cache.has(key)) return -1;
      const value = this.cache.get(key);
      this.cache.delete(key);
      this.cache.set(key, value);
      return value;
    }
    put(key, value) {
      if (this.cache.has(key)) this.cache.delete(key);
      this.cache.set(key, value);
      if (this.cache.size > this.capacity) {
        this.cache.delete(this.cache.keys().next().value);
      }
    }
  }
  ```

* **Q: curry函数（柯里化）**
  A: 柯里化将多参数函数转换为嵌套的一元函数链。
  ```javascript
  function curry(fn) {
    return function curried(...args) {
      if (args.length >= fn.length) {
        return fn.apply(this, args);
      } else {
        return (...more) => curried.apply(this, [...args, ...more]);
      }
    };
  }
  ```

* **Q: LazyMan实现sleep**
  A: LazyMan 通过任务队列和 setTimeout 实现链式调用与延迟执行。
  ```javascript
  class LazyMan {
    constructor(name) {
      this.tasks = [() => { console.log('Hi! This is ' + name); this.next(); }];
      setTimeout(() => this.next(), 0);
    }
    next() {
      const task = this.tasks.shift();
      task && task();
    }
    eat(food) {
      this.tasks.push(() => { console.log('Eat ' + food); this.next(); });
      return this;
    }
    sleep(delay) {
      this.tasks.push(() => {
        setTimeout(() => { console.log('Wake up after ' + delay + 's'); this.next(); }, delay * 1000);
      });
      return this;
    }
    sleepFirst(delay) {
      this.tasks.unshift(() => {
        setTimeout(() => { console.log('Wake up after ' + delay + 's'); this.next(); }, delay * 1000);
      });
      return this;
    }
  }
  function LazyManFactory(name) { return new LazyMan(name); }
  ```

  function getType(value) {
    if (value === null) return 'null';
    if (typeof value !== 'object') return typeof value;

* **Q: Vue3响应式原理实现**
  A: 极简实现：
  ```javascript
  const targetMap = new WeakMap();
  let activeEffect = null;
  function effect(fn) { activeEffect = fn; fn(); activeEffect = null; }
  function track(target, key) {
    if (!activeEffect) return;
    let depsMap = targetMap.get(target);
    if (!depsMap) targetMap.set(target, depsMap = new Map());
    let dep = depsMap.get(key);
    if (!dep) depsMap.set(key, dep = new Set());
    dep.add(activeEffect);
  }
  function trigger(target, key) {
    const depsMap = targetMap.get(target);
    if (!depsMap) return;
    depsMap.get(key)?.forEach(fn => fn());
  }
  function reactive(target) {
    return new Proxy(target, {
      get(target, key, receiver) {
        track(target, key);
        const res = Reflect.get(target, key, receiver);
        return typeof res === 'object' && res !== null ? reactive(res) : res;
      },
      set(target, key, value, receiver) {
        const res = Reflect.set(target, key, value, receiver);
        trigger(target, key);
        return res;
      }
    });
  }
  function ref(value) { return reactive({ value }); }
  ```

* **Q: 简洁版Promise实现**
  A:
  ```javascript
  class MyPromise {
    constructor(executor) {
      this.state = 'pending';
      this.value = undefined;
      this.reason = undefined;
      this.onFulfilledCallbacks = [];
      this.onRejectedCallbacks = [];
      const resolve = (value) => {
        if (this.state !== 'pending') return;
        this.state = 'fulfilled';
        this.value = value;
        this.onFulfilledCallbacks.forEach(fn => fn());
      };
      const reject = (reason) => {
        if (this.state !== 'pending') return;
        this.state = 'rejected';
        this.reason = reason;
        this.onRejectedCallbacks.forEach(fn => fn());
      };
      try { executor(resolve, reject); } catch (e) { reject(e); }
    }
    then(onFulfilled, onRejected) {
      return new MyPromise((resolve, reject) => {
        const handle = (callback, isFulfilled) => {
          try {
            const res = callback ? callback(isFulfilled ? this.value : this.reason) : (isFulfilled ? resolve(this.value) : reject(this.reason));
            resolve(res);
          } catch (e) { reject(e); }
        };
        if (this.state === 'fulfilled') setTimeout(() => handle(onFulfilled, true));
        else if (this.state === 'rejected') setTimeout(() => handle(onRejected, false));
        else {
          this.onFulfilledCallbacks.push(() => setTimeout(() => handle(onFulfilled, true)));
          this.onRejectedCallbacks.push(() => setTimeout(() => handle(onRejected, false)));
        }
      });
    }
    catch(onRejected) { return this.then(null, onRejected); }
  }
  ```

### 算法题
* **Q: 时间复杂度与空间复杂度概念**
  A: 时间复杂度描述算法执行时间随输入规模增长的趋势，用大 O 表示最坏情况；空间复杂度描述额外内存需求。常见时间复杂度：O(1)、O(log n)、O(n)、O(n log n)、O(n²)、O(2ⁿ)。实际应用：分析算法时关注循环层数、递归深度、哈希表等额外空间，在时间与空间之间做权衡。

* **Q: 快速排序实现与复杂度分析**
  A: 快速排序采用分治，选基准将数组分为小于和大于基准两部分，递归排序。
  ```javascript
  function quickSort(arr, left = 0, right = arr.length - 1) {
    if (left >= right) return arr;
    const pivot = partition(arr, left, right);
    quickSort(arr, left, pivot - 1);
    quickSort(arr, pivot + 1, right);
    return arr;
  }
  function partition(arr, left, right) {
    const pivot = arr[right];
    let i = left;
    for (let j = left; j < right; j++) {
      if (arr[j] < pivot) { [arr[i], arr[j]] = [arr[j], arr[i]]; i++; }
    }
    [arr[i], arr[right]] = [arr[right], arr[i]];
    return i;
  }
  ```
  平均时间 O(n log n)，最坏 O(n²)；空间平均 O(log n)，最坏 O(n)。优化：随机选基准、三数取中。

* **Q: 移动数组0到末尾**

* **Q: 二分查找实现与分析**
  A: 在有序数组中查找目标值。
  ```javascript
  function binarySearch(nums, target) {
    let left = 0, right = nums.length - 1;
    while (left <= right) {
      const mid = left + ((right - left) >> 1);
      if (nums[mid] === target) return mid;
      if (nums[mid] < target) left = mid + 1;
      else right = mid - 1;
    }
    return -1;
  }
  ```
  时间 O(log n)，空间 O(1)。注意 `mid` 用 `left + (right-left)/2` 避免溢出。

* **Q: 队列功能实现**
  A: 用两个栈实现队列。
  ```javascript
  class QueueWithTwoStacks {
    constructor() { this.inStack = []; this.outStack = []; }
    enqueue(x) { this.inStack.push(x); }
    dequeue() {
      if (!this.outStack.length) {
        while (this.inStack.length) this.outStack.push(this.inStack.pop());
      }
      return this.outStack.pop();
    }
    peek() {
      if (!this.outStack.length) {
        while (this.inStack.length) this.outStack.push(this.inStack.pop());
      }
      return this.outStack[this.outStack.length - 1];
    }
    isEmpty() { return !this.inStack.length && !this.outStack.length; }
  }
  ```
  均摊时间 O(1)。

* **Q: 括号匹配判断**

  function isValidParentheses(s) {
    const stack = [];
    const map = { ')': '(', ']': '[', '}': '{' };
    for (const char of s) {
      if (!map[char]) {
        stack.push(char);
      } else {
        if (stack.pop() !== map[char]) return false;
      }
    }
    return stack.length === 0;
  }
