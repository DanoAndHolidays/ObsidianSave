##### 实现防抖函数（debounce）
防抖（debounce）的核心思想是：在事件被触发后，延迟等待一段时间再执行回调；如果在这段等待时间内事件又被触发了，则重新计时。这就像电梯门——有人按了关门键后，如果在设定时间内又有人按了，门会重新等待一段时间再关，直到没有人再按才真正执行"关门"动作。

**为什么需要防抖？**

在前端开发中，很多高频事件（如 input 输入、scroll 滚动、resize 窗口大小调整、mousemove 鼠标移动）会在短时间内连续触发大量事件。如果每次触发都立即执行业务逻辑（如发送搜索请求），会造成严重的性能浪费和不必要的服务器压力。防抖就是用来"合并"这些高频触发的，确保在事件停止触发一段时间后才执行一次。

### 核心原理
- 利用闭包保存一个定时器变量（timer）
- 每次函数调用时，先清除上一次的定时器（cancel 上一次的等待）
- 重新设置一个新的定时器，延迟执行真正的回调
- 通过 `immediate` 参数可控制是"前缘触发"（立即执行一次，然后等待冷却）还是"后缘触发"（等事件停止后才执行）

### 应用场景
- 搜索框输入联想：用户停止输入 300ms 后再发送请求
- 窗口 resize：调整窗口大小时避免频繁触发重排重绘
- 按钮提交：防止用户连续点击提交多次表单
- 滚动事件：滚动停止后再执行懒加载等逻辑

### 注意事项
- `immediate` 模式（前缘触发）下，首次触发立即执行，但后续触发需要等待 delay 时间才能再次执行，注意两次执行的最小间隔
- 定时器清除时需要注意 timer 为 null 的情况（clearTimeout(null) 不会报错，但逻辑上要确保一致性）
- 如果函数需要取消，可以在返回的函数上绑定一个 `.cancel()` 方法，方便外部调用 `clearTimeout`
- 严格模式下需要正确处理 this 指向，使用 `fn.apply(context, args)` 保持调用上下文
- 需要注意闭包中 this 的绑定，在箭头函数中 this 继承自外层，在普通函数中需要通过 context 参数传入

**适用场景：** 搜索框输入、窗口resize、按钮点击提交等。

```javascript
/**
 * 防抖函数
 * @param {Function} fn - 需要防抖的函数
 * @param {number} delay - 延迟时间（毫秒）
 * @param {boolean} immediate - 是否立即执行（可选，默认false）
 * @returns {Function} 返回防抖处理后的函数
 */
function debounce(fn, delay, immediate = false) {
  let timer = null;
  
  return function (...args) {
    const context = this;
    
    if (immediate && !timer) {
      // 立即执行：第一次触发时立即执行，然后等待delay时间内不再触发才重置
      fn.apply(context, args);
    }
    
    // 清除上一次的定时器
    if (timer) clearTimeout(timer);
    
    // 设置新的定时器
    timer = setTimeout(() => {
      if (!immediate) {
        fn.apply(context, args);
      }
      timer = null;
    }, delay);
  };
}

// --- 使用示例 ---
// const handleInput = debounce((e) => {
//   console.log('输入内容:', e.target.value);
// }, 300);
// inputEl.addEventListener('input', handleInput);
```

##### 实现节流函数（throttle）
节流（throttle）的核心思想是：在固定时间间隔内，无论事件触发了多少次，函数最多只执行一次。节流是"稀释"执行频率，确保函数以恒定的节奏执行，而不是等事件停止后才执行（那是防抖）。

**为什么需要节流？**

与防抖不同，防抖是"等事件停了再做"，节流是"定时做，中间触发都忽略"。对于滚动加载、拖拽、鼠标移动等持续触发的事件，防抖会导致事件停止前一直不执行，体验不好；而节流可以保证在这些持续事件中，回调以固定频率执行（如每 100ms 执行一次），既减少了执行次数，又保证了实时性。

### 核心原理（三种实现方式）
1. **时间戳版（立即执行）**：记录上次执行时间，每次触发时检查当前时间与上次执行时间的差值，超过间隔才执行。优点是第一次立即执行，缺点是最后一次可能在时间窗口内被"吞掉"（即最后一次触发后如果没到时间就不会执行）。
2. **定时器版（延迟执行）**：首次触发时设置定时器，定时器执行完后才能再次触发。优点是能保证最后一次一定执行，缺点是首次触发有延迟。
3. **完整版（时间戳 + 定时器）**：结合两者优势，时间窗口内先检查时间戳决定是否立即执行，剩余时间小于 0 时立即执行并清除 pending 定时器，否则设置定时器在剩余时间后执行，保证第一次和最后一次都能执行到。

### 应用场景
- 滚动加载：滚动事件中每隔一定时间检查一次是否触底
- 拖拽操作：mousemove 事件中限制回调频率，避免卡顿
- 鼠标移动：搜索框 hover 预览、跟随鼠标的动画等
- 按钮防重复提交：虽然不是最佳选择（防抖更合适），但节流可以限制提交频率
- 游戏/动画的帧率控制：以固定频率更新画面

### 注意事项
- 时间戳版会"丢失"最后一次触发（如果在时间窗口边缘触发，下一次窗口前不会再执行），完整版通过定时器补偿解决这个问题
- 定时器版的 `clearTimeout` 要在执行后置为 null，否则判断条件 `if (!timer)` 不会生效
- 完整版中 `remaining` 时间通过 `Date.now() - lastTime` 计算，注意时间戳的单位是毫秒
- 节流和防抖的选择原则：需要"实时反馈但限频"用节流，需要"合并多次触发为一次"用防抖
- 注意 `this` 指向和参数传递，确保回调函数能正确访问调用上下文

**适用场景：** 滚动加载、拖拽、鼠标移动等。

```javascript
/**
 * 节流函数 - 时间戳版（立即执行）
 * @param {Function} fn - 需要节流的函数
 * @param {number} delay - 间隔时间（毫秒）
 * @returns {Function} 返回节流处理后的函数
 */
function throttle(fn, delay) {
  let lastTime = 0;
  
  return function (...args) {
    const context = this;
    const now = Date.now();
    
    if (now - lastTime >= delay) {
      fn.apply(context, args);
      lastTime = now;
    }
  };
}

/**
 * 节流函数 - 定时器版（延迟执行）
 * @param {Function} fn - 需要节流的函数
 * @param {number} delay - 间隔时间（毫秒）
 * @returns {Function} 返回节流处理后的函数
 */
function throttleTimer(fn, delay) {
  let timer = null;
  
  return function (...args) {
    const context = this;
    
    if (!timer) {
      timer = setTimeout(() => {
        fn.apply(context, args);
        timer = null;
      }, delay);
    }
  };
}

/**
 * 节流函数 - 完整版（结合时间戳和定时器，保证最后一次执行）
 * @param {Function} fn - 需要节流的函数
 * @param {number} delay - 间隔时间（毫秒）
 * @returns {Function} 返回节流处理后的函数
 */
function throttleComplete(fn, delay) {
  let lastTime = 0;
  let timer = null;
  
  return function (...args) {
    const context = this;
    const now = Date.now();
    const remaining = delay - (now - lastTime);
    
    // 如果剩余时间 <= 0，说明可以立即执行
    if (remaining <= 0) {
      if (timer) {
        clearTimeout(timer);
        timer = null;
      }
      fn.apply(context, args);
      lastTime = now;
    } else if (!timer) {
      // 否则设置一个定时器在剩余时间后执行（保证最后一次触发能执行）
      timer = setTimeout(() => {
        fn.apply(context, args);
        lastTime = Date.now();
        timer = null;
      }, remaining);
    }
  };
}
```

##### 实现instanceOf
`instanceof` 运算符用于检测构造函数的 `prototype` 属性是否出现在某个实例对象的原型链上。手动实现可以帮助我们理解 JavaScript 原型链的查找机制。

**为什么需要手动实现？**

在实际开发中，我们通常直接使用 `instanceof`，但理解其内部原理对于掌握原型链至关重要。面试中考察 `instanceof` 手写，主要是看你是否理解"原型链逐层查找"这一核心机制。另外，在某些边界场景下（如跨 iframe 的对象检测），原生的 `instanceof` 可能失效，手动实现可以弥补这一缺陷。

### 核心原理
- 获取实例对象的原型（`Object.getPrototypeOf`）
- 获取构造函数的 `prototype` 属性
- 沿着原型链逐层向上查找（`proto = Object.getPrototypeOf(proto)`）
- 如果找到了匹配的原型，返回 `true`；如果查到了 `null` 仍未找到，返回 `false`
- 基本类型（非 `object`）直接返回 `false`

### 应用场景
- 类型判断：判断一个对象是否属于某个类或其子类的实例
- 多态处理：根据对象类型执行不同的逻辑分支
- 框架内部：某些框架（如 Vue、React）在内部也会用类似机制判断组件类型

### 注意事项
- 基本类型（`null`、数字、字符串等）不能使用 `instanceof`，需要先判断 `typeof instance === 'object'`
- 跨 iframe 的 `instanceof` 会失效，因为不同 iframe 中的 `Array`、`Object` 等构造函数的 `prototype` 是不同的对象
- `Symbol.hasInstance` 可以自定义 `instanceof` 的行为，这是一个高级用法
- `Object.getPrototypeOf` 比 `__proto__` 更标准，推荐使用

```javascript
/**
 * 自定义 instanceof
 * @param {object} instance - 实例对象
 * @param {Function} constructor - 构造函数
 * @returns {boolean}
 */
function myInstanceof(instance, constructor) {
  // 基本类型直接返回 false
  if (typeof instance !== 'object' || instance === null) {
    return false;
  }
  
  // 获取实例的原型（__proto__）
  let proto = Object.getPrototypeOf(instance);
  
  // 获取构造函数的 prototype 对象
  const prototype = constructor.prototype;
  
  // 沿着原型链向上查找
  while (proto !== null) {
    if (proto === prototype) {
      return true;
    }
    proto = Object.getPrototypeOf(proto);
  }
  
  return false;
}

// --- 测试 ---
// console.log(myInstanceof([], Array));      // true
// console.log(myInstanceof({}, Object));     // true
// console.log(myInstanceof(1, Number));      // false（基本类型）
```

##### 实现new的过程
`new` 是 JavaScript 中用于创建实例的关键字。手动模拟 `new` 的过程，可以帮助我们理解构造函数、原型链和实例创建之间的关系。

**为什么需要手动实现？**

面试中考察 `new` 的手写，核心是看你是否理解"构造函数 + 原型链 + 实例"三者之间的关系。在工程实践中，虽然我们不常手动模拟 `new`，但理解其原理有助于掌握 JS 面向对象编程的本质，也能在需要自定义实例创建逻辑时（如依赖注入容器）提供思路。

### 核心原理（四个步骤）
1. 创建一个新对象，并将其原型链指向构造函数的 `prototype`
2. 将构造函数的 `this` 绑定到这个新对象上，并执行构造函数
3. 判断构造函数的返回值：如果返回的是对象（引用类型），则返回该对象；否则返回新创建的对象
4. 使用 `Object.create(constructor.prototype)` 可以高效地完成原型链设置

### 应用场景
- 理解 Vue、React 等框架中组件实例的创建过程
- 自定义实例创建逻辑（如 IoC 容器、工厂模式）
- 面试中考察对 JS 面向对象机制的理解深度

### 注意事项
- `Object.create(null)` 创建的对象没有原型，`Object.create(constructor.prototype)` 创建的对象原型指向 `constructor.prototype`
- 构造函数显式返回对象时，`new` 会忽略新创建的对象，返回构造函数返回的对象
- 构造函数返回原始类型（`string`、`number` 等）时，`new` 仍然返回新创建的对象
- 使用 `Object.create` 比手动设置 `__proto__` 更标准、性能更好

```javascript
/**
 * 模拟实现 new 操作符
 * @param {Function} constructor - 构造函数
 * @param {...any} args - 参数
 * @returns {object} 实例对象
 */
function myNew(constructor, ...args) {
  // 1. 创建一个空对象，并将它的原型指向构造函数的 prototype
  const obj = Object.create(constructor.prototype);
  
  // 2. 将构造函数中的 this 指向这个新对象，并执行构造函数
  const result = constructor.apply(obj, args);
  
  // 3. 如果构造函数返回了对象（引用类型），则返回该对象；否则返回新创建的对象
  return (typeof result === 'object' && result !== null) || typeof result === 'function'
    ? result
    : obj;
}

// --- 测试 ---
// function Person(name, age) {
//   this.name = name;
//   this.age = age;
// }
// const p = myNew(Person, '张三', 18);
// console.log(p.name); // 张三
```

##### 实现call方法
`call` 是 `Function.prototype` 上的方法，用于调用一个函数并指定 `this` 值和参数列表（逐个传入）。手动实现可以帮助我们理解 `this` 绑定和函数调用的本质。

**为什么需要手动实现？**

`call` 是最常用的 `this` 绑定方法之一。理解其实现原理，有助于掌握 JS 中 `this` 的工作机制。在实际开发中，`call` 常用于：借用其他对象的方法、显式指定调用上下文、实现函数式编程中的柯里化等。

### 核心原理
1. 将调用 `call` 的函数（`this`）作为目标对象的属性
2. 执行该属性（即调用函数），传入参数
3. 删除添加的属性，返回执行结果
4. 处理 `null`/`undefined` 时默认绑定到全局对象（浏览器中为 `window`，Node 中为 `globalThis`）
5. 使用 `Symbol` 作为属性键可以避免与对象已有属性冲突

### 应用场景
- 借用数组方法：`Array.prototype.slice.call(arguments)` 将类数组转为数组
- 显式指定上下文：`fn.call(obj, arg1, arg2)`
- 继承调用：`Parent.call(this, ...)` 在子类中调用父类方法
- 柯里化/偏函数应用

### 注意事项
- `globalThis` 是现代 JS 的全局对象引用，比 `window`/`global` 更通用
- `Symbol` 创建的键是唯一的，避免了属性名冲突，比字符串键更安全
- `call` 的参数是逐个传入的（与 `apply` 的数组形式不同）
- 严格模式下，`this` 为 `null`/`undefined` 不会被自动转为全局对象
- 如果被调用的函数返回对象，`call` 会正常返回该结果

```javascript
/**
 * 模拟实现 Function.prototype.call
 * @param {object|null} context - 需要绑定的 this 上下文
 * @param {...any} args - 参数列表
 * @returns {any} 函数执行结果
 */
Function.prototype.myCall = function (context, ...args) {
  // 如果 context 为 null/undefined，则指向全局对象（浏览器中是 window，Node 中是 global）
  context = context ?? globalThis;
  
  // 使用 Symbol 创建唯一键，避免属性名冲突
  const fnKey = Symbol('fn');
  
  // 将当前函数（this）作为 context 的一个属性
  context[fnKey] = this;
  
  // 执行函数并获取结果
  const result = context[fnKey](...args);
  
  // 删除添加的属性
  delete context[fnKey];
  
  return result;
};

// --- 测试 ---
// const obj = { value: 1 };
// function test(a, b) { return this.value + a + b; }
// console.log(test.myCall(obj, 2, 3)); // 6
```

##### 实现apply方法
`apply` 与 `call` 类似，都用于调用函数并指定 `this` 值，区别在于 `apply` 的参数以数组形式传入。理解 `apply` 的实现有助于掌握函数调用和 `this` 绑定的完整图景。

### 核心原理
1. 将调用 `apply` 的函数作为目标对象的属性
2. 使用展开运算符（`...args`）将数组参数逐个传入
3. 处理 `null`/`undefined` 时默认绑定全局对象
4. 删除临时属性，返回结果

### 与 `call` 的区别
- `call`：参数逐个传入 `fn.call(this, a, b, c)`
- `apply`：参数以数组形式传入 `fn.apply(this, [a, b, c])`

### 应用场景
- Math.max/min 求数组最值：`Math.max.apply(null, arr)`
- 合并数组：`Array.prototype.push.apply(arr1, arr2)`
- 函数式编程中的参数传递

### 注意事项
- `apply` 的第二个参数必须是类数组对象或数组，`call` 没有这个限制
- 现代 JS 中，展开运算符 `fn(...args)` 在大多数场景下比 `apply` 更直观
- `apply` 在处理大量参数时性能略优于逐个传入的 `call`
- `null`/`undefined` 的 this 绑定规则与 `call` 相同

```javascript
/**
 * 模拟实现 Function.prototype.apply
 * @param {object|null} context - 需要绑定的 this 上下文
 * @param {Array} args - 参数数组
 * @returns {any} 函数执行结果
 */
Function.prototype.myApply = function (context, args) {
  context = context ?? globalThis;
  
  const fnKey = Symbol('fn');
  context[fnKey] = this;
  
  // args 可能为 null/undefined
  const result = args ? context[fnKey](...args) : context[fnKey]();
  
  delete context[fnKey];
  
  return result;
};
```

##### 实现bind方法
`bind` 方法创建一个新函数，当调用新函数时将其 `this` 值绑定到提供的值，并可预设部分参数。与 `call`/`apply` 不同，`bind` 不会立即执行函数，而是返回一个绑定了 `this` 的新函数。

### 核心原理
1. 保存原始函数引用
2. 返回一个新函数 `boundFn`
3. 在 `boundFn` 中调用原始函数，使用 `apply` 绑定 `this`
4. 支持预设参数（柯里化）：调用时预设参数与传入参数合并 `[...args, ...newArgs]`
5. 支持 `new` 调用：当使用 `new boundFn()` 时，`this` 应指向新创建的实例（即 `new` 的优先级高于 bind）
6. 维护原型链：`boundFn.prototype = Object.create(originalFn.prototype)`，确保 `new` 调用时能正确继承

### 应用场景
- 事件处理函数中指定上下文：`handler.bind(this)`
- 异步回调中保持上下文：`setTimeout(fn.bind(this), 1000)`
- 偏函数/柯里化：预设部分参数生成新函数
- React/Vue 等框架中保持组件上下文

### 注意事项
- `bind` 返回的函数具有 `length` 属性（剩余参数个数），但这是一个高级特性，手动实现可简化
- 使用 `new` 调用 `boundFn` 时，`this` 指向新实例，此时 `this instanceof boundFn` 为 `true`
- `bind` 不能改变原函数的 `prototype`，通过 `Object.create` 维护原型链
- `bind` 一旦绑定了 `this`，无法再次绑定（首次 `new` 调用会忽略 bind 的 `this`）

```javascript
/**
 * 模拟实现 Function.prototype.bind
 * @param {object|null} context - 需要绑定的 this 上下文
 * @param {...any} args - 预设的参数
 * @returns {Function} 返回绑定后的新函数
 */
Function.prototype.myBind = function (context, ...args) {
  const originalFn = this;
  
  // 返回的新函数
  function boundFn(...newArgs) {
    // 如果使用 new 调用（boundFn 作为构造函数），this 指向新创建的实例
    // 此时 this instanceof boundFn 为 true
    return originalFn.apply(
      this instanceof boundFn ? this : (context ?? globalThis),
      [...args, ...newArgs]
    );
  }
  
  // 维护原型链，使 new 调用时能正确继承
  if (originalFn.prototype) {
    boundFn.prototype = Object.create(originalFn.prototype);
  }
  
  return boundFn;
};
```

##### 实现深拷贝
深拷贝（Deep Clone）是指将一个对象的所有层级完整复制一份，新对象与原对象完全独立，互不影响。与浅拷贝（如 `Object.assign`、展开运算符）不同，深拷贝会递归复制嵌套的对象和数组。

**为什么需要深拷贝？**

在实际开发中，经常会遇到需要"隔离"两个对象的场景：
- 表单重置：保留原始数据模板，重置时恢复，深拷贝可避免引用污染
- 不可变数据：Redux/Vuex 等状态管理要求状态不可变，深拷贝是实现不可变更新的基础
- 函数参数保护：防止函数内部修改外部传入的对象引用
- 数据快照：记录某一时刻的数据状态，后续修改不影响快照

### 核心原理
1. **基本类型**（`string`、`number`、`boolean`、`null`、`undefined`、`symbol`）：直接返回
2. **引用类型**（`object`、`array`）：创建新的对象/数组，递归拷贝所有属性
3. **特殊对象**：分别处理 `Date`、`RegExp`、`Map`、`Set` 等
4. **循环引用**：使用 `WeakMap` 缓存已拷贝对象，遇到循环引用时返回缓存副本
5. **所有属性键**：使用 `Reflect.ownKeys` 获取包括 `Symbol` 在内的所有键

### 深拷贝 vs 浅拷贝
- 浅拷贝只复制对象的第一层，嵌套对象仍共享引用
- 深拷贝递归复制所有层级，完全独立

### 应用场景
- 表单数据的备份与恢复
- Redux/Vuex 状态更新中的不可变操作
- 深拷贝第三方库的数据，防止意外修改
- 复杂配置对象的复制

### 注意事项
- **循环引用**：`const a = {}; a.self = a;`，不处理会导致栈溢出
- **特殊类型**：`Date`、`RegExp`、`Map`、`Set` 等需要分别处理
- **函数**：函数通常不需要深拷贝，直接引用即可（或者使用 `fn.toString()` + `eval` 但这不安全）
- **Symbol 属性**：使用 `Reflect.ownKeys` 而非 `Object.keys`，因为后者不包含 Symbol 键
- **性能**：深拷贝是 O(n) 操作，大对象深拷贝可能造成性能问题，慎用
- **无法拷贝**：`Error`、`DOM` 节点、`function`、`undefined` 的函数属性等难以完美深拷贝

```javascript
/**
 * 深拷贝函数 - 基础版（支持对象、数组、基本类型）
 * @param {any} obj - 需要拷贝的对象
 * @returns {any} 拷贝后的对象
 */
function deepClone(obj) {
  // 基本类型或 null，直接返回
  if (obj === null || typeof obj !== 'object') {
    return obj;
  }
  
  // 处理 Date
  if (obj instanceof Date) {
    return new Date(obj.getTime());
  }
  
  // 处理 RegExp
  if (obj instanceof RegExp) {
    return new RegExp(obj.source, obj.flags);
  }
  
  // 处理数组或对象
  const clone = Array.isArray(obj) ? [] : {};
  
  // 使用 Reflect.ownKeys 可以获取包括 Symbol 在内的所有键
  for (const key of Reflect.ownKeys(obj)) {
    clone[key] = deepClone(obj[key]);
  }
  
  return clone;
}
```

```ts
/**
 * 深拷贝函数 - 完整版（支持循环引用、Map、Set 等）
 * @param {any} obj - 需要拷贝的对象
 * @param {WeakMap} cache - 缓存已拷贝对象，解决循环引用
 * @returns {any} 拷贝后的对象
 */
function deepCloneComplete(obj, cache = new WeakMap()) {
  // 基本类型或 null
  if (obj === null || typeof obj !== 'object') {
    return obj;
  }
  
  // 解决循环引用
  if (cache.has(obj)) {
    return cache.get(obj);
  }
  
  // 处理 Date
  if (obj instanceof Date) {
    return new Date(obj.getTime());
  }
  
  // 处理 RegExp
  if (obj instanceof RegExp) {
    return new RegExp(obj.source, obj.flags);
  }
  
  // 处理 Map
  if (obj instanceof Map) {
    const cloneMap = new Map();
    cache.set(obj, cloneMap);
    obj.forEach((value, key) => {
      cloneMap.set(deepCloneComplete(key, cache), deepCloneComplete(value, cache));
    });
    return cloneMap;
  }
  
  // 处理 Set
  if (obj instanceof Set) {
    const cloneSet = new Set();
    cache.set(obj, cloneSet);
    obj.forEach(value => {
      cloneSet.add(deepCloneComplete(value, cache));
    });
    return cloneSet;
  }
  
  // 处理数组或普通对象
  const clone = Array.isArray(obj) ? [] : {};
  cache.set(obj, clone);
  
  for (const key of Reflect.ownKeys(obj)) {
    clone[key] = deepCloneComplete(obj[key], cache);
  }
  
  return clone;
}
```

##### 实现类的继承
ES6 `class` 语法糖内部基于寄生组合式继承实现。子类通过 `extends` 关键字继承父类，自动获得父类的属性和方法。

### 核心原理
- 子类原型链指向父类原型：`Child.prototype.__proto__ = Parent.prototype`
- 子类构造函数中调用 `super(...)`，执行父类构造函数，继承实例属性
- `super` 的本质是 `Parent.call(this, ...)`，在子类构造函数中必须在使用 `this` 之前调用
- 静态方法也会被继承：`Child.__proto__ = Parent`

### 应用场景
- 面向对象编程中复用父类逻辑
- UI 组件继承（如 Element UI、Ant Design 中的组件扩展）
- 设计模式中的模板方法、工厂方法等

### 注意事项
- ES6 `extends` 内部使用寄生组合式继承，既继承了原型方法，又调用了父类构造函数
- `super()` 在子类构造函数中必须先于 `this` 使用
- `super` 作为函数调用时，执行父类构造函数；作为对象使用时，指向父类原型
- 静态属性和方法也会被继承
- ES5 的 `inherit` 工具函数与 ES6 `extends` 的机制一致

```javascript
/**
 * 类的继承 - 使用 ES6 class 语法
 */
class Animal {
  constructor(name) {
    this.name = name;
  }
  
  speak() {
    return `${this.name} 发出声音`;
  }
  
  static isAnimal(obj) {
    return obj instanceof Animal;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name); // 调用父类构造函数
    this.breed = breed;
  }
  
  speak() {
    return `${this.name}（${this.breed}）汪汪叫`;
  }
  
  fetch() {
    return `${this.name} 在捡球`;
  }
}
```

##### 实现类的继承-简版
ES5 中的类继承通过原型链 + 构造函数窃取实现。简版只保留核心步骤，快速展示继承的本质。

### 核心原理（两步走）
1. **构造函数窃取**：在子类构造函数中调用 `Parent.call(this, ...)`，继承父类的实例属性
2. **原型链继承**：`Child.prototype = Object.create(Parent.prototype)`，继承父类的原型方法
3. **修正 constructor**：`Child.prototype.constructor = Child`，保持实例的构造函数指向正确

### 与完整版的区别
- 简版只有核心两步，缺少静态方法继承、参数处理等
- 完整版会封装成 `inherit` 工具函数，并处理静态属性、`_super` 引用等

### 应用场景
- 理解 ES5 继承的核心机制
- 在不支持 ES6 的环境中实现类继承
- 面试中快速展示对原型链的理解

### 注意事项
- `Object.create(Parent.prototype)` 是 ES5 推荐的原型链设置方式，比 `Child.prototype.__proto__ = Parent.prototype` 更标准
- `constructor` 属性需要手动修正，否则 `Child.prototype.constructor` 会指向 `Parent`
- `Parent.call(this, name)` 中的 `this` 是子类新创建的对象，确保实例属性不被共享
- 子类可以定义自己的原型方法，不会影响父类

```javascript
/**
 * 类的继承 - 简版（ES5 寄生组合式继承）
 */
function Parent(name) {
  this.name = name;
}

Parent.prototype.getName = function () {
  return this.name;
};

function Child(name, age) {
  Parent.call(this, name); // 继承属性
  this.age = age;
}

// 继承方法：Child.prototype.__proto__ = Parent.prototype
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;

Child.prototype.getAge = function () {
  return this.age;
};
```

##### ES5实现继承-详细
ES5 中的类继承有多种实现方式，但寄生组合式继承（Parasitic Combination Inheritance）被公认为最优方案。它解决了之前几种方式的缺陷：

### 各种继承方式的对比
- **原型链继承**：`Child.prototype = new Parent()` — 问题：父类实例属性被所有子类实例共享（引用类型污染）
- **构造函数窃取**：`Parent.call(this, ...)` — 问题：无法继承父类原型方法，函数被重复创建
- **组合继承**：原型链 + 构造函数窃取 — 问题：父类构造函数被调用两次，浪费性能
- **寄生组合式继承**（最优）：用 `Object.create` 代替 `new Parent()`，只调用一次父类构造函数

### 寄生组合式继承的核心
1. 使用 `Object.create(Parent.prototype)` 创建子类原型，避免调用父类构造函数
2. 使用 `Parent.call(this, ...)` 继承实例属性
3. 修正 `constructor` 指向
4. 封装为 `inherit` 工具函数，复用性强

### 应用场景
- ES5 环境下的面向对象编程
- 理解 ES6 `extends` 的底层原理（ES6 class 内部就是寄生组合式继承）
- 兼容旧浏览器时的类继承方案

### 注意事项
- `Object.create` 的性能优于 `new Parent()`，因为它不会执行父类构造函数
- `inherit` 函数中的 `_super` 引用让子类可以访问父类
- 静态方法无法通过原型链继承，需要手动复制：`Child.staticMethod = Parent.staticMethod`
- 引用类型（如数组 `hobbies`）在每个子类实例中都是独立的副本，不会共享

```javascript
/**
 * ES5 实现继承 - 寄生组合式继承（最优方案）
 */

// 工具函数：用于子类继承父类原型
function inherit(child, parent) {
  // 1. 创建以 parent.prototype 为原型的对象
  // 2. 将该对象赋值给 child.prototype
  child.prototype = Object.create(parent.prototype);
  // 3. 修正 constructor 指向
  child.prototype.constructor = child;
  // 4. 存储父类引用（便于访问父类方法）
  child._super = parent;
}

// 父类
function Person(name, age) {
  this.name = name;
  this.age = age;
  this.hobbies = ['读书', '运动'];
}

Person.prototype.sayHello = function () {
  return `你好，我叫${this.name}，今年${this.age}岁`;
};

Person.staticMethod = function () {
  return 'Person 静态方法';
};

// 子类
function Student(name, age, grade) {
  // 调用父类构造函数，继承实例属性
  Person.call(this, name, age);
  this.grade = grade;
  this.study = function () {
    return `${this.name} 在学习`;
  };
}

// 继承父类原型方法
inherit(Student, Person);

// 子类自己的原型方法
Student.prototype.getGrade = function () {
  return `${this.name} 在${this.grade}年级`;
};

// 继承静态属性
Student.staticMethod = Person.staticMethod;
```

### Promise相关
##### 实现Promise的resolve
`Promise.resolve` 是 Promise 的静态方法，用于快速创建一个已解决的 Promise。它的行为比直接 `new Promise(resolve => resolve(value))` 更复杂，需要处理三种情况。

### 核心原理（三种情况）
1. **普通值**：返回一个以该值 resolved 的 Promise
2. **thenable 对象**（有 `.then` 方法的对象）：将其"同化"为 Promise，执行其 `.then` 方法
3. **Promise 实例**：直接返回该 Promise，不做任何包装

**为什么需要 thenable 处理？**

Promise 的互操作性是重要设计。一个不是 Promise 但实现了 `.then` 方法的对象（thenable），也应该能被 Promise 机制正确处理。例如 jQuery 的 `$.Deferred` 对象、某些库的 Promise-like 对象。

### 应用场景
- 封装可能返回 Promise 或普通值的函数
- 确保函数返回类型一致（始终返回 Promise）
- Promise 链式调用中的值传递

### 注意事项
- `Promise.resolve(Promise.resolve(1))` 会返回同一个 Promise，不会产生嵌套
- `Promise.resolve({ then(fn) { fn(1) } })` 会调用 thenable 的 then 方法
- `Promise.resolve` 是"同步执行"的，返回的 Promise 已经处于 resolved 状态
- 如果 thenable 的 then 方法抛出异常，返回的 Promise 会 reject

```javascript
/**
 * 实现 Promise.resolve
 * 返回一个以给定值解析后的 Promise 对象
 * - 如果值是 Promise，则返回该 Promise
 * - 如果值是 thenable 对象，则将其转换为 Promise 并执行 then
 * - 否则返回一个以该值 resolved 的 Promise
 */
Promise.myResolve = function (value) {
  // 如果已经是 Promise 实例，直接返回
  if (value instanceof Promise) {
    return value;
  }
  
  // 如果值是 thenable 对象，用 Promise 包装并执行 then
  if (value !== null && typeof value === 'object' && typeof value.then === 'function') {
    return new Promise((resolve, reject) => {
      value.then(resolve, reject);
    });
  }
  
  // 普通值，返回 resolved 的 Promise
  return new Promise(resolve => resolve(value));
};
```

##### 实现Promise.reject
`Promise.reject` 创建一个以给定原因 rejected 的 Promise 对象。实现比 `resolve` 简单，不需要处理 thenable 的情况。

### 核心原理
- 直接返回 `new Promise((_, reject) => reject(reason))`
- `reject` 不会对 reason 做任何特殊处理，即使是 thenable 对象也直接作为拒绝原因
- 与 `resolve` 不同，`reject` 不会触发异步执行，但 then 回调会在微任务中执行

### 应用场景
- 手动创建失败的 Promise：`Promise.reject(new Error('操作失败'))`
- 错误处理链：在 `.catch()` 中重新抛出错误
- 测试中模拟失败场景

### 注意事项
- `reject` 不会对参数做 `Promise.resolve` 包装，直接传递
- `Promise.reject(reason)` 中的 `reason` 可以是任何值，包括 thenable 对象
- `Promise.reject(Promise.resolve(1))` 不会"解决"内部的 Promise，而是直接 reject 整个 Promise
- 任何对 rejected Promise 的 `.then()` 都会被跳过，进入 `.catch()`

```javascript
/**
 * 实现 Promise.reject
 * 返回一个以给定原因 rejected 的 Promise 对象
 */
Promise.myReject = function (reason) {
  return new Promise((_, reject) => reject(reason));
};
```

##### 实现Promise.prototype.finally
`Promise.prototype.finally` 用于注册一个无论 Promise 最终状态如何都会执行的回调。它类似于 `try...finally` 中的 `finally` 块，常用于清理资源、关闭加载动画等。

### 核心原理
- `finally` 返回一个新的 Promise，保持与原始 Promise 相同的最终状态
- 回调函数 `callback` 不接收任何参数（无法获取 Promise 的结果）
- 如果 `callback` 正常返回（非 thenable），新 Promise 保持原始状态
- 如果 `callback` 返回一个 thenable 或抛出错误，新 Promise 会"跟随"该结果

### 实现要点
- 使用 `this.then()` 同时处理 fulfilled 和 rejected 两种情况
- 在 fulfilled 时：执行 callback，然后透传原始值
- 在 rejected 时：执行 callback，然后重新抛出原始错误
- `Promise.resolve(callback())` 确保 callback 的返回值被正确包装

### 应用场景
- 关闭加载状态：`showLoading(); fetch().finally(hideLoading)`
- 清理副作用：`requestAnimationFrame`、`setTimeout` 的清理
- 无论成功失败都要执行的逻辑

### 注意事项
- `finally` 回调中无法获取 Promise 的结果值（没有参数）
- 如果 `finally` 返回新的 Promise 且该 Promise reject，会覆盖原始状态
- `finally` 会"穿透"错误：`rejected` 的 Promise 经过 `finally` 后仍然是 `rejected`
- `finally` 是异步执行的，即使原始 Promise 已经 settled

```javascript
/**
 * 实现 Promise.prototype.finally
 * - 无论 Promise 是 fulfilled 还是 rejected，都会执行回调
 * - 回调不接收任何参数
 * - 返回一个新的 Promise，保持状态与原始 Promise 一致
 * - 如果回调中抛出错误或返回 rejected Promise，则 finally 返回的 Promise 会以此错误 reject
 */
Promise.prototype.myFinally = function (callback) {
  return this.then(
    value => Promise.resolve(callback()).then(() => value),
    reason => Promise.resolve(callback()).then(() => { throw reason; })
  );
};
```

##### 实现Promise.all
`Promise.all` 接收一个 Promise 可迭代对象，等待所有 Promise 都成功时返回结果数组。如果任一 Promise 失败，立即 reject 该错误（短路机制）。

### 核心原理
1. 将输入转为数组，空数组直接返回 `resolved` 的空数组
2. 维护 `results` 数组（按索引存储结果，保持输入顺序）
3. 维护 `count` 计数器，每个 Promise 解决时 +1
4. `count === length` 时，所有 Promise 都成功，resolve 结果数组
5. 任一 Promise 失败时，立即 reject，触发短路

### 与 `Promise.allSettled` 的区别
- `all`：任一失败立即 reject，不会等待其他 Promise
- `allSettled`：等待所有 Promise 完成，无论成功或失败

### 应用场景
- 并行请求多个接口，等待全部完成后渲染页面
- 资源预加载：同时加载多张图片，全部完成后展示
- 批量写入：多个写操作，全部成功才算成功

### 注意事项
- 如果输入包含非 Promise 值，`Promise.resolve` 会自动包装
- 结果数组的顺序与输入顺序一致（通过索引赋值 `results[index]`）
- 短路机制：一旦有 Promise reject，已 pending 的其他 Promise 的结果会被忽略
- 空的可迭代对象直接返回 `resolved([])`，不进入异步流程
- 如果某个 Promise 永远 pending，`Promise.all` 也会永远 pending（没有超时机制）

```javascript
/**
 * 实现 Promise.all
 * - 接收一个 Promise 可迭代对象
 * - 所有 Promise 都成功时，返回一个包含所有结果的数组（顺序与输入一致）
 * - 任一 Promise 失败，立即 reject 该错误
 * - 空的可迭代对象返回一个 resolved 的空数组
 */
Promise.myAll = function (promises) {
  return new Promise((resolve, reject) => {
    // 将可迭代对象转为数组
    const iterable = Array.from(promises);
    if (iterable.length === 0) {
      resolve([]);
      return;
    }
    
    const results = [];
    let count = 0;
    
    iterable.forEach((item, index) => {
      // 用 Promise.resolve 包装，确保非 Promise 值也能处理
      Promise.resolve(item).then(
        value => {
          results[index] = value; // 保持顺序
          count++;
          if (count === iterable.length) {
            resolve(results);
          }
        },
        reason => {
          reject(reason); // 任一失败立即 reject
        }
      );
    });
  });
};
```

##### 实现Promise.allSettled
`Promise.allSettled` 等待所有 Promise 完成（无论成功或失败），返回每个 Promise 的结果对象。与 `all` 不同，它不会因为某个 Promise 失败而提前终止。

### 核心原理
1. 将输入转为数组，空数组直接返回 `resolved` 的空数组
2. 为每个 Promise 分别注册 `.then()` 和 `.catch()`（通过 `.then(success, failure)`）
3. 每个 Promise 完成后，记录 `{ status: 'fulfilled', value }` 或 `{ status: 'rejected', reason }`
4. 使用 `.finally()`（或计数器）确保每个 Promise 完成后都检查是否全部完成
5. 所有 Promise 都 settled 后，resolve 结果数组

### 与 `all` 的核心区别
- `allSettled` 永远不会 reject，总是 resolve
- 结果包含所有 Promise 的最终状态，无论成功失败
- 适合需要"全量执行"的场景（如批量操作日志记录）

### 应用场景
- 批量请求，需要知道每个请求的成败状态
- 数据同步：将数据写入多个存储，记录每个存储的写入结果
- 分析报告：分析多个接口的成功率，即使部分失败也要收集全部数据
- 队列任务：执行一系列任务，记录每个任务的结果

### 注意事项
- `allSettled` 总是返回 `fulfilled` 状态的 Promise，不会 reject
- 结果对象格式固定：`{ status: 'fulfilled', value }` 或 `{ status: 'rejected', reason }`
- 即使所有 Promise 都失败，结果数组也是 `fulfilled` 状态（包含多个 `rejected` 结果）
- 如果输入为空数组，返回 `resolved([])`
- 不会短路，所有 Promise 都会执行到 settled

```javascript
/**
 * 实现 Promise.allSettled
 * - 等待所有 Promise 完成（无论成功或失败）
 * - 返回每个 Promise 的结果对象：{status: 'fulfilled', value} 或 {status: 'rejected', reason}
 * - 不会因为某个 Promise 失败而 reject
 */
Promise.myAllSettled = function (promises) {
  return new Promise(resolve => {
    const iterable = Array.from(promises);
    if (iterable.length === 0) {
      resolve([]);
      return;
    }
    
    const results = [];
    let count = 0;
    
    iterable.forEach((item, index) => {
      Promise.resolve(item).then(
        value => {
          results[index] = { status: 'fulfilled', value };
        },
        reason => {
          results[index] = { status: 'rejected', reason };
        }
      ).finally(() => {
        count++;
        if (count === iterable.length) {
          resolve(results);
        }
      });
    });
  });
};
```

##### 实现Promise.race
`Promise.race` 返回第一个 settled 的 Promise 的结果（无论成功或失败）。"Race"（竞赛）的命名准确描述了它的行为：多个 Promise 赛跑，谁先完成就用谁的结果。

### 核心原理
1. 为每个 Promise 注册 `.then(resolve, reject)`
2. 第一个 settled 的 Promise 会触发外层 Promise 的 resolve 或 reject
3. 后续的 Promise 即使也 settled，结果也不会被采用（因为外层已经 settled）
4. 空数组时，返回的 Promise 永远处于 pending 状态

### 与 `all`/`allSettled` 的区别
- `race`：取最快的结果，不管其他
- `all`：取全部结果（短路）
- `allSettled`：取全部结果（不短路）

### 应用场景
- 超时控制：`Promise.race([fetch(), timeout(5000)])`，5 秒超时 reject
- 竞速：从多个 CDN 取最快的结果
- 资源加载：同时从多个源加载资源，取最快完成的

### 注意事项
- 空数组返回永远 pending 的 Promise（原生行为，不是 bug）
- 不会取消其他未完成的 Promise，它们会继续执行（只是结果被忽略）
- 如果最快的 Promise reject，`race` 也会 reject
- 适合需要"响应速度优先"的场景
- 不会对输入做去重，重复的 Promise 会被分别注册

```javascript
/**
 * 实现 Promise.race
 * - 返回第一个 settled 的 Promise 的结果（无论成功或失败）
 * - 空数组时 Promise 永远处于 pending 状态
 */
Promise.myRace = function (promises) {
  return new Promise((resolve, reject) => {
    const iterable = Array.from(promises);
    
    iterable.forEach(item => {
      Promise.resolve(item).then(resolve, reject);
    });
  });
};
```

##### 实现一个简版Promise
简版 Promise 包含核心状态管理和异步回调缓存机制，是理解完整 Promise 实现的基础。

### 核心原理（三要素）
1. **状态机**：三种状态 `pending` → `fulfilled` / `rejected`，状态一旦改变不可逆
2. **值缓存**：`value` 存储成功结果，`reason` 存储失败原因
3. **回调缓存**：异步执行时，先缓存 `onFulfilled`/`onRejected` 回调，状态改变后执行
4. **状态保护**：只有 `pending` 状态才能转换，防止状态被多次修改

**为什么需要回调缓存？**

Promise 的 `then` 可以在状态改变之前注册回调。如果执行 `then` 时 Promise 已经是 fulfilled/rejected，直接执行回调；如果是 pending，将回调缓存起来，等状态改变后执行。这就是"异步安全"的基础。

### 应用场景
- 理解 Promise 的核心状态机
- 作为完整 Promise 实现的精简版学习
- 面试中快速展示对 Promise 机制的理解

### 注意事项
- 简版不支持链式调用（`then` 返回 `undefined`）
- 不支持值穿透（`then()` 没有参数时不会透传值）
- 回调执行是同步的（非微任务），与原生 Promise 的异步行为有差异
- 不支持 `catch`、`finally` 等方法
- 状态不可逆：fulfilled 后不能再变成 rejected，反之亦然

```javascript
/**
 * 简版 Promise - 包含核心功能
 * 状态：pending -> fulfilled / rejected
 */
class SimplePromise {
  constructor(executor) {
    this.status = 'pending'; // 初始状态
    this.value = undefined;  // 成功值
    this.reason = undefined; // 失败原因
    this.onFulfilledCallbacks = []; // 异步时存储成功回调
    this.onRejectedCallbacks = [];  // 异步时存储失败回调
    
    const resolve = value => {
      if (this.status === 'pending') {
        this.status = 'fulfilled';
        this.value = value;
        // 执行所有缓存的成功回调
        this.onFulfilledCallbacks.forEach(fn => fn());
      }
    };
    
    const reject = reason => {
      if (this.status === 'pending') {
        this.status = 'rejected';
        this.reason = reason;
        this.onRejectedCallbacks.forEach(fn => fn());
      }
    };
    
    try {
      executor(resolve, reject);
    } catch (err) {
      reject(err);
    }
  }
  
  then(onFulfilled, onRejected) {
    if (this.status === 'fulfilled') {
      onFulfilled(this.value);
    }
    if (this.status === 'rejected') {
      onRejected(this.reason);
    }
    if (this.status === 'pending') {
      this.onFulfilledCallbacks.push(() => onFulfilled(this.value));
      this.onRejectedCallbacks.push(() => onRejected(this.reason));
    }
  }
}
```

##### Promise实现-详细
详细版 Promise 在简版基础上增加了链式调用、值穿透、异步执行等核心特性，是理解完整 Promise/A+ 规范的桥梁。

### 核心改进（相对于简版）
1. **链式调用**：`then` 返回新的 Promise，支持 `.then().then().catch()` 链式操作
2. **值穿透**：如果 `then` 的参数不是函数，则创建默认函数透传值
3. **异步执行**：使用 `setTimeout` 确保回调在微任务中执行（原生 Promise 使用微任务队列）
4. **thenable 处理**：`resolvePromise` 函数处理回调返回的 Promise/thenable
5. **循环引用检测**：如果 `then` 返回的 Promise 与当前 Promise 相同，抛 TypeError
6. **错误冒泡**：`then` 中的错误通过 `reject` 传递到 `catch`

### 链式调用原理
- `then` 返回一个新的 Promise（`newPromise`）
- 当原 Promise settled 后，执行 `onFulfilled`/`onRejected`
- 回调的返回值通过 `resolvePromise` 解析：
  - 如果是 thenable，等待其完成
  - 如果是普通值，直接 resolve
  - 如果是同一个 Promise，抛循环引用错误

### 应用场景
- 理解 Promise 链式调用的内部机制
- 实现自定义的 Promise-like 对象
- 面试中展示对 Promise 深度原理的理解

### 注意事项
- `setTimeout` 模拟的是微任务，实际 Promise 使用 `process.nextTick`（Node）或 `MutationObserver`（浏览器）
- 值穿透确保 `.then().then()` 可以连续传递值
- 循环引用检测防止无限递归
- 简版中的同步回调在详细版中变为异步执行（通过 setTimeout）
- `catch` 本质是 `then(null, onRejected)` 的语法糖

```javascript
/**
 * Promise 详细实现 - 支持链式调用
 * - 通过 then 方法返回新的 Promise 实现链式调用
 * - 处理回调返回值和 Promise 的情况
 */
class DetailedPromise {
  constructor(executor) {
    this.status = 'pending';
    this.value = undefined;
    this.reason = undefined;
    this.onFulfilledCallbacks = [];
    this.onRejectedCallbacks = [];
    
    const resolve = value => {
      if (this.status === 'pending') {
        this.status = 'fulfilled';
        this.value = value;
        this.onFulfilledCallbacks.forEach(fn => fn());
      }
    };
    
    const reject = reason => {
      if (this.status === 'pending') {
        this.status = 'rejected';
        this.reason = reason;
        this.onRejectedCallbacks.forEach(fn => fn());
      }
    };
    
    try {
      executor(resolve, reject);
    } catch (err) {
      reject(err);
    }
  }
  
  then(onFulfilled, onRejected) {
    // 参数可选，如果非函数则透传值
    onFulfilled = typeof onFulfilled === 'function' ? onFulfilled : v => v;
    onRejected = typeof onRejected === 'function' ? onRejected : r => { throw r; };
    
    const newPromise = new DetailedPromise((resolve, reject) => {
      const handleFulfilled = () => {
        setTimeout(() => { // 保证异步执行
          try {
            const result = onFulfilled(this.value);
            resolvePromise(newPromise, result, resolve, reject);
          } catch (err) {
            reject(err);
          }
        });
      };
      
      const handleRejected = () => {
        setTimeout(() => {
          try {
            const result = onRejected(this.reason);
            resolvePromise(newPromise, result, resolve, reject);
          } catch (err) {
            reject(err);
          }
        });
      };
      
      if (this.status === 'fulfilled') {
        handleFulfilled();
      } else if (this.status === 'rejected') {
        handleRejected();
      } else {
        this.onFulfilledCallbacks.push(handleFulfilled);
        this.onRejectedCallbacks.push(handleRejected);
      }
    });
    
    return newPromise;
  }
  
  catch(onRejected) {
    return this.then(null, onRejected);
  }
}

/**
 * 解析 then 回调的返回值
 * - 如果返回值是新 Promise 自身，抛循环引用错误
 * - 如果返回值是 Promise，则等待其完成
 * - 如果返回值是 thenable 对象，执行其 then 方法
 * - 否则直接 resolve
 */
function resolvePromise(promise, result, resolve, reject) {
  if (promise === result) {
    reject(new TypeError('Chaining cycle detected for promise'));
    return;
  }
  
  if (result instanceof DetailedPromise) {
    result.then(resolve, reject);
  } else if (result !== null && typeof result === 'object' && typeof result.then === 'function') {
    result.then(resolve, reject);
  } else {
    resolve(result);
  }
}
```

##### 实现Promisify
`Promisify`（也叫 promisify）是将 Node.js 风格的回调函数（Error-First Callback）转换为 Promise 版本的函数。这是 Node.js 生态中非常重要的工具函数。

**为什么需要 Promisify？**

Node.js 原生 API（如 `fs.readFile`、`child_process.exec`）普遍使用回调风格：`fn(args..., (err, result) => {})`。这种风格有以下问题：
- 回调地狱：多层嵌套难以维护
- 错误处理不一致：需要通过 `if (err)` 手动判断
- 无法使用 `async/await`：Promise 才是 `await` 的基础

`util.promisify` 是 Node.js 内置的 promisify 函数。

### 核心原理
1. 返回一个新函数，接收原始参数
2. 在新函数内部，追加一个回调函数作为最后一个参数调用原始函数
3. 回调函数遵循 Node.js 约定：`(err, ...results) => {}`
4. 如果有 `err`，`reject(err)`；否则 `resolve(results)`
5. 如果只有一个结果值，直接返回（`results.length === 1 ? results[0] : results`）

### 应用场景
- 将 `fs.readFile` 等回调 API 转为 Promise，配合 `async/await` 使用
- 统一项目中的异步风格（全部使用 Promise）
- 在浏览器端封装需要回调的第三方库

### 注意事项
- Node.js 回调约定：第一个参数是 `error`（`null` 表示无错误），后续是结果值
- 多结果值（如 `child_process.exec` 的 `(stdout, stderr)`）以数组形式返回
- 单结果值直接返回，避免多余的一层数组包装
- `promisify` 不改变原函数，返回的是新函数
- `promisifyAll` 可以将对象中所有方法批量 Promise 化（加 `Async` 后缀）

```javascript
/**
 * 实现 promisify - 将 Node.js 回调风格转为 Promise
 * @param {Function} fn - Node.js 风格函数（最后一个参数为回调）
 * @returns {Function} 返回 Promise 风格的函数
 */
function promisify(fn) {
  return function (...args) {
    return new Promise((resolve, reject) => {
      // 追加一个回调函数作为最后一个参数
      fn.call(this, ...args, (err, ...results) => {
        if (err) {
          reject(err);
        } else {
          // 如果只有一个结果值，直接返回；多个结果以数组形式返回
          resolve(results.length === 1 ? results[0] : results);
        }
      });
    });
  };
}

/**
 * promisify 全部方法 - 将一个对象中的所有回调风格方法转为 Promise
 * @param {object} obj - 包含回调风格方法的对象
 * @returns {object} 返回新对象，所有方法都 Promise 化
 */
function promisifyAll(obj) {
  const result = {};
  for (const key of Object.keys(obj)) {
    const fn = obj[key];
    if (typeof fn === 'function') {
      result[key + 'Async'] = promisify(fn);
    }
  }
  return result;
}
```

##### 完整实现Promises/A+规范
Promises/A+ 是一个开放的、可互操作的 Promise 规范，定义了 Promise 的行为标准。完整实现需要遵循该规范的所有要求，包括 then 链式调用、值穿透、异步执行、错误处理、thenable 互操作等。

### 规范核心要求
1. **三种状态**：`pending` → `fulfilled` 或 `rejected`，状态不可逆
2. **then 方法**：接收 `onFulfilled` 和 `onRejected` 两个参数，返回新的 Promise
3. **值穿透**：如果 `onFulfilled`/`onRejected` 不是函数，创建默认函数透传值
4. **异步执行**：`then` 的回调必须在微任务中执行，不能同步执行
5. **thenable 互操作**：如果 `then` 返回值是 thenable 对象，调用其 `.then` 方法
6. **循环引用检测**：如果 `then` 返回的 Promise 与当前 Promise 相同，抛 TypeError
7. **错误冒泡**：`onFulfilled` 抛出的错误被后续 `catch` 捕获

### resolvePromise 解析过程（规范 2.3 节）
- 2.3.1：`promise2 === x` → 循环引用错误
- 2.3.2：`x` 是 Promise → 等待其完成
- 2.3.3：`x` 是 thenable → 调用 `x.then`
- 2.3.3.3：确保 `then` 只被调用一次（`called` 标志）
- 2.3.4：`x` 是普通值 → 直接 resolve

### 应用场景
- 学习 Promise 的完整内部机制
- 实现自定义的 Promise 库（如 Bluebird、Q）
- 理解不同 Promise 实现之间的互操作性

### 注意事项
- 使用 `setTimeout` 模拟微任务，实际 Promise 使用更高效的微任务队列
- `called` 标志防止 thenable 的 `then` 方法被多次调用
- `deferred` 方法（`deferred()`）是测试 Promise 实现的常用辅助工具
- 完整实现需要处理大量边界情况，建议参考 [promisesaplus.com](https://promisesaplus.com/) 的测试套件验证

```javascript
/**
 * Promises/A+ 规范完整实现
 * 参考：https://promisesaplus.com/
 */

// 状态常量
const PENDING = 'pending';
const FULFILLED = 'fulfilled';
const REJECTED = 'rejected';

class PromiseA {
  constructor(executor) {
    this.status = PENDING;
    this.value = null;
    this.reason = null;
    this.onFulfilledCallbacks = [];
    this.onRejectedCallbacks = [];
    
    const resolve = value => {
      if (this.status === PENDING) {
        this.status = FULFILLED;
        this.value = value;
        this.onFulfilledCallbacks.forEach(fn => fn(this.value));
      }
    };
    
    const reject = reason => {
      if (this.status === PENDING) {
        this.status = REJECTED;
        this.reason = reason;
        this.onRejectedCallbacks.forEach(fn => fn(this.reason));
      }
    };
    
    try {
      executor(resolve, reject);
    } catch (err) {
      reject(err);
    }
  }
  
  then(onFulfilled, onRejected) {
    // 值穿透：onFulfilled/onRejected 如果不是函数则创建默认函数透传值
    onFulfilled = typeof onFulfilled === 'function' ? onFulfilled : v => v;
    onRejected = typeof onRejected === 'function' ? onRejected : r => { throw r; };
    
    const promise2 = new PromiseA((resolve, reject) => {
      // 封装执行函数，确保异步调用
      const wrapFulfilled = () => {
        setTimeout(() => {
          try {
            const x = onFulfilled(this.value);
            this.resolvePromise(promise2, x, resolve, reject);
          } catch (e) {
            reject(e);
          }
        });
      };
      
      const wrapRejected = () => {
        setTimeout(() => {
          try {
            const x = onRejected(this.reason);
            this.resolvePromise(promise2, x, resolve, reject);
          } catch (e) {
            reject(e);
          }
        });
      };
      
      if (this.status === FULFILLED) {
        wrapFulfilled();
      } else if (this.status === REJECTED) {
        wrapRejected();
      } else {
        this.onFulfilledCallbacks.push(wrapFulfilled);
        this.onRejectedCallbacks.push(wrapRejected);
      }
    });
    
    return promise2;
  }
  
  catch(onRejected) {
    return this.then(null, onRejected);
  }
  
  // Promise 解析过程：[[Resolve]](promise2, x)
  resolvePromise(promise2, x, resolve, reject) {
    // 2.3.1 如果 promise2 和 x 指向同一对象，抛出 TypeError
    if (promise2 === x) {
      reject(new TypeError('Chaining cycle detected for promise'));
      return;
    }
    
    // 2.3.2 如果 x 是 PromiseA 实例
    if (x instanceof PromiseA) {
      if (x.status === FULFILLED) {
        resolve(x.value);
      } else if (x.status === REJECTED) {
        reject(x.reason);
      } else {
        x.then(y => this.resolvePromise(promise2, y, resolve, reject), reject);
      }
      return;
    }
    
    // 2.3.3 如果 x 是对象或函数（thenable）
    if (x !== null && (typeof x === 'object' || typeof x === 'function')) {
      let called = false; // 2.3.3.3.3 确保只调用一次
      
      try {
        const then = x.then;
        
        if (typeof then === 'function') {
          // 2.3.3.3 如果 then 是函数，将 x 作为 this 调用
          then.call(
            x,
            y => {
              if (called) return;
              called = true;
              this.resolvePromise(promise2, y, resolve, reject);
            },
            r => {
              if (called) return;
              called = true;
              reject(r);
            }
          );
        } else {
          // 2.3.3.4 如果 then 不是函数，以 x 为值 resolve
          resolve(x);
        }
      } catch (e) {
        // 2.3.3.2 如果取 then 抛出异常，reject
        if (called) return;
        called = true;
        reject(e);
      }
    } else {
      // 2.3.4 如果 x 不是对象或函数，以 x 为值 resolve
      resolve(x);
    }
  }
  
  // 静态方法
  static resolve(value) {
    if (value instanceof PromiseA) return value;
    return new PromiseA(resolve => resolve(value));
  }
  
  static reject(reason) {
    return new PromiseA((_, reject) => reject(reason));
  }
  
  static all(iterable) {
    return new PromiseA((resolve, reject) => {
      const arr = Array.from(iterable);
      if (arr.length === 0) return resolve([]);
      
      const results = [];
      let count = 0;
      
      arr.forEach((item, i) => {
        PromiseA.resolve(item).then(
          val => {
            results[i] = val;
            count++;
            if (count === arr.length) resolve(results);
          },
          reject
        );
      });
    });
  }
  
  static race(iterable) {
    return new PromiseA((resolve, reject) => {
      Array.from(iterable).forEach(item => {
        PromiseA.resolve(item).then(resolve, reject);
      });
    });
  }
}

// 用于测试的 deferred 方法
PromiseA.deferred = function () {
  const result = {};
  result.promise = new PromiseA((resolve, reject) => {
    result.resolve = resolve;
    result.reject = reject;
  });
  return result;
};

// module.exports = PromiseA;
```

### 设计模式
##### 实现发布订阅模式
发布订阅模式（Pub/Sub）是一种消息范式，发送者（发布者）不直接将消息发送给接收者（订阅者），而是通过调度中心（Event Channel）来转发。解耦了发布者和订阅者。

**为什么需要发布订阅？**

在复杂应用中，组件之间往往需要通信，但直接引用会导致强耦合：
- 组件 A 需要通知组件 B 做某事，但 A 不知道 B 是谁
- 全局状态管理中需要一种"事件驱动"的通信机制
- 插件系统中，插件需要监听和响应框架事件

### 核心原理
1. **调度中心**：维护一个事件字典 `{ eventName: [callback1, callback2, ...] }`
2. **on（订阅）**：将回调函数注册到对应事件的回调列表中
3. **emit（发布）**：找到事件对应的所有回调，逐个执行并传入参数
4. **off（取消订阅）**：从回调列表中移除指定回调
5. **once（一次性订阅）**：回调执行后自动取消订阅

### 发布订阅 vs 观察者模式
- 发布订阅：通过调度中心中转，发布者和订阅者完全解耦
- 观察者模式：目标直接持有观察者引用，通知时直接调用

### 应用场景
- Vue 的 EventBus（`$on`/`$emit`/`$off`）
- Node.js 的 `EventEmitter`
- 自定义事件的实现（如 DOM 的 `addEventListener`）
- 插件系统中的事件机制

### 注意事项
- 回调函数执行错误应该被捕获，避免影响其他订阅者
- `once` 的实现：包装回调，执行后自动调用 `off`
- 内存泄漏：订阅后要记得取消订阅，否则回调函数会一直持有引用
- 事件名通常用字符串，避免全局命名冲突
- 返回值设计：`on` 返回取消函数，方便外部管理生命周期

```javascript
/**
 * 发布订阅模式（Event Emitter）
 * - on: 订阅事件
 * - emit: 发布事件
 * - off: 取消订阅
 * - once: 订阅一次
 */
class EventEmitter {
  constructor() {
    this.events = {}; // 存储所有事件及其对应的回调
  }
  
  /**
   * 订阅事件
   * @param {string} event - 事件名
   * @param {Function} callback - 回调函数
   * @returns {Function} 取消订阅的函数
   */
  on(event, callback) {
    if (!this.events[event]) {
      this.events[event] = [];
    }
    this.events[event].push(callback);
    
    // 返回取消订阅的函数
    return () => this.off(event, callback);
  }
  
  /**
   * 发布事件
   * @param {string} event - 事件名
   * @param {...any} args - 传递给回调的参数
   */
  emit(event, ...args) {
    const callbacks = this.events[event];
    if (callbacks) {
      callbacks.forEach(cb => {
        try {
          cb(...args);
        } catch (err) {
          console.error(`Event "${event}" callback error:`, err);
        }
      });
    }
  }
  
  /**
   * 取消订阅
   * @param {string} event - 事件名
   * @param {Function} callback - 要移除的回调（不传则移除该事件所有回调）
   */
  off(event, callback) {
    if (!callback) {
      // 不传回调则移除该事件所有订阅
      delete this.events[event];
      return;
    }
    
    const callbacks = this.events[event];
    if (callbacks) {
      this.events[event] = callbacks.filter(cb => cb !== callback);
    }
  }
  
  /**
   * 订阅一次（触发后自动取消）
   * @param {string} event - 事件名
   * @param {Function} callback - 回调函数
   */
  once(event, callback) {
    const wrapper = (...args) => {
      callback(...args);
      this.off(event, wrapper);
    };
    this.on(event, wrapper);
  }
}
```

##### 实现观察者模式
观察者模式（Observer Pattern）定义了对象之间的一对多依赖关系：当一个对象状态改变时，所有依赖它的对象都会收到通知并自动更新。

**为什么需要观察者模式？**

在响应式编程和数据绑定中，我们需要一种机制让数据变化自动通知视图更新。观察者模式是这一需求的基础：
- 数据模型变化时自动更新 UI
- 事件驱动的系统架构
- 框架内部的响应式系统（Vue 2 的 `Object.defineProperty` 依赖收集）

### 核心原理
1. **Subject（目标/被观察者）**：维护观察者列表，状态变化时通知所有观察者
2. **Observer（观察者）**：定义 `update(data)` 接口，收到通知后执行更新逻辑
3. **注册/移除**：观察者可以动态地订阅或取消订阅目标的变化

### 观察者模式 vs 发布订阅模式
- 观察者模式：Subject 直接持有 Observer 引用，直接调用 `observer.update()`
- 发布订阅模式：通过 Event Channel 中转，两者完全不知道对方的存在

### 应用场景
- Vue 2 响应式系统：`Dep`（依赖收集器）和 `Watcher`（观察者）
- 自定义事件：`addEventListener`/`removeEventListener`
- 数据绑定框架中的 Model 变化通知 View
- 状态管理：Redux 的 `subscribe` 监听状态变化

### 注意事项
- 观察者列表应该支持动态增删
- 通知时应该遍历所有观察者并调用 `update`
- 观察者的 `update` 方法接收数据参数，让观察者知道变化的内容
- 避免循环通知：观察者的 `update` 不应该再触发 Subject 的通知
- 内存管理：取消订阅时要正确从列表中移除观察者

```javascript
/**
 * 观察者模式
 */

// 目标对象（被观察者）
class Subject {
  constructor() {
    this.observers = []; // 观察者列表
  }
  
  // 添加观察者
  addObserver(observer) {
    if (observer && observer.update) {
      this.observers.push(observer);
    }
  }
  
  // 移除观察者
  removeObserver(observer) {
    this.observers = this.observers.filter(obs => obs !== observer);
  }
  
  // 通知所有观察者
  notify(data) {
    this.observers.forEach(observer => observer.update(data));
  }
}

// 观察者
class Observer {
  constructor(name) {
    this.name = name;
  }
  
  // 被通知时调用的方法
  update(data) {
    console.log(`${this.name} 收到通知:`, data);
  }
}

// --- 使用示例 ---
// const subject = new Subject();
// const obs1 = new Observer('观察者1');
// const obs2 = new Observer('观察者2');
// subject.addObserver(obs1);
// subject.addObserver(obs2);
// subject.notify('状态变了！');
```

##### 实现单例模式
单例模式（Singleton Pattern）确保一个类只有一个实例，并提供一个全局访问点。这是最常用的设计模式之一。

**为什么需要单例？**

在应用中，某些对象只需要一个实例：
- 全局状态管理（Vuex/Redux store）
- 数据库连接池
- 线程池
- 浏览器中的 `localStorage` 封装
- 弹窗/模态框管理器

### 核心原理
1. **私有实例变量**：用闭包或静态变量保存唯一实例
2. **构造函数判断**：在构造函数中检查实例是否已存在，存在则返回已有实例
3. **全局访问点**：提供静态方法 `getInstance()` 获取实例

### 两种实现方式
- **闭包版**：用模块级变量 `instance` 保存唯一实例，构造函数判断后返回
- **静态方法版**：用类静态属性 `Singleton._instance` 保存实例，`getInstance()` 方法提供访问

### 应用场景
- 全局配置对象
- 数据库连接
- 日志记录器
- 模态框/Toast 管理
- 任何需要"全局唯一"的资源

### 注意事项
- 多线程/异步环境下需要加锁（JavaScript 单线程无此问题）
- 单例对象的生命周期与应用相同，需要注意内存释放
- 在模块化系统中（ES Module），模块本身天然是单例的
- 测试时单例可能造成测试用例之间的状态污染，可通过重置方法解决
- 过度使用单例会导致代码难以测试和维护

```javascript
/**
 * 单例模式 - 使用闭包实现
 */
function createSingleton(className) {
  let instance = null;
  
  return class Singleton {
    constructor(...args) {
      if (instance) {
        return instance;
      }
      instance = this;
      if (typeof className === 'function') {
        className.apply(this, args);
      }
    }
  };
}

/**
 * 单例模式 - 使用静态方法实现
 */
class Singleton {
  constructor(name) {
    if (Singleton._instance) {
      return Singleton._instance;
    }
    this.name = name;
    Singleton._instance = this;
  }
  
  static getInstance(name) {
    if (!Singleton._instance) {
      Singleton._instance = new Singleton(name);
    }
    return Singleton._instance;
  }
}
```

### Ajax相关
##### 实现Ajax - 原生实现
Ajax（Asynchronous JavaScript and XML）是一种在浏览器中发送异步 HTTP 请求的技术。虽然现代开发常用 `fetch` 或 Axios，但理解原生 `XMLHttpRequest` 的实现是前端基础。

**为什么需要 Ajax？**

在 Ajax 出现之前，网页与服务器的交互需要整页刷新。Ajax 的出现使得：
- 页面可以局部更新，无需整页刷新（更好的用户体验）
- 后台异步请求数据，不阻塞页面交互
- 前后端分离架构的基础

### 核心原理
1. 创建 `XMLHttpRequest` 对象
2. 调用 `open(method, url, async)` 初始化请求
3. 设置请求头（`setRequestHeader`）
4. 注册事件监听（`onreadystatechange` 或 `onload`/`onerror`）
5. 调用 `send(body)` 发送请求

### GET vs POST 的参数处理
- GET：参数拼接到 URL 后面（`?key=value&...`），通过 `encodeURIComponent` 编码
- POST：参数放在请求体中，通常序列化为 JSON 字符串

### 应用场景
- 理解 Ajax 底层原理，为学习 `fetch`/Axios 打基础
- 面试中考察对浏览器网络 API 的理解
- 在不支持 `fetch` 的旧浏览器中使用
- 需要精细控制请求进度时（`onprogress`）

### 注意事项
- `async=true` 是异步请求（默认），`async=false` 是同步请求（会阻塞 UI，不推荐）
- `responseType` 可以设置响应类型（`json`、`text`、`blob`、`arraybuffer`）
- `onreadystatechange` 中 `readyState === 4` 表示请求完成
- 状态码 `200-299` 和 `304` 都是成功状态
- CORS 跨域问题：Ajax 受同源策略限制，跨域需要服务器配合 CORS 头

```javascript
/**
 * 原生 Ajax 实现 - 使用 XMLHttpRequest
 * @param {object} options - 配置项
 * @param {string} options.url - 请求地址
 * @param {string} [options.method='GET'] - 请求方法
 * @param {object} [options.data] - 请求数据
 * @param {boolean} [options.async=true] - 是否异步
 * @param {object} [options.headers] - 自定义请求头
 * @param {Function} [options.onSuccess] - 成功回调
 * @param {Function} [options.onError] - 失败回调
 * @param {Function} [options.onProgress] - 进度回调
 */
function ajax(options) {
  const xhr = new XMLHttpRequest();
  const method = (options.method || 'GET').toUpperCase();
  const async = options.async !== false;
  
  // 处理 GET 请求参数拼接到 URL
  let url = options.url;
  if (method === 'GET' && options.data) {
    const params = Object.entries(options.data)
      .map(([k, v]) => `${encodeURIComponent(k)}=${encodeURIComponent(v)}`)
      .join('&');
    url += (url.includes('?') ? '&' : '?') + params;
  }
  
  xhr.open(method, url, async);
  
  // 设置请求头
  if (options.headers) {
    Object.entries(options.headers).forEach(([key, value]) => {
      xhr.setRequestHeader(key, value);
    });
  }
  
  // 设置响应类型
  xhr.responseType = options.responseType || 'json';
  
  // 监听状态变化
  xhr.onreadystatechange = function () {
    if (xhr.readyState === 4) {
      if (xhr.status >= 200 && xhr.status < 300 || xhr.status === 304) {
        options.onSuccess && options.onSuccess(xhr.response);
      } else {
        options.onError && options.onError(new Error(`请求失败: ${xhr.status}`));
      }
    }
  };
  
  // 监听进度
  if (options.onProgress) {
    xhr.onprogress = options.onProgress;
  }
  
  // 发送请求
  const body = method === 'POST' && options.data ? JSON.stringify(options.data) : null;
  xhr.send(body);
}
```

##### Ajax相关 - Promise实现
Promise 版本的 Ajax 封装将回调风格的代码转为 Promise，使得异步操作可以用 `async/await` 或 `.then()` 链式调用，代码更清晰易维护。

### 核心原理
1. 创建一个 `new Promise((resolve, reject) => {})`
2. 在 Promise 内部创建 `XMLHttpRequest`
3. 根据请求方法处理参数（GET 拼到 URL，POST 放 body）
4. 监听 `onload`（成功）、`onerror`（网络错误）、`ontimeout`（超时）
5. 成功时 `resolve(response)`，失败时 `reject(error)`

### 与原生回调版 Ajax 的区别
- 原生版使用 `onSuccess`/`onError` 回调，容易造成回调地狱
- Promise 版返回 Promise，可以用 `.then()` 链式调用
- Promise 版配合 `async/await` 让异步代码看起来像同步代码
- 错误处理统一通过 `.catch()`，不需要每个请求单独写错误处理

### 应用场景
- 统一项目中的 Ajax 请求风格
- 配合 `async/await` 使用：`const data = await ajaxPromise('/api/users')`
- 拦截器：在请求前后统一添加 token、处理错误等

### 注意事项
- `withCredentials` 用于跨域请求携带 Cookie
- `timeout` 设置请求超时时间，超时触发 `ontimeout`
- `responseType` 可以设为 `json`/`text`/`blob`/`arraybuffer`
- GET 请求参数需要 `encodeURIComponent` 编码，避免特殊字符问题
- `onload` 中需要检查 `status` 范围（`200-299` 或 `304`）

```javascript
/**
 * Promise 版本的 Ajax
 * @param {string} url - 请求地址
 * @param {object} [options] - 配置项
 * @returns {Promise} 返回 Promise
 */
function ajaxPromise(url, options = {}) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    const method = (options.method || 'GET').toUpperCase();
    
    let requestUrl = url;
    if (method === 'GET' && options.data) {
      const params = Object.entries(options.data)
        .map(([k, v]) => `${encodeURIComponent(k)}=${encodeURIComponent(v)}`)
        .join('&');
      requestUrl += (url.includes('?') ? '&' : '?') + params;
    }
    
    xhr.open(method, requestUrl, true);
    
    if (options.headers) {
      Object.entries(options.headers).forEach(([key, value]) => {
        xhr.setRequestHeader(key, value);
      });
    }
    
    xhr.responseType = options.responseType || 'json';
    xhr.withCredentials = options.withCredentials || false;
    xhr.timeout = options.timeout || 0;
    
    xhr.onload = function () {
      if (xhr.status >= 200 && xhr.status < 300 || xhr.status === 304) {
        resolve(xhr.response);
      } else {
        reject(new Error(`HTTP ${xhr.status}: ${xhr.statusText}`));
      }
    };
    
    xhr.onerror = function () {
      reject(new Error('网络错误'));
    };
    
    xhr.ontimeout = function () {
      reject(new Error('请求超时'));
    };
    
    const body = ['POST', 'PUT', 'PATCH'].includes(method) && options.data
      ? JSON.stringify(options.data)
      : null;
    xhr.send(body);
  });
}

// --- 使用示例 ---
// ajaxPromise('/api/users')
//   .then(data => console.log(data))
//   .catch(err => console.error(err));
```

##### 实现JSONP方法
JSONP（JSON with Padding）是一种经典的跨域请求方案，利用 `<script>` 标签没有跨域限制的特性来获取数据。

**为什么需要 JSONP？**

在 CORS 普及之前，浏览器受同源策略限制，XHR 请求只能访问同源资源。JSONP 是一种"绕过"限制的古老方案：
- 服务端不是返回纯 JSON，而是返回一个函数调用：`callback({ data: 'xxx' })`
- 浏览器通过 `<script>` 标签加载，`<script>` 不受同源策略限制
- 全局回调函数执行后获取数据

### 核心原理
1. 动态创建 `<script>` 标签，`src` 指向跨域接口
2. 将回调函数名作为参数传给服务端（如 `?callback=myCallback`）
3. 服务端返回 `myCallback({...data})`
4. 浏览器执行全局回调函数，获取数据并 resolve Promise
5. 清理：删除全局回调函数和 `<script>` 标签

### 应用场景
- 跨域获取数据（在 CORS 和 proxy 普及之前）
- 某些不支持 CORS 的老旧 API
- 前端面试中考察对跨域方案的理解

### 注意事项
- JSONP 只支持 GET 请求，无法发送 POST/PUT 等
- 安全性风险：如果服务端被注入恶意代码，会执行在页面上下文中（XSS 风险）
- 回调函数名需要唯一（使用 `Date.now()` + 随机数生成）
- 超时处理：如果服务端无响应，需要 `setTimeout` 超时 reject
- 错误处理：`script.onerror` 可以捕获加载失败
- 现代开发中优先使用 CORS 或代理服务器，JSONP 已很少使用

```javascript
/**
 * JSONP 实现
 * @param {string} url - 请求地址
 * @param {object} params - URL 参数
 * @param {string} [callbackName='callback'] - 后端接收的回调函数名
 * @returns {Promise} 返回 Promise
 */
function jsonp(url, params = {}, callbackName = 'callback') {
  return new Promise((resolve, reject) => {
    // 生成唯一的回调函数名
    const uniqueCallback = `jsonp_${Date.now()}_${Math.random().toString(36).slice(2)}`;
    
    // 构建 URL 参数
    const queryParams = {
      ...params,
      [callbackName]: uniqueCallback
    };
    const queryString = Object.entries(queryParams)
      .map(([k, v]) => `${encodeURIComponent(k)}=${encodeURIComponent(v)}`)
      .join('&');
    
    const fullUrl = url + (url.includes('?') ? '&' : '?') + queryString;
    
    // 创建全局回调函数
    window[uniqueCallback] = function (data) {
      resolve(data);
      cleanup();
    };
    
    // 创建 script 标签
    const script = document.createElement('script');
    script.src = fullUrl;
    script.async = true;
    
    // 超时处理
    const timeout = setTimeout(() => {
      reject(new Error('JSONP 请求超时'));
      cleanup();
    }, params.timeout || 10000);
    
    // 错误处理
    script.onerror = function () {
      reject(new Error('JSONP 加载失败'));
      cleanup();
    };
    
    // 清理函数
    function cleanup() {
      clearTimeout(timeout);
      delete window[uniqueCallback];
      document.body.removeChild(script);
    }
    
    document.body.appendChild(script);
  });
}
```

##### 实现async/await
`async/await` 是 ES2017 引入的异步编程语法糖，让异步代码看起来像同步代码。它的本质是 Generator 函数 + Promise 的语法糖。

**为什么需要 async/await？**

Promise 链式调用虽然解决了回调地狱，但在复杂异步流程中仍然存在可读性问题：
- 多个 `.then()` 链太长，逻辑分散
- 错误处理需要 `.catch()` 在链末端
- 循环中的异步操作难以用 `.then()` 表达

`async/await` 通过"暂停执行"的语义，让异步代码线性化：
- `await` 暂停函数执行，等待 Promise 解决
- 代码从上到下顺序执行，逻辑清晰
- `try/catch` 直接捕获错误

### 核心原理
1. `async` 函数返回 Promise
2. `await` 后面的表达式被 `Promise.resolve()` 包装
3. Generator 函数通过 `yield` 暂停，通过 `next()` 恢复
4. 自执行器（runner）自动驱动 Generator：每次 `yield` 返回 Promise，Promise resolve 后继续 `next()`

### 应用场景
- 顺序执行的异步操作（如先请求用户信息，再请求订单列表）
- 循环中的异步操作（如并发请求多个 URL）
- 错误处理：`try/catch` 直接包裹 `await` 表达式
- 任何需要"写同步代码做异步事"的场景

### 注意事项
- `await` 只能用于 `async` 函数内部
- `await` 后面的值会被自动包装为 Promise（即使是普通值）

##### 基于Generator函数实现async/await原理
`async/await` 的底层实现基于 Generator 函数的自执行器（runner/co）。理解这一原理，可以掌握从 ES6 Generator 到 ES2017 async/await 的演进脉络。

### 核心原理（四个关键点）
1. **async 函数返回 Promise**：自执行器返回 `new Promise((resolve, reject) => {})`
2. **Generator yield 暂停**：`yield Promise` 暂停执行，等待 Promise 解决
3. **自执行器驱动**：自动调用 `generator.next()`，在 Promise resolve 后恢复执行
4. **错误传递**：`step('throw', err)` 在 Promise reject 时向 Generator 抛错

### 自执行器的执行流程
1. 调用 `generatorFn()` 获取 Generator 实例
2. 调用 `generator.next()` 开始执行
3. 遇到 `yield Promise` 时，`Promise.resolve(value).then(val => step('next', val), err => step('throw', err))`
4. Promise resolve 后，`step('next', val)` 恢复 Generator 执行，并将值传入
5. 遇到 `return` 时 `done=true`，resolve 最终结果
6. 遇到 `throw` 时，reject 最终错误

### 应用场景
- 理解 async/await 的本质
- 在不支持 async/await 的旧环境中实现类似功能
- 面试中展示对异步演进脉络的理解

### 注意事项
- 自执行器通常封装为 `asyncWrapper` 或 `co` 函数
- `step('next', arg)` 的 `arg` 会成为上一个 `yield` 表达式的返回值
- 错误处理通过 `step('throw', err)` 向 Generator 内部抛错，可以被 Generator 内部的 `try/catch` 捕获
- 递归调用 `step` 实现 Generator 的自动驱动

```javascript
/**
 * async/await 原理实现 - 使用 Generator + Promise
 * 
 * async/await 的本质：
 * 1. async 函数会返回一个 Promise
 * 2. await 后面的表达式会被 Promise.resolve() 包装
 * 3. Generator 函数通过 yield 暂停，通过 next() 恢复执行
 * 4. 自执行器（runner）自动执行 Generator，每次 yield 返回 Promise
 *    并在 Promise resolve 后继续 next()
 */

/**
 * Generator 自执行器 - 模拟 async
 * @param {GeneratorFunction} generatorFn - Generator 函数
 * @returns {Function} 返回一个函数，执行后返回 Promise
 */
function asyncWrapper(generatorFn) {
  return function (...args) {
    const generator = generatorFn.apply(this, args);
    
    return new Promise((resolve, reject) => {
      function step(key, arg) {
        let result;
        try {
          result = generator[key](arg);
        } catch (err) {
          return reject(err);
        }
        
        const { value, done } = result;
        
        if (done) {
          return resolve(value);
        }
        
        // value 可能是 Promise 或普通值，统一用 Promise.resolve 包装
        Promise.resolve(value).then(
          val => step('next', val),
          err => step('throw', err)
        );
      }
      
      step('next');
    });
  };
}

// --- 使用示例 ---
// function* fetchData() {
//   const data1 = yield Promise.resolve('数据1');
//   console.log(data1); // '数据1'
//   const data2 = yield Promise.resolve('数据2');
//   console.log(data2); // '数据2'
//   return '完成';
// }
// 
// const asyncFetchData = asyncWrapper(fetchData);
// asyncFetchData().then(result => console.log(result)); // '完成'
```

##### 实现ES6的const

### 核心原理
- 使用 `Object.defineProperty` 在全局对象上定义属性

### const vs let vs var
- `var`：函数作用域，变量提升，可重复声明
- `let`：块级作用域，暂时性死区，不可重复声明
- `const`：块级作用域 + 不可重新赋值

- `const` 声明时必须初始化：`const a;` 报 SyntaxError
- `const` 的不可变性是指"引用不可变"，对象的内部属性仍然可变（`const obj = {}; obj.prop = 1` 是允许的）
- 模拟版通过 `Object.defineProperty(globalThis, key, {...})` 定义在全局，实际 `const` 是块级作用域的
- 严格模式下重新赋值会抛 TypeError，非严格模式下静默失败
- 深层冻结需要递归（配合 `Object.freeze`）

##### 实现ES6的extends
ES6 `extends` 关键字用于类继承，其底层原理是寄生组合式继承。手动实现可以帮助我们理解 `class` 语法糖背后的机制。

### 核心原理（三个步骤）
1. **继承父类静态属性**：`Object.setPrototypeOf(child, parent)`，让 `child.__proto__ === parent`
2. **继承父类原型方法**：`child.prototype = Object.create(parent.prototype)`，设置原型链
3. **修正 constructor**：在 `child.prototype` 上设置 `constructor: child`
4. **存储父类引用**：`child._super = parent`，便于子类访问父类

### extends 的完整机制
- 子类实例 → `child.prototype` → `parent.prototype` → `Object.prototype` → `null`
- 子类构造函数调用 `super(...)` 时，执行父类构造函数，继承实例属性
- 子类可以访问父类的静态方法（通过原型链）

### 应用场景
- 理解 ES6 `class` 语法糖的底层原理
- 在不支持 ES6 的环境中实现类继承
- 面试中展示对 JS 继承机制的理解深度

### 注意事项
- `Object.setPrototypeOf(child, parent)` 是 ES6 设置函数原型的推荐方式
- `child.prototype` 的属性描述符需要设置 `writable: true, configurable: true`，与 `class` 行为一致
- `extends` 内部不会调用父类构造函数（避免寄生组合式继承中调用两次的问题）
- `super()` 在子类构造函数中必须在使用 `this` 之前调用

```javascript
/**
 * ES6 extends 实现原理（ES5 模拟）
 * - 子类继承父类：原型链继承 + 构造函数窃取
 */
function extendsImpl(child, parent) {
  // 1. 继承父类静态属性
  Object.setPrototypeOf(child, parent);
  
  // 2. 继承父类原型方法
  child.prototype = Object.create(parent.prototype, {
    constructor: {
      value: child,
      writable: true,
      configurable: true
    }
  });
  
  // 3. 存储父类引用
  child._super = parent;
}

// --- 使用示例 ---
// function Animal(name) { this.name = name; }
// Animal.prototype.speak = function() { return this.name; };
```

##### 实现Object.create
`Object.create` 创建一个新对象，使用现有的对象作为新创建对象的原型。这是实现原型继承的核心方法。

**为什么需要 Object.create？**

- 替代 `new` 创建对象时，可以精确控制原型链
- 创建"纯净"的对象（原型为 `null`，没有任何继承）
- 实现原型式继承（Prototypal Inheritance）

### 核心原理
1. 创建一个临时构造函数 `F`
2. 将 `F.prototype` 设置为传入的 `proto`
3. 使用 `new F()` 创建对象（该对象的 `__proto__` 指向 `proto`）
4. 如果 `proto` 为 `null`，使用 `Object.setPrototypeOf(obj, null)` 设置原型为 `null`
5. 处理 `propertiesObject`：使用 `Object.defineProperties` 添加属性描述符

### 与直接使用 `Object.create` 的区别
手动实现版本展示了其内部机制。原生 `Object.create` 还支持第二个参数（属性描述符），用于定义对象自身属性（不可枚举、getter/setter 等）。

### 应用场景
- 原型式继承：`const child = Object.create(parentProto)` 创建继承父类原型的对象
- 创建纯净对象：`Object.create(null)` 创建无原型的对象（常用于字典/Map）
- 对象工厂：精确控制实例的原型链

### 注意事项
- `Object.create(null)` 创建的对象没有任何原型方法（如 `toString`、`hasOwnProperty`），适合用作纯数据容器
- 第二个参数 `propertiesObject` 使用 `Object.defineProperties` 定义，支持 `writable`、`enumerable`、`configurable`、`get`、`set`
- `proto` 必须是对象或 `null`，否则抛出 TypeError
- `Object.create` 的性能优于 `new Constructor()`，因为它不会执行构造函数

```javascript
/**
 * 实现 Object.create
 * @param {object|null} proto - 新对象的原型
 * @param {object} [propertiesObject] - 属性描述符
 * @returns {object} 新对象
 */
function myObjectCreate(proto, propertiesObject) {
  // proto 必须为对象或 null
  if (typeof proto !== 'object' && typeof proto !== 'function') {
    throw new TypeError('Object prototype may only be an Object or null');
  }
  
  // 创建一个临时构造函数
  function F() {}
  F.prototype = proto;
  F.prototype.constructor = F;
  
  const obj = new F();
  
  // 如果 proto 为 null，设置原型为 null
  if (proto === null) {
    Object.setPrototypeOf(obj, null);
  }
  
  // 处理属性描述符
  if (propertiesObject !== undefined) {
    Object.defineProperties(obj, propertiesObject);
  }
  
  return obj;
}
```

##### 实现Object.freeze
`Object.freeze` 冻结一个对象，使其属性不可修改、不可添加、不可删除。冻结后的对象是"不可变"的。

**为什么需要 Object.freeze？**

- 防止意外修改：将配置对象、常量对象冻结，避免被意外修改
- 实现不可变数据：配合 `Object.freeze` 实现简单的不可变数据结构
- 性能优化：V8 引擎对冻结对象有优化（如内联缓存）
- 安全：防止恶意代码篡改核心对象

### 核心原理
1. 获取对象所有属性（包括不可枚举的、Symbol 的）：`Object.getOwnPropertyNames` + `Object.getOwnPropertySymbols`
2. 对每个属性调用 `Object.defineProperty`，设置 `writable: false, configurable: false`
3. 递归冻结：如果属性值是对象，递归调用 `myObjectFreeze`
4. 调用 `Object.preventExtensions` 阻止添加/删除属性

### 浅冻结 vs 深冻结
- 浅冻结（`Object.freeze`）：只冻结对象自身的属性，嵌套对象不受影响
- 深冻结（递归冻结）：递归冻结所有层级的嵌套对象

### 应用场景
- 冻结配置对象，防止运行时被修改
- Vue 2 冻结 `data` 对象（防止意外修改，Vue 内部会解冻代理）
- Redux 中的不可变状态管理
- 常量定义：`const CONFIG = Object.freeze({ api: '/api' })`

### 注意事项
- `Object.freeze` 是浅冻结，深层嵌套对象需要递归冻结
- 冻结后添加/修改/删除属性在严格模式下会报 TypeError
- `seal`（`Object.seal`）允许修改现有属性，`freeze` 不允许
- Symbol 属性也需要冻结，所以需要用 `getOwnPropertySymbols`
- 性能：冻结对象在 V8 中可能获得更好的优化，但在频繁修改的场景下不适用

```javascript
/**
 * 实现 Object.freeze
 * @param {object} obj - 要冻结的对象
 * @returns {object} 被冻结的对象
 */
function myObjectFreeze(obj) {
  if (obj === null || typeof obj !== 'object') {
    return obj;
  }
  
  // 获取所有属性（包括不可枚举的、Symbol 的）
  const keys = [
    ...Object.getOwnPropertyNames(obj),
    ...Object.getOwnPropertySymbols(obj)
  ];
  
  keys.forEach(key => {
    const descriptor = Object.getOwnPropertyDescriptor(obj, key);
    
    // 重新定义属性为不可写、不可配置
    Object.defineProperty(obj, key, {
      writable: false,
      configurable: false
    });
    
    // 如果属性值是对象，递归冻结
    if (descriptor && typeof descriptor.value === 'object' && descriptor.value !== null) {
      myObjectFreeze(descriptor.value);
    }
  });
  
  // 阻止添加/删除属性
  Object.preventExtensions(obj);
  
  return obj;
}
```

##### 实现Object.is
`Object.is` 判断两个值是否为同一个值，与严格相等运算符 `===` 类似，但在两个特殊场景下行为不同。

### 与 `===` 的区别
| 场景 | `===` | `Object.is` |
|------|-------|-------------|
| `NaN` vs `NaN` | `false` | `true` |
| `+0` vs `-0` | `true` | `false` |
| 其他值 | 一致 | 一致 |

### 核心原理
1. **NaN 处理**：`NaN !== NaN`，但 `Object.is(NaN, NaN)` 应该返回 `true`。判断方法：`a !== a && b !== b`（只有 NaN 满足自身不等于自身）
2. **±0 处理**：`1 / +0 === Infinity`，`1 / -0 === -Infinity`。通过 `1 / a === 1 / b` 区分 `+0` 和 `-0`
3. **其他情况**：直接使用 `===` 比较

### 应用场景
- 精确比较两个值是否相等，需要区分 `NaN` 和 `±0`
- 实现自定义的相等性判断逻辑
- 面试中考察对 JS 特殊值行为的理解

### 注意事项
- `Object.is` 不进行类型转换（与 `===` 相同，不进行隐式类型转换）
- `Object.is` 是 ES2015 引入的方法，旧浏览器需要 polyfill
- `Object.is` 与 `Object.equal`（不存在）不同，后者可能会进行递归比较
- `+0` 和 `-0` 在大多数场景下行为相同，但在某些数学计算中不同（如 `1 / +0 = Infinity`，`1 / -0 = -Infinity`）

```javascript
/**
 * 实现 Object.is
 * @param {any} a
 * @param {any} b
 * @returns {boolean}
 */
function myObjectIs(a, b) {
  // 处理 NaN 的情况
  if (a !== a && b !== b) {
    return true;
  }
  
  // 处理 +0 和 -0 的情况
  if (a === 0 && b === 0) {
    return 1 / a === 1 / b; // 1/+0 = Infinity, 1/-0 = -Infinity
  }
  
  return a === b;
}
```

##### 实现一个compose函数
`compose` 函数将多个函数组合成一个函数，从右到左依次执行。这是函数式编程中的核心工具函数，在 Redux 中间件、Koa 洋葱模型等场景中广泛使用。

### 核心原理
- 从右到左执行：`compose(f, g, h)(x)` = `f(g(h(x)))`
- 使用 `reduceRight` 或 `reduce` 实现函数组合
- 边界情况：空函数列表返回 `arg => arg`（恒等函数），单函数直接返回

### compose vs pipe
- `compose(f, g, h)`：从右到左，`f(g(h(x)))`
- `pipe(f, g, h)`：从左到右，`h(g(f(x)))`
- 两者互为反向

### 应用场景
- Redux 中间件：`applyMiddleware(thunk, logger, saga)` 内部使用 compose
- Koa 洋葱模型：中间件从外到内再从内到外执行
- 数据处理管道：一系列数据转换函数组合
- 函数式编程：将复杂操作分解为多个小函数的组合

### 注意事项
- 所有函数必须是单输入单输出（unary）
- 函数执行顺序很重要：compose 从右到左，pipe 从左到右
- 每个函数只接收前一个函数的返回值，不能访问原始参数
- compose 中的函数应该是纯函数（相同输入始终返回相同输出）
- 空列表时返回恒等函数，这是数学上的单位元

```javascript
/**
 * 实现 compose 函数 - 从右到左组合
 * @param {...Function} fns - 要组合的函数
 * @returns {Function} 组合后的函数
 */
function compose(...fns) {
  if (fns.length === 0) {
    return arg => arg;
  }
  
  if (fns.length === 1) {
    return fns[0];
  }
  
  return fns.reduce((prev, next) => {
    return (...args) => prev(next(...args));
  });
}

/**
 * 实现 pipe 函数 - 从左到右组合（compose 的反向）
 * @param {...Function} fns - 要组合的函数
 * @returns {Function} 组合后的函数
 */
function pipe(...fns) {
  if (fns.length === 0) {
    return arg => arg;
  }
  
  if (fns.length === 1) {
    return fns[0];
  }
  
  return fns.reduce((prev, next) => {
    return (...args) => next(prev(...args));
  });
}

// --- 使用示例 ---
// const add1 = x => x + 1;
// const double = x => x * 2;
// const composed = compose(double, add1); // double(add1(x))
// console.log(composed(3)); // 8 ((3+1)*2)
```

##### 实现一个迭代器生成函数
迭代器（Iterator）是 ES6 引入的核心概念，为 `for...of`、展开运算符、解构赋值等提供了基础。迭代器必须实现 `next()` 方法，返回 `{ value, done }` 结构。

**为什么需要迭代器？**

在 ES6 之前，遍历集合（数组、对象）没有统一的接口。迭代器协议（Iterator Protocol）提供了一种标准化的方式：
- 任何实现了 `[Symbol.iterator]` 方法的对象都是"可迭代的"
- 可迭代对象可以用 `for...of` 遍历、用 `[...]` 展开、用解构赋值

### 核心原理
1. **迭代器对象**：包含 `next()` 方法
2. **next() 返回值**：`{ value: any, done: boolean }`
   - `done: false` 表示还有更多元素
   - `done: true` 表示遍历结束，`value` 为返回值（`undefined` 或指定的返回值）
3. **可迭代协议**：对象实现 `[Symbol.iterator]()` 方法，返回迭代器对象
4. **状态维护**：迭代器内部维护当前位置（如 `current` 变量）

### 应用场景
- 自定义数据结构的遍历（如链表、树、图）
- 生成器函数（Generator）的基础
- `for...of`、展开运算符、解构赋值的底层实现
- 懒加载/无限序列：按需生成值，不一次性创建全部数据

### 注意事项
- `done: true` 时 `value` 可以是任意值（通常是 `undefined`）
- 迭代器是"一次性"的，遍历完后需要重新创建
- 可迭代对象与数组不同，不能直接通过索引访问
- 使用 `Symbol.iterator` 作为方法名，这是 ES6 的内置 Symbol

```javascript
/**
 * 手动实现迭代器生成函数
 * 迭代器必须实现 next() 方法，返回 { value, done }
 */

/**
 * 创建一个范围迭代器
 * @param {number} start - 起始值
 * @param {number} end - 结束值
 * @param {number} [step=1] - 步长
 * @returns {object} 迭代器
 */
function createRangeIterator(start, end, step = 1) {
  let current = start;
  
  const iterator = {
    next() {
      if (current <= end) {
        const value = current;
        current += step;
        return { value, done: false };
      }
      return { value: undefined, done: true };
    }
  };
  
  return iterator;
}

/**
 * 使普通对象可迭代 - 实现 [Symbol.iterator]
 */
function makeIterable(obj) {
  obj[Symbol.iterator] = function () {
    const keys = Object.keys(this);
    let index = 0;
    
    return {
      next: () => {
        if (index < keys.length) {
          const key = keys[index++];
          return { value: { key, value: obj[key] }, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  };
  return obj;
}
```

##### ES6对迭代器的实现
ES6 提供了多种内置的迭代器实现方式：`for...of` 循环、`Array`、`Map`、`Set`、`String`、`Generator` 等。所有内置集合类型都实现了可迭代协议。

### ES6 的可迭代协议
- 任何实现了 `[Symbol.iterator]` 方法的对象都是"可迭代的"
- `[Symbol.iterator]()` 返回一个迭代器对象（包含 `next()` 方法）
- `for...of` 循环内部自动调用 `[Symbol.iterator]()` 并反复调用 `next()`

### 常见可迭代对象
- `Array`：迭代每个元素
- `String`：迭代每个字符
- `Map`：迭代每个 `[key, value]` 数组
- `Set`：迭代每个值
- `Arguments` 对象：类数组，可迭代
- `DOM NodeList`：某些浏览器支持

### 与数组遍历的区别
- `for...of` 使用迭代器协议，可以遍历任何可迭代对象
- `for...in` 遍历对象的可枚举属性（包括原型链上的），不适合遍历数组
- `forEach` 是数组方法，无法用于 Map/Set

### 应用场景
- 使用 `for...of` 遍历 Map/Set（比 `forEach` 更灵活）
- 展开运算符 `[...iterable]` 将可迭代对象转为数组
- 解构赋值 `[a, b, ...rest] = iterable`
- 自定义类的迭代行为

### 注意事项
- 普通对象 `{}` 默认不可迭代（没有 `[Symbol.iterator]`），需要手动实现
- 迭代器是"一次性"的，遍历完后需要重新获取
- `for...of` 不能直接遍历对象（需要先转为 `Object.entries(obj)`）
- `Symbol.iterator` 是 ES6 内置 Symbol，不需要手动创建

```javascript
/**
 * ES6 迭代器实现 - 可迭代协议 [Symbol.iterator]
 */

// 实现一个可迭代的数组包装器
class IterableArray {
  constructor(arr) {
    this.data = arr;
  }
  
  // 实现 [Symbol.iterator] 方法
  [Symbol.iterator]() {
    let index = 0;
    const data = this.data;
    
    return {
      next() {
        if (index < data.length) {
          return { value: data[index++], done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
}

// --- 使用示例 ---
// const arr = new IterableArray([10, 20, 30]);
// for (const item of arr) {
//   console.log(item); // 10, 20, 30
// }
// console.log([...arr]); // [10, 20, 30]
```

##### 实现迭代器生成函数 - Generator版
Generator 函数是 ES6 提供的生成器函数，通过 `yield` 关键字实现函数的暂停和恢复，返回一个迭代器对象。

**为什么需要 Generator？**

手写迭代器需要手动维护 `current` 状态变量，代码冗长。Generator 函数让迭代器的编写变得简洁：
- `yield` 自动暂停执行，保存当前状态
- 函数返回的迭代器自动实现 `next()` 方法
- 无需手动管理状态变量和迭代逻辑

### 核心原理
1. `function*` 声明 Generator 函数
2. `yield value` 暂停执行，返回 `{ value, done: false }`
3. 下一次 `next()` 调用恢复执行，直到下一个 `yield` 或 `return`
4. 函数执行完毕返回 `{ value: returnValue, done: true }`

### Generator vs 普通迭代器
- 普通迭代器：手动实现 `next()`，维护状态变量
- Generator：`yield` 自动处理暂停/恢复，代码更简洁

### 应用场景
- 生成序列：`rangeGenerator(1, 100)` 生成 1 到 100 的序列
- 无限序列：`function* infinite() { let i = 0; while (true) yield i++; }`
- 惰性求值：按需生成值，节省内存
- 状态机：用 `yield` 实现复杂的状态转换

### 注意事项
- Generator 函数调用后不立即执行，返回的是迭代器对象
- 第一次 `next()` 才开始执行，遇到第一个 `yield` 暂停
- `next(arg)` 传入的值会成为上一个 `yield` 表达式的返回值
- Generator 可以提前终止（`return` 或 `throw`）
- `Symbol.iterator` 方法用 `function*` 声明，自动返回迭代器

```javascript
/**
 * 使用 Generator 函数实现迭代器
 * Generator 函数返回一个迭代器，每次调用 next() 执行到下一个 yield
 */

// 创建一个范围迭代器 - Generator 版
function* rangeGenerator(start, end, step = 1) {
  for (let i = start; i <= end; i += step) {
    yield i;
  }
}

// --- 使用示例 ---
// const iter = rangeGenerator(1, 5);
// console.log(iter.next()); // { value: 1, done: false }
// console.log([...rangeGenerator(1, 3)]); // [1, 2, 3]

/**
 * 使对象可迭代 - Generator 版
 * @param {object} obj - 普通对象
 * @returns {object} 可迭代的对象
 */
function makeIterableWithGenerator(obj) {
  obj[Symbol.iterator] = function* () {
    const keys = Object.keys(this);
    for (const key of keys) {
      yield { key, value: this[key] };
    }
  };
  return obj;
}
```

##### setTimeout 模拟实现 setInterval
使用 `setTimeout` 递归调用模拟 `setInterval`，可以避免原生 `setInterval` 的一些固有缺陷。

**为什么需要模拟 setInterval？**

原生 `setInterval` 存在几个问题：
- **执行叠加**：如果回调函数执行时间超过间隔时间，会出现"堆积"现象（上一次还没执行完，下一次又开始了）
- **无法暂停**：`setInterval` 一旦启动就持续执行，无法控制暂停
- **时间漂移**：如果回调执行耗时，实际间隔会大于设定值

使用 `setTimeout` 递归可以解决这些问题：每次执行完回调后再设置下一次定时器，确保"上一次执行完成后才开始计时"。

### 核心原理
1. 定义一个内部 `loop` 函数
2. `loop` 内部使用 `setTimeout` 延迟执行回调
3. 回调执行完后，再次调用 `loop()`，形成递归
4. 返回一个包含 `clear()` 方法的对象，用于停止定时器

### setTimeout 递归 vs setInterval
| 特性 | setTimeout 递归 | setInterval |
|------|----------------|-------------|
| 执行叠加 | 不会（等上次完成） | 会 |
| 时间控制 | 精确（执行完后计时） | 可能漂移 |
| 暂停能力 | 可以（不调用 loop） | 不可以 |
| 首次延迟 | 有（第一次 setTimeout） | 有 |

### 应用场景
- 轮询请求：确保上一次请求完成后再发起下一次
- 动画帧控制：确保上一帧渲染完成后再开始下一帧
- 需要精确时间控制的定时任务

### 注意事项
- `timerId` 需要在每次 `setTimeout` 后更新，`clearTimeout` 清除的是最新的定时器
- `loop()` 函数需要先调用一次，否则定时器不会启动
- `clear()` 方法需要将 `timerId` 置为 `null`，便于状态管理
- 如果回调函数抛出异常，递归会终止，需要 try/catch 保护

```javascript
/**
 * 使用 setTimeout 模拟实现 setInterval
 * 优势：可以等待上一次任务执行完成后再开始计时，避免 setInterval 可能存在的执行叠加问题
 * 
 * @param {Function} fn - 要执行的函数
 * @param {number} delay - 间隔时间（毫秒）
 * @param {...any} args - 传递给函数的参数
 * @returns {object} 返回一个包含 clear 方法的对象，用于停止定时器
 */
function mySetInterval(fn, delay, ...args) {
  let timerId = null;
  
  function loop() {
    timerId = setTimeout(() => {
      fn(...args);
      loop(); // 递归调用，实现循环
    }, delay);
  }
  
  loop();
  
  // 返回一个对象，提供取消方法
  return {
    clear() {
      clearTimeout(timerId);
      timerId = null;
    }
  };
}

// --- 使用示例 ---
// const timer = mySetInterval(() => console.log('tick'), 1000);
// setTimeout(() => timer.clear(), 5000); // 5秒后停止
```

##### setInterval 模拟实现 setTimeout
使用 `setInterval` 模拟 `setTimeout`，实现"延迟执行一次"的效果。

### 核心原理
1. 使用 `setInterval` 启动一个定时器
2. 第一次触发时，立即 `clearInterval` 清除定时器
3. 执行回调函数
4. 返回包含 `clear()` 方法的对象

### 与原生 setTimeout 的区别
- 原生 `setTimeout` 使用单独的定时器 API
- 模拟版使用 `setInterval`，第一次触发时清除自身
- 两者都只执行一次，但实现机制不同

### 应用场景
- 面试中考察对定时器 API 的理解
- 在不支持 `setTimeout` 的环境中（极少数情况）的替代方案

### 注意事项
- `setInterval` 的最小间隔通常受浏览器限制（约 4ms）
- `clearInterval` 必须在回调中立即执行，否则可能再次触发
- 返回 `{ clear() }` 对象而不是直接返回 `timerId`，提供更友好的 API
- 这种实现方式在实际工程中不推荐，因为 `setInterval` 在页面后台时会降频（浏览器优化），而 `setTimeout` 不受影响

```javascript
/**
 * 使用 setInterval 模拟实现 setTimeout

 */
function mySetTimeout(fn, delay, ...args) {
  const timerId = setInterval(() => {
    clearInterval(timerId);
    fn(...args);
  }, delay);

    clear() {
      clearInterval(timerId);
    }
  };
}
```

##### 实现Node的require方法
`require` 是 Node.js 中模块加载的核心方法。理解其实现原理，有助于掌握 CommonJS 模块规范和 Node.js 的模块系统。

**为什么需要模块系统？**

在大型项目中，代码需要拆分到多个文件。模块系统解决了以下问题：
- 作用域隔离：每个模块有独立的作用域，变量不会互相污染
- 依赖管理：自动处理模块之间的依赖关系
- 代码复用：模块可以被多个文件引用
- 循环依赖：通过缓存机制处理循环引用

### 核心原理（6 个步骤）
1. **解析路径**：将相对路径/模块名转为绝对路径（`path.resolve`）
2. **检查缓存**：模块只加载一次，后续引用直接返回缓存
3. **创建模块对象**：`{ exports: {} }`，后续代码执行后填充
4. **读取文件**：同步读取 `.js`/`.json`/`.node` 文件内容
5. **包装执行**：用函数包装器包裹模块代码，传入 `exports`/`require`/`module`/`__filename`/`__dirname`
6. **返回 exports**：执行完成后返回 `module.exports`

### CommonJS vs ES Modules
- CommonJS：`require`/`module.exports`，运行时加载，值拷贝
- ES Modules：`import`/`export`，编译时加载，引用绑定

### 应用场景
- 理解 Node.js 模块加载机制
- 面试中考察对 CommonJS 规范的掌握
- 自定义模块加载器

### 注意事项
- `moduleCache` 使用绝对路径作为键，防止不同路径指向同一文件时的缓存不一致
- 循环依赖通过缓存解决：模块 A 引用 B，B 引用 A，A 的 `exports` 可能还未完全填充
- `.json` 文件直接 `JSON.parse`，`.node` 文件是 C++ 扩展（本实现只处理 `.js`）
- `wrapper` 函数模拟了 Node.js 实际的模块包装（V8 的 `compileFunction`）
- 本实现是简化版，实际 `require` 还处理了 `node_modules` 查找、`NODE_PATH`、内置模块等

```javascript
/**
 * 简易实现 Node.js 的 require 方法
 * 
 * require 的核心机制：
 * 1. 解析模块路径
 * 2. 读取文件内容
 * 3. 用函数包装器包裹模块代码
 * 4. 传入 exports, require, module, __filename, __dirname
 * 5. 执行模块代码
 * 6. 返回 exports
 */
const fs = require('fs');
const path = require('path');

// 缓存已加载的模块
const moduleCache = {};

/**
 * 模拟 require 函数
 * @param {string} filePath - 模块文件路径
 * @returns {any} 模块导出的内容
 */
function myRequire(filePath) {
  // 1. 解析绝对路径
  const absolutePath = path.resolve(__dirname, filePath);
  
  // 2. 检查缓存
  if (moduleCache[absolutePath]) {
    return moduleCache[absolutePath].exports;
  }
  
  // 3. 创建模块对象
  const module = { exports: {} };
  moduleCache[absolutePath] = module;
  
  // 4. 读取文件内容
  let code;
  try {
    code = fs.readFileSync(absolutePath, 'utf-8');
  } catch (err) {
    throw new Error(`Cannot find module '${filePath}'`);
  }
  
  // 5. 创建包装函数（Node.js 实际上用 V8 的 compileFunction 包装）
  const wrapper = Function('exports', 'require', 'module', '__filename', '__dirname', code);
  
  // 6. 执行模块代码
  wrapper(module.exports, myRequire, module, absolutePath, path.dirname(absolutePath));
  
  return module.exports;
}
```

##### 实现LRU淘汰算法
LRU（Least Recently Used）最近最少使用缓存淘汰算法。当缓存满时，淘汰最久未使用的数据。这是计算机科学中最经典的缓存策略之一。

**为什么需要 LRU？**

在实际应用中，内存是有限的，但数据量可以无限增长：
- 浏览器缓存（图片、API 响应）
- 数据库查询缓存
- React/Vue 的虚拟 DOM diff 缓存
- 任何需要"有限内存存储无限数据"的场景

### 核心原理
1. **容量限制**：缓存有固定大小（capacity）
2. **最近使用追踪**：每次 get/put 操作都将该键标记为"最近使用"
3. **淘汰策略**：缓存满时，删除"最久未使用"的键
4. **数据结构**：使用 `Map` 保持插入顺序（Map 的迭代顺序 = 插入顺序）

### LRU 的操作逻辑
- `get(key)`：如果 key 存在，将其移到末尾（最近使用），返回值；否则返回 -1
- `put(key, value)`：如果 key 已存在，删除后重新插入（移到末尾）；如果容量满，删除 Map 的第一个元素（最久未使用）

### 时间复杂度
- `get`：O(1) — Map 的 has/get/delete/set 都是 O(1)
- `put`：O(1) — 同上

### 应用场景
- 图片缓存：浏览器中缓存已加载的图片
- API 响应缓存：缓存接口数据，减少请求
- 数据库查询缓存：缓存常用查询结果
- 操作系统页面置换

### 注意事项
- `Map` 的迭代顺序就是插入顺序，第一个元素是最久未使用的
- `get` 时需要 `delete` + `set` 将元素移到末尾（更新为最近使用）
- `put` 时如果 key 已存在，先 `delete` 再 `set`（保持顺序正确）
- `Map` 的 `keys().next().value` 获取第一个键（最久未使用）
- 面试中常考察 LRU，需要能手写并说明复杂度

```javascript
/**
 * LRU 缓存淘汰算法实现
 * 使用 Map 保证插入顺序（迭代顺序 = 插入顺序）
 * 
 * 时间复杂度：get O(1), put O(1)
 * 空间复杂度：O(capacity)
 */
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity;   // 缓存容量
    this.cache = new Map();     // 使用 Map 保持键值对顺序
  }
  
  /**
   * 获取缓存值
   * @param {any} key - 键
   * @returns {any} 值，不存在返回 -1
   */
  get(key) {
    if (!this.cache.has(key)) {
      return -1;
    }
    
    // 将该键移到末尾（表示最近使用）
    const value = this.cache.get(key);
    this.cache.delete(key);
    this.cache.set(key, value);
    
    return value;
  }
  
  /**
   * 设置缓存值
   * @param {any} key - 键
   * @param {any} value - 值
   */
  put(key, value) {
    // 如果已存在，先删除
    if (this.cache.has(key)) {
      this.cache.delete(key);
    }
    
    // 如果容量满了，删除最久未使用的（Map 的第一个元素）
    if (this.cache.size >= this.capacity) {
      const oldestKey = this.cache.keys().next().value;
      this.cache.delete(oldestKey);
    }
    
    // 插入到末尾（表示最近使用）
    this.cache.set(key, value);
  }
  
  /**
   * 获取当前缓存大小
   * @returns {number}
   */
  size() {
    return this.cache.size;
  }
  
  /**
   * 清空缓存
   */
  clear() {
    this.cache.clear();
  }
}

// --- 使用示例 ---
// const lru = new LRUCache(2);
// lru.put(1, 'a');
// lru.put(2, 'b');
// console.log(lru.get(1)); // 'a'（1被移到最近使用）
// lru.put(3, 'c');         // 容量已满，淘汰最久未使用的2
// console.log(lru.get(2)); // -1（已被淘汰）
```

### 框架相关
##### 将虚拟 Dom 转化为真实 Dom
虚拟 DOM（Virtual DOM）是真实 DOM 的 JavaScript 对象表示。将虚拟 DOM 转化为真实 DOM 是前端框架（如 React、Vue）的核心渲染流程。

**为什么需要虚拟 DOM？**

直接操作真实 DOM 存在性能问题：
- `createElement`/`appendChild` 等操作会引起浏览器的重排（Reflow）和重绘（Repaint）
- 频繁的 DOM 操作是性能杀手
- 虚拟 DOM 在内存中操作，批量更新时通过 diff 算法最小化真实 DOM 操作

### 核心原理
1. **字符串/数字**：创建文本节点 `document.createTextNode(vnode)`
2. **数组（Fragment）**：创建文档片段 `document.createDocumentFragment`，批量插入子节点
3. **对象节点**：
   - 创建 DOM 元素 `document.createElement(vnode.tag)`
   - 设置属性：事件监听（`on*` → `addEventListener`）、`class`/`className`、`style`、`htmlFor` 等
   - 递归渲染子节点并 `appendChild`

### 虚拟 DOM 结构
```javascript
{
  tag: 'div',
  attrs: { class: 'container', id: 'app' },
  children: [
    { tag: 'h1', attrs: {}, children: ['标题'] },
    { tag: 'p', attrs: {}, children: ['段落'] }
  ]
}
```

### 应用场景
- React 的 `ReactDOM.render` 内部使用类似算法
- Vue 的 `h` 函数（createElement）创建的 VNode 最终通过 render 转为 DOM
- 理解框架渲染原理的基础

### 注意事项
- 事件监听：`onClick` → `addEventListener('click', ...)`
- `className` 和 `class` 都要处理
- `style` 是对象时用 `Object.assign` 合并
- `htmlFor` 对应原生的 `htmlFor` 属性（label 的 for 属性）
- 其他属性用 `setAttribute` 设置
- 递归处理子节点，支持多层级嵌套

```javascript
/**
 * 将虚拟 DOM 转化为真实 DOM
 * 
 * 虚拟 DOM 结构示例：
 * {
 *   tag: 'div',
 *   attrs: { class: 'container', id: 'app' },
 *   children: [
 *     { tag: 'h1', attrs: {}, children: ['标题'] },
 *     { tag: 'p', attrs: {}, children: ['段落'] }
 *   ]
 * }
 */

/**
 * 将虚拟 DOM 节点渲染为真实 DOM 节点
 * @param {object} vnode - 虚拟 DOM 对象
 * @returns {HTMLElement} 真实 DOM 节点
 */
function render(vnode) {
  // 如果是字符串或数字，创建文本节点
  if (typeof vnode === 'string' || typeof vnode === 'number') {
    return document.createTextNode(vnode);
  }
  
  // 如果 vnode 是数组（Fragment），创建文档片段
  if (Array.isArray(vnode)) {
    const fragment = document.createDocumentFragment();
    vnode.forEach(child => fragment.appendChild(render(child)));
    return fragment;
  }
  
  // 创建 DOM 元素
  const dom = document.createElement(vnode.tag);
  
  // 设置属性
  if (vnode.attrs) {
    for (const [key, value] of Object.entries(vnode.attrs)) {
      // 处理事件监听
      if (key.startsWith('on')) {
        const eventType = key.slice(2).toLowerCase();
        dom.addEventListener(eventType, value);
      } else if (key === 'className' || key === 'class') {
        dom.className = value;
      } else if (key === 'style' && typeof value === 'object') {
        Object.assign(dom.style, value);
      } else if (key === 'htmlFor') {
        dom.htmlFor = value;
      } else {
        dom.setAttribute(key, value);
      }
    }
  }
  
  // 递归渲染子节点
  if (vnode.children) {
    vnode.children.forEach(child => dom.appendChild(render(child)));
  }
  
  return dom;
}
```

##### 实现事件总线结合Vue应用
事件总线（EventBus）是 Vue 2 中常用的跨组件通信方案。通过发布订阅模式实现组件间的解耦通信。

**为什么需要事件总线？**

Vue 组件之间有三种通信方式：
- `props` + `$emit`：父子组件通信
- `$refs` / `$parent` / `$children`：直接访问组件实例（不推荐）
- **事件总线**：任意组件间通信，不需要共享父组件

当组件树较深或组件间没有直接父子关系时，事件总线是最简洁的方案。

### 核心原理
1. 创建全局 `EventBus` 实例
2. 组件 A：`eventBus.emit('eventName', data)` 触发事件
3. 组件 B：`eventBus.on('eventName', callback)` 监听事件
4. 组件销毁时：`eventBus.off('eventName', callback)` 取消监听

### EventBus 的设计要点
- 使用 `Map` 存储事件和回调的映射（方便通过 ID 精确取消）
- `on` 返回事件 ID，便于精确取消订阅
- `off` 支持三种方式：传 ID 删除、传回调删除、不传参数删除整个事件
- `once` 包装回调，执行后自动取消

### 应用场景
- 兄弟组件通信：A 组件触发事件，B 组件监听
- 跨层级通信：深层子组件触发事件，祖先组件监听
- 全局状态通知：用户登录/登出、主题切换等全局事件

### 注意事项
- Vue 3 中移除了 `$on`/`$off`/`$emit`，推荐使用 mitt 库或 `provide/inject`
- 事件总线滥用会导致"数据流向不可追踪"，适合少量全局事件，不适合复杂状态管理
- 组件销毁时一定要 `off`，否则会造成内存泄漏
- 使用 ID 管理事件可以精确取消单个监听，比传回调更可靠
- 事件回调中的错误应该被捕获，避免影响其他订阅者

```javascript
/**
 * 事件总线 - 结合 Vue 应用
 * Vue 2 中常用 EventBus 进行组件间通信
 */

// 事件总线类（发布订阅模式）
class EventBus {
  constructor() {
    this.events = {};
    this._eventId = 0;
  }
  
  /**
   * 监听事件
   * @param {string} event - 事件名
   * @param {Function} callback - 回调
   * @returns {number} 事件 ID，用于取消
   */
  on(event, callback) {
    if (!this.events[event]) {
      this.events[event] = new Map();
    }
    const id = ++this._eventId;
    this.events[event].set(id, callback);
    return id;
  }
  
  /**
   * 触发事件
   * @param {string} event - 事件名
   * @param {...any} args - 参数
   */
  emit(event, ...args) {
    if (this.events[event]) {
      this.events[event].forEach(callback => {
        callback(...args);
      });
    }
  }
  
  /**
   * 取消监听
   * @param {string} event - 事件名
   * @param {number|Function} target - 事件 ID 或回调函数
   */
  off(event, target) {
    if (!this.events[event]) return;
    
    if (typeof target === 'number') {
      this.events[event].delete(target);
    } else if (typeof target === 'function') {
      for (const [id, cb] of this.events[event]) {
        if (cb === target) {
          this.events[event].delete(id);
        }
      }
    } else {
      delete this.events[event];
    }
  }
  
  /**
   * 监听一次
   * @param {string} event - 事件名
   * @param {Function} callback - 回调
   */
  once(event, callback) {
    const wrapper = (...args) => {
      callback(...args);
      this.off(event, wrapper);
    };
    this.on(event, wrapper);
  }
}

// 创建全局事件总线
const eventBus = new EventBus();

// --- Vue 中使用示例 ---
// // 组件A：发送数据
// eventBus.emit('userLogin', { name: '张三', id: 123 });
// 
// // 组件B：接收数据
// eventBus.on('userLogin', (user) => {
//   console.log('用户登录:', user);
// });
```

##### 实现一个双向绑定
双向绑定（Two-way Binding）是 Vue 2 的核心特性之一，让视图（View）和数据（Model）自动同步：视图变化更新数据，数据变化更新视图。

**为什么需要双向绑定？**

在传统开发中，手动同步数据和视图是繁琐的：
- 输入框变化 → 手动读取 `value` → 更新数据对象
- 数据对象变化 → 手动查找 DOM → 更新 `value`
- 表单多字段时，代码冗余且容易遗漏

双向绑定自动完成这些同步，开发者只需关心数据逻辑。

### 核心原理（基于 Object.defineProperty）
1. **数据 → 视图**：`set` 拦截器在数据变化时，更新 DOM 元素的 `value`
2. **视图 → 数据**：监听 DOM 的 `input` 事件，将新值赋给数据对象（触发 `set`）
3. **闭包保存引用**：通过闭包保存 DOM 元素引用和数据 key

### Vue 2 完整双向绑定的机制
- `Object.defineProperty` 劫持数据对象的 getter/setter
- `Dep`（依赖收集器）收集所有依赖该数据的 Watcher
- `Watcher` 持有更新 DOM 的回调
- `set` 触发时 `Dep.notify()`，通知所有 Watcher 更新 DOM

### 应用场景
- 表单处理：输入框实时同步到数据模型
- 数据绑定框架（Vue 2 的 `v-model`）
- 任何需要"视图与数据自动同步"的场景

### 注意事项
- Vue 3 改用 `Proxy`，解决了 `Object.defineProperty` 无法检测新增/删除属性、无法检测数组索引变化的问题
- `Object.defineProperty` 需要预先知道所有要劫持的 key
- 数组变化需要通过重写数组方法（`push`/`pop`/`splice` 等）来触发更新
- 初始化时需要先读取一次 `value`（触发 getter），确保 DOM 显示初始值
- 双向绑定可能导致"无限循环"（数据变化 → 视图更新 → 视图事件 → 数据变化），需要小心处理

```javascript
/**
 * 实现双向绑定 - 基于 Object.defineProperty
 * 类似于 Vue 2 的响应式原理
 */

function twoWayBinding(data, key, selector) {
  const element = document.querySelector(selector);
  
  // 定义响应式属性
  Object.defineProperty(data, key, {
    get() {
      return element ? element.value : null;
    },
    set(newValue) {
      if (element) {
        element.value = newValue;
      }
    },
    configurable: true
  });
  
  // 监听输入事件，更新数据
  if (element) {
    element.addEventListener('input', function () {
      data[key] = this.value; // 触发 setter
    });
  }
}

// twoWayBinding(data, 'message', '#inputEl');

// // data.message = '新值' -> 页面输入框更新
```

##### 实现一个简易的MVVM
MVVM（Model-View-ViewModel）是一种架构模式，核心是数据劫持 + 发布订阅，实现数据变化自动驱动视图更新。Vue.js 的核心思想就是 MVVM。

### MVVM 的三个组成部分
- **Model（数据模型）**：纯 JS 对象，存储应用数据
- **View（视图）**：HTML 模板，负责展示
- **ViewModel（视图模型）**：连接 Model 和 View 的桥梁，通过数据劫持和编译实现自动同步

### 核心原理（四层架构）
1. **Dep（依赖收集器）**：每个响应式属性对应一个 Dep，存储所有依赖该属性的 Watcher
2. **Watcher（观察者）**：在读取数据时触发 `Dep.depend()` 收集依赖，数据变化时 `Dep.notify()` 通知更新
3. **Observer（数据劫持）**：通过 `Object.defineProperty` 劫持所有属性的 getter/setter
4. **Compile（编译器）**：解析模板，将 `{{ }}` 插值和 `v-model` 指令编译为 Watcher

### 数据劫持 + 发布订阅的流程
1. `observe(data)` 递归遍历 data，为每个属性定义 getter/setter
2. `getter` 中调用 `dep.depend()`，将当前 Watcher 加入依赖列表
3. `setter` 中调用 `dep.notify()`，通知所有 Watcher 更新视图
4. `Compile` 解析模板时创建 Watcher，Watcher 读取数据触发依赖收集
5. 数据变化 → setter → dep.notify() → Watcher.update() → DOM 更新

### Vue 2 vs Vue 3 的响应式区别
- Vue 2：`Object.defineProperty`，需要预先遍历所有 key，无法检测新增/删除属性
- Vue 3：`Proxy`，懒代理（访问到才代理），支持新增/删除，性能更好

### 应用场景
- 理解 Vue 的响应式原理
- 面试中展示对 MVVM 架构的理解
- 实现简化版数据绑定框架

### 注意事项
- `Dep.target` 是静态变量，存储当前正在执行的 Watcher（实现依赖收集的关键）
- `Watcher.get()` 中先设置 `Dep.target = this`，读取数据后重置为 `null`
- 深层对象需要递归劫持（`observe` 递归调用）
- 数组方法需要重写（`push`/`pop`/`splice` 等），否则无法触发 setter
- 编译器只处理 `v-model` 和 `{{ }}`，实际 Vue 还支持 `v-bind`、`v-on`、`v-if` 等指令

```javascript
/**
 * 简易 MVVM 实现
 * 
 * MVVM = Model（数据模型）+ View（视图）+ ViewModel（视图模型）
 * 核心是数据劫持 + 发布订阅模式，实现数据变化驱动视图更新
 */

// 1. 观察者（依赖收集器）
class Dep {
  constructor() {
    this.subscribers = new Set();
  }
  
  depend() {
    if (Dep.target) {
      this.subscribers.add(Dep.target);
    }
  }
  
  notify() {
    this.subscribers.forEach(sub => sub.update());
  }
}

Dep.target = null;

// 2. 观察者（Watcher）
class Watcher {
  constructor(vm, key, callback) {
    this.vm = vm;
    this.key = key;
    this.callback = callback;
    this.value = this.get();
  }
  
  get() {
    Dep.target = this;
    const value = this.vm.data[this.key];
    Dep.target = null;
    return value;
  }
  
  update() {
    const newValue = this.vm.data[this.key];
    if (newValue !== this.value) {
      this.value = newValue;
      this.callback(newValue);
    }
  }
}

// 3. 数据劫持
function observe(data) {
  if (!data || typeof data !== 'object') return;
  
  Object.keys(data).forEach(key => {
    defineReactive(data, key, data[key]);
  });
}

function defineReactive(obj, key, val) {
  const dep = new Dep();
  
  // 递归劫持嵌套对象
  observe(val);
  
  Object.defineProperty(obj, key, {
    get() {
      dep.depend();
      return val;
    },
    set(newVal) {
      if (newVal === val) return;
      val = newVal;
      observe(newVal); // 新值可能是对象
      dep.notify();
    }
  });
}

// 4. 编译器（Compile）
class Compile {
  constructor(el, vm) {
    this.vm = vm;
    this.el = document.querySelector(el);
    this.compile(this.el);
  }
  
  compile(node) {
    const childNodes = node.childNodes;
    childNodes.forEach(child => {
      if (child.nodeType === 1) { // 元素节点
        this.compileElement(child);
        this.compile(child); // 递归编译子节点
      } else if (child.nodeType === 3) { // 文本节点
        this.compileText(child);
      }
    });
  }
  
  compileElement(node) {
    // 处理 v-model 指令
    if (node.hasAttribute('v-model')) {
      const key = node.getAttribute('v-model');
      node.addEventListener('input', () => {
        this.vm.data[key] = node.value;
      });
      new Watcher(this.vm, key, value => {
        node.value = value;
      });
    }
  }
  
  compileText(node) {
    const reg = /\{\{(.+?)\}\}/g;
    let match;
    while (match = reg.exec(node.textContent)) {
      const key = match[1].trim();
      new Watcher(this.vm, key, value => {
        node.textContent = node.textContent.replace(match[0], value);
      });
      // 初始渲染
      node.textContent = node.textContent.replace(match[0], this.vm.data[key]);
    }
  }
}

// 5. MVVM 主类
class MVVM {
  constructor(options) {
    this.el = options.el;
    this.data = options.data;
    
    // 数据劫持
    observe(this.data);
    
    // 编译模板
    if (this.el) {
      new Compile(this.el, this);
    }
  }
}

// --- 使用示例 ---
// <div id="app">
//   <input v-model="message" />
//   <p>{{ message }}</p>
// </div>
// 
// const vm = new MVVM({
//   el: '#app',
//   data: {
//     message: 'Hello MVVM!'
//   }
// });
```

##### 实现Vue reactive响应式
Vue 3 的 `reactive` 基于 `Proxy` 实现，相比 Vue 2 的 `Object.defineProperty` 有显著优势。这是现代前端响应式系统的标准实现。

### Proxy 相比 Object.defineProperty 的优势
1. **可以监听数组变化**：不需要重写数组方法
2. **可以监听新增/删除属性**：`set`/`deleteProperty` 拦截器
3. **懒代理**：不需要递归遍历，访问到嵌套对象时才进行代理
4. **性能更好**：大对象初始代理时不需要遍历所有 key

### 核心原理（五层架构）
1. **reactiveMap（WeakMap）**：缓存已代理的对象，避免重复代理
2. **targetMap（WeakMap）**：存储 `target → Map(key → Dependency)` 的映射
3. **Dependency 类**：每个响应式属性对应一个依赖收集器，存储所有 activeEffect
4. **effect(fn)**：注册副作用函数，立即执行完成依赖收集，依赖变化时重新执行
5. **reactive(target)**：创建 Proxy，`get` 时 `dep.depend()`，`set` 时 `dep.notify()`

### 依赖收集流程
1. `effect(() => { console.log(state.count) })` 被调用
2. 设置 `activeEffect = wrappedEffect`
3. 读取 `state.count` → Proxy `get` 拦截器
4. `getDep(target, 'count').depend()` → 将 `wrappedEffect` 加入依赖列表
5. `activeEffect` 重置为 `null`
6. 后续修改 `state.count` → `dep.notify()` → 重新执行 `wrappedEffect`

### Vue 3 的 ref 和 computed
- **ref**：用对象包装基本类型，通过 `get value()`/`set value()` 实现响应式
- **computed**：懒求值 + 缓存，依赖变化时标记 `dirty = true`，下次读取时重新计算

### 应用场景
- 理解 Vue 3 响应式原理
- 面试中展示对 Proxy 和响应式系统的深度理解
- 实现自定义的响应式数据框架

### 注意事项
- `reactiveMap` 使用 `WeakMap`，代理对象被 GC 时自动清理缓存
- `effectStack` 处理嵌套 effect（如 `effect` 内部调用另一个 `effect`）
- `activeEffect` 是全局变量，通过栈管理嵌套场景
- `Reflect.get`/`Reflect.set` 保持 `this` 指向正确（`receiver`）
- `deleteProperty` 拦截器处理属性删除
- 深层响应式通过递归 `reactive()` 实现（懒代理）

```javascript
/**
 * 实现 Vue 3 的 reactive 响应式 - 基于 Proxy
 * 
 * Proxy 相比 Object.defineProperty 的优势：
 * 1. 可以监听数组变化
 * 2. 可以监听新增/删除属性
 * 3. 不需要递归遍历，访问到才进行代理
 */

// 响应式系统
const reactiveMap = new WeakMap();
const effectStack = [];
let activeEffect = null;

// 依赖收集
class Dependency {
  constructor() {
    this.subscribers = new Set();
  }
  
  depend() {
    if (activeEffect) {
      this.subscribers.add(activeEffect);
    }
  }
  
  notify() {
    this.subscribers.forEach(effect => effect());
  }
}

// 创建依赖映射
const targetMap = new WeakMap();

function getDep(target, key) {
  let depsMap = targetMap.get(target);
  if (!depsMap) {
    depsMap = new Map();
    targetMap.set(target, depsMap);
  }
  let dep = depsMap.get(key);
  if (!dep) {
    dep = new Dependency();
    depsMap.set(key, dep);
  }
  return dep;
}

// reactive 函数 - 使用 Proxy
function reactive(target) {
  if (target === null || typeof target !== 'object') {
    return target;
  }
  
  // 如果已经 reactive，返回缓存版本
  if (reactiveMap.has(target)) {
    return reactiveMap.get(target);
  }
  
  const proxy = new Proxy(target, {
    get(target, key, receiver) {
      const dep = getDep(target, key);
      dep.depend(); // 依赖收集
      
      const result = Reflect.get(target, key, receiver);
      
      // 深层响应式：如果值是对象，递归代理
      if (typeof result === 'object' && result !== null) {
        return reactive(result);
      }
      
      return result;
    },
    
    set(target, key, value, receiver) {
      const oldValue = target[key];
      const result = Reflect.set(target, key, value, receiver);
      
      if (oldValue !== value) {
        const dep = getDep(target, key);
        dep.notify(); // 触发更新
      }
      
      return result;
    },
    
    deleteProperty(target, key) {
      const hadKey = key in target;
      const result = Reflect.deleteProperty(target, key);
      
      if (hadKey) {
        const dep = getDep(target, key);
        dep.notify(); // 删除属性时触发更新
      }
      
      return result;
    }
  });
  
  reactiveMap.set(target, proxy);
  return proxy;
}

// effect 函数 - 注册副作用
function effect(fn) {
  const wrappedEffect = () => {
    try {
      activeEffect = wrappedEffect;
      effectStack.push(wrappedEffect);
      return fn();
    } finally {
      effectStack.pop();
      activeEffect = effectStack[effectStack.length - 1];
    }
  };
  
  wrappedEffect(); // 立即执行，完成依赖收集
  return wrappedEffect;
}

// ref 函数
function ref(value) {
  const refObj = {
    get value() {
      const dep = getDep(refObj, 'value');
      dep.depend();
      return value;
    },
    set value(newValue) {
      if (newValue !== value) {
        value = newValue;
        const dep = getDep(refObj, 'value');
        dep.notify();
      }
    }
  };
  return refObj;
}

// computed 函数
function computed(getter) {
  let cachedValue;
  let dirty = true;
  
  const computedRef = {
    get value() {
      if (dirty) {
        effect(() => {
          cachedValue = getter();
          dirty = false;
        });
      }
      const dep = getDep(computedRef, 'value');
      dep.depend();
      return cachedValue;
    }
  };
  
  return computedRef;
}

// const state = reactive({ count: 0, name: 'Vue' });
// 
// effect(() => {
//   console.log('count 变化:', state.count);
// });
// 
// state.count++; // 触发 effect 重新执行
```

##### 实现模板字符串解析功能
```javascript
/**
 * 实现模板字符串解析
 * 将 "{name} 今年 {age} 岁" 中的占位符替换为实际值
 */

/**
 * 模板字符串解析函数
 * @param {string} template - 模板字符串，如 "你好，{name}"
 * @param {object} data - 数据对象
 * @returns {string} 解析后的字符串
 */
function renderTemplate(template, data) {
  // 匹配 {{xxx}} 或 {xxx} 格式
  return template.replace(/\{\{?(.+?)\}?\}/g, (match, key) => {
    const trimmedKey = key.trim();
    // 支持嵌套路径，如 {user.name}
    const value = trimmedKey.split('.').reduce((obj, k) => {
      return obj ? obj[k] : undefined;
    }, data);
    
    return value !== undefined ? value : match;
  });
}
```

```javascript
/**
 * 实现 hash 路由
 * hash 路由通过 window.location.hash 和 hashchange 事件实现
 */

class HashRouter {
  constructor() {
    this.routes = {};          // 路由表
    this.currentHash = '';     // 当前 hash

    window.addEventListener('hashchange', () => {
```

```javascript
/**
 * 实现 redux 中间件机制
 * 
 * Redux 中间件的本质：在 dispatch 前后添加自定义逻辑
 * 中间件签名：store => next => action => {}
 */

// 简易 redux 实现
function createStore(reducer, preloadedState, enhancer) {
  // 如果有 enhancer，使用 enhancer 创建 store
  if (typeof enhancer === 'function') {
    return enhancer(createStore)(reducer, preloadedState);
  }
  
  let state = preloadedState;
  let listeners = [];
  
  const store = {
    getState() {
      return state;
    },
    
    dispatch(action) {
      state = reducer(state, action);
      listeners.forEach(listener => listener());
      return action;
    },
    
    subscribe(listener) {
      listeners.push(listener);
      return () => {
        listeners = listeners.filter(l => l !== listener);
      };
    }
  };
  
  // 初始化状态
  store.dispatch({ type: '@@INIT' });
  
  return store;
}

/**
 * applyMiddleware - 应用中间件
 * @param {...Function} middlewares - 中间件函数列表
 * @returns {Function} enhancer 函数
 */
function applyMiddleware(...middlewares) {
  return createStore => (reducer, preloadedState) => {
    const store = createStore(reducer, preloadedState);
    
    // 简化的 dispatch，用于在中间件构造中避免调用完整 dispatch
    let dispatch = () => {
      throw new Error('中间件构造中不允许 dispatch');
    };
    
    // 传递给中间件的 API
    const middlewareAPI = {
      getState: store.getState,
      dispatch: (...args) => dispatch(...args)
    };
    
    // 执行所有中间件，获得 dispatch 函数链
    const chain = middlewares.map(middleware => middleware(middlewareAPI));
    
    // 组合中间件链，返回增强后的 dispatch
    dispatch = compose(...chain)(store.dispatch);
    
    return {
      ...store,
      dispatch
    };
  };
}

// compose 函数
function compose(...fns) {
  if (fns.length === 0) return arg => arg;
  if (fns.length === 1) return fns[0];
  return fns.reduce((a, b) => (...args) => a(b(...args)));
}
```

```javascript
/**
 * 实现一个迷你版的 Vue
 * 结合了响应式系统、编译器和双向绑定
 */

class MiniVue {
  constructor(options) {
    this.$el = document.querySelector(options.el);
    this.$data = options.data;
    this.$methods = options.methods;
    this._binding = {}; // 存储绑定关系
    
    // 1. 数据劫持
    this._observe(this.$data);
    
    // 2. 编译模板
    this._compile(this.$el);
  }
  
  /**
   * 数据劫持 - 使用 Object.defineProperty
   */
  _observe(data) {
    Object.keys(data).forEach(key => {
      this._defineReactive(data, key, data[key]);
    });
  }
  
  _defineReactive(obj, key, val) {
    const self = this;
    
    // 存储所有依赖该属性的 watcher
    this._binding[key] = {
      _directives: []
    };
    
    // 递归劫持
    if (typeof val === 'object' && val !== null) {
      this._observe(val);
    }
    
    Object.defineProperty(obj, key, {
      get() {
        return val;
      },
      set(newVal) {
        if (newVal === val) return;
        val = newVal;
        
        // 通知所有绑定了该属性的指令更新
        self._binding[key]._directives.forEach(item => {
          item.update();
        });
      }
    });
  }
  
  /**
   * 编译模板
   */
  _compile(root) {
    const nodes = root.children;
    
    for (const node of nodes) {
      // 处理 v-model
      if (node.hasAttribute('v-model')) {
        this._compileModel(node);
      }
      
      // 处理 v-click / @click
      if (node.hasAttribute('v-click') || node.hasAttribute('@click')) {
        this._compileClick(node);
      }
      
      // 处理 {{ }} 插值表达式
      if (node.textContent.match(/\{\{(.+?)\}\}/)) {
        this._compileText(node);
      }
      
      // 递归编译子节点
      if (node.children.length > 0) {
        this._compile(node);
      }
    }
  }
  
  _compileModel(node) {
    const key = node.getAttribute('v-model');
    node.removeAttribute('v-model');
    
    // 创建 watcher
    const watcher = {
      update: () => {
        node.value = this._getValue(this.$data, key);
      }
    };
    this._binding[key]._directives.push(watcher);
    
    // 初始赋值
    node.value = this._getValue(this.$data, key);
    
    // 监听输入事件
    node.addEventListener('input', () => {
      this._setValue(this.$data, key, node.value);
    });
  }
  
  _compileClick(node) {
    const methodName = node.getAttribute('v-click') || node.getAttribute('@click');
    node.removeAttribute('v-click');
    node.removeAttribute('@click');
    
    node.addEventListener('click', () => {
      this.$methods && this.$methods[methodName] && this.$methods[methodName].call(this.$data);
    });
  }
  
  _compileText(node) {
    const originalText = node.textContent;
    const reg = /\{\{(.+?)\}\}/g;
    let match;
    
    while (match = reg.exec(originalText)) {
      const key = match[1].trim();
      
      const watcher = {
        update: () => {
          node.textContent = originalText.replace(reg, (_, k) => {
            return this._getValue(this.$data, k.trim());
          });
        }
      };
      this._binding[key]._directives.push(watcher);
      
      // 初始渲染
      node.textContent = originalText.replace(reg, (_, k) => {
        return this._getValue(this.$data, k.trim());
      });
    }
  }
  
  _getValue(obj, path) {
    return path.split('.').reduce((current, key) => current ? current[key] : undefined, obj);
  }
  
  _setValue(obj, path, value) {
    const keys = path.split('.');
    let current = obj;
    
    for (let i = 0; i < keys.length - 1; i++) {
      current = current[keys[i]];
    }
    current[keys[keys.length - 1]] = value;
  }
}
```

##### 实现一个JS函数柯里化
```javascript
/**
 * 函数柯里化
 * 将一个多参数函数转换为一系列单参数函数
 * 
 * @param {Function} fn - 需要柯里化的函数
 * @param {number} [arity] - 函数的参数数量
 * @returns {Function} 柯里化后的函数
 */
function curry(fn, arity = fn.length) {
  return function curried(...args) {
    if (args.length >= arity) {
      // 参数数量足够，直接执行
      return fn.apply(this, args);
    } else {
      // 参数不足，返回新函数继续接收参数
      return function (...nextArgs) {
        return curried.apply(this, [...args, ...nextArgs]);
      };
    }
  };
}

/**
 * 柯里化 - 支持占位符版本
 * 使用 _ 作为占位符
 */
function curryWithPlaceholder(fn, arity = fn.length) {
  const placeholder = curryWithPlaceholder.placeholder || '_';
  
  return function curried(...args) {
    if (args.length >= arity && !args.slice(0, arity).includes(placeholder)) {
      return fn.apply(this, args);
    }
    
    return function (...nextArgs) {
      const mergedArgs = [];
      let argIndex = 0;
      let nextIndex = 0;
      
      // 合并参数：用新参数替换占位符
      while (argIndex < args.length && nextIndex < nextArgs.length) {
        if (args[argIndex] === placeholder) {
          mergedArgs.push(nextArgs[nextIndex++]);
        } else {
          mergedArgs.push(args[argIndex]);
        }
        argIndex++;
      }
      
      // 将剩余参数全部合并
      while (argIndex < args.length) {
        mergedArgs.push(args[argIndex++]);
      }
      while (nextIndex < nextArgs.length) {
        mergedArgs.push(nextArgs[nextIndex++]);
      }
      
      return curried.apply(this, mergedArgs);
    };
  };
}
curryWithPlaceholder.placeholder = '_';
```

```javascript
/**
 * 字符串查找 - 实现 String.prototype.indexOf
 * 在字符串中查找子串，返回第一次出现的索引
 * @param {string} text - 原字符串
 * @param {string} pattern - 要查找的子串
 * @param {number} [start=0] - 开始查找的位置
 * @returns {number} 索引，未找到返回 -1
 */

// 方法1：朴素字符串匹配（BF算法）
function indexOf(text, pattern, start = 0) {
  const n = text.length;
  const m = pattern.length;
  
  if (m === 0) return start;
  if (start < 0) start = 0;
  if (start + m > n) return -1;
  
  for (let i = start; i <= n - m; i++) {
    let match = true;
    for (let j = 0; j < m; j++) {
      if (text[i + j] !== pattern[j]) {
        match = false;
        break;
      }
    }
    if (match) return i;
  }
  
  return -1;
}

// 方法2：使用内置方法（模拟）
function indexOfSimple(text, pattern, start = 0) {
  if (pattern === '') return start;
  return text.slice(start).search(pattern) + (start > 0 && text.slice(start).search(pattern) >= 0 ? start : text.slice(start).search(pattern));
}

// 方法3：KMP 算法（高效）
// 时间复杂度：O(n+m)，空间复杂度：O(m)
function kmpSearch(text, pattern) {
  const n = text.length;
  const m = pattern.length;
  if (m === 0) return 0;
  
  // 构建部分匹配表（next数组）
  const next = buildKMPNext(pattern);
  
  let i = 0; // text 的指针
  let j = 0; // pattern 的指针
  
  while (i < n) {
    if (text[i] === pattern[j]) {
      i++;
      j++;
      if (j === m) {
        return i - j; // 找到匹配
      }
    } else if (j > 0) {
      j = next[j - 1]; // 利用 next 数组回溯
    } else {
      i++;
    }
  }
  
  return -1;
}

function buildKMPNext(pattern) {
  const next = [0];
  let prefixLen = 0;
  let i = 1;
  
  while (i < pattern.length) {
    if (pattern[i] === pattern[prefixLen]) {
      prefixLen++;
      next[i] = prefixLen;
      i++;
    } else if (prefixLen > 0) {
      prefixLen = next[prefixLen - 1];
    } else {
      next[i] = 0;
      i++;
    }
  }
  
  return next;
}
```

##### 字符串最长的不重复子串
```javascript
/**
 * 查找字符串中最长的不重复子串（无重复字符的最长子串）
 * 滑动窗口算法
 * 
 * @param {string} s - 输入字符串
 * @returns {{ length: number, substring: string }} 最长不重复子串的长度和内容
 * 
 * 时间复杂度：O(n)
 * 空间复杂度：O(min(m, n))，m 是字符集大小
 */

function longestUniqueSubstring(s) {
  const charMap = new Map(); // 存储字符及其最近出现的位置
  let maxLength = 0;
  let start = 0; // 窗口左边界
  let resultStart = 0; // 最长子串的起始位置
  
  for (let end = 0; end < s.length; end++) {
    const char = s[end];
    
    // 如果字符已存在且在当前窗口内，移动左边界
    if (charMap.has(char) && charMap.get(char) >= start) {
      start = charMap.get(char) + 1;
    }
    
    // 更新字符位置
    charMap.set(char, end);
    
    // 更新最大长度
    const currentLength = end - start + 1;
    if (currentLength > maxLength) {
      maxLength = currentLength;
      resultStart = start;
    }
  }
  
  return {
    length: maxLength,
    substring: s.slice(resultStart, resultStart + maxLength)
  };
}
```

```javascript
/**
 * 对象扁平化
 * 将嵌套对象转换为单层对象，键名为路径拼接
 * 
 * 输入：{ a: { b: { c: 1 }, d: 2 }, e: 3 }
 * 输出：{ 'a.b.c': 1, 'a.d': 2, 'e': 3 }
 */

function flattenObject(obj, prefix = '', result = {}) {
  if (obj === null || typeof obj !== 'object') {
    result[prefix] = obj;
    return result;
  }
  
  for (const key of Object.keys(obj)) {
    const newKey = prefix ? `${prefix}.${key}` : key;
    flattenObject(obj[key], newKey, result);
  }
  
  return result;
}

// 支持数组索引
function flattenObjectFull(obj, prefix = '', result = {}) {
  if (obj === null || typeof obj !== 'object') {
    result[prefix] = obj;
    return result;
  }
  
  const isArray = Array.isArray(obj);
  
  for (const key of Object.keys(obj)) {
    const newKey = prefix
      ? `${prefix}${isArray ? `[${key}]` : `.${key}`}`
      : key;
    flattenObjectFull(obj[key], newKey, result);
  }
  
  return result;
}

// 对象反扁平化
function unflattenObject(flatObj) {
  const result = {};
  
  for (const [key, value] of Object.entries(flatObj)) {
    const keys = key.split('.');
    let current = result;
    
    for (let i = 0; i < keys.length - 1; i++) {
      if (!current[keys[i]]) {
        current[keys[i]] = {};
      }
      current = current[keys[i]];
    }
    current[keys[keys.length - 1]] = value;
  }
  
  return result;
}
```

##### 手写深度比较isEqual
```javascript
/**
 * 手写深度比较 isEqual
 * 比较两个值是否深度相等
 * 
 * @param {any} a - 值 a
 * @param {any} b - 值 b
 * @param {WeakMap} [cache] - 缓存，处理循环引用
 * @returns {boolean}
 */
function isEqual(a, b, cache = new WeakMap()) {
  // 严格相等（处理 NaN 等）
  if (Object.is(a, b)) return true;
  
  // 其中一个为 null/undefined 或非对象类型
  if (a === null || b === null || typeof a !== 'object' || typeof b !== 'object') {
    return false;
  }
  
  // 处理循环引用
  if (cache.has(a) && cache.get(a) === b) return true;
  cache.set(a, b);
  
  // 处理 Date
  if (a instanceof Date && b instanceof Date) {
    return a.getTime() === b.getTime();
  }
  
  // 处理 RegExp
  if (a instanceof RegExp && b instanceof RegExp) {
    return a.source === b.source && a.flags === b.flags;
  }
  
  // 比较原型
  const protoA = Object.getPrototypeOf(a);
  const protoB = Object.getPrototypeOf(b);
  if (protoA !== protoB) return false;
  
  // 处理 Map
  if (a instanceof Map && b instanceof Map) {
    if (a.size !== b.size) return false;
    for (const [key, value] of a) {
      if (!b.has(key) || !isEqual(value, b.get(key), cache)) return false;
    }
    return true;
  }
  
  // 处理 Set
  if (a instanceof Set && b instanceof Set) {
    if (a.size !== b.size) return false;
    return isEqual([...a].sort(), [...b].sort(), cache);
  }
  
  // 获取所有键（包括不可枚举的，但不包括 Symbol）
  const keysA = Object.keys(a);
  const keysB = Object.keys(b);
  
  if (keysA.length !== keysB.length) return false;
  
  // 比较每个键的值
  for (const key of keysA) {
    if (!keysB.includes(key) || !isEqual(a[key], b[key], cache)) return false;
  }
  
  return true;
}
```

```javascript
    if (typeof val === 'symbol' || typeof val === 'undefined') return undefined;
    if (typeof val === 'function') return undefined;
    
    // 处理循环引用
    if (visited.has(val)) {
      throw new TypeError('Converting circular structure to JSON');
    }
    visited.add(val);
    
    const isArray = Array.isArray(val);
    const spaceIndent = typeof space === 'number' ? ' '.repeat(space) : space || '';
    const newIndent = indent + spaceIndent;
    const separator = space ? ':' + (space ? ' ' : '') : ':';
    
    if (isArray) {
      const items = val.map((item, index) => {
        if (typeof replacer === 'function') {
          item = replacer(String(index), item);
        }
        if (item === undefined || typeof item === 'function' || typeof item === 'symbol') {
          return 'null';
        }
        return newIndent + stringify(item, newIndent);
      });
      
      if (items.length === 0) return '[]';
      if (space) {
        return '[\n' + items.join(',\n') + '\n' + indent + ']';
      }
      return '[' + items.join(',') + ']';
    }
    
    // 处理对象
    let keys = Object.keys(val);
    
    // 如果 replacer 是数组，过滤键
    if (Array.isArray(replacer)) {
      keys = keys.filter(key => replacer.includes(key));
    }
    
    const items = keys.map(key => {
      let value = val[key];
      if (typeof replacer === 'function') {
        value = replacer(key, value);
      }
      if (value === undefined || typeof value === 'function' || typeof value === 'symbol') {
        return null;
      }
      const strValue = stringify(value, newIndent);
      if (strValue === undefined) return null;
      return newIndent + `"${key}"${separator}${strValue}`;
    }).filter(item => item !== null);
    
    if (items.length === 0) return '{}';
    if (space) {
      return '{\n' + items.join(',\n') + '\n' + indent + '}';
    }
    return '{' + items.join(',') + '}';
  }
  
  return stringify(value, '');
}

function escapeChar(c) {
  const map = {
    '"': '\\"',
    '\\': '\\\\',
    '\n': '\\n',
    '\r': '\\r',
    '\t': '\\t',
    '\f': '\\f',
    '\b': '\\b'
  };
  return map[c] || '\\u' + c.charCodeAt(0).toString(16).padStart(4, '0');
}
```

```javascript
/**
 * 实现 JSON.parse
 * @param {string} json - JSON 字符串

// 方法1：使用 eval（简单但不安全）
function myJSONParse(str) {
  return eval('(' + str + ')');

// 方法2：手动解析器（安全）
function myJSONParseSafe(str) {
  let index = 0;
  
  function parse() {
    skipWhitespace();
    
    if (index >= str.length) {
      throw new SyntaxError('Unexpected end of JSON input');
    }
    
    const char = str[index];
    
    if (char === '{') return parseObject();
    if (char === '[') return parseArray();
    if (char === '"') return parseString();
    if (char === 't' || char === 'f') return parseBoolean();
    if (char === 'n') return parseNull();
    if (char === '-' || (char >= '0' && char <= '9')) return parseNumber();
    
    throw new SyntaxError(`Unexpected token '${char}' at position ${index}`);
  }
  
  function skipWhitespace() {
    while (index < str.length && /\s/.test(str[index])) {
      index++;
    }
  }
  
  function parseObject() {
    index++; // 跳过 {
    const obj = {};
    
    skipWhitespace();
    if (str[index] === '}') {
      index++;
      return obj;
    }
    
    while (index < str.length) {
      skipWhitespace();
      if (str[index] !== '"') {
        throw new SyntaxError('Expected string key');
      }
      
      const key = parseString();
      
      skipWhitespace();
      if (str[index] !== ':') {
        throw new SyntaxError('Expected :');
      }
      index++; // 跳过 :
      
      skipWhitespace();
      obj[key] = parse();
      
      skipWhitespace();
      if (str[index] === ',') {
        index++;
        skipWhitespace();
        if (str[index] === '}') {
          throw new SyntaxError('Trailing comma in object');
        }
      } else if (str[index] === '}') {
        index++;
        return obj;
      } else {
        throw new SyntaxError('Expected , or }');
      }
    }
    
    throw new SyntaxError('Unterminated object');
  }
  
  function parseArray() {
    index++; // 跳过 [
    const arr = [];
    
    skipWhitespace();
    if (str[index] === ']') {
      index++;
      return arr;
    }
    
    while (index < str.length) {
      arr.push(parse());
      
      skipWhitespace();
      if (str[index] === ',') {
        index++;
        skipWhitespace();
        if (str[index] === ']') {
          throw new SyntaxError('Trailing comma in array');
        }
      } else if (str[index] === ']') {
        index++;
        return arr;
      } else {
        throw new SyntaxError('Expected , or ]');
      }
    }
    
    throw new SyntaxError('Unterminated array');
  }
  
  function parseString() {
    index++; // 跳过 "
    let result = '';
    
    while (index < str.length) {
      const char = str[index];
      
      if (char === '"') {
        index++;
        return result;
      }
      
      if (char === '\\') {
        index++;
        const next = str[index];
        switch (next) {
          case '"': result += '"'; break;
          case '\\': result += '\\'; break;
          case '/': result += '/'; break;
          case 'b': result += '\b'; break;
          case 'f': result += '\f'; break;
          case 'n': result += '\n'; break;
          case 'r': result += '\r'; break;
          case 't': result += '\t'; break;
          case 'u':
            const hex = str.slice(index + 1, index + 5);
            result += String.fromCharCode(parseInt(hex, 16));
            index += 4;
            break;
          default:
            result += next;
        }
        index++;
      } else {
        result += char;
        index++;
      }
    }
    
    throw new SyntaxError('Unterminated string');
  }
  
  function parseNumber() {
    const start = index;
    if (str[index] === '-') index++;
    
    if (str[index] === '0') {
      index++;
    } else if (str[index] >= '1' && str[index] <= '9') {
      index++;
      while (index < str.length && str[index] >= '0' && str[index] <= '9') index++;
    }
    
    if (str[index] === '.') {
      index++;
      if (index >= str.length || str[index] < '0' || str[index] > '9') {
        throw new SyntaxError('Invalid number');
      }
      while (index < str.length && str[index] >= '0' && str[index] <= '9') index++;
    }
    
    if (str[index] === 'e' || str[index] === 'E') {
      index++;
      if (str[index] === '+' || str[index] === '-') index++;
      while (index < str.length && str[index] >= '0' && str[index] <= '9') index++;
    }
    
    return Number(str.slice(start, index));
  }
  
  function parseBoolean() {
    if (str.startsWith('true', index)) {
      index += 4;
      return true;
    }
    if (str.startsWith('false', index)) {
      index += 5;
      return false;
    }
    throw new SyntaxError('Unexpected token');
  }
  
  function parseNull() {
    if (str.startsWith('null', index)) {
      index += 4;
      return null;
    }
    throw new SyntaxError('Unexpected token');
  }
  
  return parse();
}
```

##### 解析 URL Params 为对象
```javascript
/**
 * 解析 URL Params 为对象
 * 如：?name=张三&age=18&hobby=篮球&hobby=足球 => { name: '张三', age: '18', hobby: ['篮球', '足球'] }
 * 
 * @param {string} [url] - URL，默认取 window.location.href
 * @returns {object} 解析后的参数对象
 */
function parseURLParams(url) {
  const queryString = url
    ? url.split('?')[1] || ''
    : window.location.search.slice(1);
  
  if (!queryString) return {};
  
  const params = {};
  
  queryString.split('&').forEach(param => {
    const [key, value] = param.split('=').map(decodeURIComponent);
    
    // 处理 key 没有值的情况（如 ?debug）
    if (value === undefined) {
      params[key] = true;
      return;
    }
    
    // 处理数组（相同 key 出现多次）
    if (params.hasOwnProperty(key)) {
      params[key] = Array.isArray(params[key])
        ? [...params[key], value]
        : [params[key], value];
    } else {
      params[key] = value;
    }
  });
  
  return params;
}
```

```javascript
function getType(value) {

    return type; // 'string', 'number', 'boolean', 'symbol', 'undefined', 'bigint'
  }
  
  // 对象类型
  if (type === 'function') return 'function';
```

```javascript
/**
 * 对象数组列表转成树形结构
 * 常用于处理菜单、组织架构等层级数据
 * 
 * @param {Array} list - 扁平列表，每个元素包含 id 和 parentId
 * @param {string} [parentKey='parentId'] - 父级 id 的字段名
 * @param {string} [idKey='id'] - 自身 id 的字段名
 * @param {string} [childrenKey='children'] - 子节点数组的字段名
 * @param {any} [rootValue=null] - 根节点的 parentId 值
 * @returns {Array} 树形结构
 */
function listToTree(list, parentKey = 'parentId', idKey = 'id', childrenKey = 'children', rootValue = null) {
  if (!Array.isArray(list) || list.length === 0) return [];
  
  const map = new Map();
  const tree = [];
  
  // 将所有节点存入 Map
  list.forEach(item => {
    map.set(item[idKey], { ...item, [childrenKey]: [] });
  });
  
  // 建立父子关系
  list.forEach(item => {
    const node = map.get(item[idKey]);
    
    if (item[parentKey] === rootValue) {
      // 根节点
      tree.push(node);
    } else {
      // 子节点，添加到父节点的 children 中
      const parent = map.get(item[parentKey]);
      if (parent) {
        parent[childrenKey].push(node);
      } else {
        // 父节点不存在（数据异常），作为根节点处理
        tree.push(node);
      }
    }
  });
  
  return tree;
}
```

```javascript
/**
 * 树形结构转成扁平列表
 * 将树结构展开为扁平数组
 * 
 * @param {Array} tree - 树形结构
 * @param {string} [childrenKey='children'] - 子节点数组的字段名
 * @returns {Array} 扁平列表
 */
function treeToList(tree, childrenKey = 'children') {
  if (!Array.isArray(tree) || tree.length === 0) return [];
  
  const result = [];
  
  function flatten(node) {
    const { [childrenKey]: children, ...rest } = node;
    result.push(rest);
    
    if (children && children.length > 0) {
      children.forEach(flatten);
    }
  }
  
  tree.forEach(flatten);
  return result;
}

/**
 * 树形结构转列表 - 使用 DFS 迭代（避免递归）
 */
function treeToListIterative(tree, childrenKey = 'children') {
  const result = [];
  const stack = [...tree];
  
  while (stack.length > 0) {
    const node = stack.pop();
    const { [childrenKey]: children, ...rest } = node;
    result.push(rest);
    
    if (children && children.length > 0) {
      // 反向入栈以保持原有顺序
      for (let i = children.length - 1; i >= 0; i--) {
        stack.push(children[i]);
      }
    }
  }
  
  return result.reverse(); // 反转以恢复正确顺序
}
```

##### 冒泡排序
```javascript
/**
 * 冒泡排序
 * 重复遍历数组，比较相邻元素，大数逐步"冒泡"到末尾
 * 
 * 时间复杂度：O(n^2)
 * 空间复杂度：O(1)
 * 稳定性：稳定
 */

function bubbleSort(arr) {
  const len = arr.length;
  const result = [...arr]; // 不修改原数组
  
  for (let i = 0; i < len - 1; i++) {
    let swapped = false;
    
    for (let j = 0; j < len - 1 - i; j++) {
      if (result[j] > result[j + 1]) {
        [result[j], result[j + 1]] = [result[j + 1], result[j]];
        swapped = true;
      }
    }
    
    // 如果没有发生交换，说明已排序完成，提前退出
    if (!swapped) break;
  }
  
  return result;
}
```

##### 快速排序
```javascript
/**
 * 快速排序
 * 选择一个基准元素，将数组分为小于基准和大于基准两部分，递归排序
 * 
 * 时间复杂度：O(n log n)（平均），O(n^2)（最坏）
 * 空间复杂度：O(log n)
 * 稳定性：不稳定
 */

// 方法1：简单版（使用额外空间）
function quickSortSimple(arr) {
  if (arr.length <= 1) return arr;
  
  const pivot = arr[0];
  const left = [];
  const right = [];
  
  for (let i = 1; i < arr.length; i++) {
    if (arr[i] < pivot) {
      left.push(arr[i]);
    } else {
      right.push(arr[i]);
    }
  }
  
  return [...quickSortSimple(left), pivot, ...quickSortSimple(right)];
}

// 方法2：原地排序版（高效）
function quickSortInPlace(arr, left = 0, right = arr.length - 1) {
  if (left >= right) return arr;
  
  const pivotIndex = partition(arr, left, right);
  
  quickSortInPlace(arr, left, pivotIndex - 1);
  quickSortInPlace(arr, pivotIndex + 1, right);
  
  return arr;
}

function partition(arr, left, right) {
  // 三数取中法选择基准，优化最坏情况
  const mid = Math.floor((left + right) / 2);
  if (arr[left] > arr[mid]) [arr[left], arr[mid]] = [arr[mid], arr[left]];
  if (arr[left] > arr[right]) [arr[left], arr[right]] = [arr[right], arr[left]];
  if (arr[mid] > arr[right]) [arr[mid], arr[right]] = [arr[right], arr[mid]];
  
  // 将基准移到倒数第二个位置
  [arr[mid], arr[right - 1]] = [arr[right - 1], arr[mid]];
  const pivot = arr[right - 1];
  
  let i = left;
  let j = right - 1;
  
  while (i < j) {
    while (arr[++i] < pivot) {}
    while (arr[--j] > pivot) {}
    if (i < j) {
      [arr[i], arr[j]] = [arr[j], arr[i]];
    }
  }
  
  // 将基准放到正确位置
  [arr[i], arr[right - 1]] = [arr[right - 1], arr[i]];
  
  return i;
}
```

##### 选择排序
```javascript
/**
 * 选择排序
 * 每次从未排序部分选最小元素放到已排序部分的末尾
 * 
 * 时间复杂度：O(n^2)
 * 空间复杂度：O(1)
 * 稳定性：不稳定
 */

function selectionSort(arr) {
  const len = arr.length;
  const result = [...arr];
  
  for (let i = 0; i < len - 1; i++) {
    let minIndex = i;
    
    for (let j = i + 1; j < len; j++) {
      if (result[j] < result[minIndex]) {
        minIndex = j;
      }
    }
    
    if (minIndex !== i) {
      [result[i], result[minIndex]] = [result[minIndex], result[i]];
    }
  }
  
  return result;
}
```

##### 插入排序
```javascript
/**
 * 插入排序
 * 将未排序元素逐个插入到已排序部分的正确位置
 * 
 * 时间复杂度：O(n^2)
 * 空间复杂度：O(1)
 * 稳定性：稳定
 */

function insertionSort(arr) {
  const len = arr.length;
  const result = [...arr];
  
  for (let i = 1; i < len; i++) {
    const current = result[i];
    let j = i - 1;
    
    // 将大于 current 的元素向右移动
    while (j >= 0 && result[j] > current) {
      result[j + 1] = result[j];
      j--;
    }
    
    result[j + 1] = current;
  }
  
  return result;
}
```

##### 二分查找
```javascript
/**
 * 二分查找
 * 在有序数组中查找目标值，每次将搜索范围缩小一半
 * 
 * 时间复杂度：O(log n)
 * 空间复杂度：O(1)
 * 
 * @param {Array} arr - 已排序的数组
 * @param {any} target - 目标值
 * @returns {number} 目标值的索引，未找到返回 -1
 */

// 迭代版本
function binarySearch(arr, target) {
  let left = 0;
  let right = arr.length - 1;
  
  while (left <= right) {
    const mid = Math.floor((left + right) / 2);
    
    if (arr[mid] === target) {
      return mid;
    } else if (arr[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }
  
  return -1;
}

// 递归版本
function binarySearchRecursive(arr, target, left = 0, right = arr.length - 1) {
  if (left > right) return -1;
  
  const mid = Math.floor((left + right) / 2);
  
  if (arr[mid] === target) return mid;
  if (arr[mid] < target) {
    return binarySearchRecursive(arr, target, mid + 1, right);
  }
  return binarySearchRecursive(arr, target, left, mid - 1);
}

/**
 * 二分查找 - 查找第一个等于 target 的位置（有重复元素时）
 */
function binarySearchFirst(arr, target) {
  let left = 0;
  let right = arr.length - 1;
  let result = -1;
  
  while (left <= right) {
    const mid = Math.floor((left + right) / 2);
    
    if (arr[mid] === target) {
      result = mid;
      right = mid - 1; // 继续向左查找
    } else if (arr[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }
  
  return result;
}

/**
 * 二分查找 - 查找最后一个等于 target 的位置
 */
function binarySearchLast(arr, target) {
  let left = 0;
  let right = arr.length - 1;
  let result = -1;
  
  while (left <= right) {
    const mid = Math.floor((left + right) / 2);
    
    if (arr[mid] === target) {
      result = mid;
      left = mid + 1; // 继续向右查找
    } else if (arr[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }
  
  return result;
```

##### 实现一个链表结构
```javascript
/**
 * 链表节点
 */
class ListNode {
  constructor(value) {
    this.value = value;
    this.next = null;
  }
}

/**
 * 单向链表
 */
class LinkedList {
  constructor() {
    this.head = null;
    this.tail = null;
    this.length = 0;
  }
  
  /**
   * 在链表末尾添加节点
   * @param {any} value
   */
  append(value) {
    const node = new ListNode(value);
    
    if (!this.head) {
      this.head = node;
      this.tail = node;
    } else {
      this.tail.next = node;
      this.tail = node;
    }
    
    this.length++;
    return this;
  }
  
  /**
   * 在链表头部插入节点
   * @param {any} value
   */
  prepend(value) {
    const node = new ListNode(value);
    
    if (!this.head) {
      this.head = node;
      this.tail = node;
    } else {
      node.next = this.head;
      this.head = node;
    }
    
    this.length++;
    return this;
  }
  
  /**
   * 在指定位置插入节点
   * @param {any} value
   * @param {number} index
   */
  insert(value, index) {
    if (index < 0 || index > this.length) return false;
    if (index === 0) return this.prepend(value);
    if (index === this.length) return this.append(value);
    
    const node = new ListNode(value);
    let current = this.head;
    
    for (let i = 0; i < index - 1; i++) {
      current = current.next;
    }
    
    node.next = current.next;
    current.next = node;
    this.length++;
    return this;
  }
  
  /**
   * 删除指定位置的节点
   * @param {number} index
   * @returns {any|null} 被删除节点的值
   */
  removeAt(index) {
    if (index < 0 || index >= this.length || !this.head) return null;
    
    let removedNode;
    
    if (index === 0) {
      removedNode = this.head;
      this.head = this.head.next;
      if (!this.head) this.tail = null;
    } else {
      let current = this.head;
      for (let i = 0; i < index - 1; i++) {
        current = current.next;
      }
      removedNode = current.next;
      current.next = removedNode.next;
      if (!current.next) this.tail = current;
    }
    
    this.length--;
    return removedNode.value;
  }
  
  /**
   * 查找值的索引
   * @param {any} value
   * @returns {number} 索引，未找到返回 -1
   */
  indexOf(value) {
    let current = this.head;
    let index = 0;
    
    while (current) {
      if (current.value === value) return index;
      current = current.next;
      index++;
    }
    
    return -1;
  }
  
  /**
   * 遍历链表
   * @param {Function} callback
   */
  forEach(callback) {
    let current = this.head;
    let index = 0;
    while (current) {
      callback(current.value, index);
      current = current.next;
      index++;
    }
  }
  
  /**
   * 将链表转为数组
   * @returns {Array}
   */
  toArray() {
    const result = [];
    this.forEach(value => result.push(value));
    return result;
  }
}
```

```javascript
/**
 * 递归反转链表
 * 
 * 时间复杂度：O(n)
 * 空间复杂度：O(n)（递归调用栈）
 */

function reverseLinkedList(head) {
  // 空链表或只有一个节点
  if (!head || !head.next) {
    return head;
  }
  
  // 递归反转后续链表
  const newHead = reverseLinkedList(head.next);
  
  // 将当前节点接到反转后的链表末尾
  head.next.next = head;
  head.next = null;
  
  return newHead;
}

/**
 * 迭代反转链表
 * 
 * 时间复杂度：O(n)
 * 空间复杂度：O(1)
 */
function reverseLinkedListIterative(head) {
  let prev = null;
  let current = head;
  
  while (current) {
    const next = current.next; // 保存下一个节点
    current.next = prev; // 反转指针
    prev = current; // 移动 prev
    current = next; // 移动 current
  }
  
  return prev; // 新的头节点
}
```

##### 二叉树搜索
```javascript
/**
 * 二叉搜索树（BST）
 * 左子树所有节点 < 根节点 < 右子树所有节点
 */

class TreeNode {
  constructor(value) {
    this.value = value;
    this.left = null;
    this.right = null;
  }
}

class BinarySearchTree {
  constructor() {
    this.root = null;
  }
  
  /**
   * 插入节点
   * @param {any} value
   */
  insert(value) {
    const node = new TreeNode(value);
    
    if (!this.root) {
      this.root = node;
      return this;
    }
    
    let current = this.root;
    while (true) {
      if (value < current.value) {
        if (!current.left) {
          current.left = node;
          return this;
        }
        current = current.left;
      } else if (value > current.value) {
        if (!current.right) {
          current.right = node;
          return this;
        }
        current = current.right;
      } else {
        return this; // 不允许重复
      }
    }
  }
  
  /**
   * 搜索节点
   * @param {any} value
   * @returns {TreeNode|null}
   */
  search(value) {
    let current = this.root;
    
    while (current) {
      if (value === current.value) return current;
      if (value < current.value) current = current.left;
      else current = current.right;
    }
    
    return null;
  }
  
  /**
   * 查找最小值
   * @param {TreeNode} [node] - 起始节点，默认 root
   * @returns {TreeNode|null}
   */
  findMin(node = this.root) {
    if (!node) return null;
    while (node.left) node = node.left;
    return node;
  }
  
  /**
   * 查找最大值
   * @param {TreeNode} [node] - 起始节点，默认 root
   * @returns {TreeNode|null}
   */
  findMax(node = this.root) {
    if (!node) return null;
    while (node.right) node = node.right;
    return node;
  }
  
  /**
   * 移除节点
   * @param {any} value
   */
  remove(value) {
    this.root = this._removeNode(this.root, value);
  }
  
  _removeNode(node, value) {
    if (!node) return null;
    
    if (value < node.value) {
      node.left = this._removeNode(node.left, value);
      return node;
    }
    
    if (value > node.value) {
      node.right = this._removeNode(node.right, value);
      return node;
    }
    
    // 找到要删除的节点
    // 情况1：叶子节点
    if (!node.left && !node.right) return null;
    
    // 情况2：只有一个子节点
    if (!node.left) return node.right;
    if (!node.right) return node.left;
    
    // 情况3：有两个子节点，找右子树的最小节点替换
    const minRight = this.findMin(node.right);
    node.value = minRight.value;
    node.right = this._removeNode(node.right, minRight.value);
    return node;
  }
}
```

```javascript
/**
 * 二叉树层次遍历（广度优先 BFS）
 * 从上到下，从左到右逐层访问节点
 * 
 * 时间复杂度：O(n)
 * 空间复杂度：O(n)
 */

function levelOrder(root) {
  if (!root) return [];
  
  const result = [];
  const queue = [root]; // 使用队列实现 BFS
  
  while (queue.length > 0) {
    const levelSize = queue.length;
    const currentLevel = [];
    
    for (let i = 0; i < levelSize; i++) {
      const node = queue.shift();
      currentLevel.push(node.value);
      
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }
    
    result.push(currentLevel);
  }
  
  return result;
}
```

```javascript
/**
 * 二叉树深度遍历（深度优先 DFS）
 * 三种方式：前序、中序、后序
 * 
 * 时间复杂度：O(n)
 * 空间复杂度：O(n)
 */

// 前序遍历：根 -> 左 -> 右
function preorderTraversal(root) {
  const result = [];
  
  function dfs(node) {
    if (!node) return;
    result.push(node.value); // 访问根
    dfs(node.left);          // 遍历左子树
    dfs(node.right);         // 遍历右子树
  }
  
  dfs(root);
  return result;
}

// 中序遍历：左 -> 根 -> 右（BST 下为升序）
function inorderTraversal(root) {
  const result = [];
  
  function dfs(node) {
    if (!node) return;
    dfs(node.left);          // 遍历左子树
    result.push(node.value); // 访问根
    dfs(node.right);         // 遍历右子树
  }
  
  dfs(root);
  return result;
}

// 后序遍历：左 -> 右 -> 根
function postorderTraversal(root) {
  const result = [];
  
  function dfs(node) {
    if (!node) return;
    dfs(node.left);          // 遍历左子树
    dfs(node.right);         // 遍历右子树
    result.push(node.value); // 访问根
  }
  
  dfs(root);
  return result;
}

// 前序遍历 - 迭代版本
function preorderTraversalIterative(root) {
  if (!root) return [];
  
  const result = [];
  const stack = [root];
  
  while (stack.length > 0) {
    const node = stack.pop();
    result.push(node.value);
    
    // 先压右再压左，这样弹栈时先处理左
    if (node.right) stack.push(node.right);
    if (node.left) stack.push(node.left);
  }
  
  return result;
}

// 中序遍历 - 迭代版本
function inorderTraversalIterative(root) {
  const result = [];
  const stack = [];
  let current = root;
  
  while (current || stack.length > 0) {
    while (current) {
      stack.push(current);
      current = current.left; // 先走到最左
    }
    
    current = stack.pop();
    result.push(current.value);
    current = current.right; // 处理右子树
  }
  
  return result;
}

// 后序遍历 - 迭代版本（前序的变体）
function postorderTraversalIterative(root) {
  if (!root) return [];
  
  const result = [];
  const stack = [root];
  
  while (stack.length > 0) {
    const node = stack.pop();
    result.unshift(node.value); // 插入到数组头部
    
    if (node.left) stack.push(node.left);
    if (node.right) stack.push(node.right);
  }
  
  return result;
}
```

##### 异步并发数限制
```javascript
/**
 * 异步并发数限制
 * 控制同时执行的异步任务数量
 * 
 * @param {Array} tasks - 异步任务数组
 * @param {number} limit - 并发限制数
 * @returns {Promise<Array>} 所有任务结果
 */
async function asyncPool(tasks, limit) {
  const results = [];
  const executing = new Set();
  
  for (const [index, task] of tasks.entries()) {
    // 创建任务并添加到执行集合
    const promise = Promise.resolve().then(() => task());
    results.push(promise);
    executing.add(promise);
    
    // 任务完成后从执行集合移除
    const clean = () => executing.delete(promise);
    promise.then(clean, clean);
    
    // 如果达到并发上限，等待其中一个完成
    if (executing.size >= limit) {
      await Promise.race(executing);
    }
  }
  
  return Promise.all(results);
}
```

##### 实现有并行限制的 Promise 调度器
```javascript
/**
 * 有并行限制的 Promise 调度器
 * 
 * 功能：控制并发执行的任务数量，超出限制的任务排队等待
 */

class Scheduler {
  constructor(limit) {
    this.limit = limit;
    this.queue = [];    // 等待队列
    this.running = 0;   // 当前执行的任务数
  }
  
  /**
   * 添加任务到调度器
   * @param {Function} task - 返回 Promise 的函数
   * @returns {Promise} 返回 Promise，任务完成后 resolve
   */
  add(task) {
    return new Promise((resolve, reject) => {
      // 将任务包装后加入队列
      this.queue.push(async () => {
        try {
          const result = await task();
          resolve(result);
        } catch (err) {
          reject(err);
        }
      });
      
      // 尝试执行任务
      this.schedule();
    });
  }
  
  /**
   * 调度执行
   */
  schedule() {
    // 当有等待任务且运行数未达上限时，执行任务
    while (this.queue.length > 0 && this.running < this.limit) {
      const task = this.queue.shift();
      this.running++;
      
      task().finally(() => {
        this.running--;
        this.schedule(); // 执行下一个任务
      });
    }
  }
}
```

##### 实现 getValue/setValue 函数来获取path对应的值
```javascript
/**
 * 根据路径获取对象中的值
 * 类似 lodash 的 _.get
 * 
 * @param {object} obj - 源对象
 * @param {string|Array} path - 路径，如 'a.b.c' 或 ['a', 'b', 'c']
 * @param {any} [defaultValue] - 默认值，路径不存在时返回
 * @returns {any} 路径对应的值
 */
function getValue(obj, path, defaultValue = undefined) {
  // 将路径统一转为数组
  const keys = Array.isArray(path) ? path : path.split(/[\.\[\]'"]/).filter(Boolean);
  
  let current = obj;
  
  for (const key of keys) {
    if (current === null || current === undefined || typeof current !== 'object') {
      return defaultValue;
    }
    current = current[key];
  }
  
  return current !== undefined ? current : defaultValue;
}

/**
 * 根据路径设置对象中的值
 * 类似 lodash 的 _.set
 * 
 * @param {object} obj - 源对象
 * @param {string|Array} path - 路径
 * @param {any} value - 要设置的值
 * @returns {object} 修改后的对象
 */
function setValue(obj, path, value) {
  const keys = Array.isArray(path) ? path : path.split(/[\.\[\]'"]/).filter(Boolean);
  let current = obj;
  
  for (let i = 0; i < keys.length - 1; i++) {
    const key = keys[i];
    const nextKey = keys[i + 1];
    
    // 如果当前路径不存在，创建中间对象或数组
    if (!(key in current)) {
      current[key] = /^\d+$/.test(nextKey) ? [] : {};
    }
    
    current = current[key];
  }
  
  current[keys[keys.length - 1]] = value;
  return obj;
}
```

```javascript
 * 版本号格式：主版本号.次版本号.修订号（如 1.0.0, 2.10.3）
 * 
 * @param {Array<string>} versions - 版本号数组
 * @param {string} [order='asc'] - 排序方向：'asc' 升序，'desc' 降序
 * @returns {Array<string>} 排序后的版本号数组
 */
function sortVersions(versions, order = 'asc') {
  return versions.sort((a, b) => {
    const partsA = a.split('.').map(Number);
    const partsB = b.split('.').map(Number);
    
    const maxLen = Math.max(partsA.length, partsB.length);
    
    for (let i = 0; i < maxLen; i++) {
      const numA = partsA[i] || 0;
      const numB = partsB[i] || 0;
      
      if (numA !== numB) {
        return order === 'asc' ? numA - numB : numB - numA;
      }
    }
    
    return 0;
  });
}
```

```javascript
/**
 * 分片思想解决大数据量渲染问题
 * 使用 requestAnimationFrame 将渲染任务分批执行，避免一次性渲染过多 DOM 导致卡顿

/**
 * 向页面中插入大量数据
 * @param {Array} data - 数据数组
 * @param {Function} createItem - 创建 DOM 元素的函数
 * @param {HTMLElement} container - 容器元素
 * @param {number} [batchSize=20] - 每批渲染的数量
 */
function renderLargeList(data, createItem, container, batchSize = 20) {
  let index = 0;
  
  function batchRender() {
    // 计算本次要渲染的数据范围
    const end = Math.min(index + batchSize, data.length);
    
    // 使用文档片段减少回流
    const fragment = document.createDocumentFragment();
    
    for (let i = index; i < end; i++) {
      const item = createItem(data[i]);
      fragment.appendChild(item);
    }
    
    container.appendChild(fragment);
    index = end;
    
    // 如果还有数据未渲染，继续分片
    if (index < data.length) {
      requestAnimationFrame(batchRender);
    }
  }
  
  batchRender();
}

 * 使用虚拟滚动 - 更高效的大数据量渲染方案
 * 只渲染可视区域内的元素
 */
class VirtualScroll {
  constructor(options) {
    this.container = options.container;
    this.itemHeight = options.itemHeight;
    this.items = options.items;
    this.renderItem = options.renderItem;
    this.visibleCount = Math.ceil(this.container.clientHeight / this.itemHeight) + 2;
    
    // 设置容器
    this.container.style.position = 'relative';
    this.container.style.overflow = 'auto';
    
    // 创建占位元素（用于撑开滚动条）
    this.placeholder = document.createElement('div');
    this.placeholder.style.height = `${this.items.length * this.itemHeight}px`;
    this.container.appendChild(this.placeholder);
    
    // 渲染可视区域
    this.render();
    
    // 监听滚动事件
    this.container.addEventListener('scroll', () => {
      requestAnimationFrame(() => this.render());
    });
  }
  
  render() {
    const scrollTop = this.container.scrollTop;
    const startIndex = Math.floor(scrollTop / this.itemHeight);
    const endIndex = Math.min(startIndex + this.visibleCount, this.items.length);
    
    // 清空现有可视区域的元素（保留占位符）
    while (this.placeholder.previousSibling) {
      this.container.removeChild(this.placeholder.previousSibling);
    }
    
    // 渲染新的可视区域元素
    const fragment = document.createDocumentFragment();
    for (let i = startIndex; i < endIndex; i++) {
      const item = this.renderItem(this.items[i], i);
      item.style.position = 'absolute';
      item.style.top = `${i * this.itemHeight}px`;
      fragment.appendChild(item);
    }
    
    this.container.insertBefore(fragment, this.placeholder);
  }
```

##### 实现一个add方法完成两个大数相加

```javascript
/**
 * 两个大数相加
 * JS 中 Number 能安全表示的最大整数是 2^53 - 1
 * 超过这个范围的整数运算会丢失精度，需要用字符串模拟加法
 * 
 * @param {string} a - 大数字符串
 * @param {string} b - 大数字符串
 * @returns {string} 和
 */
function addBigNumbers(a, b) {
  let i = a.length - 1;
  let j = b.length - 1;
  let carry = 0;
  let result = '';
  
  // 从个位开始逐位相加
  while (i >= 0 || j >= 0 || carry > 0) {
    const digitA = i >= 0 ? parseInt(a[i]) : 0;
    const digitB = j >= 0 ? parseInt(b[j]) : 0;
    
    const sum = digitA + digitB + carry;
    carry = Math.floor(sum / 10);
    result = (sum % 10) + result;
    
    i--;
    j--;
  }
  
  return result;
}
```

##### 怎么在制定数据源里面生成一个长度为 n 的不重复随机数组
```javascript
/**
 * 从指定数据源中生成一个长度为 n 的不重复随机数组
 * 
 * @param {Array} source - 数据源
 * @param {number} n - 需要的长度
 * @returns {Array} 随机数组
 * 
 * 时间复杂度分析见各方法注释
 */

// 方法1：洗牌算法（Fisher-Yates）-- 时间复杂度 O(m)（m 为数据源长度）
function randomSampleByShuffle(source, n) {
  if (n > source.length) {
    throw new Error('n 不能大于数据源长度');
  }
  
  // 复制数组，避免修改原数组
  const arr = [...source];
  
  // Fisher-Yates 洗牌
  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  
  return arr.slice(0, n);
}
// 时间复杂度：O(m)，空间复杂度：O(m)

// 方法2：逐次抽取 -- 最坏 O(n*m)
function randomSampleByPick(source, n) {
  if (n > source.length) {
    throw new Error('n 不能大于数据源长度');
  }
  
  const result = [];
  const used = new Set();
  
  while (result.length < n) {
    const index = Math.floor(Math.random() * source.length);
    if (!used.has(index)) {
      used.add(index);
      result.push(source[index]);
    }
  }
  
  return result;
}
// 时间复杂度：O(n) 平均，最坏 O(无穷)（概率上趋向 O(n)），空间复杂度：O(n)

// 方法3：使用 Set 保证不重复
function randomSampleBySet(source, n) {
  if (n > source.length) {
    throw new Error('n 不能大于数据源长度');
  }
  
  const selected = new Set();
  
  while (selected.size < n) {
    const index = Math.floor(Math.random() * source.length);
    selected.add(source[index]);
  }
  
  return [...selected];
}
// 时间复杂度：平均 O(n)，空间复杂度：O(n)

// 方法4：当 n 接近 source.length 时，先洗牌再取前 n 个
function randomSampleAdaptive(source, n) {
  if (n > source.length) {
    throw new Error('n 不能大于数据源长度');
  }
  
  // 当 n 接近数据源长度时，洗牌更高效
  if (n > source.length / 2) {
    return randomSampleByShuffle(source, n);
  }
  
  // 当 n 较小时，使用 Set 抽取
  return randomSampleBySet(source, n);
}
```

##### 查找数组公共前缀（美团）
```javascript
/**
 * 查找数组公共前缀
 * 如 ['flower', 'flow', 'flight'] => 'fl'
 * 
 * @param {Array<string>} strs - 字符串数组
 * @returns {string} 公共前缀
 * 
 * 时间复杂度：O(m*n)，m 为最短字符串长度，n 为数组长度
 * 空间复杂度：O(1)
 */

function longestCommonPrefix(strs) {
  if (!strs || strs.length === 0) return '';
  if (strs.length === 1) return strs[0];
  
  // 以第一个字符串为基准
  const first = strs[0];
  
  for (let i = 0; i < first.length; i++) {
    const char = first[i];
    
    // 检查其他字符串的相同位置是否相同
    for (let j = 1; j < strs.length; j++) {
      // 如果当前字符串长度不够，或者字符不匹配
      if (i >= strs[j].length || strs[j][i] !== char) {
        return first.slice(0, i);
      }
    }
  }
  
  return first;
}

// 方法2：分治法
function longestCommonPrefixDivide(strs) {
  if (!strs || strs.length === 0) return '';
  return divide(strs, 0, strs.length - 1);
}

function divide(strs, left, right) {
  if (left === right) return strs[left];
  
  const mid = Math.floor((left + right) / 2);
  const leftPrefix = divide(strs, left, mid);
  const rightPrefix = divide(strs, mid + 1, right);
  
  return commonPrefix(leftPrefix, rightPrefix);
}

function commonPrefix(a, b) {
  const minLen = Math.min(a.length, b.length);
  for (let i = 0; i < minLen; i++) {
    if (a[i] !== b[i]) {
      return a.slice(0, i);
    }
  }
  return a.slice(0, minLen);
}
```

##### 判断括号字符串是否有效（小米）
```javascript
/**
 * 判断括号字符串是否有效
 * 有效括号：()、[]、{} 正确嵌套和闭合
 * 
 * @param {string} s - 括号字符串
 * @returns {boolean}
 * 
 * 时间复杂度：O(n)
 * 空间复杂度：O(n)
 */
function isValidBrackets(s) {
  if (s.length % 2 !== 0) return false; // 奇数长度直接返回 false
  
  const stack = [];
  const map = {
    ')': '(',
    ']': '[',
    '}': '{'
  };
  
  for (const char of s) {
    if (char === '(' || char === '[' || char === '{') {
      // 左括号入栈
      stack.push(char);
    } else {
      // 右括号：检查栈顶是否匹配
      if (stack.length === 0 || stack.pop() !== map[char]) {
        return false;
      }
    }
  }
  
  // 栈为空说明全部匹配
  return stack.length === 0;
}
```

```javascript
 * 实现 String.prototype.padStart
 * 用指定字符串填充原字符串到目标长度（从左侧开始）

 * @param {number} targetLength - 目标长度
 * @param {string} [padString=' '] - 填充字符串

 */
String.prototype.myPadStart = function (targetLength, padString = ' ') {
  const str = String(this);
  
  // 如果目标长度小于等于原字符串长度，返回原字符串
  if (targetLength <= str.length) {
    return str;
  }
  
  // 计算需要填充的长度
  const padLength = targetLength - str.length;
  
  // 重复填充字符串到需要的长度
  let padding = '';
  while (padding.length < padLength) {
    padding += padString;
  }
  
  // 截取需要的填充部分 + 原字符串
  return padding.slice(0, padLength) + str;

  let padding = '';
```

```javascript
function renameDeepKey(obj, oldKey, newKey) {
  if (obj === null || typeof obj !== 'object') {
    return obj;

  // 处理数组
```
