## 基础篇
### HTML
* **Q1: 前端需要注意哪些SEO**
  A: SEO优化帮助搜索引擎理解页面内容并提升排名。关键要点：使用语义化HTML标签（header、nav、main、article、section、aside、footer）构建内容层级；每页使用唯一的`<title>`（60字符以内）和`<meta name="description">`（160字符以内）；每页一个`<h1>`并保持正确的标题层级；为图片添加alt属性；使用`<link rel="canonical">`处理重复内容；保证页面加载速度（Core Web Vitals：LCP < 2.5秒，CLS < 0.1）；使用JSON-LD结构化数据获取富摘要；配置sitemap.xml和robots.txt；保证移动端友好；内部链接使用描述性锚文本。需要避免的：Flash/iframe内容无法被索引、无SSR的SPA、robots.txt屏蔽、重复内容、爬虫预算浪费。

* **Q2: `<img>`的title和alt有什么区别**
  A: alt属性：图片加载失败时显示的替代文本，也供屏幕阅读器使用。HTML5中alt是必需属性，对无障碍访问（WCAG）至关重要，同时会被搜索引擎用于图片SEO索引。alt应描述图片内容或功能。title属性：鼠标悬停时显示的提示文本，是可选的，屏幕阅读器不会稳定读取。最佳实践：编写描述性的alt文本（绝不要关键词堆砌），title仅用于提供alt之外的补充信息。装饰性图片使用alt=""（空值）可告知屏幕阅读器忽略该图片。

* **Q3: HTTP的几种请求方法用途**
  A: GET：获取资源（幂等、安全、可缓存）。POST：提交数据创建资源（非幂等）。PUT：完全替换资源（幂等）。PATCH：部分修改资源（不一定幂等）。DELETE：删除资源（幂等）。HEAD：与GET类似但只返回响应头（用于在下载前检查资源是否存在或获取元数据）。OPTIONS：查询支持的HTTP方法（用于CORS预检请求）。CONNECT：建立隧道（用于HTTPS代理）。TRACE：回显收到的请求用于调试（生产环境出于安全考虑应禁用）。REST约定：GET=查询，POST=创建，PUT=完全更新，PATCH=部分更新，DELETE=删除。

* **Q4: 从浏览器地址栏输入url到显示页面的步骤**
  A: 1. DNS解析：按浏览器缓存 -> 操作系统缓存 -> hosts文件 -> 本地DNS服务器 -> 根域名/TLD/权威服务器递归查询的顺序进行。2. TCP三次握手（SYN -> SYN-ACK -> ACK）。HTTPS还会增加TLS握手（证书验证、密钥交换）。3. HTTP请求：请求行 + 请求头 + 可选的请求体。4. 服务端处理：返回静态文件或动态生成内容。5. 浏览器渲染：解析HTML构建DOM树，解析CSS构建CSSOM，合并为渲染树，布局（计算几何位置），绘制（像素绘制），合成（图层合并）。6. 连接关闭或复用。优化手段：DNS预解析、HTTP/2多路复用、关键渲染路径优化（CSS放head、JS异步加载）。

* **Q5: 如何进行网站性能优化**
  A: 加载优化：打包合并CSS/JS、使用CDN、启用HTTP/2、资源提示（preload/prefetch/preconnect）、启用gzip/brotli压缩、使用WebP/AVIF图片格式、响应式图片srcset+sizes、懒加载、配置Cache-Control + ETag缓存。渲染优化：内联关键CSS、CSS放head、JS使用async/defer、减少DOM深度、最小化重排重绘、使用content-visibility: auto跳过屏幕外渲染、使用will-change提示合成。运行时优化：防抖节流、虚拟列表、Web Worker处理密集计算、requestAnimationFrame、对象池。测量工具：Lighthouse、WebPageTest、Chrome DevTools、RUM。追踪Core Web Vitals（LCP/FID/INP/CLS）。

* **Q6: HTTP状态码及其含义**
  A: 1xx信息响应：100 Continue（继续）、101 Switching Protocols（切换协议）。2xx成功：200 OK、201 Created（POST成功创建）、204 No Content（DELETE成功）、206 Partial Content（范围请求）。3xx重定向：301 Moved Permanently（永久重定向，SEO更新URL）、302 Found（临时重定向）、304 Not Modified（缓存有效）、307（保持请求方法）、308（永久重定向，保持请求方法）。4xx客户端错误：400 Bad Request、401 Unauthorized、403 Forbidden、404 Not Found、405 Method Not Allowed、408 Timeout、413 Payload Too Large、429 Rate Limited。5xx服务端错误：500 Internal Error、502 Bad Gateway、503 Unavailable、504 Gateway Timeout。

* **Q7: 语义化的理解**
  A: 语义化HTML使用有意义的标签（nav、article、section、aside、header、footer、h1-h6）而非纯表现性的div/span。好处：1）无障碍访问：屏幕阅读器通过landmark导航，键盘用户受益于正确的标题层级。2）SEO：搜索引擎根据语义结构评估内容权重。3）可维护性：代码自文档化。4）面向未来：跨设备标准兼容。核心原则：选择能描述内容用途的HTML元素，样式用CSS控制。反模式："div soup"——全是div没有结构含义。

* **Q8: 介绍一下你对浏览器内核的理解？**
  A: 浏览器内核（渲染引擎）负责解析HTML/CSS并渲染页面。由两部分组成：渲染引擎 + JavaScript引擎。主要渲染引擎：Blink（Chrome、Edge、Opera，多进程沙箱化，2013年从WebKit分叉）、WebKit（Safari，所有iOS浏览器都使用WKWebView）、Gecko（Firefox，Mozilla开发，Servo并行CSS）、Trident（ legacy IE，已退役）、EdgeHTML（旧版Edge）。渲染流程：HTML -> DOM，CSS -> CSSOM，DOM+CSSOM -> 渲染树，布局，绘制，合成。JS引擎：V8（Chrome，JIT+内联缓存）、SpiderMonkey（Firefox）、JavaScriptCore/Nitro（Safari）。

* **Q9: html5有哪些新特性、移除了那些元素？**
  A: 新特性：语义化标签（header、footer、nav、article、section、aside、main、figure、figcaption）；多媒体（audio、video、source、track）；Canvas（2D/WebGL）；原生SVG支持；表单增强（email、url、number、date、color等输入类型；placeholder、autofocus、required、pattern等属性）；新API（Geolocation、Web Storage、Web Workers、WebSocket、History API pushState/replaceState、拖放、File API、Intersection Observer、Resize Observer）；离线能力（Service Workers、Cache API、IndexedDB）；性能（requestAnimationFrame、requestIdleCallback）；`<details>/<summary>`、`<progress>`、`<meter>`、`<datalist>`。移除的元素：表现性标签（big、center、font、basefont、strike、tt）、框架集元素（frame、frameset、noframes）、acronym、applet、dir。

* **Q10: HTML5的离线储存怎么使用，工作原理能不能解释一下？**
  A: Service Worker：作为可编程网络代理在独立线程中运行的JS。1）注册：navigator.serviceWorker.register('/sw.js')。2）install事件：预缓存应用壳资源。3）activate事件：清理旧缓存。4）fetch事件：拦截请求并采用缓存策略——Cache First（静态资源）、Network First（API带缓存回退）、Cache Only（应用壳）、Network Only（实时数据）、Stale-while-revalidate（返回缓存同时后台更新）。存储方式：Cache API（Request/Response对）+ IndexedDB（结构化数据）。SW支持离线工作且 survives reload。AppCache（已废弃）：基于manifest文件的方式，因不透明行为和缓存投毒问题被移除。

* **Q11: 浏览器是怎么对HTML5的离线储存资源进行管理和加载的呢**
  A: 注册阶段：浏览器下载SW脚本并启动后台线程。安装阶段：新SW或更新SW时触发，用于预缓存。如果安装失败，SW会被丢弃。激活阶段：安装完成且所有旧SW标签页关闭后触发，用于删除旧缓存。版本管理：缓存名称包含版本标识符（如my-app-v2），激活处理程序删除不匹配的缓存。更新机制：浏览器在每次导航时检测SW文件的字节级差异，在后台获取新版本。新SW进入"等待"状态直到所有客户端标签页关闭。self.skipWaiting() + clients.claim()可强制立即接管。生命周期：已解析 -> 安装中 -> 已安装（等待中）-> 激活中 -> 已激活 -> 冗余。

* **Q12: 请描述一下 cookies，sessionStorage 和 localStorage 的区别？**
  A: Cookie：约4KB，生命周期由Expires/Max-Age控制，作用域为domain+path，自动通过Cookie头发送至服务端，支持HttpOnly/Secure/SameSite，通过document.cookie以字符串API操作。localStorage：约5-10MB，持久化直到手动删除，作用域为origin（协议+域名+端口），不会发送到服务端，键值API（getItem/setItem/removeItem），JS可访问（有XSS风险）。sessionStorage：约5-10MB，标签页级生命周期（关闭即清除），作用域为origin+标签页，不会发送到服务端，API与localStorage相同但标签页隔离。使用场景：Cookie用于服务端会话认证（HttpOnly+Secure+SameSite），localStorage用于客户端持久化数据（偏好设置、缓存），sessionStorage用于标签页级别的临时状态（表单草稿）。绝不要将敏感数据存在localStorage/sessionStorage中。

* **Q13: iframe有那些缺点？**
  A: 1）性能问题：每个iframe创建完整的浏览上下文（独立的DOM/CSSOM/JS引擎），增加内存消耗并阻塞父页面加载。2）SEO：搜索引擎不会完整索引iframe内容，其价值不会传递给父页面。3）安全风险：点击劫持攻击向量——使用X-Frame-Options: DENY/SAMEORIGIN或CSP: frame-ancestors防护。4）通信复杂：跨域需要通过postMessage（复杂且需注意安全）。5）无障碍：屏幕阅读器在iframe导航时表现不佳（务必添加title属性）。6）响应式：需要额外CSS处理（aspect-ratio技巧）。现代替代方案：Web Components、Fetch + innerHTML内容嵌入、服务端包含（SSI）。

* **Q14: WEB标准以及W3C标准是什么?**
  A: W3C（万维网联盟，1994年由Tim Berners-Lee创立）制定开放Web标准，确保一致性、无障碍和互操作性。核心标准：HTML（WHATWG联合维护 Living Standard）、CSS（按模块化）、DOM API、SVG、WCAG（无障碍）、WebAssembly、WebRTC、WebAuthn。WHATWG于2004年成立（Apple、Mozilla、Opera），因W3C进展缓慢而组建，现与W3C共同维护HTML。遵循标准可确保跨浏览器兼容性、面向未来的代码、无障碍支持、可维护性和性能提升。

* **Q15: xhtml和html有什么区别?**
  A: XHTML将HTML重新表述为XML格式。区别：1）语法严格性——必须闭合所有标签（<br />而非<br>）、属性必须加引号、不允许省略（checked="checked"而非checked）、标签小写、正确嵌套。2）错误处理——XHTML以application/xhtml+xml提供时使用XML解析器：任何语法错误都会显示致命的"黄屏死亡"。HTML使用宽容的解析器自动修正。3）MIME类型——大多数以text/html提供的"XHTML"实际使用HTML解析器，抵消了严格性的好处。XHTML 2.0于2009年被废弃（向后不兼容）。现代实践：使用`<!DOCTYPE html>`的HTML5。编写干净的标记，但除非需要XSLT转换，否则不要强求XML严格性。

* **Q16: Doctype作用? 严格模式与混杂模式如何区分？它们有何意义?**
  A: DOCTYPE告知浏览器使用的HTML版本，决定渲染模式。标准模式：严格遵循W3C规范（标准盒模型）。由`<!DOCTYPE html>`（HTML5）、HTML4 Strict DTD、XHTML DTD触发。混杂模式：模拟旧版IE5/Netscape 4的行为（非标准盒模型，width包含padding/border）。由缺失DOCTYPE或旧DOCTYPE触发。几乎标准模式（Firefox）：除遗留表格单元格行高行为外均为严格模式。检测方式：document.compatMode返回'CSS1Compat'（标准模式）或'BackCompat'（混杂模式）。始终使用`<!DOCTYPE html>`以确保跨浏览器一致的渲染。

* **Q17: 行内元素有哪些？块级元素有哪些？空(void)元素有那些？行内元素和块级元素有什么区别？**
  A: 行内元素：span、a、strong、em、b、i、u、small、abbr、cite、code、dfn、kbd、mark、q、samp、sub、sup、time、var、br、img、input、label、select、textarea、button。块级元素：div、p、h1-h6、ul、ol、li、table、form、section、article、nav、aside、header、footer、main、blockquote、pre、hr、address、figure、figcaption、dl、dt、dd。空元素（自闭合，无子元素）：br、hr、img、input、meta、link、area、base、col、embed、source、track、wbr。区别：行内元素在同一行显示；块级元素另起新行并占满整行宽度。块级元素支持所有width/height/margin/padding；行内元素只支持水平方向的margin/padding。块级元素可包含其他块级和行内元素；行内元素只能包含行内元素或文本（HTML5中a除外，a可包裹任何元素）。

* **Q18: HTML全局属性(global attribute)有哪些**
  A: class（CSS类选择器）、id（唯一标识符）、style（内联CSS）、title（工具提示）、lang（语言——影响连字符、引号、屏幕阅读器发音）、dir（文本方向：ltr/rtl/auto）、hidden（不相关，从渲染中隐藏）、tabindex（Tab顺序：-1=程序化控制，0=自然顺序，正数=显式顺序）、contenteditable（用户可编辑内容）、draggable（拖放）、spellcheck、translate（本地化控制）、accesskey（键盘快捷键）、data-*（自定义数据，通过element.dataset访问）、role（ARIA角色）、aria-*（无障碍属性）、slot（Shadow DOM命名插槽）、is（自定义内置元素）、part（暴露部分供::part()样式选择）。

* **Q19: Canvas和SVG有什么区别？**
  A: Canvas：基于像素的即时模式渲染。绘制命令执行后立即渲染，元素不作为对象保留。最适合动态实时图形（游戏、数据可视化、视频处理、图像滤镜）。性能随像素数量下降（画布尺寸影响）。每个元素无独立DOM——需要手动实现命中检测。分辨率依赖（需处理devicePixelRatio适配高清屏）。SVG：基于矢量的保留模式。元素作为DOM节点持久存在，可通过CSS样式化，可绑定事件。分辨率无关（任意缩放都清晰）。最适合静态/交互式可缩放图形（图标、logo、图表、插画）。性能随DOM节点数量下降。支持CSS动画/过渡。总结：Canvas用于大量动态像素的场景；SVG用于可缩放交互元素的场景。

* **Q20: HTML5 为什么只需要写 `<!DOCTYPE HTML>`**
  A: HTML5不像HTML 4.01那样基于SGML。HTML 4.01的DOCTYPE需要包含DTD URL：`<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" "http://www.w3.org/TR/html4/loose.dtd">`。HTML5放弃了SGML，使用自己的解析算法，不依赖任何形式语法。DOCTYPE的唯一作用是触发浏览器的标准模式。浏览器不会获取或验证DTD——看到`<!DOCTYPE html>`就立即切换到标准模式。向后兼容：包括IE6+在内的所有浏览器都支持。简短、简单、不可能写错。

* **Q21: 如何在页面上实现一个圆形的可点击区域？**
  A: 1）CSS border-radius：宽高相等 + border-radius: 50% + overflow: hidden + cursor: pointer。最简单，兼容性最好。点击区域即视觉圆形（CSS裁剪）。2）SVG `<circle>`：原生DOM元素，支持精确的几何点击处理和事件。3）HTML Image Map：`<area shape="circle" coords="x,y,radius">`——基于图片的原生圆形点击区域。4）Canvas：绘制圆形，使用Math.hypot(dx, dy) <= radius进行手动命中检测。大多数场景下CSS border-radius足够使用。需要像素级精确的圆形区域时使用SVG或Image Map。

* **Q22: 网页验证码是干嘛的，是为了解决什么安全问题**
  A: CAPTCHA用于区分人类和机器人。解决的问题：暴力破解密码猜测、评论垃圾信息、虚假账号注册、票务倒卖、投票作弊、资源耗尽（爬虫）。类型：文本型（扭曲字符——遗留方案，已被ML破解）；图像型（选择物体——reCAPTCHA v2）；行为型（鼠标追踪、计时——reCAPTCHA v3，无需用户操作）；音频型（无障碍支持）。现代方案：reCAPTCHA v3分配风险分数（0.0-1.0），低风险自动通过，高风险触发挑战。服务端验证是必须的（仅客户端验证可被绕过）。需要在安全性和用户体验之间取得平衡。

* **Q23: viewport**
  A: viewport元标签控制移动端的布局视口。默认移动视口约为980px（模拟桌面端），导致页面被缩小显示。`<meta name="viewport" content="width=device-width, initial-scale=1.0">`：width=device-width匹配设备CSS像素；initial-scale=1.0防止自动缩放。参数说明：width（device-width或具体像素值）、initial-scale（0.25-5.0）、minimum-scale/maximum-scale（缩放限制）、user-scalable（yes/no——设置为no违反WCAG）、viewport-fit（auto/cover/contain，适配刘海屏设备）。注意：绝不要禁用缩放（WCAG违规）。刘海屏设备使用env(safe-area-inset-*)适配。配合CSS媒体查询实现响应式设计。

* **Q24: 渲染优化**
  A: 渲染优化缩短从页面变化到像素更新的时间。关键渲染路径：在`<head>`中内联关键CSS、非关键CSS/JS延迟加载、减少DOM深度（<32层）、通过批量DOM操作和使用requestAnimationFrame最小化重排重绘。合成层：使用will-change或transform: translateZ(0)提升为合成器图层；仅对transform和opacity做动画（跳过布局/绘制）。加载优化：content-visibility: auto跳过屏幕外区域渲染、loading="lazy"图片懒加载、contain: layout style paint限制渲染范围。帧预算：所有工作需在16.67ms（60fps）或8.33ms（120fps）内完成。使用Performance面板识别瓶颈。

* **Q25: meta viewport相关**
  A: 完整语法：`<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=5.0, viewport-fit=cover">`。width=device-width：将视口设为设备CSS像素宽度（防止980px虚拟视口）。initial-scale：加载时的缩放因子（1.0=不缩放）。minimum-scale/maximum-scale：缩放范围限制。user-scalable：允许手势缩放（设置为no违反WCAG 2.0）。viewport-fit：iPhone X+适配——auto（尊重安全区域）、cover（延伸到刘海区域）、contain（保持在安全区域内）。最佳实践：响应式网站必须包含；绝不要设置user-scalable=no或maximum-scale=1.0；使用viewport-fit=cover时添加env(safe-area-inset-*)内边距；iOS Safari视口高度使用dvh单位。

* **Q26: 你做的页面在哪些流览器测试过？这些浏览器的内核分别是什么?**
  A: 桌面端：Chrome（Blink+V8）、Firefox（Gecko+SpiderMonkey）、Edge（2020年起Blink+V8，Chromium版）、Safari macOS（WebKit+JavaScriptCore）、Opera（Blink+V8）。遗留浏览器：IE（Trident+Chakra，2022年退役）。移动端：Safari iOS（WebKit——App Store政策要求所有iOS浏览器必须使用WKWebView）、Chrome Android（Blink+V8）、Samsung Internet（Blink+V8）。测试策略：最新两个版本的Chrome、Firefox、Safari（桌面+移动）。使用BrowserStack/Sauce Labs进行跨平台测试。使用CanIUse查询特性支持。企业项目：根据分析数据测试Chrome 90+和Safari 14+。

* **Q27: div+css的布局较table布局有什么优点？**
  A: 1）关注点分离：CSS将表现与内容分离；table将两者混在一起，且`<table>`语义上表示表格数据（用于布局在语义上是错误的）。2）性能：表格需要全部下载后才能渲染（列宽依赖于总内容）；CSS可渐进式渲染。3）响应式：flexbox/grid自然适配；表格结构僵硬，需要复杂的重构。4）无障碍：屏幕阅读器会播报表格行/列——用于非数据布局会造成困惑。5）可维护性：CSS是DRY的，一个文件改动影响所有页面。6）带宽：更少的标记（不需要深层嵌套的表格）。7）SEO：语义化元素有更高的权重。只在表示表格数据时使用`<table>`。

* **Q28: a：img的alt与title有何异同？b：strong与em的异同？**
  A: a) alt与title的区别：alt = 必需的替代文本，供屏幕阅读器/图片加载失败时使用，会被搜索引擎索引。title = 可选的工具提示，仅在桌面端悬停时显示，屏幕阅读器不保证读取。b) strong与em的区别：strong = 表示强烈的重要性/紧迫性，屏幕阅读器会改变音调（更大声），视觉上粗体。em = 表示强调（如同说话时的重音），屏幕阅读器会改变音高/重音，视觉上斜体。`<b>`是纯表现性粗体（用于关键词、产品名称）。`<i>`是纯表现性斜体（用于技术术语、外来词）。使用`<strong>`和`<em>`表达语义；使用CSS代替`<b>`/`<i>`做样式。

* **Q29: 你能描述一下渐进增强和优雅降级之间的不同吗**
  A: 优雅降级（Graceful Degradation）：先为现代浏览器构建完整功能（完整CSS Grid、CSS Variables），再为旧版/功能较弱的浏览器添加回退/polyfill。自顶向下（现代 -> 遗留）。示例：用CSS Grid构建，添加float回退。渐进增强（Progressive Enhancement）：从通用的基础底线开始（语义化HTML、基础CSS），逐层为支持的浏览器添加增强功能。自底向上（底线 -> 现代）。示例：简单表单（所有浏览器可用）-> CSS样式 -> JS验证 -> AJAX。现代共识：渐进增强更受推荐——它确保通用访问性，且符合Web本质上的渐进和容错特性。

* **Q30: 为什么利用多个域名来存储网站资源会更有效？**
  A: 1）并行下载：HTTP/1.1每个源限制约6个连接；多个域名增加总并发连接数。2）无Cookie域名：请求源时Cookie会随每个请求发送（包括静态资源）。独立域名避免Cookie开销，减小头部大小和延迟。3）CDN分发：多个域名通常指向CDN边缘服务器，地理距离更近。4）故障隔离：一个域名故障不会导致全部资源不可用。现代注意事项：HTTP/2多路复用使域名分片有害（破坏单连接流复用）。HTTP/2+环境下使用一个CDN域名存放静态资源。无Cookie域名的优势仍然有效。

* **Q31: 简述一下src与href的区别**
  A: src（source）：用于`<img>`、`<script>`、`<iframe>`、`<video>`、`<audio>`。资源嵌入到文档中，替换元素的内容。`<script src>`会阻塞HTML解析直到资源下载并执行完成（除非使用async/defer）。href（hypertext reference）：用于`<a>`、`<link>`、`<area>`、`<base>`。建立文档之间的关系。`<link href="style.css">`并行下载CSS，不阻塞HTML解析（但会阻塞渲染）。`<a href>`在点击前不会获取任何内容。核心区别：src嵌入资源且可能阻塞解析；href建立引用关系且通常不阻塞解析。

* **Q32: 知道的网页制作会用到的图片格式有哪些？**
  A: 位图：JPEG——有损压缩，24位色彩，适合照片，不支持透明。PNG-8——无损，256色，1位透明，简单图形。PNG-24——无损，24位，完整alpha透明。GIF——256色，支持简单动画，1位透明。WebP——Google格式，有损/无损，支持alpha和动画，比JPEG小25-35%（95%+浏览器支持）。AVIF——基于AV1，比JPEG小50%，支持HDR/广色域/alpha/动画（Chrome 85+、Firefox 93+）。矢量图：SVG——XML格式，分辨率无关，可通过CSS样式化，可DOM操作。适合图标、logo、需要清晰缩放的插画。下一代格式：JPEG XL（待广泛采用）、HEIF（Apple生态）。

* **Q33: 在CSS/JS代码上线之后，开发人员经常会优化性能。从用户刷新网页开始，一次JS请求一般情况下有哪些地方会有缓存处理？**
  A: 缓存层级（按顺序）：1）Service Worker缓存——可编程的CacheStorage拦截（开发者控制策略）。2）内存缓存（Memory Cache）——RAM，仅当前会话，最快但非持久化。3）磁盘缓存（HTTP缓存）——由Cache-Control（max-age、no-cache、immutable）控制，ETag/Last-Modified用于重新验证（未变更返回304 Not Modified）。4）CDN缓存——边缘服务器根据头部缓存。5）代理缓存——企业/ISP层（Cache-Control: private vs public）。6）HTTP/2推送缓存——通过服务器推送的资源。失效策略：文件名包含内容哈希（app.a3b4c5.js）+ immutable + 长max-age。哈希变更 -> 新URL -> 保证获取最新版本。

* **Q34: 一个页面上有大量的图片（大型电商网站），加载很慢，你有哪些方法优化这些图片的加载，给用户更好的体验。**
  A: 1）懒加载：`<img loading="lazy">`或Intersection Observer（在进入视口前约1000px触发）。2）响应式图片：srcset + sizes属性——移动设备下载适当尺寸的图片，不需要2000px的桌面版。3）现代格式：WebP/AVIF配合`<picture>`回退。4）图片CDN：Cloudinary/Imgix按需调整大小/压缩/转换。5）渐进式JPEG：先显示低质量预览，再逐步细化。6）LQIP（低质量图片占位符）：微小的模糊占位图（10x10px，约200字节）过渡到完整图片。7）预加载关键图片：`<link rel="preload" as="image">`用于首屏图片。8）缓存策略：内容哈希URL + 激进的Cache-Control。9）压缩：JPEG/WebP质量设为80-85。

* **Q35: 常见排序算法的时间复杂度,空间复杂度**
  A: 格式：最优/平均/最坏/空间/是否稳定。冒泡排序：O(n)/O(n²)/O(n²)/O(1)/稳定；选择排序：O(n²)/O(n²)/O(n²)/O(1)/不稳定；插入排序：O(n)/O(n²)/O(n²)/O(1)/稳定；归并排序：O(n log n)/O(n log n)/O(n log n)/O(n)/稳定；快速排序：O(n log n)/O(n log n)/O(n²)/O(log n)/不稳定；堆排序：O(n log n)/O(n log n)/O(n log n)/O(1)/不稳定；希尔排序：O(n log n)/O(n(log n)²)/O(n(log n)²)/O(1)/不稳定；计数排序：O(n+k)/O(n+k)/O(n+k)/O(k)/稳定；基数排序：O(nk)/O(nk)/O(nk)/O(n+k)/稳定。实践中快速排序最快（缓存局部性好），但最坏情况O(n²)（使用三数取中法可改善）。归并排序稳定且保证O(n log n)。V8的Array.sort()使用TimSort（归并+插入混合），稳定，O(n log n)。

* **Q36: web开发中会话跟踪的方法有哪些**
  A: 1）Cookie：Set-Cookie: sessionId=abc; HttpOnly; Secure; SameSite=Lax。最常用，4KB限制，可被禁用，有CSRF风险。2）URL重写：将session ID放在URL参数中。无Cookie也能工作，但ID会暴露在日志和书签中。3）隐藏表单字段：`<input type="hidden" name="sessionId">`——仅表单提交时携带。4）localStorage：约5MB，通过Authorization头发送。有XSS风险。5）HTTP头部：Authorization: Bearer <token>——REST API/SPA中常用。6）服务端会话：客户端只存session ID，实际数据存在Redis/数据库中——最安全。7）指纹识别：IP+UA+屏幕分辨率+字体组合——不准确，有隐私顾虑。最佳实践：HttpOnly+Secure+SameSite Cookie存session ID + Redis存储。JWT用于无状态API认证。

* **Q37: HTTP request报文结构是怎样的**
  A: 请求行：METHOD PATH HTTP_VERSION（如GET /api/users?page=1 HTTP/1.1）。头部（key:value，每行一个）：通用头部（Cache-Control、Connection）、请求头部（Host、User-Agent、Accept、Accept-Encoding、Authorization、Cookie）、实体头部（Content-Type、Content-Length、Content-Encoding，用于带请求体的方法）。头部以`\r\n\r\n`（空行）结束。请求体：POST/PUT/PATCH时存在（JSON、form-data、multipart、二进制）。GET/DELETE通常无请求体。HTTP/2使用二进制帧，但逻辑结构等效：伪头部替换请求行（":method"、":path"、":scheme"、":authority"）。

* **Q38: HTTP response报文结构是怎样的**
  A: 状态行：HTTP_VERSION STATUS_CODE STATUS_TEXT（如HTTP/1.1 200 OK）。头部：通用头部（Date、Connection、Cache-Control）、响应头部（Server、Set-Cookie、WWW-Authenticate）、实体头部（Content-Type、Content-Length、Content-Encoding、Last-Modified、ETag）、CORS头部（Access-Control-Allow-Origin、Access-Control-Allow-Methods）。头部以`\r\n\r\n`结束。响应体：格式与Content-Type匹配（JSON、HTML、XML、二进制、纯文本）。流式响应可能使用分块传输编码（Transfer-Encoding: chunked）。HEAD请求无响应体。204 No Content和304 Not Modified也无响应体。HTTP/2使用等效逻辑结构的二进制帧。

* **Q39: title与h1的区别、b与strong的区别、i与em的区别**
  A: title与h1：`<title>`是`<head>`中的元数据——浏览器标签页标题、书签标签、搜索结果展示。每页一个，对SEO排名至关重要。`<h1>`是`<body>`中的内容标题——页面内结构层级，屏幕阅读器导航地标。HTML5允许多个`<h1>`（每个sectioning元素一个）。b与strong：`<b>`是纯表现性粗体（风格化强调、关键词）。`<strong>`表示强烈的重要性/紧迫性——屏幕阅读器会改变发声强调。i与em：`<i>`是纯表现性斜体（技术术语、外来词）。`<em>`表示重音强调——屏幕阅读器会改变语调。黄金法则：使用语义化元素表达含义；使用CSS代替`<b>`/`<i>`做样式。

* **Q40: 请你谈谈Cookie的弊端**
  A: 1）大小限制：每个Cookie约4KB，不足以存储复杂状态。2）性能开销：每次请求源时都会发送Cookie（包括静态资源）——2KB Cookie x 100个请求 = 每页200KB不必要开销。3）安全风险：XSS（无HttpOnly时注入的JS可读取document.cookie）、CSRF（自动跨域发送——SameSite缓解）、跨站追踪（浏览器正在逐步淘汰第三方Cookie）。4）可用性：用户可禁用/清除Cookie。行为因浏览器而异（Safari ITP）。5）明文传输：HTTP上未加密传输（始终使用Secure+HTTPS）。现代方案：HttpOnly+Secure+SameSite Cookie仅存session ID，实际数据存服务端（Redis）。localStorage存纯客户端数据。JWT用于无状态API认证。

* **Q41: git fetch和git pull的区别**
  A: git fetch：将远程变更下载到本地跟踪分支（origin/main），不会修改工作分支——安全的只读操作。用于在集成前审查：git fetch origin后，通过git log origin/main..main查看落后提交，然后手动合并/rebase。git pull：git fetch + git merge（或使用--rebase时为git rebase）的快捷方式。会修改工作目录，可能创建合并提交。使用场景：谨慎审查优先的工作流用git fetch；自信时用git pull方便操作。对于共享分支，推荐git pull --rebase避免不必要的合并提交，保持整洁的线性历史。git pull = fetch + merge/merge-rebase。

* **Q42: http2.0 做了哪些改进 http3.0 呢**
  A: HTTP/2（2015年）：1）多路复用——单个TCP连接上多个并发流，消除HTTP/1.1的应用层队头阻塞。2）二进制分帧——高效的帧协议（HEADERS、DATA、SETTINGS）。3）服务器推送——服务器主动推送资源（Chrome因滥用问题正在废弃）。4）头部压缩（HPACK）——Huffman编码+动态表，减少85-90%。5）流优先级——客户端可指定关键资源优先级。6）流级流量控制。HTTP/3（2022年）：1）QUIC传输（基于UDP）——消除TCP级队头阻塞，丢包仅阻塞其所在流，不影响其他流。2）0-RTT——返回用户可立即发送数据。3）连接迁移——IP变化（Wi-Fi切蜂窝网络）时连接不中断。4）默认加密（传输层头部加密）。

* **Q43: css sprite是什么,有什么优缺点**
  A: CSS Sprite将多张小图片合并为一个文件，通过background-position显示不同区域。优点：减少HTTP请求数（HTTP/1.1下至关重要）、更好的压缩效果（共享调色板）、原子化加载（所有图标同时出现）。缺点：维护成本高（添加图标需要重新生成整个雪碧图）、带宽浪费（即使用很少图标也要下载整个雪碧图）、无法部分缓存失效（修改一个图标导致整个雪碧图失效）、高清屏适配复杂（需要单独的高清雪碧图）。现代替代方案：SVG雪碧图（`<symbol>` + `<use>`）、图标字体、或HTTP/2多路复用（减少雪碧图优化的需求，因为多个请求开销很低）。

* **Q44: css sprite是什么,有什么优缺点**
  A: 参见Q43。CSS Sprite将多张小图片合并为一个文件，通过background-position显示不同区域。优点：减少HTTP请求数、更好的压缩效果、原子化加载。缺点：维护成本高、带宽浪费、无法部分缓存失效、高清屏适配复杂。现代替代方案：SVG雪碧图（`<symbol>` + `<use>`）、图标字体、HTTP/2多路复用。

* **Q45: display: none;与visibility: hidden;的区别**
  A: display: none——将元素完全从渲染树中移除。不占任何布局空间——周围元素会重新排列填补空白。屏幕阅读器无法访问。触发回流（布局重新计算）+ 重绘。如果初始为display:none，资源（图片）可能不会加载。不能动画过渡。visibility: hidden——视觉上隐藏但布局空间保留（元素仍在渲染树中）。不触发回流——仅重绘或合成（对GPU加速图层）。屏幕阅读器仍可访问（需用aria-hidden="true"从辅助技术中隐藏）。可以做动画过渡（opacity过渡）。选择建议：真正移除元素用display:none；保留布局空间或做淡出过渡用visibility:hidden。

* **Q46: link与@import的区别**
  A: link：`<link rel="stylesheet" href="style.css">`——HTML标签，兼容所有浏览器包括旧版。与HTML解析并行加载（不阻塞解析但阻塞渲染）。可包含媒体查询（`<link media="print">`）。可通过JS动态注入（创建新的HTTP请求）。head中多个link标签不会产生额外HTTP请求。@import：`@import url('style.css')`——CSS指令，必须出现在其他CSS规则之前。串行加载（阻塞直到导入的样式表加载完成）。旧版IE（IE5之前）不支持。无法通过JS动态加载。产生额外的HTTP请求级联。不能使用媒体查询。性能方面：@import阻塞并行下载并增加关键路径，现代开发中应避免使用。

* **Q47: 什么是FOUC?如何避免**
  A: FOUC（无样式内容闪烁）发生在浏览器在所有CSS加载完成前就渲染HTML，导致样式应用前出现短暂的无样式内容闪烁。在IE和慢速网络中常见。原因：通过@import加载样式表导致的级联；样式表顺序错误；CSS加载缓慢；JavaScript等待样式表加载。预防措施：1）在`<head>`中内联首屏关键CSS。2）使用`<link>`代替@import。3）异步加载非关键CSS。4）将样式表放在`<head>`靠前位置。5）使用一致的字体加载策略（font-display: swap）。6）最大控制：用CSS opacity: 0隐藏body，CSS加载完成后再显示（配合Critical CSS + load事件）。

* **Q48: 如何创建块级格式化上下文(block formatting context),BFC有什么用**
  A: BFC（块级格式化上下文）是一个CSS渲染区域，块级元素在其中布局，与外部元素的交互相互隔离。创建BFC的方法：overflow: hidden/auto/scroll（非visible）；display: flow-root（最佳选择，无副作用）；display: flex/inline-flex/grid/inline-grid；float: left/right（非none）；position: absolute/fixed；display: inline-block；column-count: 非auto。好处：1）包含浮动——防止浮动子元素导致父元素高度塌陷。2）防止外边距折叠——BFC内部元素的外边距不会与外部元素的外边距合并。3）防止环绕浮动——创建新列旁侧浮动元素，用于多列布局。display: flow-root是首选，它创建BFC且无副作用（不像overflow会裁剪阴影）。

* **Q49: display、float、position的关系**
  A: display决定元素的盒类型和初始布局行为。float将元素移到一侧，使其脱离正常流——对大多数元素会覆盖display计算为块级（inline-table、flex等除外）。position: absolute/fixed将元素完全移出流——float被忽略（计算为none）。position: relative保持正常流但允许偏移。关系规则：1）如果position是absolute/fixed，float变为none，display计算为block。2）如果float不是none，display计算为block或table。3）display: flex/grid的子元素忽略float。理解这种级联关系可避免布局bug，比如float或绝对定位意外改变元素尺寸行为。

* **Q50: 清除浮动的几种方式，各自的优缺点**
  A: 1）使用::after伪元素的clearfix（最常用）：.clearfix::after { content: ''; display: table; clear: both; }——各处可用，无需额外HTML。2）父元素设置overflow: hidden/auto——创建BFC，包含浮动。缺点：裁剪溢出内容（阴影、绝对定位子元素）。3）父元素设置display: flow-root——创建BFC且无副作用。现代CSS，但不支持旧浏览器。4）空清除div：`<div style="clear: both">`——额外的无语义HTML元素。5）使用flexbox/grid——现代方案，完全避免浮动。建议：遗留float布局用clearfix模式；新布局优先使用flexbox/grid。

* **Q51: 为什么要初始化CSS样式?**
  A: CSS初始化（CSS reset）消除各浏览器间的默认样式差异（如body的margin、ul的padding、h1-h6的字体大小等）。不做reset的话，同样的CSS在Chrome和Firefox/Safari中可能表现不同，因为用户代理样式表不同。方案：1）CSS Reset（Eric Meyer）——将所有默认值重置为0，所有元素需要显式重新样式化。2）Normalize.css——保留有用的默认值同时标准化浏览器差异。更实用的方案。3）自定义reset——项目特定需求的最小重置（如`*, *::before, *::after { box-sizing: border-box; margin: 0; padding: 0; }`）。好处：跨浏览器一致的基线、可预测的布局计算、减少跨浏览器QA时间。

* **Q52: css3有哪些新特性**
  A: 选择器：属性选择器（[attr^=val]、[attr$=val]、[attr*=val]）、结构伪类（:nth-child、:nth-of-type、:last-child、:first-of-type、:not()）、UI伪类（:enabled、:disabled、:checked）。盒模型：box-sizing（content-box/border-box）。布局：Flexbox、CSS Grid、多列布局。视觉效果：border-radius、box-shadow、text-shadow、渐变（linear-gradient、radial-gradient）、多背景、background-size、rgba/hsla颜色、opacity。过渡：transition-property、transition-duration、transition-timing-function、transition-delay。变换：rotate、scale、translate、skew（2D + 3D）。动画：@keyframes + animation属性。Web字体：@font-face、font-display。媒体查询：@media响应式设计。计算：calc() CSS数学运算。变量：自定义属性（--var-name）。滤镜：filter（blur、grayscale、contrast）。

* **Q53: display有哪些值？说明他们的作用**
  A: none：隐藏元素（从渲染树中移除）。block：另起新行，占满整行宽度。inline：保持在行内，宽高由内容决定。inline-block：行内流但支持width/height/margin/padding（不换行）。flex：块级flex容器。inline-flex：行内级flex容器。grid：块级grid容器。inline-grid：行内级grid容器。table/inline-table/table-row/table-cell/table-caption：非table元素的表格布局行为。list-item：行为类似`<li>`。flow-root：创建BFC且无副作用。contents：将元素从渲染树中移除，子元素继承布局位置。inherit/initial/unset/revert：CSS继承控制关键字。

* **Q54: 介绍一下标准的CSS的盒子模型？低版本IE的盒子模型有什么不同的？**
  A: 标准W3C盒模型（content-box）：width/height仅包含内容区域。padding和border是额外添加的。总宽度 = width + padding-left + padding-right + border-left + border-right。IE盒模型（border-box）：width/height包含内容 + padding + border。总宽度 = width（padding/border已包含在内）。box-sizing: border-box更推荐，因为它使尺寸计算可预测——添加padding时百分比宽度不会溢出。调整padding无需重新计算宽度。大多数项目全局设置`*, *::before, *::after { box-sizing: border-box; }`。两种模型中margin都不包含在width内。

* **Q55: CSS优先级算法如何计算？**
  A: CSS优先级（特异性）按四个等级计算(a,b,c,d)：a = 内联样式（style属性）——1000；b = ID选择器（数量）——每个100；c = 类选择器、伪类、属性选择器（数量）——每个10；d = 元素选择器、伪元素（数量）——每个1。示例：#header (0,1,0,0) > .nav (0,0,1,0) > div (0,0,0,1)。!important覆盖所有优先级（慎用——破坏自然层叠）。相同优先级：后声明的规则获胜。字符串连接比较：(0,1,0,0)大于(0,0,10,0)，因为1个ID > 10个类。算法：浏览器使用四元组比较，而非十进制求和。实践建议：保持低优先级、避免!important、使用BEM命名管理优先级。

* **Q56: 对BFC规范的理解？**
  A: BFC（块级格式化上下文）是页面中块级盒子按正常流规则布局的区域，与外部元素的交互相互隔离。BFC建立独立的渲染上下文：子元素的外边距不与外部元素合并；内部浮动被包含；BFC盒在浮动元素旁创建新列（用于自适应布局）。创建BFC的方法：float（非none）、overflow（非visible）、display（inline-block、flow-root、flex、grid）、position（absolute、fixed）、contain（layout、content、paint）。display: flow-root是创建BFC的语义化方式且无副作用。现代布局（flexbox、grid）创建自己的格式化上下文，类似于BFC。

* **Q57: 谈谈浮动和清除浮动**
  A: Float将元素移出正常文档流，定位到容器的左侧或右侧。内容环绕浮动元素。Float原本用于文本环绕图片，但在flexbox/grid出现前曾是主要的CSS布局方式。问题：父元素高度塌陷（父元素不包含浮动子元素）、内容重叠、意外的宽度行为。解决方案：1）使用::after伪元素的clearfix。2）父元素设置overflow: hidden（创建BFC）。3）display: flow-root（无副作用的BFC）。现代做法：一维布局使用flexbox，二维布局使用grid。Float应仅用于其原始用途：文本环绕图片。

* **Q58: position的值， relative和absolute定位原点是**
  A: static：默认值，元素遵循正常文档流，z-index/top/left/right/bottom被忽略。relative：元素保持在正常流中但相对于其正常位置偏移（top/left/right/bottom）。为绝对定位子元素创建新的包含块。absolute：移出正常流，相对于最近的定位祖先（非static）定位。如果没有定位祖先，相对于文档（初始包含块）。宽度收缩到内容宽度。用于浮层、模态框、工具提示、精确定位。fixed：移出正常流，相对于视口（初始包含块）定位。滚动时保持固定。用途：粘性头部、悬浮按钮、返回顶部按钮。sticky：relative+fixed的混合体。滚动到阈值前表现为relative，之后固定。包含块：fixed为视口；sticky为最近的滚动容器。

* **Q59: display:inline-block 什么时候不会显示间隙？**
  A: inline-block间隙出现在HTML中inline-block元素之间有空白（空格、制表符、换行）时，因为这些空白被折叠为单个空格字符（约4px）。无间隙的情况：1）HTML中标签间无空白：`<div>a</div><div>b</div>`。2）父元素设置font-size: 0（使空格字符宽度为0，子元素重新设置font-size）。3）负margin补偿（脆弱，依赖字体）。4）Flexbox/grid（gap属性不适用于inline-block）。5）元素间使用注释：`<div>a</div><!-- --><div>b</div>`。最佳实践：布局优先使用flexbox/grid，它们原生处理间距且无空白问题。

* **Q60: PNG\GIF\JPG的区别及如何选**
  A: PNG：无损，支持完整alpha透明（PNG-24）或1位透明（PNG-8）。最适合：截图、带透明的UI元素、边缘锐利/有文字的图形、带渐变的logo。照片场景文件体积大于JPEG。GIF：无损（限制在256色），支持简单动画，1位透明（硬边缘，无alpha）。最适合：简单动画（加载动画、表情包）、小型动态图标。不适合：照片或高色彩图像（调色板限制）。JPEG：有损压缩，24位色彩（1670万色），不支持透明/动画。最适合：照片、有平滑渐变的复杂图像。照片场景比PNG小。选择原则：照片用JPEG，简单图形用PNG-8，质量+透明用PNG-24，动画用GIF，WebP/AVIF作为现代替代。

* **Q61: 行内元素float:left后是否变为块级元素？**
  A: 当行内元素（如span或a）设置float: left/right后，其计算后的display值实际上变为'block'（对大多数原始display值而言）。这是因为参与浮动会强制元素建立块级格式化上下文。但该元素并非完全等同于display: block——虽然它接受width/height和垂直margin（行内元素通常不支持），但在CSSOM中计算display值在所有情况下可能并非字面意义上的'block'。关键实际效果：浮动的行内元素可以接受显式的width、height、top/bottom margin和padding——这些是非浮动行内元素所拒绝的行为。这是CSS规范的一部分：浮动元素在布局目的上变为块级容器。

* **Q62: 在网页中的应该使用奇数还是偶数的字体？为什么呢？**
  A: 推荐使用偶数字体尺寸以获得更好的渲染和布局一致性。原因：1）子像素渲染——浏览器基于物理设备像素渲染字体。偶数尺寸（12px、14px、16px）更好地映射到设备像素，产生更清晰的文字，减少抗锯齿伪影。2）行高计算——偶数字体尺寸与常见倍数（1.5x14=21 vs 1.5x13=19.5）产生更整洁的整行高值，减少舍入不一致。3）设计惯例——大多数设计系统（Material Design、Ant Design、Bootstrap）使用基于偶数的排版比例。4）rem/em一致性——基础字体尺寸（16px）是偶数，百分比倍数产生更整洁的值。但奇数尺寸也可用于特定设计意图（创造视觉张力、匹配精确像素测量）。

* **Q63: ::before 和 :after中双冒号和单冒号 有什么区别？解释一下这2个伪元素的作用**
  A: 单冒号（:）是CSS2的遗留语法，用于伪类和伪元素（CSS3之前）：:before、:after、:first-line、:first-letter。双冒号（::）是CSS3语法，专用于伪元素：::before、::after、::first-line、::first-letter。这种区分将伪元素（创建虚拟元素）与伪类（选择状态）分开。现代浏览器对伪元素支持两种语法，但::是推荐标准。::before在元素实际内容前插入生成内容；::after在元素实际内容后插入。用途：clearfix（.clearfix::after { clear: both; }）、装饰性图标（::before配合字体图标）、工具提示、自定义复选框、引用装饰。两者都需要content属性才能渲染。自定义属性用法：content: attr(data-tooltip); 计数器：content: counter(section); 图标：content: "\f007"。

* **Q64: 如果需要手动写动画，你认为最小时间间隔是多久，为什么？（阿里）**
  A: 流畅动画的最小时间间隔（特别是使用requestAnimationFrame时）约为16.67ms（1000ms / 60fps）。这对应标准显示刷新率60Hz显示器。人眼在约60帧每秒时 perceived 运动为流畅。requestAnimationFrame与显示刷新周期同步，通常每16.67ms触发一次。对于120Hz+显示器（iPad Pro、高刷显示器），间隔约8.33ms（120fps）或4.17ms（240fps）。requestAnimationFrame自动匹配显示刷新率——使用更短的间隔（<16ms的setTimeout/setInterval）会导致不必要的计算，无视觉收益，且可能导致丢帧和电池消耗。渲染管线（样式 -> 布局 -> 绘制 -> 合成）必须在此帧预算内完成以实现无卡顿动画。

* **Q65: CSS合并方法**
  A: CSS合并将多个CSS文件合并为一个以减少HTTP请求（HTTP/1.1下很重要）。方法：1）构建工具合并（Webpack/PostCSS/Grunt/Gulp）——构建时将CSS文件串联为一个bundle。2）CSS中的@import（不推荐——产生串行阻塞请求）。3）CSS-in-JS方案（styled-components、Emotion）自然将样式与组件打包。4）CSS模块 + 打包器（Webpack CSS loader）产生合并输出。5）手动拼接（脆弱，不可扩展）。现代方案（HTTP/2+）：合并不那么关键，因为HTTP/2多路复用可高效处理多个并发请求。按组件/页面提供独立CSS文件可获得更好的缓存粒度（修改一条规则不会使整个bundle失效）。路由级CSS代码分割是最佳方案。

* **Q66: CSS不同选择器的权重(CSS层叠的规则)**
  A: CSS优先级计算分四个等级(a,b,c,d)：a = 内联样式（style属性）——1000；b = ID选择器（数量）——每个100；c = 类选择器、伪类、属性选择器（数量）——每个10；d = 元素选择器、伪元素（数量）——每个1。!important覆盖所有优先级（避免使用）。同优先级时：后声明的规则获胜。来源优先级：!important用户代理 > !important用户 > !important作者 > 动画 > 作者 > 用户 > 用户代理。层叠算法：1）按选择器匹配过滤声明。2）按来源/重要性排序。3）按优先级排序。4）按声明顺序排序。减少层叠问题：使用作用域样式（CSS模块、Shadow DOM）、BEM命名、CSS-in-JS。

* **Q67: 列出你所知道可以改变页面布局的属性**
  A: 可改变布局的CSS属性：display（block/inline/flex/grid/none）、position（static/relative/absolute/fixed/sticky）、float/clear、width/height（及min/max变体）、margin/padding、top/right/bottom/left（定位元素）、transform（translate、rotate、scale——创建新的层叠上下文，对relative/static影响布局）、flex属性（flex-direction、flex-wrap、flex-basis、flex-grow、flex-shrink、order）、grid属性（grid-template-columns/rows、grid-area、grid-column/row）、column-count/column-width（多列）、box-sizing（影响尺寸计算方式）、writing-mode/direction（影响块流方向）。现代布局使用flexbox（一维）和grid（二维）。关键理解：某些属性触发回流（width/height/top/left），其他仅触发合成（transform/opacity）——性能上需酌情选择。

* **Q68: CSS在性能优化方面的实践**
  A: CSS性能优化实践：1）简化选择器——避免深度嵌套选择器（Sass深度>4）。浏览器从右向左读取选择器，所以.content .sidebar .item > a span成本较高。2）使用类选择器代替后代选择器。3）避免昂贵属性（box-shadow、border-radius、filter、backdrop-filter导致绘制开销；will-change触发图层提升）。4）最小化重排——仅对transform和opacity做动画（仅合成）。5）减少未使用CSS——使用PurifyCSS/UnCSS移除未使用样式。6）关键CSS内联——提取首屏CSS并内联到`<head>`。7）代码分割——按路由/组件懒加载CSS。8）使用contain: layout style paint将渲染限制在子树。9）content-visibility: auto跳过屏幕外渲染。10）使用CSS变量代替多次属性更新实现主题切换。

* **Q69: CSS3动画（简单动画的实现，如旋转等）**
  A: CSS3动画使用@keyframes规则定义动画在各进度点的状态（0%-100%），通过animation属性应用。示例：`@keyframes rotate { from { transform: rotate(0deg); } to { transform: rotate(360deg); } }`，`.element { animation: rotate 2s ease-in-out infinite; }`。动画属性：animation-name、animation-duration、animation-timing-function（ease、linear、cubic-bezier）、animation-delay、animation-iteration-count（数字/infinite）、animation-direction（normal/reverse/alternate）、animation-fill-mode（none/forwards/backwards/both——控制动画前后的样式）、animation-play-state（running/paused）。性能：仅对transform和opacity做动画（仅合成，无布局/绘制）。对动画元素使用will-change或translateZ(0)提升为合成器图层。简单过渡优先使用CSS transition；复杂时间线或动态变化考虑Web Animations API。

* **Q70: base64的原理及优缺点**
  A: Base64将二进制数据（图片、字体）编码为ASCII文本字符串，可直接嵌入CSS/HTML中作为data URI：`background-image: url('data:image/png;base64,iVBOR...')`。优点：1）减少HTTP请求——资源嵌入在CSS/HTML中，无需单独请求。2）无额外DNS/TLS/连接开销。3）CSS加载后立即可用——无"图片缺失闪烁"。缺点：1）比原始二进制文件大约33%（Base64增加33%开销）。2）无法独立缓存——如果嵌入CSS中，图片作为CSS的一部分缓存；修改CSS会导致图片重新缓存。3）无法跨页面共享——每个页面的CSS都有自己的base64副本。4）CSS/HTML文件体积显著增加。适用场景：非常小的图片（2KB以下）、关键首屏图片、HTTP开销超过数据节省的图标。

* **Q71: 几种常见的CSS布局**
  A: 常见CSS布局方式：1）正常流——块级元素垂直堆叠，行内元素水平排列。2）Float布局——元素浮动实现多列（遗留方案，用于文本环绕）。3）Flexbox——一维布局（行或列）。完美适用于导航栏、居中、等高列、自动间距。4）CSS Grid——二维布局（行和列同时）。最适合整页布局、杂志风格、复杂重叠布局。5）多列——文本像报纸一样流入多列。6）定位——absolute/fixed/sticky用于浮层、工具提示、头部。7）Table布局（display: table）——垂直居中和等宽列（遗留，灵活性差）。现代最佳实践：一维组件（导航、卡片、工具栏）用Flexbox；二维页面布局（header/sidebar/main/footer）用Grid；复杂布局两者结合。

* **Q72: 流体布局**
  A: 流体布局（liquid layout）使用百分比宽度而非固定像素，使页面能拉伸适配不同屏幕宽度。关键特征：使用相对单位（%、vw、vh、em、rem）；容器按比例调整大小；使用min-width/max-width防止极端情况（太窄/太宽）。实现：主容器`{ width: 90%; max-width: 1200px; margin: 0 auto; }`，侧边栏`{ width: 30%; }`，内容`{ width: 70%; }`。优点：适用于所有屏幕尺寸，无横向滚动条。局限：不改变布局结构（列保持为列），内容可能看起来过于拉伸或压缩。比固定宽度更先进，比带媒体查询的响应式设计能力弱。现代组合：流体布局 + 媒体查询 = 响应式设计。

* **Q73: 圣杯布局**
  A: 圣杯布局：带有header和footer的三栏布局，中间栏自适应（填充剩余空间），两侧栏固定宽度。挑战：中间内容应在HTML中先加载（SEO/感知性能），但在视觉上位于两侧栏之间。Flexbox实现：.container { display: flex; } .center { flex: 1; order: 2; } .left { width: 200px; order: 1; } .right { width: 200px; order: 3; }。HTML顺序：center在前，left其次，right最后。CSS Grid实现：.container { display: grid; grid-template-columns: 200px 1fr 200px; grid-template-areas: 'left center right'; }。CSS Grid更简洁——不需要order操作。该布局起源于flexbox之前的时代，使用负边距和float实现。

* **Q74: 双飞翼布局**
  A: 双飞翼布局与圣杯布局类似，但中间栏使用不同技术实现。中间栏使用额外的wrapper div。结构：.center（100%宽度，float: left）包含.center-inner（左右margin等于侧边栏宽度）。.left（float: left，margin-left: -100%）和.right（float: left，margin-left: -width）使用负边距定位。与圣杯布局的关键区别：圣杯使用容器的padding和相对定位；双飞翼使用嵌套div和负边距，不涉及相对定位，在基于float的实现中更简洁。两者解决相同问题：中间栏自适应且HTML中先加载的三栏布局。现代flexbox和grid实现更简单易维护。

* **Q75: stylus/sass/less区别**
  A: 三者都是CSS预处理器，通过变量、嵌套、混合、函数和逻辑扩展CSS。Sass：最成熟，两种语法（.scss和.sass）。SCSS语法与CSS兼容。特性：变量（$）、嵌套、混合（@mixin/@include）、函数、控制指令（@if/@for/@each）、颜色操作、@extend。使用Dart Sass编译。Less：类似Sass但基于JavaScript（在Node/浏览器中运行）。变量使用@（@var而非$）。语法更宽容。比Sass简单。Stylus：最灵活，基于缩进（类似.sass但大括号/冒号可选）。语法非常简洁。内置函数强大。社区和工具支持较少。现代偏好：Sass（SCSS）采用最广泛。Dart Sass是参考实现。CSS-in-JS和PostCSS正在成为减少预处理器需求的替代方案。

* **Q76: postcss的作用**
  A: PostCSS是用JavaScript插件转换CSS的工具。它采用插件架构，每个插件以某种方式转换CSS。不是预处理器（虽然可以替代）。处理流程：CSS字符串 -> AST -> 插件转换 -> 转换后的CSS字符串。关键插件：Autoprefixer（自动添加浏览器前缀）、PostCSS Preset Env（启用未来CSS语法，如嵌套、自定义媒体查询）、CSS Nano（压缩）、Stylelint（代码检查）、PostCSS Modules（作用域CSS）、PostCSS Import（内联@import）、Tailwind CSS（基于PostCSS构建）。优势：模块化插件架构（只使用需要的）、比Sass快（JS-based，无Ruby）、能使用未来CSS语法。构建工具（Webpack、Vite）默认集成PostCSS。现代方案：PostCSS + 预处理器（Sass）获得最大灵活性。

* **Q77: css样式（选择器）的优先级**
  A: CSS选择器优先级（从高到低）：1）!important标注（覆盖所有，避免使用）。2）内联样式（style属性）。3）ID选择器（#header、#sidebar）。4）类选择器（.nav、.active）、伪类（:hover、:nth-child）、属性选择器（[type="text"]）。5）元素选择器（div、p、span）、伪元素（::before、::after）。通用选择器（*）和组合器（>、+、~）不增加优先级。同优先级：后声明的规则获胜。:is()和:not()伪类取最具体的参数的优先级。复合选择器优先级累加。最佳实践：保持低且平的优先级（避免过度限定：div.nav而非.nav）、使用BEM命名最小化选择器嵌套、避免!important。CSS-in-JS通过将样式限定在组件内避免了优先级战争。

* **Q78: 自定义字体的使用场景**
  A: 自定义字体（@font-face）用于超越Web安全字体的品牌字体。使用场景：1）品牌标识——在网站上使用公司自定义字体（如Airbnb的Cereal、GitHub的Mona Sans）。2）图标字体——Font Awesome、Material Icons作为图标集（正在被SVG替代）。3）国际脚本——系统字体不覆盖的语言的字体（CJK、阿拉伯语、天城文）。4）数字出版——阅读应用的变体字体（weight/width轴控制）。5）设计系统——所有产品中一致的排版。性能考虑：使用font-display: swap（FOUT）防止不可见文本；子集化字体仅包含所需字符；预加载关键字体（`<link rel="preload" as="font">`）；自托管字体vs外部服务（控制vs便利）。变体字体在一个文件中存储多个字重，减小文件大小。

* **Q79: 如何美化CheckBox**
  A: 原生复选框难以跨浏览器样式化，因为其外观是操作系统原生的。方案：1）隐藏原生复选框，使用label + ::before/::after伪元素自定义外观。`input[type="checkbox"] { position: absolute; opacity: 0; }`，`label::before { content: ''; display: inline-block; width: 20px; height: 20px; border: 2px solid #333; border-radius: 3px; }`，`input:checked + label::before { background: blue; }`，`input:checked + label::after { content: '\2713'; color: white; }`。伪元素也可为:focus、:disabled状态样式化。2）SVG方案——隐藏复选框 + SVG图标在:checked时切换。3）CSS appearance: none——`input[type="checkbox"] { appearance: none; -webkit-appearance: none; }`然后从头样式化（现代浏览器可用）。4）图标字体字符。确保无障碍：使用`<label>`包裹，保持键盘导航，包含焦点样式。

* **Q80: 伪类和伪元素的区别**
  A: 伪类（:）基于状态或位置选择元素，不创建新元素。示例：:hover（鼠标悬停）、:focus（键盘焦点）、:nth-child(n)（在父元素中的位置）、:first-child、:last-child、:not(selector)、:checked（复选框状态）、:disabled、:empty、:target（URL片段匹配元素id）。它们基于条件过滤现有元素。伪元素（::）创建不存在于DOM中的虚拟元素，允许样式化特定部分。示例：::before（在元素内容前插入内容）、::after（在元素内容后插入）、::first-letter（首字母样式）、::first-line（首行样式）、::selection（用户选中文本样式）、::placeholder（输入框占位符）、::marker（列表标记）。它们从内容生成新的样式化"元素"。核心区别：伪类描述基于状态的条件；伪元素创建虚构元素或目标化现有元素的子部分。

* **Q81: base64的使用**
  A: Base64将二进制数据编码为ASCII，以便作为data URI嵌入CSS/HTML。语法：`url('data:image/png;base64,iVBORw0KG...')`。使用场景：1）小图标（2-3KB以下）减少HTTP请求。2）必须随CSS立即显示的关键图片（避免单独请求）。3）邮件内嵌图片（单文件自包含）。4）跨元素重复的微小图案/背景。5）字体文件作为data URI（较少，体积大）。最佳实践：仅用于小文件（base64开销约33%）；不适合照片或大图；考虑内联在HTML`<link>`或CSS中而非单独请求；配合自动化构建工具（Webpack url-loader、PostCSS）；注意嵌入资源无法独立缓存或跨页面共享。HTTP/2环境下请求开销论点较弱，使base64吸引力降低。

* **Q82: 自适应布局**
  A: 响应式/自适应设计使网页在不同尺寸设备上正常工作。方案：1）流体/百分比布局——元素按视口比例调整大小。2）媒体查询——CSS @media断点（min-width: 768px、1024px）在特定宽度改变布局结构。3）弹性图片——max-width: 100%防止溢出。4）Viewport元标签——`<meta name="viewport" content="width=device-width, initial-scale=1.0">`。5）CSS Grid/Flexbox——fr单位、auto-fit、auto-fill天然响应式。常见断点：移动端<768px、平板768-1024px、桌面端>1024px。设计方法：移动优先（移动端基础样式，大屏媒体查询增强）vs 桌面优先。推荐移动优先：从单列开始，在大宽度增加复杂度。类型：响应式（流体、同URL）vs 自适应（断点处固定布局）vs 混合。

* **Q83: 请用CSS写一个简单的幻灯片效果页面**
  A: 纯CSS幻灯片使用@keyframes动画。HTML：`<div class="slideshow"><div class="slides"><img src="1.jpg"><img src="2.jpg"><img src="3.jpg"></div></div>`。CSS：`.slideshow { width: 600px; height: 400px; overflow: hidden; position: relative; }`，`.slides { display: flex; width: 300%; animation: slide 9s infinite; }`，`.slides img { width: 33.333%; }`，`@keyframes slide { 0%, 25% { transform: translateX(0); } 33%, 58% { transform: translateX(-33.333%); } 66%, 91% { transform: translateX(-66.666%); } 100% { transform: translateX(0); } }`。关键：动画在每张图片处暂停（使用%范围）然后过渡到下一张。增强：hover时设置animation-play-state: paused；使用opacity过渡的导航点；使用checkbox hack实现自动播放+手动控制。局限：纯CSS无法动态添加幻灯片或处理滑动事件。交互式幻灯片需使用JS。

* **Q84: 什么是外边距重叠？重叠的结果是什么？**
  A: 外边距折叠（margin collapsing）发生在相邻块级元素的垂直外边距重叠时，合并为一个等于两者中较大值的外边距（不是两者之和）。场景：1）相邻兄弟元素——第一个元素的底边距 + 第二个元素的顶边距折叠。2）父子元素——第一个子元素的顶边距与父元素的顶边距折叠；最后一个子元素的底边距与父元素的底边距折叠。3）空块——所有三个边距（顶、底和auto高度）折叠为一个。折叠后：结果边距 = max(margin1, margin2)。负边距：正的最大值 + 负的最小值（可相互抵消）。预防方法：在边距之间添加border/padding、创建BFC（overflow: hidden、display: flow-root）、使用flexbox/grid（不折叠）、或用padding代替margin。水平边距永远不会折叠（仅正常流中的垂直边距折叠）。

* **Q85: rgba()和opacity的透明效果有什么不同？**
  A: rgba()和opacity都创建透明度但影响不同元素。opacity：影响整个元素包括所有子元素及其背景、边框、文字。整个子树一起变透明（子元素不能比父元素更不透明）。这产生扁平化效果，后代元素的透明度受祖先opacity限制。触发新的层叠上下文（z-index行为改变）。rgba()：仅影响其应用的特定属性（color、background-color、border-color等）。子元素不受影响——正常继承颜色值（可能包含alpha值）。示例：background: rgba(0,0,0,0.5)仅使背景半透明；文字保持完全不透明。相关：hsla()与rgba()类似，使用Hue-Saturation-Lightness颜色模型。整个元素淡出用opacity；特定属性透明度用rgba/hsla。

* **Q86: css中可以让文字在垂直和水平方向上重叠的两个属性是什么？**
  A: 导致文字在垂直和水平方向重叠的CSS属性：1）letter-spacing（水平）——控制字符间距。大负值导致字符重叠：letter-spacing: -5px。2）line-height（垂直）——控制文本行高度。小于font-size配合overflow: hidden导致垂直重叠：line-height: 0.8; overflow: hidden。3）负margin——margin-top: -20px将元素（及其文字）向上拉，与前一内容重叠。4）Transform——transform: scale(2)使文字变大，可能与相邻元素重叠。5）带负偏移的定位——position: relative; top: -20px将文字上移。6）text-shadow可创建重叠视觉效果。7）white-space: nowrap配合overflow: hidden使文字水平裁剪。有意的重叠用途：堆叠文字效果、装饰性首字下沉、重叠标题。

* **Q87: 如何垂直居中一个浮动元素？**
  A: 浮动元素垂直居中：1）Flexbox（推荐）：.container { display: flex; align-items: center; justify-content: center; }——flexbox在父元素上覆盖float行为。2）Transform：.parent { position: relative; } .child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }——与宽高无关。3）行内块 + line-height：.parent { text-align: center; line-height: height; } .child { display: inline-block; vertical-align: middle; line-height: 1.2; }——hacky，需要已知父元素高度。4）表格单元格：.parent { display: table-cell; vertical-align: middle; text-align: center; }。5）CSS Grid：.parent { display: grid; place-items: center; }。最佳实践：使用flexbox或CSS grid居中——它们处理未知尺寸，兼容性好，不像绝对定位那样破坏文档流。

* **Q88: px和em的区别**
  A: px（像素）：绝对单位，1 CSS像素 = 1/96英寸（逻辑像素，非物理设备像素）。固定大小，不随用户字体大小偏好缩放。可预测且精确。em：相对单位，相对于父元素的font-size。如果父元素是16px，子元素的1em = 16px。嵌套元素会累积：基于em的父元素内的子元素会变小/变大。用于应随文本缩放的间距。rem（root em）：相对于根元素（html）的font-size。避免累积问题。默认：1rem = 16px（浏览器默认）。现代方案：字体大小和间距使用rem（无障碍——尊重用户的浏览器字体大小设置），边框、阴影和小型固定元素使用px。复杂嵌套避免使用em。布局宽度使用百分比。视口相关尺寸使用vw/vh。

* **Q89: Sass、LESS是什么？大家为什么要使用他们？**
  A: Sass（Syntactically Awesome Style Sheets）和LESS（Leaner Style Sheets）是CSS预处理器，用原生CSS没有的特性扩展CSS。它们编译为普通CSS。使用原因：1）变量——存储颜色、字体、间距值实现一致的主题化。2）嵌套——镜像HTML结构，减少重复选择器。3）混合（Mixins）——可复用的带参数的样式块（类似函数）。4）函数——颜色操作（darken/lighten）、数学运算。5）部分文件和@import——模块化CSS文件组织。6）循环和条件——以编程方式生成重复样式。7）扩展/继承——共享规则集。Sass（SCSS）更流行，使用Dart Sass编译器。LESS基于JS，更简单但功能较少。现代转变：CSS现在有原生变量（自定义属性）、嵌套（草案规范）、颜色函数。PostCSS + 未来CSS插件减少了预处理器的需求。

* **Q90: 知道css有个content属性吗？有什么作用？有什么应用？**
  A: CSS content属性与::before和::after伪元素一起使用，插入生成内容。没有content（值非none/normal），伪元素不会渲染。取值：string——content: "prefix: "; attr()——content: attr(data-tooltip); 读取元素的属性值。url()——content: url(icon.svg); 插入图片。counter()——content: counter(section); 自动编号。open-quote/close-quote——content: open-quote; 自动引号。none/normal——抑制伪元素。应用场景：1）clearfix：.clearfix::after { content: ''; display: table; clear: both; }。2）图标插入：.icon::before { content: '\f007'; font-family: 'FontAwesome'; }。3）工具提示：content: attr(data-tip);。4）标题/章节自动编号配合counter()。5）自定义列表标记：li::before { content: '>> '; }。6）装饰元素（形状、分隔线）。

* **Q91: 水平居中的方法**
  A: 水平居中方法：1）行内/行内块 + text-align：.parent { text-align: center; } .child { display: inline-block; }——适用于行内/行内块子元素。2）块级 + 自动margin：.child { width: fit-content; margin: 0 auto; }——需要设置宽度（或fit-content自适应宽度）。3）Flexbox：.parent { display: flex; justify-content: center; }——现代浏览器最佳方案。4）CSS Grid：.parent { display: grid; justify-items: center; }或.parent { display: grid; } .child { justify-self: center; }。5）绝对定位 + transform：.parent { position: relative; } .child { position: absolute; left: 50%; transform: translateX(-50%); }——未知宽度可用。6）表格：.parent { display: table; margin: 0 auto; }。Flexbox推荐——语法最简单、最灵活。

* **Q92: 垂直居中的方法**
  A: 垂直居中方法：1）Flexbox：.parent { display: flex; align-items: center; }——最简单，适用于单个/多个元素。配合justify-content: center实现双轴居中。2）CSS Grid：.parent { display: grid; align-items: center; }或.parent { display: grid; } .child { align-self: center; }。place-items: center实现双轴。3）绝对定位 + transform：.parent { position: relative; } .child { position: absolute; top: 50%; transform: translateY(-50%); }——未知高度可用。4）绝对定位 + margin: auto：.child { position: absolute; top: 0; bottom: 0; margin: auto 0; height: 100px; }——需要已知高度。5）表格单元格：.parent { display: table-cell; vertical-align: middle; text-align: center; }。6）line-height：.parent { height: 100px; line-height: 100px; } .child { display: inline-block; vertical-align: middle; line-height: 1.2; }——单行文本或行内块子元素。Flexbox最灵活且最被推荐。

* **Q93: 如何使用CSS实现硬件加速？**
  A: CSS硬件加速使用GPU（图形处理器）进行渲染，将工作从CPU卸载。触发方式：1）will-change: transform/opacity——提示浏览器创建合成器图层。2）transform: translateZ(0) / translate3d(0,0,0)——强制3D加速（旧hack，今天不太需要）。3）transform: rotateX(0) / scaleZ(1)——一般3D变换。4）opacity动画。5）filter: blur()/drop-shadow()——可在GPU上加速。工作原理：GPU加速元素被提升到独立的合成图层（类似单独纹理）。CPU仅发送初始图层内容，然后GPU合成图层。transform/opacity动画不触发布局或绘制——仅合成。好处：流畅60fps动画，降低CPU负载。注意事项：过多图层消耗GPU内存（移动端尤其严重），为数千个元素创建图层导致内存压力。谨慎使用will-change——仅在实际会动画的元素上使用。

* **Q94: 重绘和回流（重排）是什么，如何避免？**
  A: 回流（reflow/layout）：DOM几何变化时重新计算元素位置和尺寸。触发场景：添加/删除可见元素；改变width/height/margin/padding；改变font-size；窗口resize；激活CSS伪类（:hover）。触发所有后代和祖先元素几何的重新计算。开销大——影响整个渲染树或大子树。重绘（repaint）：视觉变化不影响布局时重新绘制像素（color、background-color、visibility、outline）。比重排开销小但仍消耗GPU/CPU。合成（composite）：合并预先绘制的图层。最便宜的操作（仅GPU工作）。避免重排重绘：1）使用transform代替top/left改变位置。2）使用opacity代替visibility/display显示/隐藏。3）批量DOM读写（先读后写，或使用requestAnimationFrame）。4）使用DocumentFragment批量DOM插入。5）缓存布局属性（offsetTop、scrollHeight）一次性读取。6）即将动画的元素使用will-change。

* **Q95: 说一说css3的animation**
  A: CSS3动画由@keyframes规则定义动画在各进度点的状态（0%-100%或from-to），通过animation简写属性应用。属性：animation-name（关键帧名称）、animation-duration（时间）、animation-timing-function（ease/linear/cubic-bezier）、animation-delay（开始前延迟）、animation-iteration-count（数字/infinite）、animation-direction（normal/reverse/alternate）、animation-fill-mode（none/forwards/backwards/both——控制动画前后的样式）、animation-play-state（running/paused——hover控制有用）。示例：`@keyframes pulse { 0% { transform: scale(1); opacity: 1; } 50% { transform: scale(1.2); opacity: 0.7; } 100% { transform: scale(1); opacity: 1; } }`，`.element { animation: pulse 2s ease-in-out infinite; }`。性能：仅对transform和opacity做动画以获得GPU合成流畅效果。对动画元素使用will-change。简单过渡优先CSS transition；复杂时间线或动态变化考虑Web Animations API。

* **Q96: 左边宽度固定，右边自适应**
  A: 左固定右自适应布局：1）Flexbox（最简单）：.container { display: flex; } .left { width: 200px; flex-shrink: 0; } .right { flex: 1; }——右侧填充剩余空间。2）CSS Grid：.container { display: grid; grid-template-columns: 200px 1fr; }。3）Float + BFC：.left { float: left; width: 200px; } .right { overflow: hidden; }——overflow: hidden创建BFC，防止环绕。4）绝对定位：.container { position: relative; } .left { position: absolute; left: 0; width: 200px; } .right { margin-left: 200px; }——但右侧高度不自动匹配左侧。5）Calc：.right { width: calc(100% - 200px); margin-left: 200px; }——如果两者都浮动。Flexbox和Grid推荐——清晰且灵活。多行布局Grid更优。

* **Q97: 两种以上方式实现已知或者未知宽度的垂直水平居中**
  A: 双轴居中（已知/未知尺寸）：1）Flexbox（未知尺寸，最简单）：.parent { display: flex; justify-content: center; align-items: center; }。2）CSS Grid：.parent { display: grid; place-items: center; }。3）绝对定位 + transform（未知尺寸）：.parent { position: relative; } .child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }。4）绝对定位 + margin: auto（已知尺寸）：.child { position: absolute; top: 0; left: 0; right: 0; bottom: 0; margin: auto; width: 200px; height: 100px; }。5）表格单元格：.parent { display: table-cell; vertical-align: middle; text-align: center; } .child { display: inline-block; }。6）行内块 + line-height：.parent { text-align: center; line-height: height; } .child { display: inline-block; vertical-align: middle; line-height: 1.2; }。Flexbox推荐：语法最简单，处理任意尺寸，支持多个子元素，无绝对定位问题。

* **Q98: 如何实现小于12px的字体效果**
  A: 浏览器（特别是Chrome）强制执行12px的最小字体大小（可读性的默认最小值）。显示小于12px的字体：1）transform: scale()：.small-text { font-size: 12px; transform: scale(0.5); transform-origin: left; }——视觉缩小到6px。注意：元素仍占据原始空间（使用负margin或width: 200%补偿）。2）非CSS方案——准备小字体的图片（无障碍差，维护成本高）。3）zoom属性（非标准）：.small-text { zoom: 0.5; }——IE/Chrome可用。4）SVG文字——SVG文字元素以指定的精确font-size渲染，不受浏览器最小值限制。5）Canvas文字——类似SVG，以任意大小渲染。6）浏览器设置覆盖——Chrome最小字体大小可在设置中更改（chrome://settings/fonts）。用户可设为0。transform: scale()是最实用的CSS方案。

* **Q99: css hack原理及常用hack**
  A: CSS hack利用浏览器特定的CSS解析bug/ quirks，将样式条件性应用于特定浏览器（主要是旧版IE）。类型：1）条件注释（HTML，IE专用）：`<!--[if IE]><link rel="stylesheet" href="ie.css"><![endif]-->`。2）下划线/星号hack（IE6/7）：.element { _color: red; } /* IE6 */; *color: red; /* IE7 */。3）属性值hack：.element { color: red\9; } /* IE8-10 */; color: red\0; /* IE8+ */。4）选择器hack：*html .element {} /* IE6 */; :root .element {} /* IE9+ */。5）@media hack：@media screen\0 { } /* IE8-10 */。现代方案：完全避免CSS hack。使用特性检测（Modernizr、@supports）、渐进增强、Autoprefixer自动添加前缀。Hack使代码脆弱、难以维护，且会以意外方式失败。旧版IE使用条件注释提供独立样式表。

* **Q100: CSS有哪些继承属性**
  A: CSS继承属性（子元素自动继承父元素值，除非被覆盖）：1）文本：color、font-family、font-size、font-weight、font-style、font-variant、font-stretch、letter-spacing、line-height、text-align、text-indent、text-transform、word-spacing、white-space、word-break、word-wrap。2）可见性：visibility、cursor。3）列表：list-style、list-style-type、list-style-position、list-style-image。4）表格：border-collapse、border-spacing、caption-side、empty-cells。5）其他：direction、quotes、writing-mode、hyphens、orphans、widows。不继承：1）盒模型：width、height、margin、padding、border、display、box-sizing。2）背景：background、background-color、background-image等。3）定位：position、top、left、right、bottom、z-index、overflow、float、clear。4）生成内容：content。5）其他：outline、text-decoration。inherit关键字强制继承；initial重置为浏览器默认；unset = 继承可继承属性，否则为initial。

* **Q101: 外边距折叠(collapsing margins)**
  A: 参见Q84。外边距折叠发生在相邻块级元素的垂直外边距重叠时，合并为等于较大值的单个边距。三种场景：1）相邻兄弟元素——元素的底边距与下一个元素的顶边距折叠。结果 = max(margin-bottom, margin-top)。2）父子首尾子元素——父元素的顶边距与第一个子元素的顶边距折叠。预防：父元素设置border/padding、overflow: hidden、创建BFC。3）空块——所有边距（顶、底）折叠为一个。复杂情况：负边距，正的最大值 + 负的最小值（可相互抵消）；嵌套折叠（多层嵌套元素的外边距可以穿透折叠）。重要：水平边距从不折叠。仅正常流中的块级元素折叠（浮动、定位、行内块、flex/grid项目不折叠）。容器元素使用padding代替margin可完全避免折叠问题。

* **Q102: CSS选择符有哪些？哪些属性可以继承**
  A: CSS选择器：1）元素/类型：div、p、span。2）类：.classname。3）ID：#idname。4）通用：*（所有元素）。5）属性：[attr]、[attr=val]、[attr^=val]、[attr$=val]、[attr*=val]、[attr~=val]、[attr|=val]。6）伪类：:hover、:focus、:nth-child(n)、:first-child、:last-child、:not(sel)、:checked、:enabled、:disabled、:target、:empty、:root。7）伪元素：::before、::after、::first-line、::first-letter、::selection、::placeholder。8）组合器：后代（div p）、子元素（div > p）、相邻兄弟（div + p）、通用兄弟（div ~ p）、列（div || p）。继承属性：color、font-family、font-size、font-style、font-weight、font-variant、font-stretch、letter-spacing、line-height、text-align、text-indent、text-transform、visibility、cursor、list-style、quotes、direction、empty-cells、border-collapse、hyphens、orphans、widows、white-space、word-spacing、writing-mode。

* **Q103: CSS3新增伪类有那些**
  A: CSS3伪类：1）结构伪类：:nth-child(n)、:nth-last-child(n)、:nth-of-type(n)、:nth-last-of-type(n)、:first-child、:last-child、:first-of-type、:last-of-type、:only-child、:only-of-type、:empty、:root。2）UI状态：:checked、:disabled、:enabled、:default、:indeterminate、:valid、:invalid、:in-range、:out-of-range、:required、:optional、:read-only、:read-write。3）否定：:not(selector)——选择不匹配参数的。4）目标：:target——匹配ID与URL片段（#section）相同的元素。5）:first-letter和:first-line（曾为伪元素，CSS3中仍为::）。:nth-child(an+b)：匹配位置满足an+b的元素（如:nth-child(3n+1)选择每3个中的第1个）。odd/even是2n+1/2n的简写。:of-type变体类似但仅考虑相同元素类型的兄弟元素。

* **Q104: 如何居中div？如何居中一个浮动元素？如何让绝对定位的div居中**
  A: Div居中：1）margin: 0 auto;（有宽度的块级元素）。2）display: flex; justify-content: center; align-items: center;。浮动元素居中：1）水平居中：将容器设为width: 100%; float: left，然后子元素position: relative; left: 50%，孙元素right: 50%。更好的方案：2）容器display: flex; justify-content: center;（flex中float被忽略）。3）对浮动元素使用绝对定位（absolute时float被忽略）。绝对定位div居中：1）.parent { position: relative; } .child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }——未知尺寸。2）.child { position: absolute; top: 0; left: 0; right: 0; bottom: 0; margin: auto; width: 200px; height: 100px; }——已知尺寸。3）CSS Grid：.parent { display: grid; place-items: center; }——可行但grid控制对齐。

* **Q105: 用纯CSS创建一个三角形的原理是什么**
  A: CSS三角形使用border。一个宽高为0、三边透明边框、一边边框有颜色的元素：`.triangle { width: 0; height: 0; border-left: 50px solid transparent; border-right: 50px solid transparent; border-bottom: 100px solid red; }`创建一个向上指的三角形。原理：当border在角落交汇且元素无内容时，每个border边缘形成三角形。宽高为0时，每个border占据一个三角形区域。三个边框设为透明则只显示一个可见三角形。变体：等边三角形（border-width比例）、直角三角形（不等border）、指向方向（不同border有颜色）、对话气泡（配合::before/::after）。实际使用建议：现代设计中优先使用SVG（可缩放、更易维护、无障碍更好）。

* **Q106: 一个满屏 品 字布局 如何设计?**
  A: "品"字形布局：顶部区域横跨全宽，底部一行分为两个相等的 halves。CSS Grid实现：.container { display: grid; grid-template-columns: 1fr 1fr; grid-template-rows: 1fr 1fr; gap: 10px; height: 100vh; } .top { grid-column: 1 / -1; } .bottom-left { } .bottom-right { }。Flexbox实现：.container { display: flex; flex-direction: column; height: 100vh; } .top { flex: 1; } .bottom-row { display: flex; flex: 1; } .bottom-row > div { flex: 1; }。Float实现：.top { width: 100%; height: 50%; } .bottom-left, .bottom-right { width: 50%; height: 50%; float: left; }。Grid提供最语义化和简洁的方案。确保：全视口高度（100vh）、无溢出、一致的gap。响应式：在断点处调整为垂直堆叠。

* **Q107: li与li之间有看不见的空白间隔是什么原因引起的？有什么解决办法**
  A: li元素之间的间隙是由HTML中`</li>`和`<li>`之间的空白（换行、空格）引起的。当li使用display: inline-block（旧水平导航技术）时，空白折叠为单个空格字符（约4px，取决于font-size）。解决方案：1）移除HTML中的空白：`<li>a</li><li>b</li>`（无换行）。2）父元素ul设置font-size: 0，子元素li重新设置font-size（空格字符宽度为0）。3）使用flexbox：ul { display: flex; }——flex项目忽略空白。4）负margin：li { margin-right: -4px; }——脆弱，依赖字体。5）元素间使用HTML注释：`<li>a</li><!-- --><li>b</li>`。最佳方案：水平列表使用flexbox。如果必须使用inline-block（遗留方案），父元素设置font-size: 0。此间隙也发生在img、span和任何inline-block元素上。

* **Q108: 请列举几种隐藏元素的方法**
  A: 元素隐藏方法及关键区别：1）display: none——从渲染树中移除，不占空间，屏幕阅读器不可访问，触发回流。2）visibility: hidden——视觉隐藏但空间保留（元素仍在渲染树中）。不触发回流——仅重绘或合成（GPU加速图层）。屏幕阅读器可访问（需aria-hidden="true"从AT隐藏）。可动画（opacity过渡）。3）opacity: 0——视觉透明，空间保留，仍可交互（点击事件仍会触发！）除非配合pointer-events: none。可动画过渡。4）绝对定位 + 移出屏幕：position: absolute; left: -9999px; top: -9999px;——视觉上在屏幕外，仍在渲染树中，可访问（此方式隐藏的文字会被屏幕阅读器读取）。5）clip-path: clip-path: circle(0);——视觉裁剪为无。空间可能保留。6）transform: scale(0) / translate(-9999px)——视觉隐藏，空间可能保留。7）width: 0; height: 0; overflow: hidden——零尺寸，隐藏溢出。8）`<hidden>` HTML属性：`<div hidden>`——浏览器内置隐藏状态（同display: none）。

* **Q109: rgba() 和 opacity 的透明效果有什么不同**
  A: 参见Q85。opacity影响整个元素及其所有子元素（创建单一的合并透明表面）。子元素不能比父元素更不透明。创建新的层叠上下文（影响z-index行为）。不能选择性地仅应用于背景。rgba()将透明度应用于单个属性（background-color、color、border-color等），不影响其他属性或子元素。rgba背景配合opacity: 1是实现半透明叠加层而不影响文字可读性的常用技巧。使用场景：需要透明度作用于特定属性（仅背景或仅文字）用rgba；需要整个元素包括所有子元素一起淡入淡出（常见于淡入动画、hover效果、禁用状态）用opacity。

* **Q110: css 属性 content 有什么作用**
  A: 参见Q90。content属性与::before/::after伪元素一起使用插入生成内容。伪元素要渲染必须有content属性（值非none/normal）。取值：string——content: "Hello"; attr()——content: attr(data-custom); 读取属性值；url()——content: url(/icon.svg); 插入图片；counter()——content: counter(my-counter); 自动编号；open-quote/close-quote——content: open-quote; 自动引号。常见应用：clearfix（content: ''; display: table; clear: both）、字体图标（content: '\f007'; font-family: FontAwesome）、自定义列表标记（li::before { content: '> '; }）、基于属性的工具提示（content: attr(data-tip)）、标题编号（counter-increment + content）。无障碍：插入的内容可能不会被所有屏幕阅读器读取——不要用于关键信息。

* **Q111: 请解释一下 CSS3 的 Flexbox（弹性盒布局模型）以及适用场景**
  A: Flexbox是一维CSS布局模型，用于在容器内分配空间和对齐内容。关键属性——容器：display: flex; flex-direction（row/column——主轴方向）；flex-wrap（nowrap/wrap/wrap-reverse）；justify-content（主轴对齐：flex-start/center/flex-end/space-between/space-around/space-evenly）；align-items（交叉轴对齐：stretch/center/flex-start/flex-end/baseline）；align-content（多行交叉轴分布）；gap（项目间距）。项目：flex（flex-grow、flex-shrink、flex-basis的简写）；align-self（覆盖align-items）；order（视觉重排序）。适用场景：导航栏、卡片网格、居中、等高列、表单布局、任何一维排列。不适用的：整页二维布局（使用Grid）。Flexbox是一维的——一次处理行或列。flex算法根据flex-grow因子分配剩余空间。

* **Q112: 经常遇到的浏览器的JS兼容性有哪些？解决方法是什么**
  A: 常见浏览器JS兼容性问题（主要是旧版IE）：1）addEventListener vs attachEvent——IE < 9使用attachEvent。解决：特性检测封装。2）event对象——IE使用window.event，target vs srcElement。解决：event = event || window.event; target = event.target || event.srcElement。3）preventDefault vs returnValue——IE使用event.returnValue = false。4）stopPropagation vs cancelBubble——IE使用cancelBubble = true。5）XMLHttpRequest——IE < 7使用ActiveXObject。6）getElementsByClassName——IE < 9不支持。7）Array方法（forEach、map、filter）——IE < 9缺失。使用polyfill或Babel。8）CSS属性前缀——各浏览器-webkit-、-moz-、-ms-、-o-。使用Autoprefixer。现代方案：通过Babel转译（通过browserslist配置目标浏览器）、使用polyfills（core-js、polyfill.io）、避免已废弃API。现代浏览器（Chrome、Firefox、Safari、Edge）对ES6+有良好支持。

* **Q113: 请写出多种等高布局**
  A: 等高列布局（无论内容多少高度相同）：1）Flexbox：.container { display: flex; } .column { flex: 1; }——所有列自动相同高度（align-items默认stretch）。2）CSS Grid：.container { display: grid; grid-template-columns: 1fr 1fr 1fr; }——grid项目默认等高。3）表格单元格：.container { display: table; width: 100%; } .column { display: table-cell; }——表格行为实现等高（遗留方案，灵活性差）。4）Padding + 负margin（伪等高）：.column { padding-bottom: 9999px; margin-bottom: -9999px; } .container { overflow: hidden; }——视觉上等高但每列实际高度为其内容。5）display: inline-block + line-height：hacky，不推荐。现代推荐：一维用Flexbox，二维用Grid。两者都提供真正的等高布局，无需hack。

* **Q114: 浮动元素引起的问题**
  A: 浮动元素引起的问题：1）父元素高度塌陷——浮动子元素不参与父元素高度计算（父元素高度 = 0）。解决：clearfix或overflow: hidden（创建BFC）。2）浮动下沉——容器宽度不足导致最后一个浮动元素换行。解决：使用百分比宽度、flex-wrap或确保足够空间。3）文本/行内内容环绕——内容环绕浮动元素，可能是期望行为（文本环绕）或非期望行为。解决：clear: both或在内容上设置overflow: hidden。4）连续浮动堆叠顺序——无法垂直居中浮动元素。5）负margin行为——与浮动的复杂交互。6）IE6/7同一方向margin与float方向相同时的双倍margin bug（IE特有）。现代方案：布局避免使用float。使用flexbox（一维）或grid（二维）。Float仅用于其原始用途：文本环绕图片。

* **Q115: CSS优化、提高性能的方法有哪些**
  A: CSS优化方法：1）减小文件体积——压缩（CSSNano）、移除未使用CSS（PurifyCSS/UnCSS）、合并文件（HTTP/1.1）。2）加载策略——内联关键CSS、延迟非关键CSS、使用`<link rel="preload">`加载重要CSS、避免@import（阻塞并行下载）。3）选择器优化——避免深度嵌套、使用类选择器代替后代链（浏览器从右向左读取）。4）减少重排——最小化重绘密集型属性（box-shadow、border-radius、filter），使用transform/opacity做动画。5） containment——使用contain: layout style paint将渲染限制在子树。6）content-visibility: auto在下方区域跳过渲染。7）资源优化——压缩图片、谨慎使用data URI（base64增加体积）、小图标使用雪碧图。8）图标优先使用SVG而非图标字体（更好的缩放、更小的子集）。

* **Q116: 浏览器是怎样解析CSS选择器的**
  A: 浏览器解析CSS选择器是从右到左（自底向上），而非直觉上的从左到右。示例：.sidebar .nav a——浏览器首先匹配所有`<a>`元素，然后检查是否有祖先具有.nav类，再检查.nav是否有祖先具有.sidebar类。为什么从右到左？对浏览器更高效。从关键选择器（最右侧部分）开始限制了候选集。从左到右时，引擎需要遍历每个.sidebar，然后.nav，然后内部所有`<a>`——可能很多元素不匹配最终选择器。从右到左时，先找到`<a>`元素（通常候选更少），然后按祖先过滤。性能影响：最右侧选择器应尽可能具体。右侧是*或标签名比类或id慢。选择器越具体，匹配越快。

* **Q117: 在网页中的应该使用奇数还是偶数的字体**
  A: 参见Q62。推荐使用偶数字体尺寸（12px、14px、16px）。原因：1）更好的子像素渲染——偶数尺寸更好地对齐设备像素网格，减少抗锯齿伪影。2）行高一致性——常见倍数（1.5x14=21 vs 1.5x13=19.5）产生更整洁的值。3）设计系统惯例——大多数设计系统使用基于偶数的排版比例（Material Design、Bootstrap）。4）跨浏览器渲染一致性——奇数尺寸可能在各浏览器中渲染不一致。但奇数尺寸不被禁止，可用于特定设计需求。关键是保持一致性：使用模块化排版比例实现和谐的尺寸，无论基于偶数还是奇数基础增量。

* **Q118: margin和padding分别适合什么场景使用**
  A: Padding在元素边框内部，在内容和边框之间。Margin在边框外部，在元素边框和相邻元素之间。使用padding的场景：1）在内容和容器之间添加间距（按钮padding、卡片padding）。2）在文本周围创建点击/视觉区域（链接的更大点击目标）。3）扩展背景/颜色区域（padding保持背景可见）。4）分隔同一元素内的内容。使用margin的场景：1）独立元素之间的间距（卡片之间、区块之间）。2）块级元素居中（margin: 0 auto）。3）将元素相互推离。4）创建不相关组件之间的视觉分隔。渲染差异：padding尊重背景和边框；margin始终透明。Margin折叠（垂直），padding不折叠。padding影响box-sizing: border-box尺寸；margin不改变元素大小（仅位置）。

* **Q119: 抽离样式模块怎么写，说出思路**
  A: 样式模块提取（模块化CSS）组织样式以实现可复用性和可维护性。方案：1）基础/Reset层——标准化全局默认值、box-sizing、根字体大小。2）工具类——单一用途类（text-center、mt-4、flex、hidden）。Tailwind或自定义。3）组件样式——限定在特定组件的样式（Card、Button、Modal）。使用CSS模块、BEM命名或CSS-in-JS。4）布局样式——grid/flexbox页面骨架、响应式断点。5）主题token——CSS自定义属性定义颜色、间距、排版、阴影。组织方式：按功能/组件，而非按类型（避免分离的buttons或text文件）。文件结构：每个组件有自己独立的.module.css文件。构建：PostCSS + CSS模块 + autoprefixer + 压缩。全局样式使用BEM（Block__Element--Modifier）命名空间，或使用CSS模块自动限定。

* **Q120: 元素竖向的百分比设定是相对于容器的高度吗**
  A: 通常不是。垂直百分比值（padding-top、padding-bottom、margin-top、margin-bottom、top、bottom）相对于包含块的宽度计算（而非高度）。这种反直觉的行为存在是因为CSS布局通常根据内容确定高度，使用高度作为百分比引用会造成循环依赖。例外：height属性的百分比相对于父元素的高度（当父元素有显式高度时）。如果父元素高度为auto（基于内容），百分比高度表现为auto。min-height/max-height也需要父元素有显式高度才能使用百分比。padding-top/bottom百分比：始终相对于包含块的宽度。这被用于宽高比盒子（padding-top: 56.25%实现16:9）。现代宽高比：使用aspect-ratio属性。

* **Q121: 全屏滚动的原理是什么？用到了CSS的那些属性**
  A: 全屏滚动（fullpage.js风格）捕获滚动事件以在整视口区块之间快照切换。使用的CSS属性：1）scroll-snap-type/y-scroll-snap-align——原生CSS滚动捕捉：.container { scroll-snap-type: y mandatory; overflow-y: scroll; height: 100vh; } .section { scroll-snap-align: start; height: 100vh; }。2）height: 100vh——区块填充视口。3）body设置overflow: hidden防止原生滚动。4）transform: translateY用于区块间过渡（JS驱动）。5）区块使用will-change: transform进行GPU加速。JS实现：监听wheel/touch事件，计算滚动方向，使用requestAnimationFrame或CSS过渡动画化区块transform（translateY）。防抖/节流事件防止多区块跳过。性能：使用transform实现流畅GPU合成滚动；避免触发布局的属性。无障碍：提供跳过导航、键盘支持（方向键）、正确的ARIA地标。

* **Q122: 什么是响应式设计？响应式设计的基本原理是什么？如何兼容低版本的IE**
  A: 响应式设计使页面布局和内容适配不同屏幕尺寸/设备能力。原理：1）流体网格——使用相对单位（%、fr、vw）而非固定px。2）弹性图片——max-width: 100%防止溢出。3）媒体查询——@media (min-width: breakpoint)在特定宽度改变布局。4）移动优先CSS——移动端基础样式，大屏断点渐进增强。断点：基于内容而非设备——在内容断裂的宽度写媒体查询。常见断点：480px、768px、1024px、1200px。IE兼容：IE8-9使用respond.js polyfill支持媒体查询；使用html5shiv支持HTML5元素。现代方案：使用CSS Grid auto-fill/auto-fit实现无需媒体查询的响应式布局：grid-template-columns: repeat(auto-fill, minmax(250px, 1fr))。Flexbox wrap配合flex-basis实现响应式组件。

* **Q123: 什么是视差滚动效果，如何给每页做不同的动画**
  A: 视差滚动通过滚动时背景和前景内容以不同速度移动创造深度错觉。CSS实现：background-attachment: fixed——背景看起来静止而内容在其上滚动。配合多层具有不同动画的背景。JS实现（更可控）：监听滚动事件，计算滚动进度（scrollTop / (scrollHeight - viewportHeight)），使用requestAnimationFrame根据深度因子调整元素transform（如transform: translateY(scrollTop * 0.5)实现慢速背景）。z-index分层：元素深度决定滚动速度（越深越慢）。性能：使用transform实现GPU合成；防抖滚动处理程序；使用Intersection Observer触发可见元素的视差。警告：移动端视差可能导致卡顿和电池消耗。考虑在移动端禁用或使用更简单效果。

* **Q124: a标签上四个伪类的执行顺序是怎么样的**
  A: a标签伪类执行顺序：:link -> :visited -> :hover -> :active。助记符：LoVe-HA（爱恨）。:link——未访问链接。:visited——已访问链接（样式受限——由于隐私原因仅可改变color、background-color、border-color）。:hover——鼠标悬停在链接上。:active——链接被点击的瞬间（mousedown到mouseup之间）。如果顺序错误（如:active在:hover之前），前一状态的特异性与当前相等，层叠顺序适用（后面的覆盖）。由于:active通常在:hover之后，如果顺序错误，:active可能被:hover样式隐藏。焦点状态（:focus）应包含以支持键盘无障碍：:focus-visible现代方案、:focus传统方案。:focus放置位置：在:hover和:active之后，或考虑使用:focus-visible仅在键盘导航时显示焦点。所有选择器同特异性；顺序至关重要。

* **Q125: 伪元素和伪类的区别和作用**
  A: 参见Q80。伪类（单冒号:）基于状态或位置选择元素，不修改DOM。示例：:hover（悬停状态）、:focus（焦点状态）、:nth-child(n)（位置）、:first-child、:last-child、:not(sel)、:checked、:disabled、:empty。它们过滤现有元素。伪元素（双冒号::）创建不存在于DOM中的虚拟元素，或样式化元素的不存在于DOM中的特定部分。示例：::before（在元素内容前插入内容）、::after（在元素内容后插入）、::first-letter（首字母样式）、::first-line（首行样式）、::selection（选中文本样式）、::placeholder（输入框占位符）、::marker（列表标记）。::before和::after需要content属性才能渲染。伪元素不能使用伪元素（不能::before::after）。多个伪元素可使用但某些元素不能有::before/::after（替换元素如`<img>`、`<input>`、`<select>`、`<textarea>`）。

* **Q126: ::before 和 :after 中双冒号和单冒号有什么区别**
  A: 参见Q63。单冒号（:）是CSS2语法，用于伪类和伪元素（CSS3之前）。双冒号（::）是CSS3+语法，专用于伪元素。这种区分明确了：伪类 = 现有元素的状态/条件；伪元素 = 生成的虚拟元素或目标化的现有元素子部分。现代浏览器为向后兼容接受:before和::before，但::是官方标准。示例：::before、::after、::first-line、::first-letter、::selection、::placeholder、::marker、::backdrop。这种区分有助于避免混淆:hover（状态）和::after（生成元素）。

* **Q127: 如何修改Chrome记住密码后自动填充表单的黄色背景**
  A: Chrome自动填充对表单字段应用黄色背景，覆盖用户样式（用户代理样式表使用!important）。解决方案：1）使用CSS box-shadow inset模拟背景（有效因为Chrome不覆盖box-shadow）：`input:-webkit-autofill { -webkit-box-shadow: 0 0 0 30px white inset !important; }`。2）过渡技巧——设置长的background-color过渡：`input:-webkit-autofill { transition: background-color 9999s ease-in-out 0s; }`——无限期延迟背景变更。3）通过-webkit-autofill伪类设置自动填充背景：`input:-webkit-autofill { -webkit-text-fill-color: #333 !important; background-color: #fff !important; }`。Chrome的自动填充行为是设计如此，防止网站隐藏自动填充指示器（安全）。box-shadow hack最可靠。完全控制可使用autocomplete="off"（部分浏览器已忽略）或动态表单字段命名。

* **Q128: 网站图片文件，如何点击下载？而非点击预览**
  A: 默认情况下，`<a href="image.jpg">`在浏览器中打开图片预览。强制下载：1）HTML5 download属性：`<a href="image.jpg" download="filename.jpg">Download</a>`——告知浏览器下载而非导航。download属性设置建议文件名。2）同源图片，download属性直接工作。跨域时，服务端需设置CORS头Access-Control-Allow-Origin（且图片不能被缓存）。3）JS方案：fetch图片为blob，创建object URL，触发下载：fetch('image.jpg').then(r => r.blob()).then(blob => { const a = document.createElement('a'); a.href = URL.createObjectURL(blob); a.download = 'filename.jpg'; a.click(); URL.revokeObjectURL(a.href); })。4）服务端：Content-Disposition: attachment; filename="image.jpg"头强制下载，无视HTML。跨域图片，download属性仅在CORS允许时生效（且图片上有crossorigin="anonymous"）。

* **Q129: 你对 line-height 是如何理解的**
  A: line-height控制文本行之间的垂直间距。它决定从一个基线到下一个基线的距离。工作原理：浏览器计算line-height，减去font-size，剩余差值在文字上下均分（半行距）。示例：font-size: 16px，line-height: 1.5 -> 有效行高 = 24px；半行距 = (24 - 16) / 2 = 4px，文字上下各4px。取值：normal（浏览器默认，通常约1.2）、数字（相对于font-size的倍数，1.5 = 1.5倍font-size——推荐用于继承）、长度（px、em、rem）、百分比（150% = 1.5倍font-size）。line-height影响：1）文本可读性——舒适阅读需要足够的行高（正文1.5-1.8）。2）容器高度——单行文本的line-height决定元素高度。3）垂直居中——设置line-height等于容器高度可垂直居中单行文本。line-height是继承属性。

* **Q130: line-height 三种赋值方式有何区别？（带单位、纯数字、百分比）**
  A: 三种line-height赋值方式在继承行为上不同：1）数字（无单位）：line-height: 1.5。1.5比例被子元素继承。每个子元素计算其line-height为1.5 * 子元素的font-size。这是正确方法，因为它无论font-size如何都按比例缩放。2）长度（px、em）：line-height: 24px或1.5em。计算值被继承（如父元素font-size为16px，1.5em = 24px）。子元素继承24px即使其font-size不同（24px对于12px文本 = line-height 2.0）。这导致font-size不同时间距不成比例。3）百分比：line-height: 150%。与长度同样的问题——百分比相对于父元素的font-size计算，计算的像素值被继承。150% of 16px = 24px作为24px继承，无论子元素font-size。最佳实践：始终使用无单位数字作为line-height，确保不同font-size元素间正确的比例继承。

* **Q131: 设置元素浮动后，该元素的 display 值会如何变化**
  A: 当元素设置float: left/right后，其计算display值变为'block'（或表格相关行内值为'table'）。这是因为浮动元素必须建立块级格式化上下文。具体：行内元素 -> 块级；行内块 -> 块级；行内表格 -> 表格；表格单元格/表格行/表格标题 -> 块级；flex/行内flex -> flex（flex项目）；grid/行内grid -> grid。元素的原始display作为'display-outside'，float会覆盖它。display: none或position: absolute/fixed的元素不会被浮动（float计算值变为'none'）。实际影响：浮动的行内元素（如`<span>`）可以接受width、height和垂直margin——这些是非浮动行内元素所拒绝的行为。这是CSS规范的一部分：浮动元素在布局目的上变为块级容器。

* **Q132: 让页面里的字体变清晰，变细用CSS怎么做？（IOS手机浏览器字体齿轮设置）**
  A: iOS Safari默认以较粗的笔画渲染字体（特别是在Retina显示屏上）。改善字体渲染（使文字看起来更细更清晰）：1）-webkit-font-smoothing: antialiased; ——启用子像素抗锯齿以获得更清晰的文字。默认是subpixel-antialiased。antialiased使文字更细更轻；auto使用浏览器默认。2）-moz-osx-font-smoothing: grayscale;（Firefox macOS等效）。3）font-weight: 300或更轻的字重——iOS默认渲染使即使是轻字重也看起来正常。4）text-rendering: optimizeLegibility; ——改善字距和连字支持。注意：-webkit-font-smoothing: antialiased不是标准CSS属性（WebKit扩展）。可能影响无障碍（降低对比度）。默认渲染因操作系统而异：macOS/Safari默认使用子像素AA（略粗）；antialiased模式使用灰度AA（更细）。在实际设备上测试。全局应用：body { -webkit-font-smoothing: antialiased; }。

* **Q133: font-style 属性 oblique 是什么意思**
  A: oblique是font-style属性的一个值，与normal和italic并列。italic和oblique都产生倾斜/斜体文字，但来自不同的字体文件。italic：使用专门的斜体字体变体（由字体设计师专门设计的草书字形，形状不同）。oblique：使用常规（罗马）字体面并应用倾斜变换（剪切/倾斜）创建斜体文字，不使用单独的字体设计。许多字体有italic变体但没有oblique变体。当指定oblique但只有italic可用时，浏览器通常使用italic作为回退（反之亦然）。CSS font-style属性还可接受带角度的oblique：font-style: oblique 15deg（倾斜角度，CSS Fonts Level 4）。实际区别：italic通常由字体设计师设计，字形经过修改；oblique是机械变换。大多数Web使用italic更受欢迎。

* **Q134: display:inline-block 什么时候会显示间隙**
  A: 参见Q59。display: inline-block间隙出现在HTML空白（空格、制表符、换行）在inline-block元素之间时，因为inline-block元素被视为行内内容，空白折叠为单个空格字符（约4px）。无间隙的情况：1）HTML中移除空白：`<span>a</span><span>b</span>`（无间隙）。2）父元素font-size: 0（子元素重新设置）——空格字符宽度为0。3）负margin补偿：margin-right: -4px（脆弱，依赖字体）。4）元素间注释：`<!-- -->`（降低可读性）。5）使用flexbox替代——flex项目完全忽略空白。6）display: flex + gap属性实现受控间距（现代）。间隙仅在垂直书写或水平行内上下文中可见。最佳方案：水平布局使用flexbox（项目间有gap，无空白问题）。如果必须使用inline-block，父元素设置font-size: 0。

* **Q135: 一个高度自适应的div，里面有两个div，一个高度100px，希望另一个填满剩下的高度**
  A: 第一个div高度100px时第二个div填充剩余高度：1）Flexbox：.container { display: flex; flex-direction: column; height: 100%; } .fixed { height: 100px; flex-shrink: 0; } .fill { flex: 1; }——自动填充剩余空间。2）CSS Grid：.container { display: grid; grid-template-rows: 100px 1fr; height: 100%; }。3）Calc：.fill { height: calc(100% - 100px); }——容器需要有定义高度且第一个div高度已知。4）绝对定位：.container { position: relative; height: 100%; } .fixed { height: 100px; } .fill { position: absolute; top: 100px; bottom: 0; left: 0; right: 0; }——无需知道剩余高度即可填充。5）表格：.container { display: table; height: 100%; width: 100%; } .row-group { display: table-row-group; } .fixed { display: table-row; height: 100px; } .fill { display: table-row; height: auto; }。Flexbox和Grid是最易维护和响应式的方案。

* **Q136: css 的渲染层合成是什么 浏览器如何创建新的渲染层**
  A: 合成层合成（渲染层创建）是浏览器为页面部分创建独立图层并通过GPU合成它们的过程。当浏览器将元素提升到独立的合成层时：元素被绘制到单独的纹理上，后续的transform/opacity更改仅需重新合成（GPU）而无需重新绘制（CPU）。创建新合成层的触发条件：1）3D变换（translate3d、rotateX、scaleZ）。2）will-change: transform/opacity/top/left。3）`<video>`、`<canvas>`、`<iframe>`元素。4）position: fixed。5）带透明度的opacity动画。6）CSS滤镜（blur、contrast）。7）mix-blend-mode。8）overflow: scroll配合-webkit-overflow-scrolling: touch。好处：隔离动画、GPU加速合成（60fps）。成本：增加GPU内存使用、图层管理开销、潜在的图层爆炸（数千个图层）。谨慎使用will-change——仅在实际会动画的元素上使用。
