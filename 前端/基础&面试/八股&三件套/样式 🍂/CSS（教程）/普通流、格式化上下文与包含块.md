## 核心概念
| 概念                         | 解决的问题            |
| -------------------------- | ---------------- |
| 普通流（Normal Flow）           | 盒子如何按常规块级、行内规则排布 |
| 格式化上下文（Formatting Context） | 一组盒子按照哪套规则布局     |
| 包含块（Containing Block）      | 某些尺寸和位置参照哪个矩形    |


**同一个元素可以承担多个角色，但这些概念不能互相替代。**

布局处理的是 **Box Tree**，不是直接对 DOM Tree 排版。DOM 父子关系不保证等于布局中的直接参照关系。

## 普通流
### 块级排布
普通横排中，块级盒子沿块轴依次排列，通常从上往下。

```text
.container {
  width: 500px;
}

.item {
  width: 100px;
}
```

相邻 `.item` 即使很窄，也不会自动并排。

块级盒子另起一块，是排布规则决定的，不是因为宽度占满而把后面的盒子挤下去。

```text
.item {
  width: fit-content;
}
```

缩窄尺寸不会改变它作为普通块级盒子的排布方式。

### 行内排布与行盒
行内布局把文字和行内级盒子组织成行，空间不足时按换行规则继续排布。

```text
<p>
  学习 <span>CSS 普通流与行内布局</span> 的运行机制。
</p>
```

行盒（Line Box）是一行行内内容的布局区域，不对应某个特定 HTML 元素。

- 一个行盒可以包含多个元素的内容。
- 一个 `span` 可以跨越多个行盒，形成多个盒片段。
- 换行位置不必与标签边界一致。
- 行盒高度受行高、内容尺寸、基线和对齐方式影响，不固定等于 `font-size` 或父元素的 `line-height`。

### inline-block 的整体性
`inline-block` 对外是**原子行内级盒子（Atomic Inline-level Box）**，外部行布局将它作为整体处理。

```text
.badge {
  display: inline-block;
  width: 90px;
}
```

外部不会把它切成两半分别放在两行，但它内部的文字仍然可以换行。

### 匿名块盒
块容器中混合出现行内内容与块级内容时，浏览器会生成匿名块盒来组织布局。

```text
<div>
  前面的文字
  <div>中间的卡片</div>
  后面的文字
</div>
```

前后两段文字分别进入匿名块盒，内部再进行行内排布。

**匿名盒存在于盒树，不代表 DOM 中真的增加了元素。**

## BFC 与 IFC
|类型|主要职责|
|---|---|
|BFC：块格式化上下文|组织块级布局，处理相关的 margin 折叠、浮动关系等|
|IFC：行内格式化上下文|将文字和行内级盒子组织成行，并进行对齐|

```text
<article>
  <p>普通文字 <strong>重点内容</strong></p>
</article>
```

对于 `p`：

- 对外：作为块级盒子参与所在的块级布局。
- 对内：通过 IFC 排布文字和 `strong`。

### 参与与建立的区别
**“自己参与哪个 BFC”和“自己为内部建立哪个 BFC”是两个问题。**

```text
.box {
  display: block; /* 不保证建立新 BFC */
}

.isolated {
  display: flow-root; /* 明确建立新 BFC */
}
```

`flow-root` 保留普通流的内部排布，同时建立独立的 BFC 边界。

BFC 不会隔绝一切关系：继承、尺寸依赖等仍然存在。

## 外边距折叠
外边距折叠（Margin Collapsing）指符合条件的相邻 margin 合并为一个共同外边距。
本节限定普通横排，主要讨论普通流中块级盒子的上下 margin；左右 margin 不发生这种折叠。

### 发生条件
**参与同一个 BFC 是必要条件，不是充分条件。**
还需要相关 margin 在布局上相邻，没有相应的 border、padding、行盒、清除浮动产生的间隔等将其隔开，并满足对应场景的尺寸条件。

主要有三类：

|关系|典型情况|
|---|---|
|相邻兄弟|前一个下 margin 与后一个上 margin|
|父子边界|父元素与首个、末个流内块级子元素|
|空块自身|空块自己的上下 margin|

### 折叠后的数值
对一组确定会折叠的 margin：

**结果 = 最大正值 + 最小负值；缺少的类别按 0 处理。**

|参与折叠的值|结果|
|---|---|
|`20px`、`30px`|`30px`|
|`20px`、`-10px`|`10px`|
|`-20px`、`-30px`|`-30px`|
|`20px`、`30px`、`-10px`|`20px`|

折叠可以涉及多个 margin，不一定只有两个。

### 父子折叠
```text
.parent {
  margin: 0;
  background: lightblue;
}

.child {
  height: 40px;
  margin: 30px 0 0;
}
```

若父子上 margin 满足折叠条件，子元素的 `30px` 可能出现在父元素外部，父背景内部没有预期的顶部留白。

**父元素 margin 为 0，也能参与折叠。**

常见处理：
```text
.parent {
  display: flow-root;
}
```

此时父子 margin 不再跨边界折叠，示例中的父容器自动高度可为 `70px`。

如果需求本来就是容器内留白，更直接的表达是：
```text
.parent {
  padding-top: 30px;
}

.child {
  margin: 0;
}
```

父子下 margin 折叠还涉及父元素自动高度、最小高度等条件，不能机械套用上边界规则。

### flow-root 不会阻止所有折叠
```text
.a,
.b {
  display: flow-root;
}

.a {
  margin-bottom: 20px;
}

.b {
  margin-top: 30px;
}
```

A、B 各自为内部建立 BFC，但自身仍可能参与同一个外部 BFC，彼此的相邻 margin 仍可能折叠为 `30px`。

同样，父容器设置 `flow-root`，也不会自动阻止其内部兄弟之间折叠。

需要统一管理列表间距时：
```text
.list {
  display: flex;
  flex-direction: column;
  gap: 30px;
}

.list > * {
  margin: 0;
}
```

Flex 项之间的 margin 不折叠。

## BFC、overflow 与浮动
### flow-root 与 overflow
```text
.parent {
  display: flow-root;
}
```

适合明确表达“建立 BFC”。

普通块容器上的 `overflow: hidden` 也能建立独立格式化上下文，但同时改变裁剪与滚动行为。

```text
.parent {
  overflow: clip; /* 单独使用不建立 BFC */
}
```

如果既需要裁剪又需要 BFC：
```text
.parent {
  overflow: clip;
  display: flow-root;
}
```

旧口诀“overflow 不为 visible 就建立 BFC”不完整，必须考虑 `clip` 以及两轴的计算值。

### 浮动保留结论
- 浮动脱离普通流，但仍影响周围行盒，产生文字绕排。
- 普通父容器的自动高度可能不包含浮动子元素。
- BFC 根的自动高度会纳入参与该 BFC 的浮动。
- 传统浮动布局与 clearfix 不作为本学习路线的展开重点。

## 包含块
包含块是尺寸、位置计算所使用的参考矩形，**不等于 DOM 父元素，也不等于 BFC**。

判断时分两步：

1. 找到谁建立了包含块。
2. 确认使用它的哪条边界。

### 普通流中的参照
普通块、行内布局中的 `static` 或 `relative` 元素，通常以最近块容器祖先的 **content box** 为包含块。

```text
.parent {
  box-sizing: content-box;
  width: 400px;
  padding: 20px;
  border: 10px solid;
}

.child {
  width: 50%; /* 200px */
}
```

`display: contents` 的祖先不生成自身盒子，不能用这个不存在的盒子提供尺寸参照。

### absolute 的参照
`absolute` 查找最近能为它建立绝对定位包含块的祖先。

常见条件包括：

- 非 `static` 的 `position`。
- 非 `none` 的 `transform`。
- 其他能够建立定位包含块的属性。

因此，“最近非 static 父元素”不是完整规则。

对于常见块容器祖先，绝对定位包含块通常由其 **padding box** 形成。

```text
.parent {
  position: relative;
  box-sizing: content-box;
  width: 400px;
  padding: 20px;
}

.normal {
  width: 50%; /* 200px */
}

.absolute {
  position: absolute;
  width: 50%; /* 220px */
}
```

### fixed 的参照
`fixed` 通常参照视口，但祖先可能为它建立固定定位包含块。

```text
.panel {
  transform: translateX(0);
}

.dialog {
  position: fixed;
  inset: 0;
}
```

`.dialog` 位于 `.panel` 内时，会改为参照 `.panel`。即使变换没有视觉位移，其值不是 `none`，仍然产生影响。

|祖先设置|建立 absolute 包含块|建立 fixed 包含块|
|---|---|---|
|单独 `position: relative`|是|否|
|普通块盒上的非 `none` transform|是|是|
|单独 `display: flow-root`|否|否|

全局弹窗可以通过 Portal 将实际 DOM 放到局部祖先之外，但新的祖先链也不能存在相同问题。

## 百分比高度与确定尺寸
*这些玩阴真的能用到吗。。。*

确定尺寸（Definite Size）在本节简单场景中，可理解为不依赖待排布子内容就能确定的尺寸。复杂布局有额外规则。

### 确定参照链
```text
.outer {
  height: 400px;
}

.middle {
  height: 50%; /* 200px */
}

.inner {
  height: 50%; /* 100px */
}
```

按 `.outer > .middle > .inner` 嵌套时，可以逐层解析。

中间层改成 `auto`：
```text
.middle {
  height: auto;
}

.inner {
  height: 100%;
}
```

在普通流场景中，`.inner` 不能跳过 `.middle`，直接参照 `.outer` 的 `400px`。

**找到包含块，不等于它的高度一定能用来解析百分比。**

### min-height 不能直接代替 height
```text
.parent {
  min-height: 300px;
}

.child {
  height: 100%;
}
```

普通块布局中，父元素 `height` 仍为 `auto`。`min-height` 约束最终尺寸，不直接提供流内子元素所需的确定高度参照。

### absolute 子元素的区别
```text
.parent {
  position: relative;
}

.content {
  height: 120px;
}

.overlay {
  position: absolute;
  height: 50%;
}
```

若 `.content` 和 `.overlay` 同为父元素的子元素，且无额外干扰：

- 流内 `.content` 将父元素撑到 `120px`。
- `.overlay` 不参与父元素的普通流高度计算。
- `.overlay` 可根据定位包含块解析出 `60px`。

不能把普通流的百分比高度规则直接套到绝对定位元素上。

覆盖父容器也可以用四边约束：
```text
.overlay {
  position: absolute;
  inset: 0;
}
```

在无额外尺寸约束时，由四边约束求出自动宽高；计算方式不同于 `width/height: 100%`。

## 滚动容器与滚动视口
滚动容器提供滚动机制；滚动视口是查看滚动内容的窗口，通常对应其 padding box。

```text
.panel {
  height: 300px;
  overflow: auto;
}

.content {
  height: 800px;
}
```

面板高度保持 `300px`，滚动改变的是可见内容位置。

### overflow 的区别
对普通元素，两轴使用同一个值时：

|值|行为|滚动容器|
|---|---|---|
|`visible`|内容允许显示在盒子外|否|
|`auto`|溢出时提供用户滚动机制|是|
|`scroll`|提供滚动机制|是|
|`hidden`|裁剪，禁止直接用户滚动，允许程序滚动|是|
|`clip`|裁剪，禁止包括程序滚动在内的滚动|否|

**滚动容器、实际可滚动距离、可见滚动条，是不同概念。**

没有高度限制时，容器可能随内容增长，即使设置 `overflow: auto`，也没有垂直滚动范围。

### 两轴的计算值联动
```text
.wrapper {
  overflow-x: hidden;
  /* overflow-y 初始为 visible，计算后成为 auto */
}
```

当一轴既不是 `visible` 也不是 `clip` 时，另一轴的 `visible` 会计算为 `auto`，`clip` 会计算为 `hidden`。

只设置横向裁剪，也可能改变纵向滚动参照。

## sticky 的两个参照
`sticky` 保留普通流占位，同时根据滚动情况调整显示位置。

```text
<div class="scroller">
  <article class="article">
    <div class="title">标题</div>
    <div class="content">文章内容</div>
  </article>
  <div class="tail">后续内容</div>
</div>
```

```text
.scroller {
  height: 300px;
  overflow: auto;
}

.title {
  position: sticky;
  top: 0;
}

.content {
  height: 600px;
}

.tail {
  height: 400px;
}
```

|参照关系|本例对象|作用|
|---|---|---|
|最近祖先滚动容器的 scrollport|`.scroller`|吸附偏移的参照|
|包含块|`.article` 的内容区域|约束活动范围|

标题滚到顶部时吸附，但文章结束时仍受文章范围限制，不会一直停留在后续内容上方。

**吸附偏移看滚动视口，活动范围受包含块约束。**

### overflow:hidden 导致吸附不符合预期
```text
.wrapper {
  overflow: hidden;
}

.title {
  position: sticky;
  top: 0;
}
```

`.wrapper` 成为更近的滚动容器，即使它没有实际滚动。页面滚动时，整个 wrapper 被移走，标题不会按预期吸附到浏览器顶部。

排查时优先确认：

1. 实际滚动的是谁？
2. sticky 最近的祖先滚动容器是谁？
3. 它的包含块提供了多大的活动空间？
4. 祖先 overflow 的计算值是否改变了滚动参照？

## 布局诊断中的职责区分
|现象|优先检查|
|---|---|
|margin 没有按相加结果产生间距|折叠关系、所属 BFC、边界条件|
|设置 flow-root 后 absolute 仍未参照该元素|BFC 与定位包含块不是同一职责|
|fixed 跟着局部容器移动|祖先是否建立 fixed 包含块|
|height:100% 没有填满|包含块高度能否确定、参照链是否中断|
|overflow:auto 没有出现滚动|尺寸是否受限、是否真的存在溢出|
|sticky 未吸附到预期位置|最近滚动容器与包含块是否符合预期|
