# 值、单位与尺寸计算
> Last Format Time：10/6/2026 02:27:25

> Last Format Time：9/28/2026 21:03:20

---
## 核心模型
CSS 尺寸计算需要依次判断：

1. **值类型**：数字、长度、百分比、关键字或表达式。
2. **参照对象**：字号、包含块、视口或内容本身。
3. **布局算法**：普通块、行内块、Flex、Grid 等如何处理尺寸。
4. **尺寸约束**：`min-*`、`max-*`、宽高比等。
5. **内容处理**：换行、裁剪、滚动或溢出。

**声明的 `width` 是布局算法的输入，不保证等于最终使用宽度。**

---
## 值类型与单位
|类型|示例|含义|
|---|---|---|
|数字 `<number>`|`0.5`、`2`|无单位数值|
|长度 `<length>`|`200px`、`2em`|使用单位表达长度|
|百分比 `<percentage>`|`50%`|参照值由属性规定|
|关键字|`auto`、`min-content`|采用对应算法|
|计算表达式|`calc(100% - 2rem)`|根据环境计算值|

```text
.box {
  width: 20;   /* 无效：非零数字不能直接当长度 */
  width: 20px;
  width: 0;    /* 零长度通常可以省略单位 */
}
```

`px` 表示 **CSS 像素（CSS pixel）**，不保证对应一个屏幕物理像素。

## 字体相对单位
### em
`em` 的参照需要结合属性判断：

- 用于 `font-size`：参照父元素的计算后字号。
- 用于 `padding`、`width` 等普通长度属性：参照当前元素的计算后字号。

```css
.parent {
  font-size: 20px;
}

.button {
  font-size: 1.5em;   /* 30px */
  padding: 0.5em 1em; /* 15px 30px */
}
```

适合让组件间距跟随自身字号变化：
```css
.button {
  padding: 0.5em 1em;
}

.button.small {
  font-size: 12px;
}

.button.large {
  font-size: 20px;
}
```

嵌套放大来自**每层重新声明字号倍数**，不是单纯嵌套就会放大。

```css
body {
  font-size: 16px;
}

.level {
  font-size: 1.5em;
}

/* .level 嵌套时：24px → 36px → 54px */
/* 只继承字号、没有重新声明倍数的子元素不会继续放大 */
```

### rem
普通元素上的 `rem` 参照根元素 `<html>` 的计算后字号。

```text
html {
  font-size: 16px;
}

.card {
  font-size: 24px;
  padding: 1rem; /* 16px，不受 card 字号影响 */
}
```

`1rem` 不固定等于 `16px`，取决于根字号。

|需求|常用单位|
|---|---|
|跟随组件自身字号|`em`|
|跟随全局根字号|`rem`|
|直接指定 CSS 长度|`px`|

## 百分比与参照对象
**百分比没有统一的“父元素参照”规则，具体由属性定义。**

包含块（Containing Block）是布局计算使用的参考矩形。在下述普通文档流例子中，父块容器的内容区域构成子元素的包含块。

|属性|本节普通布局场景下的百分比参照|
|---|---|
|`width`|包含块宽度|
|`height`|包含块高度，但必须能够解析|
|四个方向的 `padding`|全部参照包含块宽度|
|四个方向的 `margin`|全部参照包含块宽度|
|`font-size`|父元素字号|

```text
.parent {
  width: 400px;
  height: 300px;
}

.child {
  width: 50%;       /* 200px */
  height: 50%;      /* 150px */
  padding-top: 10%; /* 40px */
}
```

`padding-top` 既不参照父元素高度，也不参照子元素自己的宽度。

### 百分比高度的解析条件
普通流中，父元素高度由内容决定时，子元素的百分比高度通常无法据此解析，按 `auto` 处理。

```text
.parent {
  height: auto;
}

.child {
  height: 100%; /* 不能简单理解成父元素最终高度 */
}
```

提供明确参照后：
```text
.parent {
  height: 300px;
}

.child {
  height: 100%; /* 300px */
}
```

**父元素最终存在实际高度，不等于这个高度能作为子元素百分比的解析依据。**

不要背成“必须给父元素写 px”：Flex、Grid、定位布局还有其他规则，后续结合算法展开。

## 视口单位
视口（Viewport）是浏览器展示网页的窗口区域，不是整篇文档的高度，也不是屏幕物理尺寸。

|单位|含义|
|---|---|
|`1vw`|视口宽度的 1%|
|`1vh`|视口高度的 1%|
|`1vmin`|`1vw` 与 `1vh` 中较小值|
|`1vmax`|`1vw` 与 `1vh` 中较大值|

```text
.box {
  width: 50vw;
  height: 50vh;
}
```

视口单位不因父容器变窄而改变参照。

### svh、lvh、dvh
移动端地址栏等浏览器界面展开、收起时，可见空间会变化。

|单位|高度参照|特点|
|---|---|---|
|`svh`|可伸缩界面展开时的小视口|相对稳定|
|`lvh`|可伸缩界面收起时的大视口|相对稳定|
|`dvh`|随当前界面状态变化的动态视口|随状态调整|

当前规范中，`vh` 对应 `lvh`。因此地址栏展开时，`100vh` 可能高于当前可见区域。

```text
.page {
  min-height: 100dvh;
}
```

注意：

- `dvh` 不保证随着地址栏动画逐帧平滑变化。
- 软键盘可能覆盖内容，不一定使 `dvh` 缩小。
- `svh`、`lvh` 的稳定性以视口本身没有被重新调整为前提。

## auto 与尺寸约束
### auto 由布局算法解释
`auto` 没有统一的“撑满”或“包住内容”含义。

|场景|常见行为|
|---|---|
|普通非替换块元素的 `width: auto`|根据横向可用空间计算|
|普通流中的 `height: auto`|根据内容计算|
|普通非替换行内块的 `width: auto`|收缩适应内容与可用空间|

```text
.block {
  display: block;
  width: auto;
}

.inline-block {
  display: inline-block;
  width: auto;
}
```

相同内容下，前者通常利用整行可用宽度，后者通常收缩包住内容。

### width:auto 与 width:100%
假设父元素内容宽度为 `400px`：
```text
.child {
  box-sizing: content-box;
  padding: 20px;
  border: 2px solid;
  margin: 0;
}
```

|声明|内容宽度|border box 宽度|
|---|---|---|
|`width: auto`|`356px`|`400px`|
|`width: 100%`|`400px`|`444px`|

在这个普通块布局中，`auto` 会在宽度计算时给 padding、border 留出空间；`100%` 则先指定内容宽度。

```text
.child {
  box-sizing: border-box;
  width: 100%;
}
```

改为 `border-box` 后，`100%` 包含 padding 和 border，但仍不包含 margin。

### 首选尺寸与上下限
|属性|作用|
|---|---|
|`width` / `height`|首选尺寸|
|`min-width` / `min-height`|最小尺寸约束|
|`max-width` / `max-height`|最大尺寸约束|

```text
.a {
  width: 600px;
  max-width: 400px; /* 最终 400px */
}

.b {
  width: 200px;
  min-width: 300px; /* 最终 300px */
}

.c {
  width: 200px;
  min-width: 500px;
  max-width: 300px; /* 最终 500px */
}
```

以上假设普通块布局，没有额外干扰。上下限冲突时，**最小尺寸约束优先**；这属于尺寸算法，不是 Cascade 覆盖。

### height 与 min-height
```text
.fixed-panel {
  height: 100dvh;
  overflow: auto;
}

.page {
  min-height: 100dvh;
  /* height: auto */
}
```

- `height`：指定高度，内容更多时可能溢出。
- `min-height`：指定下限，普通流内容需要更多空间时可以继续增长。

## 内在尺寸计算
内在尺寸（Intrinsic Size）主要根据内容本身及其排版规则计算。普通文本同样具有内在尺寸，不仅图片有自然尺寸。

以下以横排文本为例：
```text
<div class="label">Build flexible interfaces</div>
```

### max-content
**不进行软换行时，内容需要的宽度。**

```text
.label {
  width: max-content;
}
```

会尽量完整排成一行，即使父容器更窄也可能溢出。`<br>` 等强制换行仍然有效。

`max-content` 不是“撑满父容器”。

### min-content
**利用允许的软换行机会，内容尽量收窄后的宽度。**

```text
.label {
  width: min-content;
}
```

对上述默认英文文本，通常由最长单词 `interfaces` 的宽度决定。

“最长单词宽度”只是特定条件下的近似：

- 中文有不同的换行规则。
- 连续长字符串可能没有断点。
- `white-space`、`overflow-wrap` 等会影响结果。

```text
.label {
  width: min-content;
  white-space: nowrap;
}
```

禁止软换行后，这段简单文本的 `min-content` 与 `max-content` 会相同。

### fit-content
结合内容需求与可用空间，效果是“空间大时包住内容，空间小时尝试换行”。

```text
.label {
  width: fit-content;
}
```

忽略额外盒模型尺寸时，可用以下公式理解：
```text
result = Math.max(
  minContent,
  Math.min(availableWidth, maxContent)
);
```

- 可用空间大于 `max-content`：取 `max-content`。
- 介于两者之间：跟随可用空间。
- 小于 `min-content`：取 `min-content`，可能溢出。

真实布局中的可用尺寸还要考虑 margin、padding、border 等。

### 内在尺寸与尺寸约束的区别
```text
.a {
  width: min-content; /* 作为首选宽度 */
}

.b {
  min-width: min-content; /* 作为最小宽度限制 */
}
```

`min-content` 是一个尺寸值；它是否构成下限，取决于属性及布局算法。

## 换行、收缩与溢出
### overflow-wrap 对内在尺寸的影响
```text
.message {
  width: fit-content;
  overflow-wrap: anywhere;
}
```

`anywhere` 允许必要时在原本不可断开的字符串内部换行，新增断点会参与 `min-content` 计算。

|值|必要时拆分长字符串|新增断点参与 min-content|
|---|---|---|
|`anywhere`|是|是|
|`break-word`|是|否|

### Flex 子项的自动最小尺寸
普通横向 Flex 中，子项默认的 `min-width: auto` 可能形成基于内容的最小宽度，阻止继续收缩。完整规则还受 overflow、首选尺寸等影响。

```text
.content {
  flex: 1;
  min-width: 0;
}
```

`min-width: 0` 允许盒子缩小，但还需要决定文字如何显示。

允许换行：
```text
.content {
  flex: 1;
  min-width: 0;
  overflow-wrap: anywhere;
}
```

单行省略：
```text
.content {
  flex: 1;
  min-width: 0;
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

**盒子能否缩小，与盒子缩小后内容如何显示，是两个问题。**

## 尺寸计算函数
### calc()
组合不同单位，表达尺寸关系：
```text
.panel {
  width: calc(100% - 2rem);
}
```

规则：

- 二元 `+`、`-` 两侧需要空白。
- 运算必须满足类型规则，不能用长度减时间。
- 百分比仍遵循所在属性的参照规则。
- 无法解析的百分比高度，不会因为包进 `calc()` 就变得可解析。

### min() 与 max()
```text
.article {
  width: min(100%, 960px); /* 选择较小值，常用于上限 */
}

.page {
  padding-inline: max(16px, 4vw); /* 选择较大值，常用于下限 */
}
```

### clamp()
将期望值限制在上下限之间：
```text
.title {
  font-size: clamp(1.5rem, 1rem + 2vw, 3rem);
}
```

参数顺序：
```text
clamp(下限, 期望值, 上限)
```

等价关系：
```text
Math.max(lower, Math.min(preferred, upper))
```

注意：

- 上下限冲突时，下限优先。
- 函数内部可直接写算式，不必额外嵌套 `calc()`。
- 函数只提供属性值，不取消其他尺寸约束。

```text
.box {
  width: min(100%, 400px);
  min-width: 500px; /* 普通块布局下仍可能得到 500px */
}
```

## 逻辑尺寸与逻辑方向
逻辑属性（Logical Properties）根据书写方向映射到物理方向。

- **行内轴（Inline Axis）**：一行文字展开的方向。
- **块轴（Block Axis）**：行与块逐步排列的方向。

|逻辑属性|普通横排对应|竖排对应|
|---|---|---|
|`inline-size`|`width`|`height`|
|`block-size`|`height`|`width`|
|`min-inline-size`|`min-width`|`min-height`|
|`max-block-size`|`max-height`|`max-width`|

```text
.card {
  inline-size: 300px;
  padding-inline: 16px;
  padding-block: 12px;
  margin-inline-start: 8px;
}
```

横排中的行内起止侧：

|direction|inline-start|inline-end|
|---|---|---|
|`ltr`|左|右|
|`rtl`|右|左|

尺寸轴主要由 `writing-mode` 决定；行内起止方向还与 `direction` 有关。

- 表达“文字起始侧”：使用逻辑属性。
- 明确表达“物理左侧”：使用 `left` 对应属性。
- 行内轴、块轴不等于 Flex 主轴、交叉轴，后者还受 `flex-direction` 影响。

## aspect-ratio
`aspect-ratio` 设置**首选宽高比（Preferred Aspect Ratio）**，可用于从一个尺寸推导自动尺寸。

```text
.cover {
  width: 320px;
  height: auto;
  aspect-ratio: 16 / 9;
}
```

无内容或其他约束干扰时，高度为 `180px`。

```text
.cover {
  width: 320px;
  height: 100px;
  aspect-ratio: 16 / 9;
}
```

宽高都明确时，仍为 `320 × 100`。宽高比需要至少一个自动尺寸才能参与首选尺寸推导；内容、min/max 约束及布局规则可能使最终比例不被保持。

图片示例：
```text
.cover {
  display: block;
  width: 100%;
  height: auto;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}
```

- `aspect-ratio`：参与确定元素盒子的比例。
- `object-fit`：决定图片内容如何填入盒子，`cover` 必要时裁剪。

## 尺寸问题排查顺序
1. **参照对象**：百分比、`em`、`rem`、视口单位分别参照谁？参照值能否确定？
2. **盒模型**：声明作用于 content box 还是 border box？是否还需要加 margin？
3. **布局算法**：当前是普通块、行内块、Flex 还是 Grid？`auto` 如何解释？
4. **尺寸约束**：是否有 min/max、自动最小尺寸、宽高比或拉伸规则？
5. **内容尺寸**：是否存在长字符串、禁止换行、图片自然尺寸等？
6. **溢出处理**：需要换行、省略、裁剪，还是内部滚动？
