# 闭包是绑定
> Last Format Time：9/16/2026 19:24:51

闭包是词法环境中的绑定，不是捕获变量某一时刻的值
对，这里**确实用到了闭包**。而且这个现象恰好能说明一个很关键的点：

> **闭包保存的是对外部变量的访问能力，而不是把变量当时的值“拍照保存下来”。**

看你的代码：

```js
let user = {
  name: "dano",
  eat() {
    console.log(this.name + " is eating!");
  }
};

setTimeout(() => user.eat(), 1000);
```

这个箭头函数：

```js
() => user.eat()
```

内部使用了外部作用域里的 `user`，所以它形成了闭包。

但是它闭包捕获的是：

```text
user 这个变量
```

而不是：

```text
user 当时指向的那个对象
```

所以可以把它想象成：

```text
外部作用域

user ──────► 对象A
              { name: "dano" }

callback 闭包
   │
   └──── 能访问变量 user
```

如果在 1 秒内：

```js
user = {
  name: "jack",
  eat() {
    console.log(this.name + " is eating!");
  }
};
```

那么现在变成：

```text
user ──────► 对象B
              { name: "jack" }

callback
   │
   └──── 仍然访问的是 user 变量
```

等 `setTimeout` 真正执行的时候，它才会运行：

```js
user.eat()
```

此时 `user` 已经指向对象 B 了，所以得到：

```text
jack is eating!
```

### 为什么不是 dano？
因为这两件事发生的时间不同：

```js
setTimeout(() => user.eat(), 1000);
```

执行这行代码的时候，并没有执行：

```js
user.eat()
```

只是**创建了一个函数**：

```js
() => user.eat()
```

然后把这个函数交给 `setTimeout`。

1 秒之后才真正执行函数体：

```js
user.eat()
```

所以 `user` 的查找也是在那时候发生。


这和我们之前讲 React 闭包时的概念其实是同一个东西：

```js
let a = 1;

const fn = () => {
  console.log(a);
};

a = 2;

fn(); // 2
```

`fn` 的闭包里并不是：

```js
a = 1
```

而是类似于：

```text
fn
 │
 └──► 外部词法环境
           │
           └── a = 2
```

所以调用 `fn()` 时，会沿着词法作用域找到现在的 `a`。

## 那怎么保证一定调用原来的 user？
可以提前保存对象：

```js
const savedUser = user;

setTimeout(() => savedUser.eat(), 1000);
```

之后即使：

```js
user = anotherUser;
```

也不会影响：

```js
savedUser
```

关系变成：

```text
user      ───► 对象B

savedUser ───► 对象A

callback
   │
   └──► savedUser ───► 对象A
```

所以最后还是调用对象 A。


还有另一种经典写法：

```js
setTimeout(user.eat.bind(user), 1000);
```

`bind` 做的事情稍微不同。

原来的：

```js
user.eat
```

只是拿到了函数：

```text
eat函数
```

对象关系没了，所以：

```js
setTimeout(user.eat, 1000);
```

执行时没有：

```js
user.eat()
^^^^
```

这个调用者，因此 `this` 丢失。

而：

```js
user.eat.bind(user)
```

生成一个新函数，把 `this` 永久绑定到了当前这个对象。


你可以把这三个写法放一起理解：

```js
// 1. this 丢失
setTimeout(user.eat, 1000);
```

这里传的是：

```text
函数本身
```

没有 `user.` 这个调用关系。


```js
// 2. this 不丢，但是 user 变量可能变化
setTimeout(() => user.eat(), 1000);
```

闭包保存的是：

```text
对 user 变量的访问
```

执行时再查 `user`。


```js
// 3. 保存当前对象
const savedUser = user;
setTimeout(() => savedUser.eat(), 1000);
```

闭包访问的是：

```text
savedUser 变量
```

而 `savedUser` 一直指向原来的对象。


所以这里有一个特别值得记住的结论：

> **闭包捕获变量（更准确说是词法环境中的绑定），不是捕获变量某一时刻的值。**

因此：

```js
() => user.eat()
```

不是在创建函数时计算：

```js
user.eat
```

而是在**未来调用这个函数时**，再读取 `user`，再取 `.eat`，再调用。

这也是为什么：

```js
let x = 1;

const fn = () => console.log(x);

x = 100;

fn(); // 100
```

而不是 `1`。

如果把这个点彻底搞明白，你之前 React 里遇到的“闭包陷阱 / stale closure / useRef 为什么能拿到最新值”其实就能串成同一套知识体系了。
