你现在卡住的点，其实就是 JS 里这三个概念混在一起了：

**变量、值、对象。**

先记最核心的一句话：

> **变量是“名字/容器”，值是“里面存的东西”，对象也是一种值，只不过对象值通常通过引用访问。**

可以先看最简单的：

```js
let a = 10;
```

这里：

```text
变量：a
值：10
```

可以粗略理解成：

```text
a
↓
10
```

然后：

```js
a = 20;
```

变成：

```text
a
↓
20
```

变量 `a` 还是那个变量，只是它里面保存的值从 `10` 变成了 `20`。

---
## 什么是变量？
变量本质上可以理解为一个**名字对应一个存储位置**。

比如：

```js
let count = 0;
```

可以想象成：

```text
变量名
 count
   │
   ▼
┌───────┐
│   0   │
└───────┘
```

之后：

```js
count = 1;
```

只是把里面的值换掉：

```text
 count
   │
   ▼
┌───────┐
│   1   │
└───────┘
```

所以：

```js
let count = 0;

const fn = () => {
  console.log(count);
};

count = 100;

fn();
```

输出：

```text
100
```

因为 `fn` 闭包引用的是 **count 这个变量**。

后来 `count` 变量里的值变成了 `100`。


# 变量、值、对象
> Last Format Time：9/16/2026 19:24:51

JS 里变量保存的是**值**。

例如：

```js
let a = 1;
let b = "hello";
let c = true;
let d = null;
```

这些：

```text
1
"hello"
true
null
```

都是值。

大致可以分两类：

```text
JS 的值
│
├── 原始值
│   ├── number
│   ├── string
│   ├── boolean
│   ├── null
│   ├── undefined
│   ├── bigint
│   └── symbol
│
└── 对象值
    ├── {}
    ├── []
    ├── function
    ├── Date
    └── Map ...
```

所以：

> **对象也是值。**

这一点非常重要。


# 3. 那对象有什么特殊？

看：

```js
const user = {
  name: "Dano"
};
```

你可以粗略理解成：

```text
user
 │
 ▼
引用
 │
 ▼
┌────────────────┐
│ { name:"Dano"} │
└────────────────┘
```

变量 `user` 里，并不是简单塞进了整个对象内容。

更准确地理解：

> `user` 保存的是一个能够找到这个对象的“引用值”。

当然 JS 规范层面不要求你把它理解成真正的内存地址，但学习时这样理解非常有帮助。

---
## 为什么对象修改和普通值不一样？
看这个：

```js
let a = 10;
let b = a;

b = 20;

console.log(a);
```

结果：

```text
10
```

因为原始值复制：

```text
a
↓
10

b
↓
10
```

虽然刚开始都是 `10`，但它们是两个独立变量。

之后：

```js
b = 20;
```

就是：

```text
a → 10

b → 20
```

互不影响。


但是对象：

```js
const a = {
  name: "Dano"
};

const b = a;
```

这里不是复制一个新对象。

而是：

```text
a ─────┐
       │
       ▼
    对象 #1
       ▲
       │
b ─────┘
```

`a` 和 `b` 保存的引用，都指向**同一个对象**。

所以：

```js
b.name = "Tom";

console.log(a.name);
```

得到：

```text
Tom
```

因为：

```text
a ─────┐
       ▼
  { name: "Tom" }
       ▲
b ─────┘
```

你不是修改了 `b` 变量本身。

你修改的是：

> `b` 找到的那个对象内部的 `name` 属性。

而 `a` 也指着同一个对象。


# 5. 这里一定要区分两个操作

这是你现在最需要区分的。

### 操作一：修改变量保存的值
```js
let a = 10;

a = 20;
```

这是：

```text
a 原来 → 10

a 现在 → 20
```

或者对象：

```js
let user = { name: "A" };

user = { name: "B" };
```

这是让 `user` **改为指向另一个对象**：

```text
之前：

user
 ↓
对象 A


之后：

user
 ↓
对象 B
```


### 操作二：修改对象内部
```js
const user = {
  name: "A"
};

user.name = "B";
```

这完全不同。

变量 `user` 保存的引用**没变**：

```text
user
 ↓
同一个对象
 ↓
name: A → B
```

所以：

```js
const user = {};
```

虽然 `user` 是 `const`，你还是可以：

```js
user.name = "Dano";
```

因为你没有做：

```js
user = 其他值;
```

你只是修改了它指向的对象内部。


# 6. 为什么 `const` 对象还能修改？

这个也能帮你理解变量和对象。

```js
const user = {
  name: "A"
};

user.name = "B"; // ✅
```

但是：

```js
user = {
  name: "C"
}; // ❌
```

因为 `const` 限制的是：

> **变量绑定不能重新赋值。**

不是说：

> 对象不能修改。

画出来：

```text
const user
   │
   │ 永远保持这个引用
   ▼
┌───────────────┐
│ name: "A"     │
└───────────────┘
```

你可以修改对象：

```text
const user
   │
   ▼
┌───────────────┐
│ name: "B"     │
└───────────────┘
```

但是不能：

```text
const user ─────→ 对象2
```

因为这意味着修改 `user` 变量保存的值。


# 7. 再来看 `useRef`，你就能彻底串起来

React：

```js
const ref = useRef(0);
```

可以粗略想象成：

```js
const ref = {
  current: 0
};
```

重点来了：

```text
变量 ref
   │
   ▼
引用值
   │
   ▼
┌───────────────┐
│ current: 0    │
└───────────────┘
```

然后：

```js
ref.current = 10;
```

不是：

```text
ref 变量改变
```

而是：

```text
ref
 │
 ▼
还是同一个对象
 │
 ▼
current: 0 → 10
```

所以一个闭包：

```js
const fn = () => {
  console.log(ref.current);
};
```

捕获了：

```text
ref 变量
 ↓
同一个 ref 对象
```

以后：

```js
ref.current = 100;
```

`fn` 再执行：

```js
fn();
```

就是：

```text
ref
 ↓
同一个对象
 ↓
current = 100
```

所以打印 `100`。


# 8. React 的 `count` 为什么不同？

例如：

```tsx
function Counter() {
  const [count, setCount] = useState(0);
}
```

你千万不要想成：

```js
let count = 0;

count = 1;

count = 2;
```

React 每次 render 更接近：

```text
第一次执行 Counter：

变量 count₁
   ↓
   0
```

重新 render：

```text
第二次执行 Counter：

变量 count₂
   ↓
   1
```

再 render：

```text
第三次执行 Counter：

变量 count₃
   ↓
   2
```

所以是：

```text
Render 1        Render 2        Render 3

count₁          count₂          count₃
  ↓               ↓               ↓
  0               1               2
```

这是**三个不同的变量绑定**。

旧闭包：

```js
() => {
  console.log(count);
}
```

如果出生于第一次 render：

```text
闭包
 ↓
count₁
 ↓
0
```

它当然不知道：

```text
count₂
count₃
```

的存在。


# 9. 而 `useRef` 为什么不一样？

虽然每次 render：

```js
const ref = useRef();
```

都有一个局部变量叫 `ref`。

但 React 每次会把**同一个对象**交给你。

可以理解成：

```text
Render 1

ref₁ ─────┐
          │
          ▼
       对象 A
     { current: 0 }


Render 2

ref₂ ─────┐
          │
          ▼
       对象 A
     { current: 1 }


Render 3

ref₃ ─────┐
          │
          ▼
       对象 A
     { current: 2 }
```

注意一个很细但是很重要的地方：

严格来说：

```text
ref₁
ref₂
ref₃
```

也是每次函数执行产生的不同局部变量绑定。

但是：

> **它们保存的值，是同一个对象引用。**

因此旧闭包哪怕捕获的是：

```text
ref₁
```

也没问题。

因为：

```text
ref₁
 ↓
对象 A
```

而现在 React 仍然更新的是：

```text
对象 A.current
```

因此旧闭包照样能读到最新值。


# 10. 这几个关系你可以这样记

最重要的一张图：

```text
变量
 │
 │ 保存
 ▼
值
 │
 ├── 原始值
 │     例如 1、"abc"、true
 │
 └── 引用值
       │
       ▼
      对象
```

例如：

```js
let a = 10;
```

就是：

```text
变量 a
 ↓
值 10
```

而：

```js
const user = {
  name: "Dano"
};
```

可以理解为：

```text
变量 user
 ↓
引用值
 ↓
对象
 ↓
{ name: "Dano" }
```

## 最后再给你三个非常关键的例子
### ① 原始值重新赋值
```js
let a = 1;

a = 2;
```

```text
变量没换
值换了

a
↓
1

变成：

a
↓
2
```


### ② 对象属性修改
```js
const a = {
  value: 1
};

a.value = 2;
```

```text
变量没换
引用没换
对象没换
对象内部变了

a
↓
对象 A
↓
value: 1 → 2
```


### ③ 对象重新赋值
```js
let a = {
  value: 1
};

a = {
  value: 2
};
```

这是：

```text
之前：

a
↓
对象 A
{ value: 1 }


之后：

a
↓
对象 B
{ value: 2 }
```

不是修改对象 A。

而是：

> `a` 变量改为保存另一个对象的引用。


你现在可以先死记这四句话，后面的闭包、React、`useRef` 都会顺很多：

```text
1. 变量是名字 / 绑定。
2. 变量里面保存的是值。
3. 对象也是一种值，但变量通常保存的是对象的引用。
4. 修改变量 ≠ 修改对象内部。
```

尤其是第 4 条：

```js
a = xxx;
```

是**修改变量保存的值**。

而：

```js
a.xxx = xxx;
```

是**通过变量找到对象，然后修改对象内部**。

这两个一定要分开。
