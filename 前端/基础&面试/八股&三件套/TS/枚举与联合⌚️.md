# 枚举与联合
枚举和联合类型都可以表达一个有限的取值集合，但它们的定位不一样

---
## 联合类型
[[4联合类型]]
优点是比较轻量，和接口数据、字符串字面量以及类型收窄结合得很好

联合类型主要是类型层面的约束，它在编译后会被擦除，不会生成运行时代码：
```ts
type Status = 'loading' | 'success' | 'error';
```

---
## 枚举类型
现代开发中常用 [[as const⌚️💡]] 来代替枚举类型

[[4 枚举⌚️]]
枚举是一个运行时对象：
```ts
enum Status {
  Loading = 'loading',
  Success = 'success',
  Error = 'error',
}
```

它编译后通常会保留 JavaScript 对象，所以可以在运行时访问、遍历或者传给需要运行时值的代码

但枚举也有一些问题：

- 会增加运行时代码
- 数字枚举可能产生反向映射
- 和后端字符串、JSON 数据交互时，需要注意实际传输值
- 在某些场景下类型推导和兼容性不如字面量联合直观

---
## 选择
如果只是表示一个有限的业务状态，默认我会优先使用联合类型：
```ts
type ReviewStatus = 'draft' | 'published' | 'archived';
```

如果需要运行时遍历、和已有后端枚举或第三方 SDK 对齐，或者项目本身已经统一使用枚举，我才会使用枚举

在我们项目中，核心业务契约更倾向于通过 Zod Schema 定义，然后从 Schema 推导 TypeScript 类型：
```ts
const statusSchema = z.enum(['draft', 'published', 'archived']);

type Status = z.infer<typeof statusSchema>;
```

这样同时具备运行时校验和静态类型约束，也能保证前后端数据契约一致

如果需要同时维护运行时对象和类型，我也会考虑：
```ts
const statusValues = ['draft', 'published', 'archived'] as const;

type Status = typeof statusValues[number];
```

默认选择是联合类型或 `as const`，因为它更轻量，更贴合接口数据；只有在确实需要运行时对象或者兼容现有枚举体系时，才选择 enum
