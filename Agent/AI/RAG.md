# RAG
> Last Format Time：10/8/2026 23:35:46

RAG 是 Retrieval-Augmented Generation，即检索增强生成。

它解决的问题是：

模型本身不一定知道企业最新知识、私有文档或实时业务数据，因此我们可以先检索外部知识，再把检索结果交给模型辅助生成回答。

核心过程：

离线准备：
	
	业务文档
	
	切分 Chunk
	
	Embedding 向量化
	
	建立检索索引

在线问答：
	
	用户问题
	
	检索相关片段
	
	排序 / 筛选
	
	LLM 生成回答

这里的“召回”主要指从大量知识片段中找出可能与用户问题相关的候选内容。

##### 常见召回方式
|方式|原理|典型用途|
|---|---|---|
|关键词检索|BM25 等文本匹配算法|专业术语、精确名称、编号|
|向量检索|计算 Embedding 语义相似度|表述不同但语义相近的问题|
|混合检索|结合关键词与向量结果|同时兼顾精确匹配和语义匹配|

例如，用户问：

“我买的机票能免费改签吗？”

知识库里的内容可能是：

“航班变更政策：部分舱位支持免手续费调整。”

向量检索可以帮助匹配这两种表达。

实际系统还常在初步召回之后增加 Rerank（重排序），对候选片段进行更精细的相关性排序，筛选适合放入模型上下文的内容。

面试可能继续追问：

为什么 RAG 已经检索到文档，模型还会回答错误？

因为检索到的内容可能不够相关、存在冲突、已经过时，也可能是模型没有正确依据材料作答。

所以 RAG 不是“检索一下就不会幻觉”，而是需要同时关注召回质量、上下文组织和答案可靠性。
