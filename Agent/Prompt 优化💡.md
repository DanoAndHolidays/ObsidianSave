## 你如何确认 Prompt 优化真的让 Agent 变好了？
Prompt 优化让 Agent 在特定任务上的表现更好，并且能够被验证。

举个假设性例子：你开发一个可以调用工具查询机票的 Agent。

旧版 Prompt：
```text
你是一个机票助手，请帮助用户查询机票。
```

新版 Prompt：
```text
你是一个机票查询助手。

涉及实时票价和余票时，必须调用查询工具。
不得编造实时价格。
如果缺少出发城市或日期，先询问用户。
返回结果时要包含时间、价格和数据来源。
```

怎样证明新版更好？

不能只拿一次对话说“你看，这次回答对了”。

正确的工程做法是建立 Evaluation（评测）。

|指标|测量什么|
|---|---|
|任务成功率|是否完成用户指定目标|
|工具调用准确率|是否选对工具、传对参数|
|幻觉率|是否出现无依据或编造信息|
|格式合规率|是否符合结构化输出要求|
|响应延迟|完成任务需要多长时间|
|Token / 成本|完成任务的资源开销|

然后准备一套固定的测试集。

例如 100 个真实业务场景：正常查询、缺少参数、查询失败、工具超时、多轮补充信息等。

在尽量控制模型版本、工具条件和其他变量的情况下，分别运行旧版与新版 Prompt，并对比指标。

还可以使用 Trace（执行轨迹）分析每次 Agent 的模型调用、工具调用和最终回答，定位失败的原因。OpenAI 的 Agent 评测实践也明确强调使用轨迹、数据集、评分器和回归测试，而不只是主观检查答案。
