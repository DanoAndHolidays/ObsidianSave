# 设计模式
> Last Format Time：9/16/2026 19:24:55

---
## Singleton（单例模式）
控制实例数量：全局只保留一个实例：
```js
new A() === new A()
```

常用于：
- 全局配置
- Store
- SDK Client
- 数据库连接

注意：滥用容易变成全局变量，导致隐藏依赖、难测试。

---
## Factory（工厂）
控制对象创建：调用方不关心对象具体怎么创建

```js
const user = createUser()
```

工厂负责封装：
```text
new 哪个类
初始化参数
依赖注入
创建流程
```

---
## Abstract Factory（抽象工厂）
创建一整套相互匹配的对象（Product Family，产品族）：
```text
MacFactory
├─ MacButton
├─ MacInput
└─ MacDialog

WindowsFactory
├─ WindowsButton
├─ WindowsInput
└─ WindowsDialog
```

---
## Proxy（代理模式）
控制对象访问：调用者不直接访问真实对象，而是经过代理

```text
调用者
  ↓
Proxy
  ↓
真实对象
```

常见用途：
- 权限控制
- 缓存
- 懒加载
- 日志
- 请求拦截

JS `Proxy` 可以用来实现代理模式，但 **Proxy API ≠ Proxy Pattern**。

---
## Decorator（装饰器模式）
不修改原对象，通过包装动态增加功能

```text
Decorator B
    ↓
Decorator A
    ↓
原对象
```

例如：
```text
Coffee
↓
+ Milk
↓
+ Sugar
```

---
## Proxy vs Decorator
两者代码结构可能非常像，真正区别在**设计意图**：

|Proxy|Decorator|
|---|---|---|
|核心|控制访问|增强功能|
|关注|能不能 / 怎么访问|增加什么能力|
|例子|权限、缓存、懒加载|日志增强、功能组合|

```text
Singleton      → 控制实例数量
Factory        → 控制对象创建
AbstractFactory→ 控制一组对象创建
Proxy          → 控制对象访问
Decorator      → 控制功能组合
```
