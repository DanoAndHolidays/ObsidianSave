## IoC、DI 与 Bean
*已补充*

- IoC（Inversion of Control，控制反转）：对象把依赖的创建和组装交给外部机制管理，在 Spring 中通常由 IoC 容器负责。
- DI（Dependency Injection，依赖注入）：对象通过构造方法、方法参数或属性声明依赖，容器创建 Bean 时把依赖传入。它是实现 IoC 的一种方式。
- Bean：由 Spring 容器管理的对象。Java 类并不会因为存在于项目中就自动成为 Bean。
- `ApplicationContext`：常用的 Spring 容器接口，负责读取配置、管理 Bean 和解析依赖。

例如 Service 需要 DAO。直接在 Service 中 `new` 具体 DAO，会让业务代码负责选择和创建实现；把 DAO 作为构造参数，则可由容器或测试代码提供实现。它类似普通 JavaScript 函数接收一个 `apiClient` 参数：依赖从外部传入，而不是在内部写死。

定义与设计理由见 [Spring Dependency Injection](https://docs.spring.io/spring-framework/reference/core/beans/dependencies/factory-collaborators.html)。

## 注解：注册与注入
*已纠正*

`@Component` 标记的是可被组件扫描发现的类。它及其派生注解用于注册 Bean；`@Autowired` 声明注入点。注册对象和注入对象是两个步骤，`@Autowired` 不会把一个未注册的普通类自动变成 Bean。

![[Pasted image 20260912200617.png]]

| 注解 | 作用 | 常见位置 |
|---|---|---|
| `@Component` | 通用组件标记 | 自定义工具组件等 |
| `@Service` | 表达业务服务角色，属于 `@Component` 的特化 | Service 实现类 |
| `@Repository` | 表达持久层角色，可参与 Spring 持久层异常转换机制 | DAO 实现类 |
| `@Controller` | MVC 控制器组件 | 返回视图的控制器 |
| `@RestController` | 组合 `@Controller` 与 `@ResponseBody` | 返回响应体的 API 控制器 |
| `@Configuration` + `@Bean` | 用配置类中的工厂方法注册返回的对象 | 第三方对象或需要自定义创建过程的组件 |
| `@Autowired` | 按类型等候选规则解析并注入依赖 | 构造方法、字段、Setter 等方法 |

以上组件注解需要被扫描或显式导入才会生效。`@Repository` 本身不会为普通 DAO 接口生成实现。参见 [组件扫描](https://docs.spring.io/spring-framework/reference/core/beans/classpath-scanning.html)。

## 构造方法注入示例
*已补充*

下面三个文件放在快速开始项目的 `src/main/java/com/example/demo/user/` 中，演示接口与实现分离；数据暂时写在内存中，未连接 MySQL。

`UserDao.java`：
```java
package com.example.demo.user;

public interface UserDao {
    String findNameById(long id);
}
```

`MemoryUserDao.java`：
```java
package com.example.demo.user;

import org.springframework.stereotype.Repository;

@Repository
public class MemoryUserDao implements UserDao {
    @Override
    public String findNameById(long id) {
        return id == 1L ? "Dano" : "Unknown";
    }
}
```

`UserService.java`：
```java
package com.example.demo.user;

import org.springframework.stereotype.Service;

@Service
public class UserService {
    private final UserDao userDao;

    public UserService(UserDao userDao) {
        this.userDao = userDao;
    }

    public String getDisplayName(long id) {
        return userDao.findNameById(id);
    }
}
```

容器发现 `MemoryUserDao` 和 `UserService`，解析构造方法所需的 `UserDao`，把符合类型的 Bean 传给 `UserService`。依赖是接口，但容器需要一个可实例化并已注册的实现。

只有一个构造方法时可以省略 `@Autowired`，多个构造方法时要按规则明确选择。构造注入让必需依赖显式可见，也允许字段使用 `final`，方便写不依赖 Spring 容器的单元测试。参见 [Using @Autowired](https://docs.spring.io/spring-framework/reference/core/beans/annotation-config/autowired.html)。

以下代码可放在普通测试方法中，用 Lambda 提供测试实现：
```java
UserService service = new UserService(id -> "Test User");
System.out.println(service.getDisplayName(1L)); // Test User
```

## 三种注入方式
*已修改*

![[Pasted image 20260912203117.png]]

截图中的“多个同类型 Bean 就报错”应理解为：需要单个对象且无法按候选规则选出唯一对象时才报错。图中的 `@Resource(name = "...")` 则按指定名称注入，常用于字段或 Setter；Spring Boot 3 / 4 项目使用 `jakarta.annotation.Resource`，不用于构造方法。参见 [Injection with @Resource](https://docs.spring.io/spring-framework/reference/core/beans/annotation-config/resource.html)。*已纠正*

| 方式 | 写法 | 特点 |
|---|---|---|
| 构造方法注入 | 构造参数声明依赖 | 适合必需依赖，优先用于业务组件 |
| 字段注入 | 字段上加 `@Autowired` | 简短，但依赖隐藏在字段中，手动构造时不会自动赋值 |
| Setter 注入 | Setter 方法上加 `@Autowired` | 适合允许后续设置的依赖；默认仍要求有匹配 Bean |

字段注入与 Setter 注入的局部写法如下，仅用于比较，不要与上例的 `final` 字段混用：
```java
// 字段注入：位于一个已注册的组件类内
@Autowired
private UserDao userDao;
```

```java
// Setter 注入：位于另一个已注册的组件类内
private UserDao userDao;

@Autowired
public void setUserDao(UserDao userDao) {
    this.userDao = userDao;
}
```

这两段需要导入 `org.springframework.beans.factory.annotation.Autowired`。手动 `new` 出来的普通对象通常不经过 Spring 的注入处理；在测试中手动传入完整依赖则是正常做法。

## 扫描范围与启动注解
*已纠正*

`@ComponentScan` 指定要扫描的包。`@SpringBootApplication` 自带组件扫描，默认从**被该注解标记的启动类所在包**向下扫描，并非扫描项目所有包，也不是把包内所有类都注册为 Bean。

```text
com.example.demo
├── DemoApplication      ← 启动类
├── controller           ← 默认覆盖
├── service              ← 默认覆盖
└── user                 ← 默认覆盖

com.example.external     ← 不在上述默认范围内
```

确实需要扩大范围时，可在启动类上使用：
```java
@SpringBootApplication(scanBasePackages = {"com.example.demo", "com.example.external"})
```

`scanBasePackages` 控制组件扫描，不能代替 JPA 实体扫描、Spring Data Repository 扫描或 MyBatis Mapper 扫描的专门配置。初学项目优先把启动类放在业务根包，避免无意漏扫。

参见 [@SpringBootApplication](https://docs.spring.io/spring-boot/reference/using/using-the-springbootapplication-annotation.html)。

## 多实现与自定义 Bean
*已补充*

当 `UserDao` 有多个已注册实现时，仅凭接口类型可能无法选出一个 Bean。可以用 `@Primary` 指定默认候选，或在注入点通过 `@Qualifier` 限定候选。例如替换上例的构造方法：
```java
public UserService(@Qualifier("memoryUserDao") UserDao userDao) {
    this.userDao = userDao;
}
```

需要导入 `org.springframework.beans.factory.annotation.Qualifier`；`memoryUserDao` 是这个组件默认生成的 Bean 名称。复杂命名规则或自定义命名器可能改变默认名。参见 [Qualifier](https://docs.spring.io/spring-framework/reference/core/beans/annotation-config/autowired-qualifiers.html)。

无法给第三方类加组件注解时，可在 `com.example.demo` 或子包中新建 `AppConfig.java`：
```java
package com.example.demo;

import java.time.Clock;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class AppConfig {
    @Bean
    public Clock clock() {
        return Clock.systemUTC();
    }
}
```

其他 Bean 便可用构造参数 `Clock clock` 接收它。`@Bean` 标记工厂方法，容器管理方法返回的对象。参见 [@Bean](https://docs.spring.io/spring-framework/reference/core/beans/java/bean-annotation.html)。

## 生命周期与常见问题
*已补充*

默认作用域是 singleton，即同一个容器中同一 Bean 定义通常对应一个共享实例，不是“整个 JVM 中这个类只能有一个对象”。共享实例并不自动保证线程安全，因此不要把某次请求的用户名等数据放在 Service 的可变成员字段中。参见 [Bean Scopes](https://docs.spring.io/spring-framework/reference/core/beans/factory-scopes.html)。

| 问题 | 检查方向 |
|---|---|
| 找不到匹配 Bean | 实现类是否注册，是否在扫描范围，激活条件是否满足 |
| 候选 Bean 不唯一 | 使用 `@Qualifier`、`@Primary` 或显式注入集合 |
| 字段为 `null` | 对象是否由容器创建，是否过早访问字段注入的依赖 |
| A 依赖 B，B 又依赖 A | 构造注入会形成无法解析的循环；拆分职责或提取第三个服务 |
| 测试难以构造对象 | 优先用构造方法显式声明依赖，传入替身实现 |

不要通过随意更换注入方式掩盖循环依赖；先检查业务职责是否耦合过紧。
