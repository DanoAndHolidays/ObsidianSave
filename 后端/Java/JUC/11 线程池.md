## 构造函数
```java
ThreadPoolExecutor(int corePoolSize,          // 核心线程数量
			       int maximumPoolSize,      // 救急 + 核心
				   long keepAliveTime,       // 救急线程的存活时间
                   TimeUnit unit,            // 救急线程的存活时间单位
                   BlockingQueue<Runnable> workQueue,                        
                   ThreadFactory threadFactory,  
                   RejectedExecutionHandler handler)
```

救急线程是在阻塞队列满（必须是有界队列时，才可能会满），依旧有任务进来的情况下被创建，时间结束被销毁，如果救急和阻塞队列都满了，此时才会拒绝（Tomcat 的线程池实现有些不同）

## Executors
### 工厂函数
固定大小的线程池：
```java
public static ExecutorService newFixedThreadPool(int nThreads) {  
    return new ThreadPoolExecutor(nThreads, nThreads,  
                                  0L, TimeUnit.MILLISECONDS,  
                                  new LinkedBlockingQueue<Runnable>());  
}
```

带缓冲的：
```java
public static ExecutorService newCachedThreadPool() {  
    return new ThreadPoolExecutor(0, Integer.MAX_VALUE,  
                                  60L, TimeUnit.SECONDS,  
                                  new SynchronousQueue<Runnable>());  
}
```

单线程线程池：
```java
public static ExecutorService newSingleThreadExecutor(ThreadFactory threadFactory) {  
    return new AutoShutdownDelegatedExecutorService  
        (new ThreadPoolExecutor(1, 1,  
                                0L, TimeUnit.MILLISECONDS,  
                                new LinkedBlockingQueue<Runnable>(),  
                                threadFactory));  
}
```

## 设计模式
让有限的工作线程（WorkerThread）来轮流异步处理无限多的任务
也可以将其归类为==分工模式==，它的典型实现就是线程池，也体现了经典设计模式中的==享元模式==

不同的任务类型应该使用不用的线程池：

- 提升效率
- 防止==线程饥饿==问题（一个线程池中的任务有相互依赖就可能引发线程饥饿）

## Fork / Join
Fork/Join 是 JDK 1.7 加入的新的线程池实现，它体现的是一种==分治==思想，适用于能够进行任务拆分的 cpu 密集型运算

所谓的任务拆分，是将一个大任务拆分为算法上相同的小任务，直至不能拆分可以直接求解。跟递归相关的一些计算，如归并排序、斐波那契数列、都可以用分治思想进行求解

Fork/Join 在分治的基础上加入了多线程，可以把每个任务的分解和合并交给不同的线程来完成，进一步提升了运 算效率 

Fork/Join 默认会创建与 cpu 核心数大小相同的线程池
