## 先记住：JDK、JRE、JVM 的关系
*已修改*

- **JVM（Java Virtual Machine，Java 虚拟机）**：执行 `.class` 文件中 JVM 指令（字节码）的抽象计算机。它定义了指令集、类文件格式和运行时内存区域，但不限定必须采用解释器还是哪一种底层实现。
- **JRE（Java Runtime Environment，Java 运行时环境）**：运行 Java 程序所需的 JVM、标准类库以及相关运行时组件的概念性集合。
- **JDK（Java Development Kit，Java 开发工具包）**：面向开发者的完整工具包，包含运行 Java 所需的能力，并额外提供 `javac`、`jdb`、`jcmd`、`jstack`、`jmap`、`jfr`、`javap` 等开发、调试和诊断工具。

可以把它们理解为：

```text
JDK = 开发工具 + Java 运行时能力
Java 运行时能力 = JVM + 标准类库 + 其他运行时组件
```

现代 Java 开发中，不要再把“单独安装一个 JRE”当成默认方案。Java SE 9 之后的 JDK 发行版通常不再提供传统意义上的独立 JRE 下载；开发机直接安装 JDK，部署时可以使用完整 JDK，也可以使用 `jlink` 按模块生成定制运行时镜像。 *已补充*

## 从源码到运行：`javac`、字节码与 `java`
*已修改*

### 2.1 `javac`：编译源代码
`javac` 读取 `.java` 源文件，检查语法、类型和访问权限，并将其编译成可在 JVM 上运行的 `.class` 文件：

```text
Hello.java  --javac-->  Hello.class
```

`.class` 文件通常包含：

- JVM 字节码指令；
- 常量池和符号引用；
- 类、字段、方法、访问权限等元数据；
- 版本号，表示它依赖的 class-file 格式版本。

`javac` 不只是“把代码翻译成机器码”：它的主要产物是与硬件无关的 class 文件，真正启动和执行应用由 `java` 启动器完成。

### 2.2 `java`：启动 JVM 并调用入口方法
`java` 命令会启动 JVM，加载指定的主类，解析其依赖，并调用：

```java
public static void main(String[] args)
```

因此，运行类时写**完全限定类名**，不要写 `.class` 后缀：

```powershell
java -cp out com.example.Hello
```

这里的 `-cp out`（`--class-path out`）告诉 JVM 去 `out` 目录查找类文件。也可以运行 JAR：

```powershell
java -jar app.jar
```

JAR 的 `META-INF/MANIFEST.MF` 中需要通过 `Main-Class` 指定入口类。 *已补充*

### 2.3 字节码、类加载与执行
JVM 看到一个主类后，大致会经历以下步骤：

1. **类加载**：由类加载器读取 class 文件，并按需加载依赖类。
2. **链接**：进行验证、准备和解析，确保 class 文件结构和符号引用满足 JVM 约束。
3. **初始化**：执行类初始化逻辑，例如静态字段初始化和静态代码块。
4. **执行**：解释器先执行字节码；运行过程中收集方法调用和分支的运行信息。
5. **优化**：对反复执行的“热点”代码进行 JIT（Just-In-Time）编译，生成当前平台的本地机器码，并在条件变化时进行去优化或重新编译。

“混合型编译/解释”不表示程序简单地一半解释、一半编译，也不表示启动前会把全部代码一次性编译完。HotSpot 通常先用解释器快速启动，再用自适应编译器把性能关键部分编译和优化，低频代码可能始终保持解释执行。 *已纠正*

JVM 规范本身不要求某一种实现方式：JVM 可以解释字节码，也可以把字节码编译为本地指令，甚至采用硬件或微码实现。Java 的跨平台关键在于 class-file 格式和 JVM 规范，而不是“所有平台执行完全相同的机器码”。 *已补充*

查看 class 文件和字节码：

```powershell
javap -c -v -p -classpath out com.example.Hello
```

- `-c`：反汇编方法字节码；
- `-v`：输出更完整的 class 文件信息；
- `-p`：显示私有成员；
- `-classpath`：指定 class 文件搜索路径。

注意：class 文件有版本号。使用较新的 JDK 编译出来的 class 文件，旧 JVM 可能无法运行；使用 `--release` 编译可以同时约束语言特性、API 和目标 class-file 版本。 *已补充*

## 截至 2026-09-09 的 JDK 25 选择建议
*已补充*

OpenJDK 25 已于 **2025-09-16** 达到 GA；Oracle 的 Java SE 支持路线图将 Java SE 25 列为 **LTS（长期支持）**，而 Java SE 26 列为非 LTS。以 **2026-09-09** 为基准，JDK 25 是学习、新项目和长期维护项目的稳妥默认基线。

按项目类型选择：

| 场景 | 建议 | 原因 |
| --- | --- | --- |
| 学习 Java、练习基础语法和 JVM 工具 | JDK 25 | 版本新、周期长，适合作为统一学习环境 |
| 新建生产项目 | 优先 JDK 25 LTS | 便于获得较长的厂商支持周期和稳定的依赖生态 |
| 已有 Java 21 项目 | 先保持 JDK 21，按升级计划迁移到 25 | 现有框架、插件、生产镜像和 CI 可能仍以 21 为支持基线 |
| 想试验新特性 | 可单独安装 JDK 26 | 非 LTS 版本适合验证特性，不应无条件作为长期生产基线 |
| 需要兼容更旧的运行环境 | 在 JDK 25 上使用 `--release` 指定目标版本 | 让编译器同时约束语法、标准 API 和 class 文件版本 |

JDK 版本选择不能只看“本机能不能编译”。还要检查：

- 使用的框架、应用服务器、插件和构建工具是否支持目标 JDK；
- 生产环境容器或服务器实际运行的 JDK 版本；
- CI/CD、测试矩阵和监控工具是否一致；
- 组织规定的发行版、许可证和安全更新来源。

推荐在项目中明确编译目标，例如项目必须运行在 Java 21 时：

```powershell
javac --release 21 -d out src\Hello.java
```

`--release 21` 通常比只写 `-source 21 -target 21` 更安全，因为它还限制了编译时可使用的 Java SE API。 *已补充*

## Windows 配置 `JAVA_HOME` 与 `PATH`
*已补充*

### 4.1 变量应该指向哪里
- `JAVA_HOME`：指向 **JDK 根目录**，例如 `C:\Program Files\Java\jdk-25`，不要指向 `bin`。
- `PATH`：加入 `%JAVA_HOME%\bin`，让系统能够找到 `java.exe`、`javac.exe` 等命令。
- `CLASSPATH`：一般不要全局设置；通过 `-cp`、`--class-path` 或构建工具声明依赖更清晰，也更不容易污染其他项目。

### 4.2 只对当前 PowerShell 会话生效
```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-25'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

上面的写法只影响当前终端窗口。长期配置请使用 Windows 的“系统属性 → 高级 → 环境变量”，或者由团队统一的开发环境脚本管理。不要随意用 `setx PATH ...` 覆盖整个 PATH，因为拼接错误可能丢失已有工具路径，而且新值不会回写当前 PowerShell 会话。 *已补充*

### 4.3 验证是否配置正确
```powershell
java -version
javac -version
where.exe java
where.exe javac
Get-Command java | Select-Object -ExpandProperty Source
Get-Command javac | Select-Object -ExpandProperty Source
```

排查重点：

1. `java -version` 和 `javac -version` 是否来自同一套 JDK；
2. `where.exe` 返回的第一条路径是否是预期路径；
3. `JAVA_HOME` 是否误指向 JRE 或 JDK 的 `bin`；
4. 修改环境变量后是否重新打开终端或重新加载 IDE。

## 命令行编译并运行第一个程序
*已补充*

推荐把源代码和编译产物分开：

```text
hello-java/
├─ src/
│  └─ Hello.java
└─ out/
```

`src\Hello.java`：

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java 25!");
    }
}
```

在 `hello-java` 目录运行：

```powershell
New-Item -ItemType Directory -Force out | Out-Null
javac -encoding UTF-8 -d out src\Hello.java
java -cp out Hello
```

预期输出：

```text
Hello, Java 25!
```

- `-encoding UTF-8`：明确源文件编码，避免中文注释或字符串在不同系统上乱码；
- `-d out`：把 `.class` 文件输出到 `out`，而不是污染 `src`；
- `-cp out`：运行时把 `out` 加入 class path。

Java 11 及更高版本还支持单文件源码运行：

```powershell
java src\Hello.java
```

它适合快速实验；正式项目仍应使用 Maven、Gradle 或其他可复现构建流程。 *已补充*

常见错误：

| 报错 | 常见原因 | 排查方式 |
| --- | --- | --- |
| `java is not recognized` | PATH 没有 JDK 的 `bin` | 检查 `JAVA_HOME`、PATH 并重开终端 |
| `javac is not recognized` | 只安装了运行时或 PATH 指向错误目录 | 确认安装的是 JDK，并运行 `where.exe javac` |
| `Could not find or load main class` | class path、包名或类名不匹配 | 使用完全限定类名并检查 `-cp` |
| `UnsupportedClassVersionError` | 编译 JDK 比运行 JDK 新 | 升级运行时，或用 `javac --release` 重新编译 |
| 中文乱码 | 编译时和终端编码不一致 | 显式使用 `-encoding UTF-8` 并检查终端字体/编码 |

## IntelliJ IDEA、Maven 与 Gradle 的关系
*已补充*

三者职责不同：

- **IntelliJ IDEA**：编辑器和 IDE，负责代码导航、补全、重构、断点调试、运行配置以及项目视图。
- **Maven**：以 `pom.xml` 描述依赖、插件、生命周期和打包规则，常用命令包括 `mvn test`、`mvn package`。
- **Gradle**：以 `build.gradle` 或 `build.gradle.kts` 描述任务、依赖和构建逻辑，常用命令包括 `gradlew test`、`gradlew build`。

IDEA 可以直接编译和运行代码，但团队项目应把 `pom.xml` 或 `build.gradle(.kts)` 作为可复现构建的主要来源，并让 CI 使用同一构建脚本。IDEA 的以下配置可能彼此不同，不能混为一谈：

1. **Project SDK**：IDEA 用于索引、编译和运行项目的 JDK；
2. **Maven/Gradle 使用的 JVM**：构建工具自身启动所使用的 JDK；
3. **Java toolchain**：构建脚本要求编译任务使用的 JDK；
4. **编译目标**：例如 Maven Compiler Plugin 的 `release`，或 Gradle 的 `JavaLanguageVersion`。

新项目建议：

- 提交 Maven Wrapper（`mvnw`）或 Gradle Wrapper（`gradlew`），固定构建工具版本；
- 在构建文件中明确 Java 版本，不只依赖开发者本机的 IDEA 设置；
- 在 CI 中执行与本地一致的测试和打包命令；
- IDEA 导入构建文件后，优先使用构建工具模型，不要只依赖 IDE 私有配置。

## 常用 JDK 诊断与学习工具
*已纠正*

| 工具/命令 | 用途 | 典型示例 |
| --- | --- | --- |
| `java -version` | 查看启动器和运行时版本 | `java -version` |
| `java -XshowSettings:properties -version` | 查看 Java 系统属性、用户目录等环境信息 | `java -XshowSettings:properties -version` |
| `javac` | 编译 Java 源码 | `javac --release 25 -d out src\Hello.java` |
| `javap` | 查看 class 文件、字节码和常量池 | `javap -c -v -p -classpath out Hello` |
| `jcmd` | 向运行中的 JVM 发送诊断命令；通常优先使用 | `jcmd -l`、`jcmd <pid> Thread.print` |
| `jps` | 列出当前用户可见的 Java 进程 | `jps -l` |
| `jstack` | 输出 Java 线程栈，适合初步排查死锁和线程阻塞 | `jstack <pid>` |
| `jstat` | 周期性查看类加载、GC 等统计信息 | `jstat -gcutil <pid> 1000` |
| `jmap` | 查看堆相关信息或生成 heap dump；权限和安全影响较大 | `jmap -dump:live,format=b,file=heap.hprof <pid>` |
| `jfr` | 启动、停止和查看 Java Flight Recorder 记录 | `jfr start <pid>`、`jfr print recording.jfr` |
| `jdb` | 命令行 Java 调试器 | `jdb -classpath out Hello` |
| `jhsdb` | 高级服务性故障分析，例如检查 core dump 或进程 | 仅在明确诊断方案后使用 |

常用 `jcmd` 示例：

```powershell
jcmd -l
jcmd <pid> VM.version
jcmd <pid> VM.flags
jcmd <pid> VM.system_properties
jcmd <pid> Thread.print
jcmd <pid> GC.class_histogram
```

生产环境使用诊断工具时要先确认权限、数据敏感性和停顿风险；heap dump、线程栈和系统属性可能包含业务信息或路径信息，不要未经授权上传到公共位置。

### 7.1 `jhat` 的纠正
`jhat` **不是 JDK 25 的可用诊断工具**。OpenJDK 的 JEP 241 已将它在 **JDK 9** 中移除，原因是它实验性强、已过时，已有更好的堆分析器。因此不要再把 `jhat` 写进现代 JDK 工具清单。

分析 heap dump 时，可以根据团队工具链选择 VisualVM、Eclipse MAT 或 JDK Mission Control 等专用工具；它们不是 `jhat` 的命令行兼容替代品，具体选择应结合安全策略和数据规模。 *已纠正*

## 一套可重复的环境检查清单
*已补充*

```powershell
# 1. 版本
java -version
javac -version

# 2. 路径
where.exe java
where.exe javac
$env:JAVA_HOME

# 3. 编译与运行
Remove-Item -Recurse -Force out -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force out | Out-Null
javac -encoding UTF-8 -d out src\Hello.java
java -cp out Hello

# 4. 查看字节码
javap -c -v -p -classpath out Hello
```

通过后再在 IDEA 中打开项目，并确认 IDEA 的 Project SDK、构建工具 JVM 和项目实际编译目标一致。 *已补充*
