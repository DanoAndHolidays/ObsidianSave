### try catch
![[Pasted image 20260910203638.png]]

```java
int[] arr = {1, 2, 4, 5};  
  
try {  
    // 只能捕获第一异常  
    System.out.println(arr[6]);  
  
    // 如果上面有Exception，下面就不执行了  
    System.out.println("666");  
} catch (ArrayIndexOutOfBoundsException | ArithmeticException e) {  
    System.out.println(e.toString());  
    // java.lang.ArrayIndexOutOfBoundsException: Index 6 out of bounds for length 4  
  
    // 父类一定写在下面  
} catch (Exception e){  
    // ...  
}

// 如果try中的问题，没有被catch捕获到，就会fallback到JVM处理
```

结构：
```text
try {

} catch (Exception e) {

} finally {

}
```

`finally` 的核心语义不管 try 正常结束还是异常结束，通常都会执行 finally（在 JVM 正常执行控制流的情况下，finally 通常都会执行）

这是一个经典面试坑。

```text
static int test() {

    try {
        return 10;
    } finally {
        return 20;
    }

}
```

最终：
```text
20
```

因为 `finally` 的 return 覆盖了前面的 return。

更严重的是：
```text
try {

    throw new RuntimeException("发生异常");

} finally {

    return;

}
```

异常甚至可能被吞掉。

### try-with-resources
这是现代 Java 非常重要的知识。以前操作文件可能写：
```java
InputStream input = null;

try {
    input = new FileInputStream("a.txt");
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (input != null) {
        try {
            input.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

}
```

很麻烦，现在：
```text
try (
    InputStream input =
        new FileInputStream("a.txt")
) {

    // 使用 input

}
```

结束以后：
```text
input.close();
```

自动执行，这叫 try-with-resources（自动资源管理）

要求资源实现：
```text
AutoCloseable
```

例如：
```text
InputStream
OutputStream
Reader
Writer
Connection
Statement
```

很多资源类都支持。

try-with-resources 有一个比较进阶但应该知道的设计。

例如：

```text
try (Resource r = new Resource()) {

    throw new RuntimeException("业务异常");

}
```

如果：

```text
r.close()
```

又产生：

```text
关闭异常
```

这时候有两个异常：

```text
业务异常
关闭异常
```

Java 不希望关闭异常覆盖真正的业务异常。

所以：

```text
主异常：业务异常
Suppressed Exception：关闭异常
```

可以通过：

```text
e.getSuppressed()
```


多个资源：

```text
try (
    InputStream input = new FileInputStream("a.txt");
    OutputStream output = new FileOutputStream("b.txt")
) {

}
```

关闭顺序是：

```text
创建：
input
↓
output

关闭：
output
↓
input
```

也就是：

> 后创建的资源先关闭。

类似栈：

```text
LIFO
Last In First Out
```
