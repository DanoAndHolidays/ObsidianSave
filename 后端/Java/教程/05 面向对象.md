## 类、对象与封装
*已补充* 类定义一类对象的字段和行为；`new` 创建实例，变量保存引用。封装的重点是让对象始终保持合法状态，而不只是为每个字段生成 getter / setter。

以下是一个完整类，可保存为 `Student.java`：

```java
public class Student {
    private String name;
    private int age;

    public Student() {
        this("未命名", 0);
    }

    public Student(String name, int age) {
        setName(name);
        setAge(age);
    }

    public String getName() { return name; }
    public int getAge() { return age; }

    public final void setName(String name) {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("姓名不能为空");
        }
        this.name = name;
    }

    public final void setAge(int age) {
        if (age < 0 || age > 150) {
            throw new IllegalArgumentException("年龄必须在 0～150 之间");
        }
        this.age = age;
    }

    public void study() {
        int age = 10;
        System.out.println("局部变量：" + age);
        System.out.println(name + "，年龄：" + this.age);
    }
}
```

*已修改*

在调用处创建两个对象：

```java
Student s1 = new Student("小诗诗", 18);
Student s2 = new Student("小丹丹", 19);
s1.study(); // 局部变量：10；小诗诗，年龄：18
s2.study(); // 局部变量：10；小丹丹，年龄：19
```

*已修改*

两个实例各有自己的 `name`、`age`。截图用 `0x0011`、`0x0022` 表示引用，是帮助理解“指向哪个对象”的示意，不是 Java 代码能直接读写的物理地址。未显式赋值的实例字段有默认值，例如 `int` 为 `0`、引用为 `null`；局部变量必须在读取前明确赋值。

上例在构造器中调用的 setter 被声明为 `final`，避免构造期间动态调用子类重写的方法。真实领域对象也可以采用私有校验方法，或者只通过构造器赋值。

## this 与对象传参
### this 指向当前实例
*已纠正* `this` 是当前实例的引用。不是“this 优先使用局部变量”：**不带限定符的名称**可能被局部变量遮蔽，`this.age` 则明确访问当前对象的字段。成员查找也必须满足访问权限，不能用 `this` 绕过父类的 `private`。

```java
public void setAge(int age) {
    this.age = age; // 左边是实例字段，右边是参数
}
```

*已修改*

对比 JavaScript：Java 实例方法的 `this` 由接收该调用的对象确定，没有 `call` / `apply` / `bind` 这一套动态绑定规则。静态方法没有当前实例，不能直接使用 `this`。

### Java 始终按值传递
*已纠正* 传入对象时，复制的是**引用值**。调用者与形参可以指向同一个对象；改变对象会被双方观察到，给形参重新赋值则不会替换调用者的变量。

以下方法写在另一个测试类中，与前面的 `Student` 配合：

```java
static void update(Student student) {
    student.setAge(20);
    student = new Student("另一个学生", 30);
}

public static void main(String[] args) {
    Student a = new Student("小诗诗", 18);
    Student b = a;
    update(a);
    System.out.println(a == b);       // true
    System.out.println(a.getAge());   // 20
    System.out.println(b.getName());  // 小诗诗
}
```

*已修改*

图中的“多个变量指向同一对象，任意一个变量修改字段后其他变量也能看到”描述的是共享对象。不要把它记成可以修改调用者变量的“按引用传递”。参见 [Java 官方参数传递教程](https://dev.java/learn/classes-objects/calling-methods-constructors/)。

## 构造方法与初始化顺序
### 构造方法的规则
*已修改* 构造方法名称与类名一致，没有返回类型，连 `void` 都不写。构造器不能像普通方法那样通过 `对象.构造器()` 调用；`new`、`this(...)`、`super(...)` 是常见调用位置。

- 普通类未声明任何构造器时，编译器才提供默认构造器；通常无参数。
- 只要声明了构造器，就不会再自动补一个无参构造器。
- 构造器可以重载，但不会被继承或重写。
- `this(...)` 委托给本类其他构造器，不能形成循环。
- `super(...)` 调用直接父类构造器，不会额外创建一个独立的父类对象。
- 同一个对象初始化时可能经过多个构造器，所以“一个对象只执行一次构造方法”不够准确。

```java
class Person {
    private final String name;
    Person(String name) { this.name = name; }
    String getName() { return name; }
}

class Employee extends Person {
    private final int level;

    Employee(String name) {
        this(name, 1);
    }

    Employee(String name, int level) {
        super(name);
        this.level = level;
    }
}
```

*已修改*

*已纠正* 对普通子类构造器，如果没有显式的 `this(...)` 或 `super(...)`，会隐式调用 `super()`。这是语言与编译规则，不是 JVM 给父类临时添加无参构造器。如果父类没有可访问的无参构造器，子类必须显式调用合适的有参构造器，否则编译失败。

### Java 25 的构造器规则变化
*已纠正* 原图中的“`super()` 必须是第一条语句”适用于 Java 21 等未启用相关预览特性的旧版本。Java 25 正式允许在显式构造器调用前放置受限制的语句，例如参数校验；并不允许任意读取尚未完成初始化的当前实例。

```java
// Java 25；父类为上面的 Person
class CheckedPerson extends Person {
    CheckedPerson(String name) {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("姓名不能为空");
        }
        super(name);
    }
}
```

*已补充*

兼容旧项目时，把构造器调用放在首行仍然最容易阅读。精确限制见 [JLS 25：Constructor Body](https://docs.oracle.com/javase/specs/jls/se25/html/jls-8.html#jls-8.8.7)。

### 初始化先后顺序
*已补充* 对常见的“`super(...)` 在首行”的代码，可以这样跟踪：父类静态初始化 → 子类静态初始化（每个类首次需要初始化时）→ 对象字段获得默认值 → 父类实例字段初始化/实例初始化块/构造器主体 → 子类相应初始化与构造器主体。字段初始化器和初始化块在各自类内按源代码顺序执行；`this(...)` 委托不会让同一层实例初始化重复执行。

不要在构造器里调用可被子类重写的方法，否则可能进入子类实现，而子类字段还没准备好。也不要在构造期间把 `this` 注册到全局回调或启动使用它的线程。

## static、工具类与 main
### 静态字段属于类
*已修改* 截图中的 `teacherName` 由所有 `Student` 实例共享，可以写作：

```java
class SchoolStudent {
    static String teacherName;
    String name;
    int age;

    void show() {
        System.out.println(name + ", " + age + ", " + teacherName);
    }
}
```

*已修改*

```java
SchoolStudent.teacherName = "阿玮老师";
SchoolStudent s1 = new SchoolStudent();
s1.name = "小诗诗";
s1.age = 23;
SchoolStudent s2 = new SchoolStudent();
s1.show(); // 小诗诗, 23, 阿玮老师
s2.show(); // null, 0, 阿玮老师
```

*已修改*

类静态成员通常也能通过实例表达式访问，但推荐始终写 `类名.成员`。共享范围是同一个运行时类；不同类加载器加载的同名类，不必共享同一份静态状态。静态字段初始化涉及类的准备、初始化阶段，不能把“加载类”与“执行全部静态初始化代码”混成一个动作。

### 静态方法的限制
*已纠正* “静态只能访问静态”省略了“直接”二字。静态方法没有隐含的 `this`，但拿到对象后仍可访问其有权限的实例成员：

```java
static void printStudent(Student student) {
    System.out.println(student.getName());
}
```

*已补充*

实例方法既能访问实例成员，也能访问静态成员。`static` 不提供线程安全：共享计数器的 `count++` 仍可能发生并发丢失更新。

### 工具类与测试类
*已修改* 原来的“方法类”通常指工具类。截图中的 `ArrayUtil` 提供最大值、最小值、总和、平均值等操作；典型设计是见名知意、私有构造器、静态方法。

```java
final class ArrayUtil {
    private ArrayUtil() { }

    static int max(int[] values) {
        if (values == null || values.length == 0) {
            throw new IllegalArgumentException("数组不能为空");
        }
        int result = values[0];
        for (int value : values) result = Math.max(result, value);
        return result;
    }
}
```

*已修改*

“测试类”不是 Java 特殊语法种类。有 `main` 的类可以用于手工实验，JUnit 测试通常由测试框架执行，并不需要 `main`。工具类也不是“只要没有 main 就算”：它的职责才是判断依据。

### main 的各部分
*已修改* 传统、跨版本通用的入口如下：

```java
public static void main(String[] args) {
    System.out.println(args.length);
}
```

*已修改*

| 部分 | 含义 |
| --- | --- |
| `public` | 传统入口使用公开访问权限 |
| `static` | 调用传统入口不需要先创建该类实例 |
| `void` | 方法本身不返回值，不等于进程没有退出状态 |
| `main` | 入口方法名称 |
| `String[] args` | 命令行参数，`args` 只是可更换的参数名 |

同一个类里的其他方法不必是静态方法。Java 25 也支持符合条件的实例 `main` 等简化入口；这里保留传统写法用于兼容。见 [Java 25 启动规则](https://docs.oracle.com/javase/specs/jls/se25/html/jls-12.html#jls-12.1.4)。

## JavaBean 与领域对象
*已纠正* “JavaBean 类没有 static”不是规范。JavaBean 的属性通常通过实例 getter / setter 暴露，所以每个对象拥有自己的属性状态；类中仍可有静态常量或辅助方法。顶层普通类本来就不能写 `static class`，而静态嵌套类可以。

前面的 `Student` 展示了常见 Bean 风格：无参构造器、私有字段、公开访问器。布尔属性常见 `isActive()`；只读属性可以只有 getter。属性不必与字段一一对应，也可以由方法计算。参见 [JavaBeans 属性约定](https://docs.oracle.com/javase/tutorial/javabeans/writing/properties.html)。

*已补充* 不要把 JavaBean、Spring Bean、数据库实体当成同一个概念。Spring Bean 强调由容器管理；实体强调持久化映射；JavaBean 强调属性等组件约定。领域对象应通过 `pay()`、`cancel()` 之类的方法保护状态转换，不一定要暴露任意 setter。

## 继承、super 与访问权限
### 单继承与成员继承
*已修改* 类只能直接继承一个类，但可以多层继承，并实现多个接口。普通类未写 `extends` 时直接父类为 `Object`；例如 `Dog → Animal → Object`。这里的箭头表示子类到父类。

*已纠正* 必须区分“对象中包含父类定义的状态”“子类继承成员”“当前代码有权访问成员”：

| 成员 | 规则 |
| --- | --- |
| 构造器 | 不继承，用 `super(...)` 调用 |
| `private` 字段、方法 | 不被子类继承；父类字段仍是对象状态的一部分，可由父类方法操作 |
| 可继承的普通实例方法 | 可以继承；满足条件时可以重写 |
| 可继承的 `final` 实例方法 | 可以继承，不能重写 |
| 类的可继承 `static` 方法 | 可以继承；同签名子类静态方法是隐藏，不是重写 |
| 包访问成员 | 是否继承与能否访问还受包边界影响 |

因此，截图的“final / static 方法不能继承”应改为上述规则。接口的静态方法又有不同规则，见 [[06 接口]]。[官方继承教程](https://dev.java/learn/inheritance/what-is-inheritance/)

### this 与 super 的查找差异
*已修改* 截图中的同名变量例子可转为：

```java
class Fu {
    String name = "Fu";
}

class Zi extends Fu {
    String name = "Zi";

    void show() {
        String name = "ziShow";
        System.out.println(name);       // ziShow
        System.out.println(this.name);  // Zi
        System.out.println(super.name); // Fu
    }
}
```

*已修改*

`super.name` 访问父类侧的字段；`super.method()` 可以调用父类实现。`super` 不是另一个独立对象，也不能写 `super.super`。字段同名属于隐藏，工程中应尽量避免。

### 权限表及边界
*已修改* 以下表格假设声明类本身可访问，且暂不考虑模块导出限制：

| 修饰符 | 声明类内 | 同包其他类 | 跨包子类 | 跨包无关类 |
| --- | --- | --- | --- | --- |
| `private` | 可 | 不可 | 不可 | 不可 |
| 不写（包访问） | 可 | 可 | 不可 | 不可 |
| `protected` | 可 | 可 | 有条件可 | 不可 |
| `public` | 可 | 可 | 可 | 可 |

*已补充* `protected` 跨包访问实例成员时，还限制接收者的类型。例如 `Child extends Parent`，在 `Child` 内可通过 `this`、`super` 或 `Child` 类型的引用访问相应受保护成员，不能随便通过一个 `Parent` 类型变量访问。`private` 则允许同一顶层类内部的嵌套类之间相互访问；这不表示私有成员被子类继承。模块化项目中，`public` 还受模块可读性与包导出影响。[JLS 访问控制](https://docs.oracle.com/javase/specs/jls/se25/html/jls-6.html#jls-6.6)

## 重载、重写与多态
### 重载与重写不是一回事
*已修改*

| 对比 | 重载 overload | 重写 override |
| --- | --- | --- |
| 关系 | 同名、不同参数列表 | 子类提供父类实例方法的实现 |
| 选择依据 | 编译期类型及重载解析 | 所选实例方法在运行期的接收对象类型 |
| 仅改变返回类型 | 不能构成重载 | 引用返回类型可协变 |
| 常用检查 | 留意装箱、可变参数与 null 歧义 | 写 `@Override` 让编译器检查 |

*已纠正* 重写时参数不能随意改类型；可见性不能缩小；引用返回类型可更具体，基本类型返回值和 `void` 必须匹配；受检异常不能扩大。`private` 方法不参与重写，`static` 方法是隐藏，`final` 方法禁止重写。`final class` 自己仍能重写其父类允许重写的方法，只是不能再有子类。[官方重写与隐藏教程](https://dev.java/learn/inheritance/overriding/)

### 编译期看类型，运行期选择重写实现
*已修改* 以下完整程序保存为 `PolymorphismDemo.java`：

```java
public class PolymorphismDemo {
    static class Animal {
        String label = "animal";
        void speak() { System.out.println("animal speaks"); }
        static void kind() { System.out.println("Animal.kind"); }
    }

    static class Dog extends Animal {
        String label = "dog";
        @Override void speak() { System.out.println("woof"); }
        static void kind() { System.out.println("Dog.kind"); }
        void fetch() { System.out.println("fetch"); }
    }

    static void inspect(Animal animal) { System.out.println("Animal overload"); }
    static void inspect(Dog dog) { System.out.println("Dog overload"); }

    public static void main(String[] args) {
        Animal animal = new Dog();
        animal.speak();                    // woof：动态选择重写实现
        System.out.println(animal.label);  // animal：字段看编译期类型
        Animal.kind();                     // Animal.kind：静态调用
        inspect(animal);                   // Animal overload：重载看编译期类型
        if (animal instanceof Dog dog) {
            dog.fetch();                   // fetch：检查后调用子类特有方法
        }
    }
}
```

*已修改*

*已纠正* 父类型变量不能直接调用子类型独有的方法，是因为编译器按变量的静态类型检查成员，不叫“逆变”。向上转型不改变对象；向下转型也不会创建或改造对象，错误转换会抛 `ClassCastException`。`instanceof` 对 `null` 返回 `false`。

多态让一个参数类型接收多种实现，从而减少业务中的类型分支。重写能体现不同实现的行为差异，但不必把“子类必须重写某方法”当成允许向上转型的前提。

### 虚方法表只是实现模型
*已纠正* 原图通过 `Fu`、`Zi`、`Object` 的虚方法表解释调用：子类可以使用继承的公开方法、添加自己的方法；父类私有方法不成为可继承的子类方法。图中的地址与固定“5 个/6 个方法”只是教学示意。

理解重写时应先掌握语言行为：编译器选择方法声明，运行时按对象类型进行适当分派。JVM 可使用虚方法表，也可通过 JIT 去虚拟化、内联等优化。编译器通常生成符号引用，不是在编译 Java 源码时确定最终机器地址。不能把“重写”定义成修改父类方法地址，更不能推导“final 一定更快”。

## 抽象类与抽象方法
*已修改* 原截图展示的错误是：普通类里声明了 `abstract` 方法，编译器要求类也声明为抽象类。下面用 `Shape` 和 `Circle` 演示正确写法：

```java
abstract class Shape {
    private final String color;

    protected Shape(String color) { this.color = color; }
    public String getColor() { return color; }
    public abstract double area();
}

final class Circle extends Shape {
    private final double radius;

    Circle(String color, double radius) {
        super(color);
        if (!Double.isFinite(radius) || radius < 0) {
            throw new IllegalArgumentException("半径必须为有限非负数");
        }
        this.radius = radius;
    }

    @Override public double area() { return Math.PI * radius * radius; }
}
```

*已修改*

抽象类不能直接实例化，可以有构造器、实例字段和已实现的方法，也可以完全没有抽象方法。具体子类必须使所有需要实现的抽象方法得到实现，否则子类也要是抽象类。抽象方法用分号结尾，没有方法体；不能同时标记为 `private`、`static` 或 `final`。

*已补充* 抽象类适合共享状态与部分实现，接口适合描述能力与契约。一旦继承抽象类，就占用了唯一的类继承位置，因此只想表达“能通知”“能支付”时通常先考虑接口。详见 [[06 接口]]。

## final、不可变对象与 Object 方法
### final 的三个含义
*已修改*

- 修饰变量：只能赋值一次；引用不能重新绑定，但对象内部可能可变，类似 JavaScript 的 `const`。
- 修饰方法：不允许子类重写，但满足权限条件时可以继承。
- 修饰类：不允许声明其子类；不意味着对象不可变。

```java
final java.util.List<String> names = new java.util.ArrayList<>();
names.add("Alice"); // 合法：修改对象
// names = new java.util.ArrayList<>(); // 非法：重新绑定引用
```

*已修改*

### equals、hashCode 与 toString
*已补充* 引用的 `==` 比较是否指向同一对象；`equals` 表达逻辑相等，`Object` 的默认实现仍比较身份。重写 `equals` 时要保持自反、对称、传递、一致，以及与 `null` 比较为假，并同步实现 `hashCode`：相等对象必须同哈希，不同对象仍可哈希碰撞。

作为 `HashMap` 键或 `HashSet` 元素时，不要修改参与相等性/哈希计算的字段。`toString` 用于可读表示，不是持久化协议；默认输出的 `类名@十六进制哈希` 也不是可靠的内存地址。`getClass()` 获得运行时类；原图中的 `wait` / `notify` 属于并发协作专题。[Object API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Object.html)

### record 与防御性复制
*已补充* Java 16 起正式提供 `record`，适合表示数据值。它生成组件访问器、`equals`、`hashCode` 和 `toString`；类隐式为 `final`，组件字段也为 `final`，但只保证浅层不可变。

```java
record UserView(long id, java.util.List<String> roles) {
    UserView {
        if (id <= 0) throw new IllegalArgumentException("id 必须为正数");
        roles = java.util.List.copyOf(roles);
    }
}
```

*已补充*

`List.copyOf` 防止外部修改列表结构；本例元素是不可变的 `String`，因此容易安全共享。如果元素是可变对象，还要考虑逐个复制。访问器是 `view.id()`，不是 `getId()`；`record` 不等于传统可变 JavaBean。

## 枚举：用类型表达有限状态
*已纠正* 枚举是有限命名实例组成的类型，不是“特殊 JavaBean”。每个枚举常量对应隐式的 `public static final` 字段；枚举构造器可以显式写 `private`，也可以省略访问修饰符，但不能写 `public` 或 `protected`，外部不能用 `new` 创建枚举实例。

截图中的六种订单状态转写如下，名称字段改为只读的 `label`：

```java
enum OrderState {
    PAYMENT_PENDING("待支付"),
    PROCESSING("处理中"),
    SHIPPED("已发货"),
    OUT_FOR_DELIVERY("配送中"),
    DELIVERED("已送达"),
    CANCELLED("已取消");

    private final String label;

    OrderState(String label) { this.label = label; }
    public String getLabel() { return label; }
}
```

*已修改*

枚举常量在其他成员之前列出，逗号分隔；后面有成员时需要分号。调用及匹配示例：

```java
OrderState state = OrderState.PAYMENT_PENDING;
System.out.println(state.getLabel()); // 待支付
for (OrderState value : OrderState.values()) {
    System.out.println(value.name());
}
System.out.println(OrderState.valueOf("DELIVERED") == OrderState.DELIVERED); // true
String action = switch (state) {
    case PAYMENT_PENDING -> "付款";
    case PROCESSING -> "等待发货";
    case SHIPPED, OUT_FOR_DELIVERY -> "查看物流";
    case DELIVERED -> "评价";
    case CANCELLED -> "重新下单";
};
```

*已修改*

*已补充* `valueOf` 按常量名称精确匹配，未知名称抛 `IllegalArgumentException`。`name()`、显示标签和业务存储编码可以不同；不要把 `ordinal()` 当稳定数据库编码，插入或重排常量会改变序号。枚举限制了“有哪些状态”，合法转换仍需由 `pay()`、`cancel()` 等业务方法约束。

## 内部类与匿名内部类
### 分类与创建方式
*已修改* 宽泛的“嵌套类”包括非静态成员内部类、静态嵌套类、局部类、匿名类。手写的静态内部类创建与调用规则整理为：

| 种类 | 定义位置 | 创建/使用形式 |
| --- | --- | --- |
| 非静态成员内部类 | 外部类中、方法外 | `outer.new Inner()`，关联外部实例 |
| 静态嵌套类（常称静态内部类） | 成员位置，写 `static` | `new Outer.Nested()`，无需关联外部实例 |
| 局部类 | 方法或局部块内 | 在可见作用域内 `new Local()` |
| 匿名类 | 实例创建表达式中 | `new 接口或父类(...) { ... }` |

*已纠正* 原截图把 `static class Engine` 与 `new Outer().new Inner()` 放在一起，两者不匹配。前者应使用静态嵌套类的创建语法。Java 16 之前内部类一般不能声明静态成员，但常量变量是例外；Java 16 起放宽限制。成员类的访问修饰符与是否 `static` 是两回事。

### 非静态成员内部类
*已修改* 原图的 `10 / 20 / 30` 作用域示例：

```java
class Outer {
    private int a = 10;

    class Inner {
        private int a = 20;

        void show() {
            int a = 30;
            System.out.println(Outer.this.a); // 10：关联的外部对象
            System.out.println(this.a);       // 20：内部对象
            System.out.println(a);            // 30：局部变量
        }
    }

    static class Nested {
        int read(Outer outer) { return outer.a; }
        static String kind() { return "nested"; }
    }
}
```

*已修改*

```java
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();
inner.show();
Outer.Nested nested = new Outer.Nested();
System.out.println(nested.read(outer)); // 10
System.out.println(Outer.Nested.kind()); // nested
```

*已修改*

`Inner` 可以访问关联外部实例的私有字段。`Nested` 没有隐含的 `Outer.this`，但可以接收现有的 `Outer` 对象后访问它，不一定要在内部另建一个外部对象。静态嵌套类的实例方法仍需要其自身实例。[官方嵌套类教程](https://dev.java/learn/classes-objects/nested-classes/)

### 局部类
*已纠正* 手写的“定义在方法内”是对的，“没啥用”可改为“较少用”。局部类适合仅在一段逻辑里使用、又需要字段或多个方法的小类型。捕获的局部变量须为 `final` 或有效 final（赋值后不再重新赋值）。不需要命名类时，可考虑匿名类或 Lambda。

```java
static Runnable newTask(String prefix) {
    class LocalTask implements Runnable {
        @Override public void run() { System.out.println(prefix + "完成"); }
    }
    return new LocalTask();
}
```

*已补充*

### 匿名内部类到 Lambda
*已修改* 手写形式 `new 类/接口() { ... }` 同时声明一个没有名字的类并创建实例；整个表达式的结果是对象，类体本身不是对象。接口后的 `()` 不是在调用接口构造器。

```java
@FunctionalInterface
interface Message {
    void send();
}

class MessageDemo {
    static void sendMessage(Message message) { message.send(); }

    public static void main(String[] args) {
        Message message = new Message() {
            @Override public void send() {
                System.out.println("匿名类发送消息");
            }
        };
        sendMessage(message);
        sendMessage(() -> System.out.println("Lambda 发送消息"));
    }
}
```

*已修改*

*已纠正* 手写的“匿名类可以继承父类”成立，也可以实现接口。匿名类可以重写多个方法；只有目标为函数式接口等条件满足时，才能改成 Lambda。函数式接口只有一个函数方法，`@FunctionalInterface` 可以让编译器检查，但不是必须注解。

匿名类中的 `this` 是匿名类实例，Lambda 中的 `this` 沿用外围语境；迁移时须检查这类语义差异。匿名类没有显式命名构造器，但可以使用实例初始化块。完整语法和常用函数式接口继续看 [[07 Lambda表达式]]。

## 面向后端开发的设计重点
*已补充*

- **组合优先于不合适的继承**：订单“有一个”支付策略，不是“一种”支付策略；用字段持有接口对象更自然。继承应满足子类能替换父类的契约。
- **控制可变性**：构造器保证必填数据有效；公开行为方法保护状态；集合输入输出明确是否复制。
- **区分实体和值对象**：用户实体可能按稳定 ID 识别，金额或坐标按值比较。先确定业务相等性，再写 `equals`。
- **保持对象职责集中**：订单负责订单状态，数据库访问交给仓储，通知交给通知服务；避免一个类同时处理 HTTP、SQL 与全部业务。
- **谨慎使用静态可变状态**：Web 请求之间通常应隔离数据；不要把当前用户、购物车存进静态字段。
- **按需使用 sealed**：Java 17 起的密封类型可限定允许的直接子类型，适合有限的领域分支；直接子类按规则选择 `final`、`sealed`、`non-sealed`。有限常量用枚举，需要各分支携带不同数据时再考虑密封层次。
