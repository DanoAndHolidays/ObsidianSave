# 06 接口
> Last Format Time：9/9/2026 11:44:47

接口（`interface`）是一组对外暴露的规范或能力契约。它描述“实现类必须具备什么能力”，而不规定实现类必须采用什么内部数据结构或算法。接口关系独立于类的继承体系，适合表达跨层、跨类型的共同能力。 *已修改*

---
## 接口的定义与实现
### 定义语法
```java
public interface 接口名 {
    // 常量、抽象方法、默认方法、静态方法、私有方法
}
```

接口使用 `interface` 关键字定义。顶层接口通常声明为 `public`，也可以使用包访问权限；嵌套接口还可以使用其他适用的访问修饰符。

### 实现语法
```java
public class 类名 implements 接口名 {
    // 必须实现接口中的抽象方法
}
```

类与接口之间是“实现”关系，通过 `implements` 表示。接口不能直接实例化，以下写法不合法：

```java
// 错误：接口不能创建对象
// Runnable task = new Runnable();
```

实现类必须满足以下条件之一：

- 实现接口中全部抽象方法；
- 将自己声明为 `abstract`，把未实现的方法继续交给子类实现。

一个类可以实现多个接口，也可以在继承一个父类的同时实现多个接口：

```java
class SmartPhone extends Device implements Camera, Network {
    // 同时继承一个类、实现多个接口
}
```

接口只规定能力，不等于对象一定具有某种具体实现；真正的对象仍然由实现类创建。 *已补充*

## 接口成员
### 成员变量：隐式常量
接口中的字段默认被 `public static final` 修饰，必须在声明时初始化，因此它们是公开常量而不是对象属性：

```java
public interface AppConfig {
    int MAX_RETRY = 3; // 等价于 public static final int MAX_RETRY = 3;
    String VERSION = "1.0";
}
```

推荐使用全大写加下划线命名常量。调用时通常使用接口名访问：

```java
int retry = AppConfig.MAX_RETRY;
```

接口字段不能声明为实例变量，也不能在实现类中重新赋值。 *已纠正*

### 抽象方法
传统接口抽象方法默认被 `public abstract` 修饰，可以省略这两个关键字：

```java
public interface Payment {
    void pay(long amount); // 等价于 public abstract void pay(long amount)
}
```

抽象方法只有方法签名，没有方法体；实现类必须提供具体实现。接口中的 `default`、`static`、`private` 方法不属于抽象方法。

接口方法的可见性不能降低。实现类重写接口方法时必须使用 `public`，不能改成 `protected` 或包访问权限：

```java
class Alipay implements Payment {
    @Override
    public void pay(long amount) {
        System.out.println("支付宝支付：" + amount);
    }
}
```

## 类与接口的关系
### 类与类：继承
- 类与类之间使用 `extends`。
- Java 类只能直接继承一个父类，不能多继承。
- 类可以形成多层继承链，例如 `Animal -> Mammal -> Dog`。

```java
class Animal {}
class Mammal extends Animal {}
class Dog extends Mammal {}
```

### 类与接口：实现
- 类与接口之间使用 `implements`。
- 一个类可以实现一个或多个接口。
- 类仍然只能继承一个父类，但可以实现任意多个接口。

```java
interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

class Duck extends Animal implements Flyable, Swimmable {
    @Override
    public void fly() {
        System.out.println("fly");
    }

    @Override
    public void swim() {
        System.out.println("swim");
    }
}
```

### 接口与接口：继承
接口与接口之间使用 `extends`。一个接口可以继承一个或多个接口：

```java
interface Readable {
    String read();
}

interface Writable {
    void write(String text);
}

interface Document extends Readable, Writable {
}
```

接口继承接口后，会组合父接口公开的契约；实现 `Document` 的类需要满足继承链上的全部抽象方法。 *已修改*

## 默认方法（`default`）
Java 8 允许在接口中定义带方法体的默认方法，使用 `default` 修饰。它的主要用途是：在接口升级时增加通用行为，尽量避免破坏已有实现类。 *已补充*

### 定义格式
```java
public interface Logger {
    default void info(String message) {
        System.out.println("INFO: " + message);
    }
}
```

完整格式为：

```java
public default 返回值类型 方法名(参数列表) {
    // 方法体
}
```

`public` 可以省略，但 `default` 不能省略。默认方法不是抽象方法，实现类可以直接继承，也可以按需重写：

```java
class ConsoleLogger implements Logger {
    // 不重写 info，也可以直接使用接口提供的默认实现
}

ConsoleLogger logger = new ConsoleLogger();
logger.info("started");
```

实现类重写时要移除 `default`，并保留 `public`：

```java
class CustomLogger implements Logger {
    @Override
    public void info(String message) {
        System.out.println("CUSTOM: " + message);
    }
}
```

### 默认方法冲突
如果一个类实现的多个接口提供了同名、同参数列表的默认方法，类必须主动解决冲突：

```java
interface A {
    default void show() {
        System.out.println("A");
    }
}

interface B {
    default void show() {
        System.out.println("B");
    }
}

class C implements A, B {
    @Override
    public void show() {
        A.super.show(); // 也可以编写自己的实现
    }
}
```

如果父类已经提供了具体实例方法，父类方法优先于接口默认方法；实现类可以通过重写来明确行为。默认方法只能通过实现类对象调用，不能通过接口名像静态方法一样调用。 *已补充*

## 静态方法（`static`）
Java 8 允许接口定义静态方法。静态方法属于接口本身，不属于实现类实例，也不会被实现类继承或重写。 *已补充*

### 定义格式
```java
public interface NumberUtil {
    static int max(int a, int b) {
        return a > b ? a : b;
    }
}
```

完整格式为：

```java
public static 返回值类型 方法名(参数列表) {
    // 方法体
}
```

`public` 可以省略，但 `static` 不能省略。

### 调用方式
静态方法只能通过接口名调用：

```java
int result = NumberUtil.max(10, 20);
```

以下调用方式不合法或不应使用：

```java
class Demo implements NumberUtil {
    void test() {
        // max(1, 2);       // 不能当作实例方法直接调用
        // NumberUtil.super.max(1, 2); // 静态方法不能这样调用
    }
}
```

接口静态方法不会成为实现类的成员，因此不能通过实现类名或对象名调用。 *已纠正*

## 私有方法（Java 9+）
Java 9 起接口可以声明 `private` 方法，用于在多个默认方法或静态方法之间复用实现细节，避免重复代码。私有方法不能被实现类访问、继承或重写。 *已补充*

```java
public interface TextFormatter {
    default String formatName(String name) {
        return normalize(name);
    }

    default String formatTitle(String title) {
        return normalize(title);
    }

    private String normalize(String value) {
        return value == null ? "" : value.trim();
    }

    private static boolean isBlank(String value) {
        return value == null || value.isBlank();
    }
}
```

私有接口方法只能被接口内部的其他方法调用，不能作为接口对外暴露的契约。

## 函数式接口与 Lambda
函数式接口（Functional Interface）是**恰好包含一个抽象方法**的接口。默认方法、静态方法和私有方法不计入抽象方法数量；从 `Object` 继承的公开方法也不破坏函数式接口定义。 *已补充*

推荐使用 `@FunctionalInterface` 让编译器帮助检查：

```java
@FunctionalInterface
public interface Calculator {
    int calculate(int a, int b);
}
```

函数式接口可以使用 Lambda 表达式或方法引用创建实现：

```java
Calculator add = (a, b) -> a + b;
Calculator multiply = (a, b) -> a * b;

System.out.println(add.calculate(2, 3));
System.out.println(multiply.calculate(2, 3));
```

常见 JDK 函数式接口包括：

| 接口 | 抽象方法 | 典型用途 |
| --- | --- | --- |
| `Predicate<T>` | `boolean test(T)` | 判断条件 |
| `Function<T, R>` | `R apply(T)` | 类型转换 |
| `Consumer<T>` | `void accept(T)` | 消费数据 |
| `Supplier<T>` | `T get()` | 提供数据 |
| `BiFunction<T, U, R>` | `R apply(T, U)` | 接收两个参数并返回结果 |

函数式接口的抽象方法签名决定了 Lambda 的参数和返回值类型；接口可以同时拥有多个 `default` 或 `static` 方法。

## 接口与抽象类对比
| 对比项 | 接口 | 抽象类 |
| --- | --- | --- |
| 关系关键字 | `implements` | `extends` |
| 数量限制 | 类可实现多个接口 | 类只能继承一个抽象类 |
| 构造方法 | 不能定义构造方法 | 可以定义构造方法 |
| 实例字段 | 不能有实例字段，字段默认是 `public static final` | 可以有实例字段 |
| 抽象方法 | 可声明抽象方法 | 可声明抽象方法 |
| 有方法体的方法 | 可有 `default`、`static`、`private` 方法 | 可有普通实例方法、静态方法和抽象方法 |
| 状态复用 | 不适合保存对象状态 | 适合保存子类共享状态和基础实现 |
| 适用场景 | 定义能力、行为契约、跨层解耦 | 表达稳定的“is-a”层次和共享基础代码 |

选择建议：

- 需要让不相关的类拥有同一种能力时，优先考虑接口，例如 `Comparable`、`Runnable`、`AutoCloseable`。
- 需要共享实例状态、构造逻辑或大量受保护基础实现时，考虑抽象类。
- 需要同时复用一个父类和多个能力契约时，使用“继承抽象类 + 实现多个接口”。
- 不要为了复用少量代码滥用继承；可以使用组合、委托或接口默认方法。 *已补充*

## 接口设计原则
### 面向抽象编程
变量、参数和返回值优先使用接口类型，而不是具体实现类型：

```java
List<String> names = new ArrayList<>();
```

这样可以在不改变调用方代码的情况下替换实现：

```java
List<String> names = new LinkedList<>();
```

### 接口隔离原则（ISP）
接口应当小而专注，调用方不应该被迫依赖它不使用的方法。不要设计一个包含几十个无关方法的“大接口”，而应按职责拆分：

```java
interface Printer {
    void print(String text);
}

interface Scanner {
    String scan();
}

class SimplePrinter implements Printer {
    @Override
    public void print(String text) {
        System.out.println(text);
    }
}
```

### 依赖倒置与依赖注入
高层业务代码应依赖接口，具体实现通过构造方法或配置注入：

```java
interface UserRepository {
    String findNameById(long id);
}

class UserService {
    private final UserRepository repository;

    UserService(UserRepository repository) {
        this.repository = repository;
    }

    String getName(long id) {
        return repository.findNameById(id);
    }
}
```

测试时可以传入内存实现或 Mock，避免 `UserService` 直接绑定数据库实现。 *已补充*

### 设计接口时的检查清单
- 接口名称是否表达能力或职责，而不是某个具体技术实现？
- 方法是否足够小、足够稳定，是否把不相关职责拆开？
- 是否需要暴露实现细节？如果只是内部复用，考虑 `private` 方法。
- 新增方法会不会迫使所有实现类修改？若需要兼容升级，可评估 `default` 方法，但不要用默认方法掩盖不合理的接口设计。
- 是否存在多个接口的默认方法冲突？是否需要在实现类中明确覆盖？
- 调用方是否依赖了具体类而不是抽象接口？
- 是否需要使用 `@FunctionalInterface` 约束 Lambda 契约？

## 易错点与总结
- 接口不能直接 `new`，但可以声明接口类型的变量，实际引用实现类对象。
- 接口字段默认是 `public static final`，不能当作实例变量修改。
- 传统抽象接口方法默认是 `public abstract`；实现类重写时必须是 `public`。
- 默认方法可以被继承，也可以被实现类重写；多个默认方法冲突时必须显式解决。
- 静态接口方法属于接口本身，只能通过接口名调用，不会被实现类继承或重写。
- Java 9+ 的接口私有方法只服务于接口内部复用。
- 一个类只能继承一个父类，但可以实现多个接口；一个接口可以继承多个接口。
- 函数式接口只能有一个抽象方法，适合与 Lambda 和方法引用配合。
- 接口强调能力和契约，抽象类强调状态与共享实现；二者不是简单的“谁更高级”，应根据变化方向和复用方式选择。

> 接口的核心价值不是“把方法写在另一个文件里”，而是让调用方依赖稳定的能力契约，让实现可以替换，让系统更容易扩展、测试和维护。 *已补充*
