## 一、集合概述
集合（Collection）是 Java 中用于存储多个数据的容器。与数组相比，集合通常可以动态扩容，并提供了更丰富的增删改查方法。

### 单列集合与双列集合
- **单列集合**：每个元素只包含一个值，例如 `List`、`Set`。
- **双列集合**：每个元素由键和值组成，例如 `Map`。

集合体系可以简化理解为：

```text
Collection（单列集合）
├── List（有序、可重复、有索引）
│   ├── ArrayList
│   ├── LinkedList
│   └── Vector
└── Set（通常不允许重复）
    ├── HashSet
    │   └── LinkedHashSet
    └── TreeSet

Map（双列集合，与 Collection 平行）
```

*补充*：`Map` 不属于 `Collection` 体系。`Map` 中保存的是键值对（`key-value`），而 `Collection` 中保存的是单个元素。

### 泛型与原始类型
如果使用集合时没有声明泛型，集合会按照**原始类型（raw type）**处理，读取元素时通常只能得到 `Object`，并且编译器会给出未经检查的类型转换警告。

```java
Collection list = new ArrayList();
list.add("Java");
list.add(100);

Object value = list.iterator().next();
```

推荐声明泛型，让编译器帮助检查类型：

```java
Collection<String> list = new ArrayList<>();
list.add("Java");
// list.add(100); // 编译错误
```

*补充*：泛型主要在编译期提供类型检查，运行时会发生类型擦除；泛型不能直接使用基本数据类型，需要使用包装类，例如 `List<Integer>`，而不能写成 `List<int>`。

### Collection 常用方法
`Collection` 是单列集合的祖宗接口，许多单列集合都可以直接使用它定义的方法。

| 方法 | 说明 |
| --- | --- |
| `boolean add(E e)` | 将指定元素添加到当前集合中 |
| `void clear()` | 清空集合中的所有元素 |
| `boolean remove(Object o)` | 删除集合中指定的元素；如果成功删除则返回 `true` |
| `boolean contains(Object o)` | 判断集合中是否包含指定元素 |
| `boolean isEmpty()` | 判断集合是否为空 |
| `int size()` | 返回集合中元素的数量 |

示例：

```java
import java.util.ArrayList;
import java.util.Collection;

public class CollectionDemo {
    public static void main(String[] args) {
        Collection<String> list = new ArrayList<>();

        list.add("1");
        list.add("2");
        list.add("3");
        list.add("Java");

        System.out.println(list);              // [1, 2, 3, Java]
        System.out.println(list.contains("2")); // true
        System.out.println(list.size());       // 4
    }
}
```

## 二、Collection 的遍历方式
### Iterator 迭代器
迭代器不依赖索引，是 `Collection` 专用的遍历方式。

```java
import java.util.ArrayList;
import java.util.Collection;
import java.util.Iterator;

public class IteratorDemo {
    public static void main(String[] args) {
        Collection<String> list = new ArrayList<>();
        list.add("1");
        list.add("2");
        list.add("3");
        list.add("Java");

        Iterator<String> iterator = list.iterator();

        while (iterator.hasNext()) {
            // 获取当前元素，并将指针向后移动
            String value = iterator.next();
            System.out.println(value);
        }
    }
}
```

输出：

```text
1
2
3
Java
```

迭代器的两个核心方法：

- `hasNext()`：判断当前位置后面是否还有元素。
- `next()`：获取下一个元素，并将迭代器指针向后移动。

注意事项：

1. 迭代器遍历结束后，指针不会自动复位；如果要重新遍历，需要获取新的迭代器对象。
2. 当前循环中通常只调用一次 `next()`，不要在同一轮循环中重复调用，否则可能跳过元素或抛出 `NoSuchElementException`。
3. 遍历 `Collection` 时，不要直接调用集合对象的结构修改方法来增删元素。
4. 如果需要删除当前元素，应使用 `Iterator.remove()`。

##### 迭代器遍历时直接删除集合元素
下面的写法不安全：

```java
Collection<String> list = new ArrayList<>();
list.add("1");
list.add("2");
list.add("3");
list.add("4");

Iterator<String> iterator = list.iterator();

while (iterator.hasNext()) {
    String value = iterator.next();

    if (value.equals("3")) {
        list.remove(value); // 不要这样做
    }

    System.out.println(value);
}
```

`ArrayList` 的迭代器内部维护了游标 `cursor`。删除元素后，后面的元素会向前移动，但迭代器的游标不会按照集合的变化重新调整，因此可能出现以下情况：

```text
删除前： [1, 2, 3, 4]
读取 1 后 cursor = 1
读取 2 后 cursor = 2
读取 3 后 cursor = 3

删除 3 后： [1, 2, 4]
此时 cursor = 3，size = 3
```

`ArrayList` 迭代器的 `hasNext()` 判断可以近似理解为：

```java
return cursor != size;
```

因此此时 `hasNext()` 可能直接返回 `false`，元素 `4` 没有机会被访问。

如果删除的是 `2`，删除后可能仍有下一个元素需要访问，下一次执行 `next()` 时就可能检测到集合的结构已经被外部修改，从而抛出：

```text
java.util.ConcurrentModificationException
```

*补充*：`ConcurrentModificationException` 属于 fail-fast（快速失败）机制，目的是尽早发现错误的并发或结构修改；它不是并发安全保证，也不保证在所有情况下都一定抛出。

##### 使用 Iterator 安全删除
```java
import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class IteratorRemoveDemo {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("1");
        list.add("2");
        list.add("3");
        list.add("4");

        Iterator<String> iterator = list.iterator();

        while (iterator.hasNext()) {
            String value = iterator.next();

            if (value.equals("3")) {
                iterator.remove();
            }

            System.out.println(value);
        }

        System.out.println(list); // [1, 2, 4]
    }
}
```

`Iterator.remove()` 会同步更新迭代器的内部状态，因此适合删除本次 `next()` 返回的当前元素。

### 增强 `for` 循环
增强 `for` 适合只关心元素、不关心下标的遍历：

```java
for (String value : list) {
    System.out.println(value);
}
```

对于 `Collection`，增强 `for` 底层可以近似理解为：

```java
Iterator<String> iterator = list.iterator();
while (iterator.hasNext()) {
    String value = iterator.next();
    System.out.println(value);
}
```

数组也可以使用增强 `for`：

```java
int[] numbers = {1, 2, 3};

for (int number : numbers) {
    System.out.println(number);
}
```

*补充*：数组并没有实现 `Iterable`，数组的增强 `for` 是编译器按照下标遍历的语法糖；`Collection` 的增强 `for` 则依赖 `Iterable` 和 `Iterator`。

##### 修改增强 `for` 中的变量
```java
for (String value : list) {
    value = "new value";
}
```

上面的代码只修改了循环变量 `value`，不会修改集合中的元素引用。

如果集合中的元素是对象，修改对象的字段则会影响原对象：

```java
for (User user : users) {
    user.setName("Tom");
}
```

这是因为 `user` 与集合中的元素引用指向同一个对象。

增强 `for` 的主要限制：

- 无法直接获得当前元素的下标。
- 不适合精细控制指针移动。
- 遍历 `Collection` 时不应直接调用 `list.remove()` 修改集合结构。

选择建议：

```text
只关心元素              → 增强 for
需要下标                → 普通 for
遍历过程中需要安全删除  → Iterator
```

### `forEach()`、Lambda 与方法引用
`forEach()` 是集合提供的方法，增强 `for` 是 Java 的语法结构，两者不是同一个东西。

```java
// 增强 for
for (String value : list) {
    System.out.println(value);
}

// forEach 方法
list.forEach(value -> System.out.println(value));
```

下面两种写法效果相同：

```java
list.forEach(value -> System.out.println(value));
list.forEach(System.out::println);
```

- `value -> System.out.println(value)` 是 Lambda 表达式。
- `System.out::println` 是方法引用。
- `::` 是方法引用运算符。

`forEach()` 接收的参数可以理解为 `Consumer<String>`：

```java
void accept(String value);
```

它表示接收一个参数、不返回结果的操作。

可以记成：

```text
value -> System.out.println(value)
                    ↓ 可以简写
           System.out::println
```

*补充*：只有当 Lambda 主要是在转调一个已经存在的方法，并且参数顺序、返回值等签名匹配时，才适合改写为方法引用。

## 三、List
`List` 的特点：

- 有序：元素按照插入顺序保存。
- 有索引：可以通过下标访问元素。
- 可重复：允许多个相同元素。
- 继承了 `Collection` 的方法，并增加了许多索引相关的操作。

### List 特有方法
| 方法 | 说明 |
| --- | --- |
| `void add(int index, E element)` | 在指定索引处插入指定元素 |
| `E remove(int index)` | 删除指定索引处的元素，并返回被删除的元素 |
| `E set(int index, E element)` | 修改指定索引处的元素，并返回被修改的元素 |
| `E get(int index)` | 返回指定索引处的元素 |
|

示例：

```java
import java.util.ArrayList;
import java.util.List;

public class ListMethodDemo {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        list.add("A");
        list.add("C");

        list.add(1, "B");       // [A, B, C]
        String old = list.set(0, "a"); // old = A
        String value = list.get(1);    // value = B
        String removed = list.remove(2); // removed = C

        System.out.println(list); // [a, B]
    }
}
```

### `List<Integer>` 的 `remove` 重载陷阱
`List` 中常见的两个 `remove` 方法是：

```java
E remove(int index);       // 按索引删除
boolean remove(Object o);  // 按元素删除
```

示例：

```java
List<Integer> list = new ArrayList<>();
list.add(1);
list.add(2);
list.add(3);
list.add(4);

list.remove(3);                  // 删除 index = 3 的元素，即 4
list.remove(Integer.valueOf(2)); // 删除值为 2 的元素

System.out.println(list);        // [1, 3]
```

第一句 `list.remove(3)` 中的 `3` 是 `int`，优先匹配：

```java
remove(int index)
```

因此删除的是下标为 `3` 的元素，也就是 `4`。

第二句传入的是 `Integer` 对象：

```java
Integer.valueOf(2)
```

它会匹配 `remove(Object o)`，因此删除的是值为 `2` 的元素。

记忆方式：

```java
list.remove(2);                  // 删除下标 2 的元素
list.remove(Integer.valueOf(2)); // 删除值为 2 的元素
```

Java 中：

```text
int      → 基本数据类型
Integer  → 包装类，是 Object 的子类

int → Integer：自动装箱
Integer → int：自动拆箱
Integer → Object：向上转型
```

自动装箱示例：

```java
Integer number = 10;
```

可以近似理解为：

```java
Integer number = Integer.valueOf(10);
```

自动拆箱示例：

```java
Integer number = 10;
int value = number;
```

可以近似理解为：

```java
int value = number.intValue();
```

### ListIterator
`ListIterator` 是 `List` 专用的列表迭代器，比普通 `Iterator` 多提供了向前遍历、添加和修改等能力。

```java
import java.util.ArrayList;
import java.util.List;
import java.util.ListIterator;

public class ListIteratorDemo {
    public static void main(String[] args) {
        List<Integer> list = new ArrayList<>();
        list.add(1);
        list.add(2);
        list.add(3);
        list.add(4);

        ListIterator<Integer> iterator = list.listIterator();

        while (iterator.hasNext()) {
            int value = iterator.next();

            if (value == 1) {
                iterator.add(0);
            }

            System.out.println(value);
        }

        System.out.println(list); // [1, 0, 2, 3, 4]
    }
}
```

常用方法：

| 方法 | 说明 |
| --- | --- |
| `hasNext()` | 判断后面是否有元素 |
| `next()` | 获取后一个元素并向后移动 |
| `hasPrevious()` | 判断前面是否有元素 |
| `previous()` | 获取前一个元素并向前移动 |
| `add(E e)` | 在迭代器当前位置插入元素 |
| `set(E e)` | 修改最近一次 `next()` 或 `previous()` 返回的元素 |
| `remove()` | 删除最近一次返回的元素 |

*补充*：`ListIterator` 的遍历方向和修改位置都依赖迭代器游标，使用 `add()` 后，新增元素通常不会被当前这次向后遍历再次返回。

### ArrayList
`ArrayList` 底层使用动态数组保存元素，适合**查询多、增删少**的场景。

特点：

- 查询速度快，可以根据索引快速访问元素。
- 尾部添加元素通常较快。
- 中间插入或删除元素时，需要移动后续元素，成本较高。
- 允许存储重复元素和 `null`。
- 非线程安全。

底层扩容过程可以这样理解：

1. 使用无参构造方法创建集合时，底层数组初始可能为空。
2. 第一次添加元素时，通常创建默认容量为 `10` 的数组。
3. 容量不足时，通常按照约 `1.5` 倍扩容。
4. 如果一次添加多个元素，`1.5` 倍容量仍然放不下，则会按照实际需要的容量创建数组。
5. 扩容时需要创建新数组并复制旧元素，因此应尽量根据数据规模设置初始容量。

*补充*：上面的容量数字是常见 JDK 实现的底层细节，不属于 `ArrayList` 的接口契约，不应把它当作所有 Java 实现都必须永远遵守的规则。

```java
List<String> list = new ArrayList<>(100);
```

当能够估计数据量时，可以通过初始容量减少扩容和数组复制次数。

### LinkedList
`LinkedList` 底层是双向链表，适合需要频繁在首尾插入、删除的场景。

特点：

- 查询指定索引较慢，需要从链表的一端逐步查找。
- 在已定位节点后进行插入、删除较方便。
- 适合充当队列或双端队列。
- 实现了 `List` 和 `Deque`，可以使用 `addFirst()`、`addLast()`、`pollFirst()`、`pollLast()` 等方法。

*补充*：在大多数普通业务场景中，`ArrayList` 通常是更常见的默认选择；不要仅因为“删除方便”就默认使用 `LinkedList`，还需要考虑查询、缓存局部性和实际数据规模。

### Vector
`Vector` 也是动态数组结构，与 `ArrayList` 类似，但其许多方法带有同步控制。

特点：

- 线程安全特性来自方法级同步。
- 并发场景下的性能通常不如专门设计的并发集合。
- 属于较早期的集合类，现代代码中通常优先考虑 `ArrayList` 或 `CopyOnWriteArrayList` 等更合适的实现。

*补充*：线程安全不等于复合操作天然安全。例如“先判断再删除”仍可能需要额外的同步或并发控制。

## 四、Set
`Set` 的主要特点：

- 通常不允许重复元素。
- 没有索引，不能通过下标访问元素。
- 元素是否有序，取决于具体实现类。

判断重复的基础与 `equals()`、`hashCode()` 或排序规则有关，不能简单理解为“只要内容看起来一样就一定能判断为重复”。

### HashSet
`HashSet` 基于哈希表保存元素，通常具有以下特点：

- 不保证元素的插入顺序。
- 不允许重复元素。
- 查询、添加和删除的平均时间复杂度通常接近 `O(1)`。
- 允许一个 `null` 元素。

```java
import java.util.HashSet;
import java.util.Set;

public class HashSetDemo {
    public static void main(String[] args) {
        Set<String> set = new HashSet<>();
        set.add("Java");
        set.add("Python");
        set.add("Java"); // 重复元素不会被再次添加

        System.out.println(set.size()); // 2
    }
}
```

`HashSet` 判断元素是否重复，主要依赖元素的 `hashCode()` 和 `equals()`：

1. 先根据 `hashCode()` 定位可能的存储位置。
2. 如果位置上存在候选元素，再使用 `equals()` 判断是否真正相等。
3. `equals()` 返回 `true` 时，认为元素重复。

*补充*：如果自定义类重写了 `equals()`，通常也必须同时重写 `hashCode()`，并且保证“相等对象必须具有相同的哈希值”。

### LinkedHashSet
`LinkedHashSet` 是 `HashSet` 的子类，在哈希表基础上维护了链表关系。

特点：

- 不允许重复元素。
- 保持元素的插入顺序。
- 查询、添加和删除通常仍接近哈希表的性能。
- 允许一个 `null` 元素。

```java
Set<String> set = new java.util.LinkedHashSet<>();
set.add("B");
set.add("A");
set.add("C");

System.out.println(set); // [B, A, C]
```

### TreeSet
`TreeSet` 基于树结构保存元素，能够按照排序规则维护元素顺序。

特点：

- 不允许重复元素。
- 默认按照元素的自然排序排列。
- 可以通过构造方法传入 `Comparator` 自定义排序规则。
- 添加、删除和查询通常为 `O(log n)`。

自然排序示例：

```java
import java.util.Set;
import java.util.TreeSet;

public class TreeSetDemo {
    public static void main(String[] args) {
        Set<Integer> set = new TreeSet<>();
        set.add(3);
        set.add(1);
        set.add(2);

        System.out.println(set); // [1, 2, 3]
    }
}
```

自定义排序示例：

```java
Set<String> set = new TreeSet<>((a, b) -> b.compareTo(a));
set.add("A");
set.add("C");
set.add("B");

System.out.println(set); // [C, B, A]
```

*补充*：使用 `TreeSet` 时，元素必须能够按照同一套规则进行比较。比较器返回 `0` 时，`TreeSet` 会把两个元素视为“重复”，即使它们的 `equals()` 结果不一定为 `true`。

### Set 实现类对比
| 实现类 | 是否重复 | 是否保证顺序 | 底层/特点 |
| --- | --- | --- | --- |
| `HashSet` | 不允许 | 不保证 | 哈希表，平均性能较好 |
| `LinkedHashSet` | 不允许 | 保持插入顺序 | 哈希表 + 链表 |
| `TreeSet` | 不允许 | 按排序规则 | 树结构，通常为 `O(log n)` |

*补充*：应根据需求选择 `Set` 实现：不关心顺序时优先考虑 `HashSet`；需要保持插入顺序时考虑 `LinkedHashSet`；需要自动排序时考虑 `TreeSet`。

## 五、集合实现类选择总结
```text
需要有序、可重复、支持索引
→ List

需要快速按索引查询
→ ArrayList

需要频繁操作首尾，或需要双端队列
→ LinkedList / Deque

需要老式同步的动态数组
→ Vector（一般不作为首选）

需要去重，不关心顺序
→ HashSet

需要去重，并保持插入顺序
→ LinkedHashSet

需要去重，并按照规则排序
→ TreeSet
```

### 常见易错点
1. `List<Integer>.remove(int)` 删除的是索引，不是值。
2. 遍历集合时，不要直接通过集合对象结构性修改集合；需要删除时优先使用 `Iterator.remove()`。
3. `HashSet` 是否认为两个对象重复，取决于 `hashCode()` 和 `equals()` 的实现。
4. `TreeSet` 的“重复判断”与比较器返回值有关。
5. 增强 `for` 中给循环变量重新赋值，不会替换集合中的元素引用。
6. `ArrayList`、`HashSet` 等常用集合默认都不是线程安全集合。

*补充*：集合接口描述的是能力和契约，具体实现类的扩容比例、内部字段和部分性能细节可能随 JDK 版本变化；学习底层原理时要区分“接口保证”和“当前 JDK 实现”。
