# 08 泛型
> Last Format Time：9/9/2026 11:50:19

---
## 学习目标
*已补充* 泛型（Generics）把类型作为参数传递给类、接口和方法，使同一套代码能够在编译期安全地处理多种类型。学完本篇应能够：

- 使用泛型类、泛型接口和泛型方法；
- 理解类型参数、类型实参、上界、下界和通配符；
- 掌握 `? extends T`、`? super T` 的读取与写入规则；
- 理解泛型不变性、类型擦除和原始类型的风险；
- 在集合 API 和业务 API 中设计安全、易用的泛型签名。

---
## 泛型的作用
*已修改* 泛型于 JDK 5 引入，主要在**编译阶段**约束数据类型并进行类型检查。泛型的类型参数写在尖括号中：

```java
List<String> names;
List<Integer> numbers;
```

`String` 和 `Integer` 是类型实参，`List` 是泛型类型。

主要收益：

1. **编译期类型安全**：错误尽早暴露在编译阶段；
2. **减少强制类型转换**：从集合中取值时可以直接得到声明的类型；
3. **提高代码复用**：一套实现可以服务于多个引用类型；
4. **改善 API 表达力**：方法签名能表达输入和输出之间的类型关系。

```java
List<String> names = new ArrayList<>();
names.add("Alice");
String first = names.get(0); // 不需要强制转换
```

*已纠正* 泛型类型参数只能使用引用类型，不能直接使用基本类型：

```java
// List<int> numbers = new ArrayList<>(); // 编译错误
List<Integer> numbers = new ArrayList<>();
```

需要基本类型时，使用包装类型并依靠自动装箱和拆箱：

```java
numbers.add(42);       // int -> Integer，自动装箱
int value = numbers.get(0); // Integer -> int，自动拆箱
```

## 类型参数的命名约定
类型参数只是编译期使用的符号，不负责存储数据。常见命名约定如下：

| 符号 | 常见含义 |
| --- | --- |
| `T` | Type，普通类型 |
| `E` | Element，集合元素 |
| `K` | Key，键 |
| `V` | Value，值 |
| `R` | Return，返回类型 |
| `N` | Number，数值类型 |

实际项目中，复杂 API 可以使用具有业务含义的名称，例如 `UserId`、`Request`、`Response`，以提高可读性。

## 泛型类
### 基本写法
```java
public class Box<T> {
    private T value;

    public Box(T value) {
        this.value = value;
    }

    public T get() {
        return value;
    }

    public void set(T value) {
        this.value = value;
    }
}
```

使用时指定类型实参：

```java
Box<String> textBox = new Box<>("Java");
String text = textBox.get();

Box<Integer> numberBox = new Box<>(42);
Integer number = numberBox.get();
```

`<>` 是菱形语法，编译器可以根据变量的目标类型推断构造器中的类型实参：

```java
Box<String> box = new Box<>("hello");
```

### 多个类型参数
```java
public class Pair<K, V> {
    private final K key;
    private final V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K key() {
        return key;
    }

    public V value() {
        return value;
    }
}

Pair<String, Integer> score = new Pair<>("Alice", 95);
```

### 有界类型参数
*已补充* 可以限制类型参数必须是某个类型或其子类型：

```java
public static <T extends Number> double doubleValue(T value) {
    return value.doubleValue();
}
```

`T extends Number` 表示 `T` 可以是 `Integer`、`Long`、`BigDecimal` 等 `Number` 子类型。上界允许在泛型实现中调用上界提供的方法。

多个上界中，类必须放在最前面，接口放在后面：

```java
public static <T extends Number & Comparable<T>> T max(T left, T right) {
    return left.compareTo(right) >= 0 ? left : right;
}
```

类型参数的上界使用 `extends`，即使后面的约束是接口也仍然使用 `extends`。

## 泛型方法
泛型方法的类型参数写在返回值之前：

```java
public static <T> T identity(T value) {
    return value;
}
```

调用时通常由参数和目标类型推断 `T`：

```java
String text = identity("Java");
Integer number = identity(100);
```

也可以显式指定类型实参：

```java
String text = GenericsDemo.<String>identity("Java");
```

*已纠正* 泛型方法的标准格式是：

```java
修饰符 <类型参数> 返回值类型 方法名(参数列表) {
    // 方法体
}
```

例如：

```java
public <T> void show(T value) {
    System.out.println(value);
}
```

这里的 `T` 是类型参数，不是用来记录数据的变量；调用 `show("Java")` 时，编译器根据实参推断出 `T` 为 `String`。

## 泛型接口
泛型接口的定义和泛型类类似：

```java
public interface Repository<ID, E> {
    E findById(ID id);

    void save(E entity);
}
```

实现时可以继续保留类型参数：

```java
public class MemoryRepository<ID, E> implements Repository<ID, E> {
    @Override
    public E findById(ID id) {
        return null;
    }

    @Override
    public void save(E entity) {
        // 保存实体
    }
}
```

也可以把类型参数固定为具体类型：

```java
public class UserRepository implements Repository<Long, User> {
    @Override
    public User findById(Long id) {
        return null;
    }

    @Override
    public void save(User entity) {
        // 保存用户
    }
}
```

接口继承也可以继续声明泛型：

```java
interface Identifiable<ID> {
    ID id();
}

interface UserView extends Identifiable<Long> {
    String username();
}
```

## 泛型不变性
*已纠正* 即使 `Integer` 是 `Number` 的子类型，`List<Integer>` 也不是 `List<Number>` 的子类型：

```java
List<Integer> integers = new ArrayList<>();
// List<Number> numbers = integers; // 编译错误
```

如果允许上述赋值，就可以通过 `List<Number>` 放入 `Double`，从而破坏原来 `List<Integer>` 的类型安全。

```java
List<Number> numbers = new ArrayList<>();
numbers.add(1);
numbers.add(3.14);
```

数组与泛型集合的行为不同：Java 数组是协变的，但错误可能延迟到运行期：

```java
Number[] numbers = new Integer[1];
// numbers[0] = 3.14; // ArrayStoreException
```

泛型集合通常通过编译期不变性更早地阻止这类错误。

## 通配符
通配符 `?` 表示某个未知类型。它适合描述“类型范围”，而不是声明一个需要在多个位置保持一致的类型参数。

### 无界通配符 `<?>`
```java
public static void printAll(List<?> values) {
    for (Object value : values) {
        System.out.println(value);
    }
}
```

`List<?>` 可以接收任意元素类型的 `List`。从中读取的元素只能安全地当作 `Object`，不能向其中添加普通值（`null` 除外）：

```java
List<String> names = new ArrayList<>();
List<?> values = names;
Object value = values.get(0);
// values.add("Alice"); // 编译错误
values.add(null);        // 合法
```

### 上界通配符 `<? extends T>`
`? extends Number` 表示某个未知的 `Number` 子类型：

```java
public static double sum(List<? extends Number> values) {
    double result = 0;
    for (Number value : values) {
        result += value.doubleValue();
    }
    return result;
}
```

它可以接收 `List<Integer>`、`List<Double>` 等列表：

```java
sum(List.of(1, 2, 3));
sum(List.of(1.5, 2.5));
```

但不能安全地添加 `Integer`，因为实际列表可能是 `List<Double>`：

```java
List<? extends Number> values = new ArrayList<Integer>();
// values.add(1); // 编译错误
```

### 下界通配符 `<? super T>`
`? super Integer` 表示某个 `Integer` 的父类型，例如 `Integer`、`Number` 或 `Object`：

```java
public static void addDefaults(List<? super Integer> values) {
    values.add(1);
    values.add(2);
}
```

读取时只能安全地当作 `Object`：

```java
List<? super Integer> values = new ArrayList<Number>();
values.add(1);
Object value = values.get(0);
```

### PECS
*已补充* 记忆规则：**Producer Extends，Consumer Super**。

- 只读取数据、作为生产者：使用 `? extends T`；
- 只写入数据、作为消费者：使用 `? super T`；
- 既要读取又要写入：通常使用精确类型参数 `T`。

```java
public static <T> void copy(
        List<? super T> destination,
        List<? extends T> source) {
    for (T value : source) {
        destination.add(value);
    }
}
```

`Collections.copy` 的设计就是这一思想的典型应用。

## 原始类型与类型擦除
### 类型擦除
*已补充* Java 泛型主要通过类型擦除实现：编译器使用泛型进行类型检查和插入必要的转换，运行时通常不会保留完整的参数化类型信息。

```java
List<String> names = new ArrayList<>();
String name = names.get(0);
```

编译器会保证取值类型，并在需要时生成类型转换；运行时对象通常仍是普通的 `ArrayList`。

因此，以下操作不能直接进行：

```java
// if (value instanceof List<String>) { } // 非法
if (value instanceof List<?>) { }
```

不能直接用类型参数创建实例或数组：

```java
class Factory<T> {
    // T value = new T();       // 非法
    // T[] values = new T[10]; // 非法
}
```

通常使用构造器、工厂函数或传入 `Class<T>` 解决：

```java
public static <T> T create(Class<T> type) throws ReflectiveOperationException {
    return type.getDeclaredConstructor().newInstance();
}
```

### 原始类型
*已纠正* 不写类型实参使用的是原始类型（raw type），例如 `List`，它主要为了兼容 Java 5 以前的代码，不应在新代码中主动使用：

```java
List raw = new ArrayList();
raw.add("Java");
raw.add(42);
```

从原始类型读取时通常需要转换，错误可能延迟到运行期：

```java
String text = (String) raw.get(1); // ClassCastException
```

应使用参数化类型：

```java
List<Object> values = new ArrayList<>();
```

*已纠正* “不写泛型时类型默认是 `Object`”是初学者的简化记忆，但严格来说，`List` 是原始类型，不等同于 `List<Object>`；二者的类型检查和方法调用规则不同。

## 泛型数组与可变参数
泛型数组不能直接创建，但可以使用集合或由调用者传入数组：

```java
public static <T> List<T> listOf(T... values) {
    return List.of(values);
}
```

由于泛型可变参数可能产生堆污染，编译器可能发出警告。只有在实现确实安全时才考虑使用 `@SafeVarargs`，且该注解只能用于构造器、`static` 方法或 `final` 实例方法：

```java
@SafeVarargs
public static <T> List<T> listOf(T... values) {
    return List.of(values);
}
```

不要把可变参数数组暴露给不可信代码，也不要在泛型可变参数数组中存放不同参数化类型的对象。

## 泛型与继承
子类可以指定父类的类型参数：

```java
class Animal {
}

class Dog extends Animal {
}

class AnimalBox<T> {
    T value;
}

class DogBox extends AnimalBox<Dog> {
}
```

一个泛型类不能同时以不同类型参数直接继承同一个泛型父类：

```java
// class Invalid implements Comparable<String>, Comparable<Integer> { }
```

实现 `Comparable<T>` 时，类型参数通常应与当前类一致：

```java
final class User implements Comparable<User> {
    private final long id;

    User(long id) {
        this.id = id;
    }

    @Override
    public int compareTo(User other) {
        return Long.compare(id, other.id);
    }
}
```

## API 设计建议
*已补充* 设计泛型 API 时遵循以下原则：

1. 让类型参数表达真实的类型关系，不为了“看起来高级”而泛型化；
2. 输入参数尽量使用合适的通配符，输出结果尽量返回明确类型；
3. 生产者使用 `extends`，消费者使用 `super`；
4. 不向调用者暴露原始类型和未经说明的 unchecked 警告；
5. 在类型参数名称复杂时使用语义化名称；
6. 对外 API 尽量返回接口类型，如 `List<T>`，而不是具体实现类；
7. 对可变集合明确所有权和是否允许修改；
8. 泛型只解决类型关系，不替代业务校验、权限校验和运行时数据验证。

---
## 常见错误
1. 把 `List<Integer>` 当成 `List<Number>` 使用；
2. 用 `List` 原始类型替代 `List<?>` 或参数化类型；
3. 在 `List<? extends T>` 中尝试写入 `T`；
4. 把 `?` 当成可以直接使用的类型变量；
5. 忽略自动装箱带来的性能和 `null` 拆箱风险；
6. 误以为泛型信息在运行时始终完整保留；
7. 直接创建 `new T()` 或 `new T[]`；
8. 为了消除警告随意添加 `@SuppressWarnings("unchecked")`；
9. 设计嵌套通配符导致 API 难以阅读；
10. 只靠类型擦除解释所有问题，却忽略编译器仍会生成转换并可能在运行时抛出 `ClassCastException`。

## 核心记忆
- 泛型在编译期提供类型安全和代码复用。
- 泛型类型参数只能是引用类型，基本类型要使用包装类型。
- `List<Integer>` 不是 `List<Number>` 的子类型，泛型默认是不变的。
- `? extends T` 适合读取，`? super T` 适合写入，记忆为 PECS。
- 泛型方法在返回值前声明类型参数：`<T> T method(T value)`。
- 类型擦除让泛型主要服务于编译期；原始类型只用于兼容旧代码。
- 设计 API 时让泛型表达真实的类型关系，并优先保证可读性和类型安全。
