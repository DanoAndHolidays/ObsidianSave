# 注解 & 构造函数注入


---
## @Resource & @Autowired
##### @Autowired 
为Spring专属注解，默按类型注入（byType），若 IoC 容器内存在多同类型 Bean 会导致初始化异常，需搭配 @Primary 或 @Qualifier 解决

![[Pasted image 20261018161201.png]]

##### @Resource
源自 JSR-250 规范，默按名称注入（byName），同时支持 byType 模式，先 name 再 type 无需附加注解即灵活适配命名需求

## 构造函数注入
实际项目中，优先使用构造函数注入，Spring 官方也推荐这种方式。它让依赖关系更清晰，也更方便测试

假设 `OrderService` 需要使用 `UserService`，那么 `UserService` 就是它的**依赖**，由 Spring 把所需的对象提供给它，这个过程就叫**依赖注入（DI）**

##### 构造函数注入
通过构造函数的参数接收依赖
```java
@Service
public class OrderService {

    private final UserService userService;

    public OrderService(UserService userService) {
        this.userService = userService;
    }
}
```

Spring 创建 `OrderService` 时，会找到合适的 `UserService` Bean，然后调用构造函数，把这个对象传进来

这里的 `this.userService = userService`，就是把传入的依赖保存到成员变量中

当类只有一个构造函数时，可以省略构造函数上的 `@Autowired` [docs.spring.io](https://docs.spring.io/spring-framework/reference/core/beans/annotation-config/autowired.html?utm_source=chatgpt.com)

##### 字段注入
对象创建后，由 Spring 直接给字段赋值
```java
@Service
public class OrderService {

    @Autowired
    private UserService userService;
}
```

这里没有显式编写构造函数，Java 会提供默认的无参构造函数

Spring 先创建 `OrderService` 对象，然后在后续的依赖注入阶段给 `userService` 字段赋值

执行构造函数时，这个字段还没有被 Spring 注入 [docs.spring.io](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/beans/factory/annotation/AutowiredAnnotationBeanPostProcessor.html?utm_source=chatgpt.com)

两者可以这样对比：

|对比点|构造函数注入|字段注入|
|---|---|---|
|依赖从哪里传入|构造函数参数|标注了 `@Autowired` 的字段|
|注入时间|调用构造函数时传入|对象构造完成后赋值|
|依赖是否直观|看构造函数就知道需要什么|需要检查类中的字段|
|使用 `final`|可以，固定依赖引用|不适合这种构造后赋值的方式|
|普通单元测试|可以直接传入测试替身|通常需要额外工具给私有字段赋值|

### 构造函数注入优势
##### 依赖明确
对于前面的构造函数版本：
```
new OrderService();            // 编译错误：缺少参数
new OrderService(userService); // 正确：明确提供依赖
```

而字段注入版本允许这样写：
```
OrderService service = new OrderService();
```

这段代码可以编译，但**普通的 `new` 不会自动触发 Spring 注入**，内部的 `userService` 仍然是 `null`。构造函数注入让调用者更难遗漏必需依赖

同时，也能将循环依赖问题暴露出来

##### 依赖稳定
可以使用 `final`，让依赖引用保持稳定
```
private final UserService userService;
```

赋值后，不能再把这个字段改成另一个对象。注意，`final` 限制的是**引用重新赋值**，不会让 `UserService` 对象本身自动变成不可变对象。[docs.spring.io](https://docs.spring.io/spring-boot/reference/using/spring-beans-and-dependency-injection.html?utm_source=chatgpt.com)

##### 方便测试
与 IoC 容器强耦合，单元测试困难
测试时可以直接把模拟的依赖传进去：
```
OrderService service = new OrderService(fakeUserService);
```

这样就能单独测试 `OrderService`，不必为了注入依赖而启动 Spring 容器。依赖注入带来的这种可测试性，也是 Spring 官方强调的优点。

##### 生命周期
在构造函数中调用一个 Autowired 注入的 Bean 会导致拿到一个 null，因为对象的生命周期中，构造方法运行的时候，Bean 还没注入
