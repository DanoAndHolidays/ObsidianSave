## 需求与接口设计
表格每页只显示固定条数，后端不能一次把所有员工都返回

```text
GET /emps?page=1&pageSize=10
        ↓
{
  "code": 1,
  "msg": "success",
  "data": {
    "total": 28,       // 总记录数：用来算总页数
    "rows": [ ... ]    // 当前页数据：用来渲染表格
  }
}
```

`total` 和 `rows` 是分页的一对：少了 `total` 前端画不出分页器，少了 `rows` 表格没有数据

---
## 整体链路
```text
GET /emps?page=1&pageSize=10
  │
  ├─ EmpController.page(page, pageSize)   接参数、统一封装 Result
  ├─ EmpService.page(page, pageSize)      算偏移量、组装 total + rows
  ├─ EmpMapper.count()                    统计总记录数
  ├─ EmpMapper.list(start, pageSize)      LIMIT 取当前页
  └─ return Result.success(pageResult)
```

---
## 分页公式
| page | pageSize | start = (page-1)*pageSize | SQL | 取到的记录 |
| --- | --- | --- | --- | --- |
| 1 | 10 | 0 | `LIMIT 0, 10` | 第 1–10 条 |
| 2 | 10 | 10 | `LIMIT 10, 10` | 第 11–20 条 |
| 3 | 5 | 10 | `LIMIT 10, 5` | 第 11–15 条 |

页码从 1 开始，SQL 的起始索引从 0 开始，所以要先减 1

写成 `LIMIT page, pageSize` 是最常见的错，第一页会跳掉一条数据

## Controller
Java 不支持方法默认参数，通常通过方法重载来实现类似效果，可以使用注解 `@RequestParam(defaultValue = "1")` 来设置默认值：
```java
@RequestMapping("/emps")
@RestController
public class EmpController {
    @Autowired
    private EmpService empService;

    @GetMapping
    public Result page(Integer page, Integer pageSize){
        log.info("获取员工分页查询page与pageSize: {}, {}", page, pageSize);
        PageResult<Emp> pageResult = empService.page(page, pageSize);
        return Result.success(pageResult);
    }
}
```

- `@RestController` = `@Controller` + `@ResponseBody`，返回的对象由 Jackson 直接序列化成 JSON
- 类上的 `@RequestMapping("/emps")` + 方法上的 `@GetMapping`，拼出 `GET /emps`
- `page`、`pageSize` 是 query 参数，参数名和方法参数名一致就能自动绑定，并自动完成 `String → Integer` 转换

## Service
```java
@Service
public class EmpServiceImpl implements EmpService {

    @Autowired
    EmpMapper empMapper;

    @Override
    public PageResult<Emp> page(Integer page, Integer pageSize) {
        List<Emp> list = empMapper.list((page - 1) * pageSize, pageSize);
        Long count = empMapper.count();
        return new PageResult<>(list, count);
    }
}
```

接口和实现分开（`EmpService` / `EmpServiceImpl`），是为了以后加事务、加 AOP 日志时不用改调用方 —— 面向接口编程

注意 `(page - 1)` 是 `Integer` 拆箱运算，前端没传 `page` 时它是 `null`，这里会直接空指针

## Mapper
```java
@Mapper
public interface EmpMapper {

    @Select("SELECT COUNT(*) FROM emp LEFT JOIN dept ON emp.dept_id = dept.id")
    public Long count();

    @Select("SELECT emp.*, dept.name AS deptName FROM emp LEFT JOIN dept ON emp.dept_id = dept.id ORDER BY emp.update_time desc LIMIT #{start}, #{pageSize}")
    public List<Emp> list(Integer start, Integer pageSize);
}
```

两个方法就是两条 SQL

```text
count()  → 总数（不带 LIMIT，数全部）
list()   → 当前页（带 LIMIT，只要一页）
```

为什么 `count()` 也写 `LEFT JOIN`：单纯的 `COUNT(*)` 确实不需要 join，但两边数据范围必须一致。以后 `list` 加了"按姓名模糊查""按部门筛选"，`count` 忘记同步，就会出现"总数 100、实际只查出 3 条"

## 数据封装
```java
@Data
public class PageResult<E> {
    private Long total;
    private List<E> rows;

    public PageResult(List<E> rows, Long total) {
        this.rows = rows;
        this.total = total;
    }
}
```

用泛型 `PageResult<E>`，部门分页、班级分页都能复用，不用每个模块写一个返回类

`Emp` 里的 `deptName` 不是 emp 表的字段，是给前端显示用的扩展属性

```java
private String deptName;
```

---
## 细节
### 为什么 dept.name 要 AS deptName
`emp.*` 里没有部门名称。MyBatis 的驼峰映射（`map-underscore-to-camel-case: true`）只负责 `entry_date → entryDate` 这类下划线转驼峰，`name` 和 `deptName` 名字对不上，必须手动起别名，而且别名要和 Java 属性名完全一致

### 为什么 #{start} 不加 @Param 也能用
MyBatis 多参数默认只能叫 `param1`、`arg0`，能直接用形参名，是因为 Spring Boot 父 POM 编译时默认带了 `-parameters` 保留形参名。换成没开这个开关的项目，必须写 `@Param("start")`、`@Param("pageSize")`

### ORDER BY 不是装饰
`ORDER BY emp.update_time desc` 保证分页顺序确定。没有排序时 MySQL 不保证返回顺序，翻页会出现同一条数据重复出现、或者某些数据整条被跳过

更严谨的写法是 `ORDER BY emp.update_time DESC, emp.id DESC`，加唯一列兜底，避免 `update_time` 相同时排序不稳定

---
## 易踩的坑
| 坑 | 说明 | 处理 |
| --- | --- | --- |
| 参数缺省 NPE | page 为 null 时 `(page-1)` 拆箱报错 | `@RequestParam(defaultValue = "1")` |
| pageSize 无上限 | 前端传 999999 等于一次拉全表 | 后端限制最大值，比如 100 |
| 深分页慢 | `LIMIT 1000000, 10` 要先扫过 100 万行 | 数据量大用游标分页 `WHERE id > ? LIMIT 10` |
| 两条 SQL 不一致 | list 和 count 不是同一个快照 | 分页场景可接受，要求严格时放进同一个 `@Transactional` |
| deptName 为 null | 员工的 dept_id 为 NULL 时 | 前端做空值兜底 |

## 前端消费
```ts
const { data } = await axios.get('/emps', { params: { page: 1, pageSize: 10 } });

const rows = data.data.rows;   // 表格数据
const total = data.data.total; // 分页组件总条数
const totalPages = Math.ceil(total / pageSize);
```

页码和后端一致，从 1 开始，切换页码时把新的 `page` 重新发一次请求即可

## PageHelper
现在是手写版，`pom.xml` 里没有 pagehelper 依赖，用 PageHelper 简化

![[Pasted image 20260920173707.png]]

```java
PageHelper.startPage(page, pageSize);       // 开始分页，后面紧跟的第一条查询自动被分页
List<Emp> list = empMapper.list();          // 只写普通查询，不用手算 start
PageInfo<Emp> info = new PageInfo<>(list);  // 包装出 total、pages 等
new PageResult<>(info.getTotal(), info.getList());
```

注意不能加分号 `;`，而且只对其后第一个查询语句生效

|     | 手写版                       | PageHelper 版                   |
| --- | ------------------------- | ------------------------------ |
| SQL | 自己写两条，含 `LIMIT` 和 `COUNT` | 只写一条普通查询                       |
| 原理  | 全部显式写在代码里                 | 拦截器 + ThreadLocal 改写 SQL       |
| 优点  | 无依赖、行为可控、面试好讲             | 代码少、自动算总页数                     |
| 缺点  | 模板代码多、count 容易忘同步         | 隐式魔法，`startPage` 后没紧跟查询就"分页失效" |

## 条件查询
```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<!--
    Mapper 映射文件
    namespace 必须和 EmpMapper 接口的全限定名一致，MyBatis 才会把它绑定到接口上。
-->
<mapper namespace="org.dano.mapper.EmpMapper">
    <!--
        条件分页查询
        - 用 resultType 即可：emp 的下划线字段（dept_id / entry_date / create_time / update_time）
          由 application.yml 中的 map-underscore-to-camel-case: true 自动映射成驼峰属性
        - 关联查询出来的 deptName 与属性同名，会自动映射
        - 这里不写 LIMIT，分页由 Service 层的 PageHelper 负责拼接
    -->
    <select id="list" resultType="org.dano.pojo.Emp">
        SELECT
        emp.*,
        dept.NAME AS deptame
        FROM
        emp
        LEFT JOIN dept ON emp.dept_id = dept.id
        WHERE
        emp.gender = #{gender}
        AND emp.entry_date BETWEEN #{begin}
        AND #{end} AND emp.name LIKE CONCAT('%', #{name}, '%')
        ORDER BY
        emp.update_time DESC
    </select>
    <!--    注意，这里的预编译如果?出现在''中，就要CONCAT 一下了-->
</mapper>
```

### 动态 SQL
优化后：
```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="org.dano.mapper.EmpMapper">
	<select id="list" resultType="org.dano.pojo.Emp">
	    SELECT emp.*, dept.NAME AS deptame
	    FROM emp
	    LEFT JOIN dept ON emp.dept_id = dept.id

	    <!--可以动态添加where-->
	    <where>
	        <!--自动去除多余的 AND 与 OR-->
	        <if test="name != null and name != ''">
	            emp.name LIKE CONCAT('%', #{name}, '%')
	        </if>
	        <if test="gender != null">
	            AND emp.gender = #{gender}
	        </if>
	        <if test="begin != null and end != null">
	            AND emp.entry_date BETWEEN #{begin} AND #{end}
	        </if>
	    </where>
	    ORDER BY emp.update_time DESC
	</select>
</mapper>
```

## 新增
动态的插入数量：
![[Pasted image 20260920230115.png]]

```xml
<insert id="insertBatch">
    INSERT INTO emp_expr(emp_id, begin, end, company, job) VALUES
    <foreach collection="exprList" item="expr" separator=",">
        (#{expr.empId}, #{expr.begin}, #{expr.end}, #{expr.company}, #{expr.job})
    </foreach>
</insert>
```

利用主键返回可以得到主键自增的id

```java
// 主键返回
@Options(useGeneratedKeys = true, keyProperty = "id")
@Insert("INSERT INTO emp(name, username, gender, phone, job, salary, image, entry_date, dept_id, create_time, update_time)" +
        "VALUES(#{name}, #{username}, #{gender}, #{phone}, #{job}, #{salary}, #{image}, #{entryDate},#{deptId},#{createTime},#{updateTime})")
void insert(Emp emp);
```
