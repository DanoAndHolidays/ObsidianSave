# MySQL：唯一约束与唯一索引

[[02 索引]]

唯一约束（Unique Constraint）：数据完整性规则，用于保证字段值不重复
唯一索引（Unique Index）：既能保证数据唯一性，也能加速查询的数据结构

---
## 核心关系
在 MySQL（InnoDB）中，唯一约束通过唯一索引实现

- 添加唯一约束 → 自动创建唯一索引
- 创建唯一索引 → 同时保证数据唯一性
- 两者都能防止重复数据写入，也都能提供索引查询能力
- 对同一组字段，不需要同时创建唯一约束和唯一索引

---
## 创建方式
方式一：添加唯一约束，MySQL 会自动为 `email` 创建唯一索引
```
CREATE TABLE users (
    id BIGINT PRIMARY KEY,
    email VARCHAR(255),
    CONSTRAINT uk_email UNIQUE (email)
);
```

方式二：直接创建唯一索引
```
CREATE UNIQUE INDEX idx_email
ON users(email);
```

两种方式都能保证 `email` 唯一，并支持索引查询

---
## 原理 
InnoDB 的唯一索引通常使用 B+ 树

插入或更新数据时：

1. 检查唯一索引是否存在冲突的键值
2. 如果存在重复值，拒绝写入
3. 如果不存在冲突，则允许写入并维护索引
4. 通过锁等并发控制机制保证唯一性检查的正确性

因此，唯一索引不仅用于查询，还参与数据写入时的约束检查

---
## 注意事项
唯一索引允许多个 NULL
```
email VARCHAR(255) UNIQUE
```

在 MySQL 中允许多个 `NULL`。如果要求不能为空且不能重复：
```
email VARCHAR(255) NOT NULL UNIQUE
```

联合唯一索引保证组合唯一
```
UNIQUE (user_id, product_id)
```

允许不同组合，但不允许重复组合（假设字段均非 `NULL`）

唯一索引不代表查询一定走索引，MySQL 优化器会根据执行计划决定是否使用索引

联合唯一索引也遵循==最左前缀==原则

|类型|保证唯一性|加速查询|
|---|---|---|
|普通索引 `INDEX`|❌|✅|
|唯一索引 `UNIQUE INDEX`|✅|✅|
|唯一约束 `UNIQUE`|✅|✅（自动建立唯一索引）|
|主键约束 `PRIMARY KEY`|✅，且不允许 NULL|✅（InnoDB 中为聚簇索引）|

### 并发问题
Service 可以先查询：
```
有没有名为 Alpha 的团队？
```

如果没有，再创建团队。但并发时可能出现：
```
请求 A：查询，没有 Alpha
请求 B：查询，也没有 Alpha
请求 A：创建 Alpha
请求 B：创建 Alpha
```

如果数据库没有唯一索引，最终会创建两个同名团队

因此需要两层保护：

1. Service 预查询：用来提前返回容易理解的“团队名称已存在”错误

2. 数据库唯一索引 ：负责处理并发竞态，确保无论同时发起多少请求，数据库中最多只有一个同名团队
