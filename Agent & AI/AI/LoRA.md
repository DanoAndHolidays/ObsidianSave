LoRA（Low-Rank Adaptation，低秩适配） 是一种用于大模型的参数高效微调（PEFT）技术。

简单来说：不修改大模型原本的大量参数，而是额外训练一小部分参数，让模型学会新的知识、风格或任务能力。

它主要解决一个问题：大模型参数太多，完整微调的成本很高。

## 1. 为什么需要 LoRA？

假设你有一个包含 70 亿参数（7B）的开源大语言模型。

现在想让它更擅长回答 Java 编程问题。

传统方法是全量微调（Full Fine-Tuning）：

- 训练时更新模型原有的大量参数。
    
- 占用大量 GPU 显存和计算资源。
    
- 每个任务可能需要保存一套完整的模型权重。
    

而 LoRA 的思路是：

原来的模型参数不动，只训练额外添加的小型矩阵。

示意图：LoRA 通常只需更新相对少量的参数，不代表固定的训练比例。

## 2. LoRA 的工作原理

假设模型中原本有一个权重矩阵：

\[ W\in\mathbb{R}^{d\times k} \]

全量微调需要直接调整整个 \(W\)。

LoRA 则认为：不必训练完整的权重变化矩阵，可以用两个更小的矩阵相乘来近似它。

\[ \boxed{W'=W+\underbrace{BA}_{\Delta W}} \]

其中：

- \(W\)：原始权重，冻结不训练。
    
- \(A\)、\(B\)：新增的低秩矩阵，需要训练。
    
- \(\Delta W\)：通过 LoRA 学到的权重增量。
    

例如，原来的权重矩阵是 `4096 × 4096`：

|方案|训练参数量|
|---|---|
|全量训练该矩阵|16,777,216|
|LoRA（rank = 8）|65,536|

对于这个矩阵，LoRA 需要训练的参数减少了约 99.6%。

当然，实际整个模型的训练参数比例还取决于 LoRA 应用在哪些层。

## 3. LoRA 和其他技术有什么区别？

|技术|核心作用|
|---|---|
|Prompt Engineering|通过提示词引导模型回答|
|RAG|检索外部资料，为模型提供上下文|
|LoRA|训练少量参数，改变模型在特定任务上的表现|
|Full Fine-Tuning|调整模型原有的全部参数|

举个 Java AI 助手的例子：

- Prompt：告诉模型“你是一位 Java 高级工程师”。
    
- RAG：从 Java 官方文档中检索内容，再交给模型回答。
    
- LoRA：通过 Java 代码、问答及相关任务数据微调，让模型更适应 Java 开发场景。
    

需要注意，LoRA 不是专门用来灌输大量事实知识的。如果需求是让模型实时查询最新的 Java 文档，通常 RAG 更合适。

## 4. LoRA 常见应用场景

LoRA 不仅用于大语言模型，也广泛用于图像生成模型。

- 大语言模型：行业领域微调、固定输出格式、客服对话、代码任务等。
    
- 图像生成：训练特定人物、绘画风格或角色形象，例如 Stable Diffusion 的 LoRA。
    
- 多任务适配：同一个基础模型搭配不同 LoRA Adapter，适配不同场景。
    

另外，还有一种常见技术叫 QLoRA，它结合量化和 LoRA，进一步降低微调时基础模型权重占用的显存。

## 5. 你应该怎么理解它？

站在开发者角度，可以把一个基础大模型看成通用能力很强的程序。

LoRA 就像是在不修改核心程序的前提下，训练一个轻量级的能力补丁，并在运行时将这个补丁应用到原模型上。

但与普通插件不同，LoRA 学到的内容是神经网络权重的变化，不是一段独立的业务代码。

一句话总结，适合记笔记：

> LoRA（低秩适配）是一种参数高效微调技术。它通过冻结预训练模型的原始权重，引入两个可训练的低秩矩阵来近似权重更新，从而以较少的训练参数和较低的资源成本，让大模型适应特定任务。

如果你准备系统学习 AI Agent，可以先把 LoRA 归类到 AI / 大模型 / 模型训练与微调 / PEFT。它属于模型微调技术，而不是 Agent 框架本身。
