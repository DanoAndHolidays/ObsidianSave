# 完整笔记结构示例
这是一个"好笔记"的标准结构示例。整篇文件展示了所有允许的标题层级、章节分隔符、列表、代码块、链接的正确用法。

---
## 主要章节
H2 下面是 H3。H3 下面紧跟正文（不空行）。
正文段落直接跟在 H3 后面，不空一行。如果正文后接列表，列表前也不空行：
- 列表项 1
- 列表项 2
- 列表项 3

列表项之间不空行。
##### 罕见的五级标题
H4 不用。需要进一步细分时直接跳到 H5。H5 用法示例：
H5 下面是正文，紧跟不空行。H5 上方空一行（按"上一段正文结尾 → 下一个标题 空一行"规则）。

---
## 第二个章节
每个 H2 紧上面（不空行）有一个 `---` 分隔符。H2 紧跟正文（不空行）。
### 带代码块的子章节
代码块前后各空一行（除非代码块紧跟标题/列表）。这里举例：

```tsx
import { useState } from 'react';

const Counter = () => {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
};
```

代码块下面是正文，前后空一行保持可读。
### 带列表的子章节
列表前不空行，列表后空一行再接下一段：
- 列表项 A
- 列表项 B
- 列表项 C

上面列表结束后空一行再接这段正文。
### 嵌套列表
列表里可以嵌套子列表：
1. 第一项
2. 第二项
    - 嵌套 A
    - 嵌套 B
3. 第三项

数字列表和 `-` 列表都可以。

## 例外说明
任何规则都允许例外。例外必须用斜体说明原因。例如，如果 H1 必须跟文件名一致但你想保留 H1 = `# 旧标题`，可以这样写：

```markdown
*原标题：# 旧标题，因为是历史笔记保留原貌*

# 旧标题
正文...
```

上面的 `# 旧标题` 因为有斜体说明是允许的例外。
